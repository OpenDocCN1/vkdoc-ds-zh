# 7. 运输管理参与所需的团队组成和技能矩阵：如何建立运输管理能力

在本章中，我们将讨论以下内容：

- 团队组成对 SAP TM 项目的重要性
- 角色及其技能组合
- 所有阶段的团队组成（从实施到支持）
- 如何组建团队并建立能力
- 留住 SAP TM 顾问的方法

在第 6 章中，我们讨论了成功实施 SAP TM 的各种方法。您可以根据组织的规模、业务需求、挑战和愿景选择其中任何一种方法。成功还取决于领导层的承诺、准备工作以及系统集成商合作伙伴。然而，关键因素是为实施而选择的团队。因此，团队组成非常重要。您需要针对不同阶段（实施、推广和支持）组建具有不同技能组合的团队。由于 SAP TM 9.0 版本相对较新，市场上很难找到经验丰富的顾问。项目发起人目前很难招募到 SAP TM 功能和技术顾问，但这种情况将随着持续进行的实施项目将经验丰富的人才带入市场而改变。团队中应有足够数量的物流领域顾问，他们需全面了解并理解物流流程，能够验证业务需求、例外情况和偏差——这些顾问不仅能加速业务流程映射，还能提供零差错的交付成果。

完全依靠内部团队并不可取。您应该聘请合格的系统集成商，为所需的各种角色提供经验丰富的资源。在设计方案并将其需求与 SAP 股份公司未来的路线图对齐时，您还应该与 SAP 的运输业务部门合作。您需要在内部组建三个团队：一个专注于战略，一个负责指导和监控业务与技术架构，另一个负责管理项目。建议您将项目分解为若干规模可控的子项目。根据已确定的愿景和路线图，许多项目可以同时或依次进行。同时建议将架构角色保留在内部。但是，如果您的公司没有称职的架构师，也绝不应从您已聘请来负责实施的公司/渠道引入架构师。由您自己设计和监控架构总是更好的选择。这将确保您的架构最佳实践得到遵循。此外，您应该将业务架构掌控在自己手中，因为您的业务属于您自己——您知道它与其他竞争对手的不同之处、您独特的销售主张以及公司机密。您最了解什么会影响您的业务。为了从投资中获得最大收益，业务和技术架构团队必须归属于同一个团队。

在现有 SAP 系统中，您的系统集成商合作伙伴在时间、质量和成本方面可能是最佳选择，但对于实施 SAP TM 而言却不一定是最合适的。很少有系统集成商（包括一些领先的厂商）有实施 SAP TM 的成功记录。相比之下，一些精品咨询公司过去几年投入了时间和精力，几乎完全掌握了 SAP TM 的功能，并建立了与其他系统和资产的集成，从而能够加速实施。事实上，这些公司可以在几周内建立一个证明您场景可行性的试点项目。经验是选择的标准之一；在聘请系统集成商之前，您还应考虑的其他因素如下：

-   系统集成商是否充分了解物流领域？
-   系统集成商拥有多少经过培训、经验丰富的资源？
-   系统集成商是否拥有一个实验室或环境，其资源已在该环境中构建或正在构建场景？
-   系统集成商与 SAP 股份公司的运输部门合作有多紧密？系统集成商是否正在联合构建任何解决方案，还是它是 SAP 定制开发计划的一部分？
-   系统集成商是否已投资托管 SAP TM 解决方案？

这些问题的答案可以帮助您选择合适的系统集成商合作伙伴。

## 实施团队的组成

SAP TM 实施项目不同于实施 SAP 企业资源规划模块，因为 SAP TM 不是一个模块，而是一个完整的微型 ERP，它解决了物流业务的核心功能。因此，迁移到 SAP TM 作为核心系统需要领导层最高程度的承诺，以及组织在技术和流程领域为转型做好准备。流程标准化是优化流程、明确角色与职责以及消除个人依赖的关键；此外，文档化的流程可作为组织中每个员工的参考指南。流程标准化是为如此重大的举措做好准备的第一步。在适当考虑本地需求（如税务、跨境法规以及特定国家/产品文档）的前提下进行标准化流程，有助于 SAP TM 的蓝图设计。鉴于这些考虑以及此类项目的重要性，我们在此提出在公司层面和项目层面的角色建议。



## 企业级角色

在实施 SAP TM 的组织中，企业级建议设置以下角色：

**项目发起人**：首席运营官（`COO`）或业务部门负责人通常为 SAP TM 实施项目提供发起支持。需准备一份商业论证，详细阐述愿景、目标和目的、范围、暂定时间表、成功标准、拟议投资、改进领域、增长机会以及投资回报率。可能需要进行详细研究才能构建有意义的商业论证。项目发起人向必须批准该计划的董事会或所有者提交商业论证。项目发起人的职责是确保交付商业论证中向业务部门承诺的价值。发起人需解决组织层面的问题以及任何外部影响，以确保项目顺利进行。发起人还必须指导项目团队。其他职责包括监控项目成本、进度和关键成功因素，并参与与软件、咨询、系统集成商、硬件、通信和培训供应商的价格与条款谈判。建议发起人每月至每季度对项目进行审查，以监控项目健康状况。

**指导委员会**：项目发起人在获得商业论证批准后应任命指导委员会成员。指导委员会由来自不同职能部门的指定领导者组成，例如流程工程、采购、风险与合规、质量控制、业务拓展、客户服务、战略规划、预算编制和技术。首席信息官（`CIO`）通常担任委员会主席，并定期向项目发起人汇报。委员会的宗旨是指导项目组织，并通过提供解决方案和消除依赖关系来帮助项目顺利运行。委员会负责制定供应商选择框架、选择供应商并与之签约、监控项目进度以及指导项目团队。委员会还负责预算，因此必须评估支出与目标达成情况。建议委员会至少每月召开一次会议，以评估项目状况。

**企业架构师**：由企业架构师领导的一组业务和技术架构师在此类规模的项目中扮演着重要角色。业务架构师处理业务变更及其影响、改进领域、自动化机会及流程标准化。技术架构师确保遵循设计原则并遵守架构指南。他们需理解现有技术格局、计划中的转型以及商业论证中详述的愿景。两个团队均应在企业架构师的领导下，确保在 SAP TM 项目的整个生命周期中实施企业架构。如前所述，由内部人员组成该团队符合组织的利益。若团队需要外部资源，则应从未被分配实施或推广任务的供应商处获取。同时建议，鉴于新技术平台、产品和模型正快速演进，应详细研究行业专家的架构框架。

**项目经理（负责人）**：项目经理（负责人）是该项目的单一联络点（`SPOC`）。项目经理（负责人）最好应具备管理物流或供应链管理领域大型项目的经验。拥有成功交付大型 SAP 项目的经验更佳。项目发起人应在指导委员会组建期间任命项目经理（负责人）。项目经理（负责人）负责创建用于任命供应商的范围文档，将范围逻辑地分解为可管理的项目，识别与项目相关的风险，并编写缓解计划。其他职责包括创建变更管理和关键资源计划；识别依赖关系；以及制定项目组织结构、衡量标准、入职计划和报告机制。项目经理（负责人）还需负责签收来自供应商的有意义的可交付成果。

无论是试点项目、部分实施还是组织级实施，这些角色对于在企业层面取得成功都是必要的。



### 项目层级角色

基于我们在运输管理（TM）项目中的经验，我们建议在实施过程中设立以下项目层级角色。具体人数将取决于项目的规模和范围。

#### 项目经理（系统集成商）

项目经理（系统集成商）是系统集成商方项目的单一联络人。理想情况下，项目经理（系统集成商）应具备物流或供应链管理领域大型项目的管理经验。有大型 SAP 项目交付经验者优先。项目发起人应在解决方案构建阶段任命项目经理（系统集成商）。项目经理（系统集成商）必须确保按照工作说明书（SOW）中规定的范围完成交付。项目经理（系统集成商）需与项目经理（甲方）紧密合作，保持步调一致，并在项目层级解决问题。项目经理（系统集成商）向项目经理（甲方）汇报项目进度，后者再向管理层汇报。其他职责包括根据合同规定，从项目经理（甲方）或指导委员会处获取项目里程碑完成确认。

#### 项目经理（项目层面）

项目经理负责制定并监控项目计划。同时负责状态报告、风险管理、升级团队无法解决的问题，以及总体确保项目在预算范围内、按计划并依照商定范围完成交付。作为此大型转型项目的一部分，每个已识别的子项目都需要配备项目经理。可以混合配备人员，既可从内部招聘，也可从系统集成商或其他供应商处引入。

#### 物流领域顾问（主题专家）

该角色对于 SAP TM 的成功实施至关重要。一位在物流行业拥有多年经验的顾问能够理解难点领域以及物流公司内不同角色所面临的挑战。因此，他/她能在构建正确的解决方案中发挥重要作用。具有 SAP TM 实施经验的物流领域顾问更受青睐；然而，具备实施 SAP TM 之外的其他运输管理产品经验的顾问也能满足您的需求。事实上，这类顾问可能是宝贵的资产，因为他们了解实施其他产品的优缺点；这些知识可以加以利用。

由于行业组织方式的特点，很难找到一位对所有业务领域都有深刻理解的人。一些顾问可能精通海运，但没有空运或增值服务的经验。背景为公路运输的顾问可能不具备全球贸易管理的必要知识。因此，根据您的实施策略，您可以选择按业务线或按业务流程来聘用物流领域顾问。您可以组合聘用顾问——部分来自组织内部，部分来自系统集成商或咨询机构。

建议内部选拔至少占主题专家团队的 50%。从系统集成商或商业咨询机构选聘的顾问能带来多样化的经验以及竞争对手/行业领袖遵循的最佳实践。通过举办研讨会，物流领域顾问可以轻松地与业务用户建立联系，以获取关键绩效指标、成功标准、生态系统中各角色的职责、数据交换需求、跨境要求、合规需求以及交易量。物流领域顾问还需提供流程优化建议。此外，物流领域顾问是流程顾问；因此，具备使用业务流程建模或映射工具的经验是可取的。

#### SAP TM 功能顾问

功能顾问需要具备扎实的 SAP TM 知识和丰富的实践经验。顾问应充分理解业务规则框架增强版（`BRFPlus`）。聘用具备其他 SAP 模块经验（如 SAP 物流执行系统（`SAP LE`）、SAP ERP 销售与分销（`SAP SD`）和 SAP 物料管理（`SAP MM`））的顾问将更具优势。具备物流领域知识也是可取的。SAP TM 功能顾问的主要职责是在 SAP TM 中映射业务需求，并配置满足业务需求的系统。

#### SAP TM 技术顾问

SAP TM 技术顾问必须精通高级业务应用程序编程（`ABAP`）并具备 SAP TM 生态系统的实践经验。技术顾问还需要充分理解以下领域：

- **业务对象处理框架（BOPF）**：用于在设计时基于业务对象结构创建服务接口。`BOPF`被认为是 SAP TM 技术领域的核心，SAP TM 技术顾问应具备良好的相关知识。
- **界面方案管理器（FPM）**：一种用户界面，与流程控制框架以及调整流程步骤顺序的策略进行交互；添加额外的、客户特定的步骤以支持 SAP TM 业务策略，同时创建条件和决策点以影响 SAP TM 中的业务策略。
- **SAP NetWeaver 业务客户端（NWBC）**。
- **业务规则框架增强版（BRFPlus）**。

#### SAP 流程集成（PI）顾问

SAP PI 需要将 SAP TM 与 SAP ERP 中央组件（`SAP ECC`）以及您组织中由供应商、客户和边境机构使用的其他系统和第三方产品连接起来。SAP PI 顾问负责构建这些接口。SAP TM 还需要与 SAP 事件管理（`SAP EM`）、SAP 全球贸易服务（`SAP GTS`）、商业智能（`BI`）和仓库管理系统（`WMS`）进行接口对接。应聘用一位具有实践经验的 SAP PI 顾问，最好具备供应链执行与协同系统接口方面的经验。

#### SAP 基础（Basis）顾问

SAP 基础顾问负责处理 SAP TM 的系统管理，包括安装（SAP R/3、SAP NetWeaver 及 NetWeaver 组件、SAP 解决方案管理器[`SolMan`]）、配置（打印机、远程函数调用[`RFC`]、SAP 传输管理系统[`SAP STMS`]）、管理（用户、客户端、备份）和维护（监控服务器、后台作业及系统性能；避免瓶颈）。SAP 基础顾问负责确保系统平稳运行并具有高性能。

#### SAP 财务与控制（FICO）顾问

如果您是 SAP 环境并且已经实施了 FICO，那么您的财务设置可能已经配置完毕。SAP FICO 顾问负责在 SAP ECC 系统中配置财务设置。SAP TM 与 SAP ECC 集成，通过应收账款（`AR`）、应付账款（`AP`）、总账（`GL`）、成本中心和利润中心来管理客户收款和供应商付款。

#### SAP 物料管理（MM）顾问

SAP MM 顾问为系统创建服务框架，从而实现供应商发票结算。仅在实施 SAP TM 时尚未具备必要配置的情况下，才需要此顾问。一般来说，已经在使用 SAP ECC 的组织可能已具备这些配置。

#### SAP 事件管理（EM）顾问

事件管理是最受欢迎的功能之一。客户根据您事件管理能力的成熟度来评价您的服务。正确的设置是必需的。因此，需要一位事件管理顾问。



### 全球贸易管理（GTM）顾问

建议您聘请一位能够配置 GTM 功能的顾问。全球贸易设置必须极其谨慎地进行，因为错误配置的后果十分严重，可能导致业务损失或遭受处罚。

### 遗留系统专家

遗留系统专家的参与对于系统退役至关重要，因为在数据迁移过程中，您可能会丢失多年来以特殊需求形式积累的宝贵经验。该角色在系统接口和数据迁移方面同样至关重要。

### 质量保证顾问

此职位建议由内部人员担任，因为您比任何人都更了解自身业务。如果您决定与外部供应商合作来运行测试工厂，请确保找到的供应商既熟悉测试工厂又精通物流领域。测试和质量控制之所以重要，不仅因为 SAP TM 9.0 是新产品，还因为它需要与您的大部分内部系统及外部系统进行接口交互。请确保批处理进程按预期运行，并且所有接口、功能，尤其是定制功能都能正常工作。

这里讨论的部分资源可能只需要按兼职方式或按需配置，具体参照项目计划中的安排。建议整个项目团队集中在一个地点办公，以便更好地协作。根据实施及后续支持阶段的成功情况，您可能需要重新审视您的推广计划。实施团队会举办研讨会，向推广领导层分享解决方案细节、架构方面、环境、配置、用户设置以及文档资料。

## 推广与版本发布管理的团队构成

公司核心团队将在整个推广过程中持续存在。一个良好的做法是，从实施团队中保留几名关键人员参与初始推广工作。这些人员可以作为推广团队的导师。指导委员会根据项目地点数量和时间分配，会指定一个或多个推广合作伙伴及版本发布管理合作伙伴。

### 推广团队

推广合作伙伴最好在全球模板实施的最后阶段加入。他们应在第一个站点的质保期内跟随实施团队学习。

您需要实施团队的各类技能来执行推广工作。但是，您不需要同样数量的资源。应保留拥有多种技能组合的顾问。此外，实施所需的业务能力水平高于推广。推广顾问应了解目标国家或站点的具体本地化要求。不同国家有不同的法律和法规要求；在推广标准模板时必须解决这些问题。表格和文档也可能需要使用当地语言和格式。

如果您能从实施团队中抽调几名成员参与推广，您很快就能实现自主推广。然而，从公司或区域团队为推广团队提供人员支持并非总是可行。从您这边来看，您必须在站点安排所有必要的支持，以协助执行推广工作的团队。指导委员会有责任组建一个本地推广支持团队，其成员包括站点经理、站点 IT 单一联络点（`IT SPOC`）、本地流程负责人、关键用户以及作为测试人员的核心业务用户。

除项目经理外，推广团队成员需要为他们各自领域/范围内确定的关键用户和核心同事提供培训。推广团队负责以下工作：数据迁移；按全球模板的要求演示端到端场景；识别并记录新功能；配置本地化设置；以及开展培训。

推广经理负责在指导委员会指定的站点推广全球模板。大规模的站点推广可能需要一个专门团队；然而，一个推广团队也可以被部署到多个规模较小、复杂度较低的站点工作。这些团队可以同时执行推广任务。在这种情况下，最佳做法是将小型站点的关键人员集中到一个中心地点进行培训，之后当他们在各自站点开展推广工作时进行远程指导。

### 版本发布管理团队

一个良好的做法是，为推广和版本发布管理聘请两个不同的供应商。版本发布管理团队为推广团队提供支持，推广团队会分享在推广过程中发现的新需求以及遇到的问题。版本发布团队则独自或在 SAP AG 开发团队的协助下解决这些问题。指导委员会对新需求进行优先级排序。版本发布团队负责实施那些需要立即开发的需求。部分需求会考虑在稍后阶段进行推广，其余的需求则要么获批要么不予考虑。新开发的功能会被回滚或前滚到推广团队已通过版本发布管理团队操作的站点。

版本发布管理团队最好在全球模板实施的最后阶段加入。该团队应进一步在第一个站点的质保期内跟随实施团队学习。版本发布管理团队可以开始见习，随后接管成为主要团队。通过这种方式，团队成员可以学习系统以及问题解决的方法，并逐渐理解框架、产品开发工具包和文档。

版本发布管理团队还应具备实施 SAP TM 解决方案所需的全部技能。该团队大部分工作可以远程完成，但某些团队成员可能需要前往站点进行重大版本的培训。版本发布管理团队还需同时支持多个推广项目。建议设置两到三个不同的版本发布管理团队，分别支持同一地区和时区的国家。您还可以通过让不同时区的团队工作时间部分重叠来实现优化。版本发布管理团队由版本发布经理领导，并由各版本发布团队的负责人提供支持。

## 支持团队构成

支持管理团队将接替版本发布管理团队的工作。供应商可以不同，也可以相同。不建议内部自行组建支持团队，因为系统集成商（SI）能够提供最佳实践、工具和资产，这些有助于优化支持资源。此外，由于这是`24/7`的持续需求，SI 供应商具有利用低成本国家的共享资源和团队的优势。

建议支持管理团队中包含 SAP TM 功能和技术顾问、SAP Basis 顾问以及 SAP PI 顾问。

# 8. 业务如何与数据团队互动

> *没有你，就没有改变*
>
> ——Mötley Crüe《Without You》

要从数据中获得最大价值，本书所述的数据团队与你所在组织的业务部门之间需要持续互动。数据产品本身并不能创造价值。数据科学家可以全年分析数据，但只有在实现某种业务价值时，才能产生影响力。

企业究竟如何从大数据中获益？这一切都始于将`不可能`变为`可能`。每个数据团队都以自己的方式支持价值链的创造。对于业务部门而言，价值链的最终收益可能来自许多方面，具体取决于组织及其收入形式。有时，业务部门从一开始就知道自己想要什么，并赞助一个项目或整个数据团队的创建。另一些时候，业务部门会以某种方式引入赞助或合作伙伴关系。无论如何，业务部门都在试图将客户或用户的问题与技术解决方案联系起来。

业务互动对于确保数据产品回答以下问题至关重要：

*   当前的数据产品是否真正满足了业务需求？

*   数据产品是否创造了价值？

*   数据产品的创建或完成时间是否在业务可接受的范围内？

本章将从以下几个方面探讨这些互动：

*   推动变革的源头

*   数据团队及其成员应设在何处

*   业务部门应如何与数据团队互动

*   资金与资源

*   互动的主题

*   奖励与衡量成功

## 如何实现变革

成为一家以数据为中心的公司需要经历巨大的变革。管理层需要站在推动这一变革的最前沿。组织如何实施变革将取决于推动变革的是组织的哪个层级：自上而下、中层还是自下而上。

### 自上而下的推动

自上而下的推动意味着变革来自组织的首席级别或其他高管。在实现转变的三种方式中，这是影响变革最不痛苦的一种。

高管面临的困难在于，如何让整个组织在数据目标和战略上达成一致。仅仅制定数据战略是不够的。高管们需要持续推动，使组织成为以数据为中心的机构。他们可以通过在决策时要求提供相关数据来以身作则。

自上而下的压力在确保打破数据孤岛方面最为有效。高管们需要确保组织中的其他团队理解与数据团队合作的重要性。

高管们还需要确保为团队提供适当的资源。这包括为新的数据团队设置人员编制。其他资源还包括团队在学习分布式系统或特定架构咨询方面所需的外部帮助。这可以防止团队陷入困境，无法在数据战略上取得进展。

### 中层的向上与向下施压

有时，中层管理人员会更早地看到组织变革的必要性。他们的困难在于身处所有人的中间。他们必须通过向上和向下同时施压来推动变革。

我经常发现架构师也处于中间位置。他们需要同时关注组织的技术和业务需求。他们可能是最早看到`不可能`的人之一。

这个中间位置对于推动变革来说是困难的，但并非不可能。中层管理人员需要花时间说服高层管理人员，让他们认识到创建数据团队的需求和业务价值。中层管理人员还需要说服普通员工，让他们认为值得花时间和精力去学习分布式系统。我强烈建议管理者从寻找创建数据团队的业务价值开始，并将大部分精力用于说服高层管理人员相信其好处。

可能无法说服所有人相信这些好处，尤其是高层管理人员。在这种情况下，我建议中层管理人员通过项目的成功来引领，例如，创建一个“臭鼬工厂”项目来解决组织中的一个`不可能`。这个项目应该清楚地展示出，如果组织开始直接投资于一个数据团队，将会带来怎样的潜在价值和好处。大多数人——尤其是高层管理人员——倾向于支持一个已经取得胜利并展现出前景的团队，而不是在一个未经证实的项目和团队上冒险。

### 自下而上

虽然这本书是为管理层写的，但我猜普通员工也会阅读。我假设你看到了对数据团队的需求，并且正在想办法实现它。这也许是因为管理层——无论是中层还是高层——对此不感兴趣，或者并不真正理解数据的潜在价值。自下而上地推动会很有挑战性，但确实有人做到了。

普通技术人员往往缺乏正确的措辞或定位来推动事情的发展。你是否在说我们需要开始使用分布式系统技术 X？这也许无法引起管理层的共鸣，因为他们不知道也不关心分布式系统技术 X 能为组织做什么或将做什么。技术 X 可能并非完成这项工作的合适工具。相反，你应该谈论这项技术将为组织带来什么，或者能实现什么样的特定业务成果。如果你专注于将`不可能`变为`可能`，并说明在那之后业务能做什么，那么业务部门就会更容易接受关于创建数据团队的新想法。

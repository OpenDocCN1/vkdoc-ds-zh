# 客户服务算法

该中心专注于管理客户互动（例如路由工单、推荐回复等）的算法。

数据科学家负责自行编写`ETL`、训练模型并将其部署到生产环境。Stitch Fix 希望他们的数据科学家尽可能贴近业务问题——与业务部门合作，验证某个模型或新方法是否真正解决问题或改善指标。在某些情况下，数据科学家就是业务本身，肩负着直接影响营收及其他指标的责任。

## 平台团队

平台团队负责搭建开发和运行算法所需的一切基础设施和工具。实际上，他们让数据科学家无需深入了解运行算法所需的大量高级计算机科学概念——如容器化、分布式处理、自动故障转移等。这样一来，数据科学家便可以在更高的抽象层级上编写代码，乐得不知后台发生的分布式与并行化处理。这使他们能够专注于将科学应用于业务问题，同时避免将工作交接给他人。

通过为数据科学团队和平台团队招聘合适的人才，并让各自专注于自己擅长的领域，管理者可以让数据科学家的工作效率大大提高。借助该平台，数据科学家可以拥有并创建解决整个业务问题的方案。Eric 在描述该平台时表示：“它真正让数据科学家能够掌控他们正在处理问题的方方面面——从思考如何构建模型，到获取数据、设计算法、训练模型、因果性地衡量影响，以及与业务部门的合作伙伴协作，全程无需将工作移交或交接给其他职能部门。”

运营职责由平台团队和数据科学团队共同承担。Stitch Fix 已建立对生产系统的广泛监控，这有助于他们快速定位问题根源。根据问题的明显根源，负责该系统的团队会收到需要运营支持的警报。每个算法都有不同的`SLA`，具体取决于其成熟度和风险因素。团队不希望采用一刀切的`SLA`，因为在许多领域，他们更看重创新而非稳定性。

Stitch Fix 的架构完全在云端运行。他们从云计算中获得的主要优势是敏捷性。数据科学家和平台工程师能够随时启动新集群来尝试新想法。如果该想法未能产生预期效果，这些资源也可以同样迅速地关闭。这减少了对围绕尝试哪些想法建立大量流程的需求。

## 自下而上的方法

我发现 Stitch Fix 创造算法的方法非常吸引人。在大多数组织中，事情往往采取自上而下的方式。某位高管下达指令，每个人执行该指令，或者一个业务部门资助特定功能的工作。相比之下，Stitch Fix 鼓励数据科学采用一种自发涌现或自下而上的方法。

“这源于一个事实，即这类算法无法预先设计；它们必须边进行边学习，”Eric 分享道。公司很早就意识到数据科学的工作流程与其他学科不同。“你不能预先指定一个模型，而必须让数据和机器学习`揭示`模型。”业务部门不能仅仅制定一个需求规格，就指望数据科学家去实现它。

由于这种开放的学习方式，数据科学家自己就能发现通过模型进行改进或优化的需求或可能性。“那些最接近数据、日复一日与数据打交道的人，会发现别人发现不了的东西。我们许多算法能力并非被要求的，”Eric 说。“这些想法并非来自业务人员或甚至我本人或 Brad 的自上而下指令。这些想法来自数据科学家自己。”

Eric 声称，是好奇心驱使数据科学家去探索一个想法。“他们在数据中看到了关联，这暗示了更高效执行某事的方法，或者构建一个全新能力的方法，”Eric 说。“他们情不自禁。一旦观察到，他们就会被迫去追查。”借助对数据的访问权限以及平台提供的几乎无限的计算资源，数据科学家近乎零成本地探索这些想法。“我称之为`低成本探索`。他们无需请求许可就可以探索这些想法。”

但这种好奇心并非臆测；它有数据和统计的支持。“他们有证据——`AUC`（曲线下面积）和其他统计指标——让他们知道何时走在正确的道路上。并非所有想法都会产生好结果。但是，数据和统计提供的证据可以告知你，你究竟是走进了死胡同，还是正在接近可能颠覆游戏规则的东西。” 由此，数据科学家可以将他们的发现提交给团队其他成员，以展示其探索的潜在影响。

Brad 说：“团队中的大多数人都是热衷于解决业务问题、并寻找将数据和算法应用于业务的方法的人。在很多方面，我认为我们最大的成功来自于那些重新思考我们如何运用数据和算法运营业务不同部分的人所带来的突破。这既是解决业务问题，也是解决数学问题。”

当我们谈到这种自发性时，我假设 Stitch Fix 正在推行类似谷歌 20% 项目时间政策的做法，即每个人可以将五分之一的时间用于与日常工作不直接相关的项目。Stitch Fix 决定不这样做，因为他们担心创造某物的过多结构和压力实际上可能对创新不利。他们担心每个人会觉得只需要研究“惊天动地”的想法，而许多简单的想法同样可能有效。

于是，Eric 和 Brad 决定继续让创新由好奇心驱动。“数据科学家几乎总是被好奇心困扰。那种痒必须得挠，”Eric 说。“我最近和团队里的几个人聊天，问他们‘是什么让你想出了那个没人要求但你却做到了的伟大能力？’他们的回答几乎总是‘因为我不得不这样做。’‘我必须弄清楚它为什么不能分解。’或者，‘我必须解释那个异常现象，’又或者，‘我必须验证这个假设是否成立。’”

尽管好奇心是他们进行研究的主要基础，但数据科学家仍然需要对业务有良好的基本了解。Eric 说：“我们的数据科学家具备丰富的业务背景，因此他们可以自行判断某件事的价值有多大。他们可以访问数据来验证自己的想法，并且具备业务背景，知道一个新能力能产生多大的影响。”

数据科学家并非唯一有能力让新想法涌现的人。平台工程师同样受观察驱动。他们并非从数据科学家那里获取需求，而是观察他们的工作方式，并构建框架来使数据科学家更加高效——即使数据科学家并未提出这样的要求。

### 项目管理

要找到一个完美适配数据科学工作中研发环节的项目管理框架实属不易。因为团队无法预料且无法规划的情况实在太多，充满了太多曲折与变数。正因如此，Stitch Fix 并未采用 `Scrum` 或看板这类项目管理框架。他们采用的模式，我将其描述为更接近埃里克·S·雷蒙德在《大教堂与集市》一书中描述的开源项目实践。

通过组建小型团队并配备亲力亲为的管理者，团队便无需复杂的项目管理架构。他们可以更快速、更非正式地推进工作。布拉德表示：“我们采取的方法更像是做一个园丁，你只需要创造让人们能做好工作的环境，偶尔需要修剪一下枝杈，或为新树苗腾出空间，但总的来说，你只需努力营造合适的条件，然后顺势而为。”

埃里克补充道：“这个过程堪称神奇，在我看来，它与当今大多数数据科学公司的运作方式截然不同，那些公司更倾向于自上而下的管理。” 在其他那些自上而下的公司里，通常由数据科学团队之外的人发号施令或构思创意，然后指派数据科学团队的人去执行这些想法。“最好的创意应该来自数据科学家。他们是最接近数据的人。他们能看到我们其他人看不到的模式和异常。”

### 数据的竞争优势

Stitch Fix 身处零售业中竞争异常激烈的细分领域。他们依靠数据来维持竞争优势。“Stitch Fix 的商业模式提供了与众不同的客户体验。但正是这种模式所提供的数据，造就了我们的差异化。它使我们能够比其他零售商实现更好的个性化服务，”埃里克说。Stitch Fix 专注于建立积极的反馈循环和洞察力，以便更好地服务客户。

对于实体零售商而言，许多潜在的反馈循环无法建立。例如，如果有人把衣服留在试衣间，零售商就无法追踪到这件衣服被试穿和拒绝的信息。电商公司能获取更多关于自身业务的数据，但只能从客户挑选的商品中学习。而 Stitch Fix 则专注于闭环这些反馈循环。例如，Stitch Fix 能够让客户尝试他们自己可能不会挑选的衣服。这使得他们能够捕捉到关于合身度、风格、尺码等方面的偏好数据——即使客户最终退回了部分商品。关于客户为何不喜欢某件商品的数据，通常与为何喜欢的数据同样宝贵。这些数据不仅帮助 Stitch Fix 向客户推荐未来的商品，还为他们提供采购哪些库存的决策依据，甚至能让他们设计新款服装。

Stitch Fix 通过数据与客户建立了互惠互利的关系。客户向 Stitch Fix 提供关于自己尺码和风格偏好的宝贵数据；Stitch Fix 则向客户提供高度相关的服装——甚至包括他们从未想过的款式。这种通过数据建立的共生关系使双方都能受益，并为客户分享真实想法创造了绝佳理由。这是采用更传统模式的零售商难以复制的。

通过真正拥有数据的竞争优势并加以利用，算法团队对业务产生了直接影响。“我认为我们算法部门的一个新颖之处在于它对业务的直接影响程度，”埃里克说。“布拉德的部门要对各项指标的实际影响负责，无论是增加收入还是优化降低成本。除了自身影响外，他们还与公司几乎每个部门（营销、商品采购、运营、造型设计等）合作，提供嵌入这些职能中的算法能力。这在 Stitch Fix 非常独特：那是一种真正的责任感。”

Stitch Fix 因其采用的`人在回路中`算法而闻名。在某些情况下，他们需要机器学习的能力，结合人类判断的细微差别能力。例如，用于为客户挑选衣物的造型算法就是如此。然而，在其他情况下，人类判断无法增加价值，只需要机器计算即可。他们称之为`机器对机器算法`。例如，如何将库存分配到各个仓库，或如何为客户匹配造型师。这些算法最初可能是`人对机器`，但一旦对算法有足够信心，就可以将人完全从回路中移除。

要让组织信任并接受“机器对机器”算法，确实非常困难。布拉德说：“这是艺术与科学的结合——人类与机器协同工作。有时会有张力，但那是健康的张力。目标不仅仅是将人类能做的事情自动化，而是让算法能够完成人类自身无法完成的事情。存在一些非常有趣的案例，有时机器和人类意见相左。这就带来了赢得信任和信誉的挑战。但随着时间的推移，当我们能证明机器可以产生非常好的结果时，那就很了不起。尤其是在像 Stitch Fix 这样的公司里赋能员工时，你可以通过实验和数据来实证地证明这一点，表明这确实能让客户更满意。”

埃里克说：“我们的商业模式天生就适合进行实验。我们开展随机对照试验，从而了解事物之间的因果关系。这让我们得以了解决策的结果。而且，事实证明这常常令人感到谦卑！我们了解到，我们的直觉经常出错。我们的许多好主意最终都被证明是错的；它们要么毫无效果，要么甚至会产生反效果！” 秉承数据科学的风格，团队有时会写下他们对各种实验结果预测。实验结束后，他们会拿实际结果与预测进行比较。“通常，我们会发现我们之中没有一个人，甚至连方向上的预测都是对的。看到我们的预测差得有多远，着实令人警醒。但我们必须学会这一点。很可能在商业史上，情况一直都是如此。只是在我们有能力进行恰当的对照实验之前，我们从来不知道决策的结果。无知即是福啊！”

### 给其他公司的建议

我曾与全球各地的管理层交流，他们声称像`Stitch Fix`这样的公司之所以能取得成就，是因为它们位于旧金山。这些管理者认为，世界其他地区的公司无法同等程度地利用数据、招聘优秀人才或高效执行。我将这个问题直接抛给了埃里克和布拉德。

“我确实认为，工作和数据科学总体上并非地理均匀分布。但除了旧金山湾区或纽约之外，也在涌现出越来越多的中心。远程工作的兴起，对全国各地的人们来说可能是个好趋势，”布拉德说。

“聪明人会被其他聪明人所吸引。这使得人才得以聚集，反过来又会吸引更多的公司——尤其是那些真正重视顶尖人才并提供更多创新岗位的公司。这种良性循环将人才集中在相对较少的地方。所以，如果你的公司不在这类地方，这确实是个挑战，”埃里克说。

基于这一挑战，我请他们给那些行动缓慢的大型企业提出建议。

埃里克说：“嗯，我不想太悲观，但对一家老牌守旧的公司来说，这是一条上坡路。公司往往抗拒变革。流程和价值观在初创期就已确立，并成为组织固有的一部分，有点像公司的 DNA。如果这种 DNA 不包含经验主义、实验精神、创新等要素，那么成功引入数据科学团队将会很困难。这就像向体内注入一个外来物种；防御机制会排斥它。并非不可能，但要在一家现有公司做出如此根本性的改变，将会非常艰难。”

布拉德建议：“尝试在公司内部找到这样一个位置：既能提供解决问题所需的数据，又具备使用数据的意愿。理想情况下，你需要一个团队，它不仅利用数据获取洞察或撰写报告，而是真正想要利用数据和算法来做出决策。我认为很少有组织真正倾向于这个方向。但在一个大型组织内部，也可能存在一些团队或能力单元，让你拥有更多机会。”

埃里克补充道：“在一家成熟的现有公司中增加数据科学，远比从一开始就拥有它并让其自然成长要困难得多。作为现有公司的一项新尝试，数据科学团队很可能需要事先声明其计划，甚至要引用投资回报率（ROI）的估算。相比之下，在`Stitch Fix`，数据科学从一开始就是公司架构的一部分。这使得数据科学团队能够探索机会，并在事后认识到投资的回报。也就是说，我们允许先对许多新想法进行试验，在它们被证明成功之后，再投入额外的人力。这消除了事先为单个想法声明 ROI 估算的压力。数据科学解决方案本身存在大量不确定性；最好的方式是通过大量的试错进行广泛探索。”

`Stitch Fix` 在旧金山湾区的人才市场上面临激烈竞争。他们专注于招募背景多样的数据科学家，例如化学、生物学、神经科学领域，偶尔也直接从博士项目中招聘人选。为了找到合适的人，布拉德说：“解决难题，并且真正接受过用科学方法处理问题的训练，这是一套相当通用的技能。我们通常发现，那些具有解决科学问题并运用技术和数据背景的人，做得相当不错。”

我问他们，如果公司能为数据团队提供来自最高管理层（C-level）的大力支持，企业将如何受益。

`Stitch Fix` 早在初期就获得了这种来自管理层的支持。埃里克曾是首席算法官，也是最高管理层成员。“从一开始，我们就将数据科学确立为一等实体，拥有高管代表和专门部门，”埃里克说。布拉德后来接替了他的职位，与 CTO 和 CFO 同属最高管理层。

布拉德补充道：“让所有团队成员向一位最高管理层汇报，会带来若干好处。对于团队而言，我认为这为我们提供了一个非常出色的社区，以及更好的机会和职业发展。” 由于布拉德身居最高管理层，他能够决定数据团队的组织结构。“至于团队向最高管理层成员汇报，我认为在决策层拥有一席之地至关重要。这意味着我们不仅仅是在执行其他团队的想法，而是在真正帮助改变公司思考数据、不确定性以及运用算法的方式。正如埃里克提到的，我认为`Stitch Fix`成功的一部分原因正是我们所拥有的、非常强调经验主义的数据优先文化。而在很大程度上，我将此归功于埃里克——尤其是他在首次加入公司后的许多年里，一直担任最高管理层高管。”

### 事后反思的教训

我问他们，如果以事后诸葛亮的智慧，会做出什么改变或采取不同做法。

埃里克说：“随着数据科学家快速开发模型，我们曾带来一些困扰。模型投入了生产，但可能没有以最稳健的方式编码，所以最终不得不在它们上线运行后进行替换。因此，当然，如果当时能拥有现在的认知，我们一开始就会以正确的方式编写所有算法，这样就不必重写了。但这说来轻松，不过是事后反思罢了！”

布拉德声称他不会做太多改变。“我认为，那些让团队表现得如此出色的通用原则，在相当多的环境中都能奏效：推崇自下而上的创新，雇佣擅长界定问题的通才，并真正让人们能够自主负责。”

我问埃里克和布拉德，他们认为自己在哪些方面做得非常出色。

埃里克说：“我们在算法上下了如此大胆的赌注。事实证明，这对我们的商业模式至关重要。我们的成功很大程度上归功于一开始就拥有一张白纸，能够以正确的方式建立一切。你在职业生涯中会学到东西——通常是从自己的错误中——但原地纠正这些错误可能非常困难。你常常需要一张白纸重新开始。例如，在 Netflix，我的团队内部存在劳动分工，将分析或商业智能团队与数据科学团队分开。两个团队都向我汇报，但他们的工作被分割开来，以利用他们各自的技能组合。这导致了上下文、工具和基础设施的碎片化。我想解决这个问题，但这样做意味着要拆解多年的遗留代码和流程，以及不得不更换大部分团队成员。在同时交付公司优先事项的同时，这样做尤其令人望而却步。但是，在 Stitch Fix，我拥有一张白纸。没有什么需要拆解的。我能够从一开始就建立正确的组织原则。当然，有些东西必须边做边学。但是，我们非常小心地保留可选性，并避免那些难以逆转的事情。”

其他明智的选择包括“尽早引入平台团队，与我们共同成长”以及“为我们自身建立一定的自主权”。将平台团队纳入自己的组织，使他们能够设定自己的方向并统一原则。埃里克回忆道：“我们不想必须把数据科学家的需求‘移交’给工程师去实现。移交限制了快速迭代的能力。相反，我们的算法平台团队构建了一个基础设施，使数据科学家能够自己实现解决方案。”事实证明，这对他们来说是绝妙的一步。埃里克进一步回忆道：“我记得我们风格算法的第一个版本。它是在历史数据上训练的，看起来非常有前景。到了实施的时候，我们有选择：我们可以构建 API 来与工程团队对接，或者他们来做。最终我们决定自己做，这是一个极好的决定。通过拥有 API，我们可以让工程团队完全脱离我们所有的实验和迭代。如果我们没有自己构建它，我们就需要为每一次变更与他们协商，将其纳入他们的路线图。这将会非常困难，因为他们有自己的重要优先事项。”

他总结道：“工程团队和算法团队之间的接口变得相当清晰。部分原因是两个团队使用了完全不同的技术栈：工程团队使用`Ruby`；算法团队使用`Python`和`R`。这导致了良好的解耦，这对我们非常有利。”

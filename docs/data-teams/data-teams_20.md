# 技术债务

数据团队中技术债务的产生——如第 3 章所述——需要被指出并为人所知。当采用“爬行、行走、奔跑”的通用策略实施项目时，团队会有意制造技术债务，这些债务将在下一阶段逐步偿还。公开承认并认可技术债务，将有助于在团队无法 100%实现某个用例时，避免自我谴责或他人的指责。对于那些目前处于 0%水平的业务，50%的水平或许暂时就足够了。剩余的 50%则作为技术债务留存，团队将在后续阶段或迭代中进一步偿还。

管理层应敏锐地意识到正在产生的技术债务。管理者需要确保团队通过协同努力来偿还技术债务——无论这些债务是有意制造还是无意造成的。如果管理层主动或无意中阻止团队回头修复技术债务，数据团队对管理层的信心就会减弱。团队成员会认为管理层对未来不负责任，并且过度关注新功能。不修复技术债务最终会导致大规模的代码重写，耗费大量时间，因为团队从未获得过逐步偿还技术债务的时间。

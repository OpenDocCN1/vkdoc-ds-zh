# 14. 埃里克·科尔森与布拉德·克林根伯格访谈

| --- | --- |
| 时间跨度 | 2011–2019 |

### 背景说明

Stitch Fix 是全球领先的线上个人造型服务商——通过数据科学与人工判断相结合，为客户提供符合其独特品味、生活方式和预算的服装、鞋履及配饰。该服务覆盖美国女性、男性和儿童，以及英国女性和男性。Stitch Fix 的目标是帮助客户展现并成为最好的自己。

埃里克·科尔森于 2012 年创立了 Stitch Fix 的数据团队。他的官方头衔是首席算法官，现已转为荣誉职务。加入 Stitch Fix 前，他曾任 Netflix 数据科学与工程副总裁、雅虎分析经理。埃里克拥有经济学学士学位、信息系统硕士学位，以及管理科学与工程硕士学位。

布拉德·克林根伯格现任 Stitch Fix 首席算法官，是埃里克的继任者。他是 Stitch Fix 数据团队的早期成员。布拉德曾在 Google、Netflix 及其他金融公司担任数据科学家，拥有斯坦福大学统计学博士学位。

### 起点

当埃里克来到 Stitch Fix 创建算法部门时，他是从零开始的。当时，公司的技术栈看起来就像一个典型的 Ruby Web 开发栈，包含一个 Ruby Web 应用程序、一个数据库和 Web 服务器。所有数据都来自 Web 团队或内部系统（如库存管理系统等）。

在典型的 Web 开发者模式下，每当发生变更时，许多字段都会被覆盖。例如，当一件衣服的价格发生变化时，以前的历史价格并不会被保存。这个故事凸显了 Web 开发者和数据团队成员之间的一个重大差异。如果由数据科学家决定，数据将永远不会被删除或更新。这也展示了组织在发展初期必须经历的一些成长和变化。为了让数据科学家开始创建定价模型，Web 工程团队需要创建所有价格的历史数据集。

Web 开发者为数据科学家提供的一个巨大优势是高质量的数据模型。Stitch Fix 早期就将数据的完整性和真实性作为优先事项。数据通过一个具有直观且一致模式的关系型数据库暴露出来。关系型数据库的使用中存在一些需要改变的可变性担忧，例如不保留历史价格，因为历史价格会被直接覆盖。除了可变性的问题外，这种高质量的数据意味着数据科学家可以专注于创造价值，而不是试图判断他们是否能够信任这些数据。当数据出现异常时，数据科学家可以专注于找出异常的业务原因以及如何利用它，而不是试图找出数据存在缺陷的技术原因。所有数据都妥善地存储在数据库中，数据科学家无需进行大量修改就可以直接使用。

### 成长与招聘

起初，埃里克亲力亲为。他很快就意识到需要创建一个团队。他最初招聘的三个人都是数据科学家。第一个员工最初专注于为业务提供基础洞察。第二个员工则被聘用来从事商品销售领域的工作。第三位数据科学家布拉德被聘用来处理造型算法，并改进埃里克早期的一些模型。

由于公司刚起步，数据量起初是可控的。算法部门不需要做太多的数据工程工作，因为他们可以借助 Web 工程师已经创建的系统。因此，数据科学家复制了 Web 工程师使用的 PostgreSQL 数据库，并创建了自己的实例。从那时起，所有分析处理都可以在内存中通过单台计算机使用`Python`或`R`来完成。

随着团队规模扩大到 20 到 24 人，埃里克和团队不得不思考如何创建组织结构。他们不想简单地照搬前公司的默认管理或组织领导策略。相反，团队在封闭会议上从构建部门的基本原则开始讨论。他们辩论了诸如“层级的作用是什么？”以及“我们在设计组织时优化的是什么？”之类的话题。他们决定构建一个为创新而优化的组织结构。^(³⁰) 他们对此非常明确，并认识到这意味着他们在系统稳定性或执行预制需求等其他领域将不那么擅长。但他们知道，在这些领域做出牺牲，换取更多的创新，是非常值得的。

为了契合这一目标，他们建立了一种动手型管理者的文化，这些管理者喜欢亲自参与数据科学工作，而不是主要从事行政管理工作。每位管理者最初只带少数直接下属（最初上限约为五人），以便管理者能保持成就感并在智力上参与到真正的数据科学能力中。布拉德是最早的动手型管理者之一，并持续专注于业务中的造型部分。

仅仅创建管理结构并不能保证生产力或实现组织目标。他们提出了“充满信心地授权责任”这一说法，以此来证明引入层级结构的合理性。这意味着人员管理角色的存在是为了拥有整个算法能力（或一组能力），包括所有技术职能（`建模`、`ETL`、实施、度量等）以及人员职能（招聘、管理、提供反馈等）。这种对能力的垂直聚焦，而不是对技术职能的水平聚焦，使得团队能够扩展到超过 100 名数据科学家，同时保留了快速行动所需的自主权。此外，这种组织结构使他们能够在促进自下而上的创新的同时，交付业务成果。

在实践中，这种方法意味着数据科学家必须拥有多样化的技能才能管理整个能力。他们必须成为通才，并被期望自己完成建模、`ETL`和部署工作。这对于避免与更专业化的劳动分工相关的交接和排期挑战是必要的。这些能力成为组织的基础。相关的能力被组合在一起形成团队，团队再组成部门。以这种方式组织人员，为每个团队创造了自主权，因为它们向上融入组织的其他部分。

最终，部门规模变得足够大，需要增加一层管理层。那时，埃里克招聘了几位总监级别的人员来监督各个团队。这使得团队能够继续扩展。当布拉德接管团队后，他进一步扩大了规模，如今算法团队拥有超过 125 名数据科学家和平台工程师。

### 主要划分：数据科学与平台团队

最终，完全在内存中使用`Postgres`进行处理的方式开始触及数据库和服务器的硬件限制。团队不得不处理 PB 级数据，并需要为算法处理开发一个定制平台。此外，他们还需要提供清晰的接口（`API`），将算法结果交付给各个生产系统。这些活动更需要计算机科学家的技能，而不是数据科学家的技能。因此，Stitch Fix 的算法部门由两个主要小组组成：*数据科学*和*算法平台*，两者都向首席算法官汇报。数据科学团队基本符合本书中设定的定义，只是编程能力要求更高，并涉及更多运维工作。而平台团队则构建基础设施和工具，使数据科学家能够保持自主性。

#### 数据科学团队

数据科学团队进一步划分为与公司主要职能相对应的中心。

##### `商品销售算法`

该中心开发算法来管理库存，并就如何采购和为客户创造最佳产品做出决策。

##### `造型算法`

该中心专注于为造型推荐引擎提供支持的算法。更广泛地说，该中心处理一套将客户与产品进行匹配的算法，包括服装推荐、造型师选择算法以及库存定向。

##### `客户算法`

该中心专注于在服务中为客户个性化体验，独立于服装本身。例如，有些算法可以个性化地决定何时以及如何与每位客户互动。

##### `运营算法`

该中心专注于协调整个公司资源流动的算法，确保劳动力（仓库工人、客服人员、造型师等）的供应与需求相匹配。

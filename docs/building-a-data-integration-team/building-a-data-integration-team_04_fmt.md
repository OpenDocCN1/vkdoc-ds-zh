# 集成背景

> *如果你不能将自己所做的事情描述为一个流程，那么你就不知道自己正在做什么。*
> 
> —W. 爱德华兹·戴明^(⁵)

过去几十年间，技术发展如此迅速，以至于我们常常忘记，如今看似简单的事物，曾经是多么复杂。数据集成最早出现在 20 世纪 70 年代，当时公司员工认识到可以利用大型机数据库来存储不同类型的业务信息。公司及其开发者们制作了早期版本的提取、转换和加载（`ETL`）工具，用于将数据从一个或多个源复制到目标系统。这些多个数据存储库的集合，便是当今数据仓库的前身。

在 20 世纪 80 年代末至 90 年代初，随着数据仓库的概念融入主流技术，大型机、小型机、个人计算机和电子表格之间的集成变得越来越必要。^(⁶) 倡导利用数据集成的支持者随之涌现。被誉为数据仓库之父的比尔·恩门将这一产物称为“企业智慧”，认为它应成为企业基础设施的标准组成部分。^(⁷)

数据仓库是一项广受欢迎的技术突破，软件公司（正如它们在有盈利前景的事业中惯于做的那样）带着各自专有的解决方案进入市场。每个公司都声称自己比竞争对手更胜一筹，结果导致组织内的一个部门（或许只关注自身需求）会采用与另一个部门完全不同的`ETL`工具。因此，与集成所承诺的愿景背道而驰，工具的泛滥反而导致了数据孤岛的*增加*，而非减少。

除此之外，互联网繁荣时期的并购浪潮迫使企业采用多种`ETL`解决方案。每种方案都有其特定的框架，整个仓库解决方案要么需要合并成一个单一系统，要么维持原样，从而将整个架构搞得一团糟。

# 服务

`Gist` 是 `Zoo` 中的核心抽象，它是代码共享的中心。然而，若要组合多个分析代码片段，仅凭 `Gist` 是不够的。例如，它无法表达不同代码片段如何组合在一起的结构。因此，我们引入了另一种抽象：`service`（服务）。

一个服务由三部分组成：`Gists`、`types` 以及 `dependency graph`（依赖图）。`Gists` 是这个服务所需的 `Gist` ID 列表。`Types` 是这个服务的参数类型。任何服务都有零个或多个输入参数和一个输出。这种设计遵循了 `OCaml` 函数的模式。`依赖图`是一种图结构，其中包含关于服务如何组合的信息。图中的每个节点代表一个来自 `Gist` 的函数，并包含该 `Gist` 的名称、ID 以及该函数的参数数量。

`Zoo` 提供了三个关于服务的核心操作：`create`（创建）、`compose`（组合）和 `publish`（发布）。`create_service` 操作根据给定的 `Gist` ID 创建一个服务字典。该操作会从该 `Gist` 中读取服务配置文件，并为配置文件中指定的每个函数创建一个服务。`compose_service` 操作提供了一系列操作，用于将多个服务组合成一个新服务。组合操作通过比较两个服务的“types”字段来进行类型检查。如果组合了不兼容的服务，则会引发错误。组合后的服务可以保存到新的 `Gist` 中，或用于进一步的组合。`publish_service` 操作将服务的代码转换为最终用户可以直接使用的形式。`Zoo` 设计支持多种后端用于这些发布形式。目前，其目标后端包括 Docker 容器、JavaScript 和 MirageOS [37]。

## 类型检查

如第 9.3 节所述，服务组合最重要的任务之一是确保类型匹配。例如，假设有一个图像分析服务，它接受 PNG 格式的图像，如果我们再连接另一个生成 JPEG 图像的服务，那么所得到的服务将因数据类型不匹配而产生无意义的输出。`OCaml` 提供了基本类型，例如 `integer`、`float`、`string` 和 `Boolean`。`Owl` 的核心数据结构是 `ndarray`。然而，所有这些类型都不足以满足上述高级服务类型检查的需求。这促使我们推导出更丰富的高级类型。

为了支持这一点，我们在 `OCaml` 中使用了广义代数数据类型（GADT）。不同平台上已经存在一些模型集合，例如 `Caffe` 和 `MXNet`。我观察到，目前大多数流行的深度学习模型通常可以归纳为三种基本类型：`image`（图像）、`text`（文本）和 `voice`（语音）。基于此，我们为每种类型定义了子类型：`PNG` 和 `JPEG` 图像、`French` 和 `English` 文本，以及 `voice`，即`png img`、`jpeg img`、`fr text`、`en text`、`fr voice` 和 `en voice` 类型。将来可以在 `Zoo` 中轻松添加更多类型。因此，`OCaml` 中的类型检查确保了高级深度学习服务组合的类型安全性和有意义性。

## DSL

`Zoo` 提供了一个极简的 DSL，用于服务组合和部署。

**组合：** 要从 ID 为 `gid` 的 `Gist` 中获取服务，我们使用 `$gid` 创建一个字典，该字典将服务名称字符串映射到服务。我使用 `OCaml` 中的 `Hashtbl` 实现了字典数据结构。`#` 操作符被重载以表示“获取项”操作。因此

`$gid#sname`

可用于获取名为“sname”的服务。现在假设我们有 `n` 个服务：`f[1]`、`f[2]`、…、`f[n]`。它们的输出类型分别为 `t[f1]`、`t[f2]`、…、`t[fn]`。每个服务 `s` 接受 `m[s]` 个输入参数，其类型分别为 `t_s¹`、`t_s²`、…、`t_s^m_s`。此外，还有一个服务 `g` 接受 `n` 个输入，每个输入的类型为 `t_g¹`、`t_g²`、…、`t_g^n`。其输出类型为 `t[o]`。这里，`Zoo` 提供了 `$>` 操作符，用于将一个服务列表与另一个服务组合：`[f1, f2, ..., fn] $> g`

此操作返回一个新服务，该服务有 `sum_{s=1}^n m_s` 个输入，输出类型为 `t[o]`。此操作会进行类型检查，以确保 `t_fi = t_g^i, 对于所有 i 属于 1, 2, ..., n`。

**部署：** 对于一个服务 `s`（无论是基础服务还是组合服务），可以使用以下语法进行部署：

`s $@ backend`

`$@` 操作符将服务发布到某个后端。它返回一个表示要部署的资源 URI 的字符串。

请注意，`$>` 操作符会生成一个树状结构，这在大多数情况下足以满足我们实际的服务部署需求。然而，一个更通用的操作是支持图结构。这将是我下一步的工作。

## 服务发现

这些服务需要一个服务发现机制。为简单起见，每个新发布的服务都会被添加到托管在服务器上的公共记录中。该记录是一个项列表，每个项包含以下内容：该服务所基于的 `Gist` ID；该服务的一行描述；一个表示该服务输入和输出类型的字符串，例如“图像 → 整数 → 字符串 → 文本”；一个服务 URI。对于容器部署，URI 是 Docker Hub 链接；对于 JavaScript 后端，URI 是指向 `JavaScript` 文件本身的 URL 链接。服务发现机制是使用现成的数据库实现的。

## 用例

为了说明上述工作流程，我们设想一个合成场景。爱丽丝是一名法国数据分析师。她知道如何在现有平台上使用机器学习与深度学习模型，但并非专家。她最近的工作是测试不同图像分类神经网络的性能。为此，她首先需要使用基于深度神经网络的神经风格迁移算法修改图像。神经风格迁移算法接收两张图像，并输出一张新图像，该图像在内容上接近第一张图像，在风格上接近第二张图像。这张新图像需要传递给一个图像分类深度神经网络进行推理。最后，分类结果需要翻译成法语。她不想将与学术相关的信息放到谷歌的服务器上，但也找不到任何单一的预训练模型能完成这一系列任务。

这时，Zoo 系统来解决这个问题。爱丽丝找到了可以分别进行图像识别、神经风格迁移和翻译的 Gist。更棒的是，她还可以使用另一个 Gist 进行图像分割，从而大幅提升神经风格迁移的性能。她需要提供的只是一些生成她所需风格图像的简单代码。然后，她可以使用 Zoo 轻松地将这些部分组合在一起。

```ocaml
open Zoo
(* 图像分类 *)
let s_img = $ "aa36e" # "infer";;
(* 图像分割 *)
let s_seg = $ "d79e9" # "seg";;
(* 神经风格迁移 *)
let s_nst = $ "6f28d" # "run";;
(* 英译法翻译 *)
let s_trans = $ "7f32a" # "trans";;
(* 爱丽丝自己的风格图像生成服务 *)
let s_style = $ alice_Gist_id # "image_gen";;
(* 组合服务 *)
let s = [s_seg; s_style] $> s_nst   $> n_img $> n_trans;;
(* 发布到新的 Docker 镜像 *)
let pub = (List.hd s) $@   (CONTAINER "alice/image_service:latest");;
```

请注意，由于列宽限制，代码中使用的 Gist ID 已从 32 位缩短为 5 位。一旦爱丽丝创建了新服务并将其发布为容器，她就可以在本地运行它，将带有图像数据的请求发送到已部署的机器上，并获取法语版本的图像分类结果。

## 讨论

需要注意的一点是，在服务组合中，类型检查是一个很好的特性，但并非唯一特性。从 Web 服务到微服务，业界和研究人员已经研究了组合问题多年。除了检查消息类型、接口等静态信息外，有时还需要检查服务之间的动态行为。在我们的数据分析服务组合场景中也是如此。

例如，生成对抗网络是巨大的网络家族。生成对抗网络由两部分组成：生成器和判别器。生成器尽力根据现有参数合成图像。判别器接收生成器生成的图像，并尽力使用布尔值或百分比值将生成的数据与真实数据区分开。这种相互欺骗的过程会不断迭代，直到判别器无法再区分生成的数据和真实数据。使用 Zoo，用户可能希望将不同的判别器与同一个生成器组合，看看哪种组合能产生最可信的伪造图像。要做到这一点，仅仅匹配这两个服务的类型是不够的。用户还需要指定动态信息，例如服务间消息交换的顺序、数量以及消息本身。

为了解决这个问题，可能需要引入某种形式化方法作为理论基础，以结构化交互并推理服务间的通信过程。其中一种选择是会话类型 [31]。会话类型是针对以通信为中心的编程的一种类型规范。它基于 *π* 演算，其基本思想是通信协议可以被描述为一种类型，这种类型可以在运行时或静态时进行检查。会话类型近年来备受关注，并已在多种语言中实现，包括 OCaml。这种方法可以有效增强 Zoo 中的类型检查，是我在下一步工作中值得追求的一个有前景的未来方向。

## 总结

在本章中，我们首先介绍了 Zoo，这是 Owl 中的一个脚本共享工具，包括其用法和设计。在此基础上，我们探讨了两个主题：服务组合和部署。Zoo 提供了一个小型领域特定语言，以便对不同数据分析服务进行类型检查的组合，并对服务进行版本控制和部署到多个后端。它得益于 OCaml 强大的类型系统。我们还通过一个用例展示了该领域特定语言在组合图像识别、文本翻译等高级机器学习服务方面的表达能力。Zoo 的领域特定语言还支持将组合后的服务部署到多个后端：容器、unikernel 和 JavaScript；服务部署通常需要选择合适的一个后端。

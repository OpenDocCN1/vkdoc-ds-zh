## 前言

在我十岁时，我会花数小时在当地的图书馆里，埋头阅读书籍，并记录一页又一页的笔记，试图吸收所有我能获取的信息。我稳步构建着自己的知识库，以便能够随时准备好所有答案，无论我是用这些知识来写读书报告，还是通过快速回忆世界上的统计数据与事实来给父母留下深刻印象。时光快进到今天，我八岁的儿子对着我厨房台面上的设备喊出问题，便能立即得到答案，无需访问任何网站、翻阅书籍，甚至无需离开家门去寻找那个确切的事实。本质上，这是从可能存储在数据湖——而非结构化数据仓库或书本——的数据中学习。世界已经改变。我们拥有海量数据，仅仅是因为我们具备了捕获数据的能力——我们不再局限于事务系统或仅以书面形式捕获的数据。然而，尽管可用数据量呈指数级增长，真正利用其价值却取决于我们能否在需要时、以需要的方式获取数据。作为技术领导者，我们有责任让这些数据变得可访问，以便将其转化为更有价值的信息。

作为科技和管理出版物中一个广受关注的话题，有人可能会问：我们难道还没解决这个问题吗？嗯，我们有了一个良好的开端，但我认为新的挑战已经出现。信息不再以过去的方式结构化，而是以结构化和非结构化数据集的形式被捕获。在引领我们的组织向前发展时，我们必须通过数据民主化来赋能用户——将数据交到最终用户手中，以便他们能以相关且有意义的方式将其转化为信息。这个概念很强大，许多组织正在拥抱它，但如何有效实施这一挑战仍然是一个障碍。捕获非结构化数据、处理它、然后允许查询访问，这些阶段是怎样的？除此之外，你如何管理访问权限和安全级别？这些都是当今技术领导者面临的新挑战。

好消息是，这些挑战并非不可克服。然而，重要的是，随着数据量的增加，以速度管理数据处理的需求变得至关重要。企业用户期望获得“类似消费者”的体验，其中速度和易用性是关键。我们现在需要的是应对这一现实的实用方法。根据我的经验，这始于一个连贯的企业数据湖战略。数据湖战略需要以最终用户为中心进行架构设计，并要能解决各种问题陈述。与传统的交易报告（在旅程开始时阐明问题陈述）不同，数据湖试图从根本上反向处理这一问题。数据不再是副产品。相反，它等待着用户应用上下文、连接并发现数据，将其转化为能够驱动成果的信息。数据驱动文化的时代已经到来，企业数据湖的原则和架构需要准备好处理数据量、复杂性和灵活性。

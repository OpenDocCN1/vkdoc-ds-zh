# 备份期间处于等待状态的任何 SharePoint Designer 工作流步骤都将在备份完成后恢复并完成。

正如微软所建议的，请确保您的备份和恢复计划能应对适用于您环境的任何声明性或自定义声明性工作流场景。声明性工作流（例如您在 Microsoft SharePoint Designer 中创建的工作流）存储在它们所部署到的网站集的内容数据库中。备份内容数据库可以保护这些工作流。声明性仅意味着工作流的某些部分是预编写的，在此情况下由 SharePoint Designer 编写，这样就不必从头开始编写所有代码。

自定义声明性工作流操作在以下三个位置包含组件：

- 活动的 Visual Studio 程序集存储在全局程序集缓存 (GAC) 中。
- XML 定义文件（`.ACTIONS` 文件）存储在 14（或更高版本）的 `\TEMPLATE\{LCID}\Workflow` 目录中。
- 一个用于将该活动标记为授权类型的 XML 条目存储在它被使用的 Web 应用程序的 `Web.config` 文件中。

如果您的场工作流使用了自定义操作，您应该使用文件备份系统来保护这些文件和 XML 条目。与 Web 部件和事件接收器之类的 SharePoint Server 功能类似，这些文件应在恢复后根据需要重新应用于场。

依赖自定义代码的工作流（例如使用 Visual Studio 创建的工作流）存储在两个位置。工作流的 Visual Studio 程序集存储在全局程序集目录 (GAC) 中，而 XML 定义文件存储在功能目录中。这与 Web 部件和事件接收器等其他类型的 SharePoint Server 功能相同。如果工作流是作为解决方案包的一部分安装的，那么备份内容数据库可以保护这些工作流。

如果您创建的自定义工作流与工作流部署所在的网站集之外的网站集交互，则必须备份这两个网站集以保护该工作流。这包括写入另一个网站集中的历史列表或其他自定义列表的工作流。执行场备份足以备份场中的所有网站集以及与之关联的所有工作流。

尚未部署的工作流必须像任何其他数据文件一样单独备份和恢复。当您正在开发新的工作流但尚未将其部署到 SharePoint Server 场时，请确保使用 Windows 备份或其他文件系统备份应用程序来备份存储工作流项目文件的文件夹。

## 总结

您的场是一个独特且不断变化的复杂系统。在专注于如何成功备份和恢复它时，您需要清晰记录并经过测试的步骤。您不能完全依赖自动化工具，部分原因是它们无法捕获所有内容，另一部分原因是它们只能捕获您指示它们捕获的内容和时间。请记住，您的 SharePoint 场将具有外部依赖项，这些依赖项必须在场恢复之前进行备份和恢复。此外，SharePoint 不仅仅是 SharePoint 应用程序及其设置；它还建立在 Windows 服务器、网络和 SQL Server 之上。没有这些部分，它就无法为用户运行。

您的 SharePoint 场中最重要和最有价值的部分是花费最多时间和精力创建的部分：开发人员编写的代码和用户创建的内容。有些代码和内容比其他代码和内容更重要，我已经讨论过如何对内容进行优先级排序以实现组织的恢复点和恢复时间目标。使用 SharePoint 备份所有内容并创建良好的文档，您将为自己提供成功备份的最佳机会。

归根结底，准备工作和您的知识比您选择的工具更重要。

# 总结思考

你对颠覆性创新的看法取决于你所处的立场。

-   如果你的组织购买并使用分析软件和服务，那么颠覆性创新就是一个机会，让你能够提高分析投资的有效性并降低成本。避免被那些面临颠覆风险的供应商锁定。

-   如果你的组织试图用创新的产品和服务去颠覆他人，那么前几章介绍的开源项目则提供了绝佳的基础。

-   如果你的组织拥有提供业务分析软件和服务的既得业务领域，请当心背后；有人正想抢走你的饭碗。

要从颠覆性创新中获利，请执行以下事项：

-   **围绕客户对数据驱动洞察的需求进行组织。** 不要将分析视为某个大型供应商可以为你解决的单一问题。你的客户对数据驱动洞察有着多样化的需求；请据此定制解决方案。

-   **审慎定义首席分析官的角色。** 在大多数情况下，期望某一位高管“拥有”完整的分析价值链是不切实际的。应委派首席分析官负责在组织中推动数据驱动洞察，然后仔细平衡首席分析官、首席信息官及各职能高管的角色与职责。

-   **将对分析平台的决策权与成本责任相匹配。** 避免出现用户选择平台却无需承担成本责任，而成本是“别人的问题”这种情况。

-   **招聘合适的人才。** 对于分析师，少看重资历和理论知识，多看重分析成果和协作能力。

-   **实践敏捷商业智能。** 将专家部署到职能团队，并鼓励紧密协作。如果有需求，就投资自助式服务工具，但不要认为你对分析专家的需求会消失。

-   **实践敏捷机器学习。** 专注于可重复的流程、缩短周期时间、快速部署以及对生产模型进行持续改进。投资于能够最大化高价值数据科学家生产力的平台。

-   **制定精益数据策略。** 不要再将你的数据仓库视为战略性投资；它不是。将数据收集与对数据驱动洞察的需求对齐。不要收集那些没有定义用户和利益相关者的数据。

-   **评估你的商业软件许可与使用情况。** 冷静、严格地审视你组织中的软件许可情况；如今你几乎肯定存在过度许可的问题。挑战那些坚持必须使用高端商业软件的人。

-   **构建开源技术栈。** 为业务分析定义、构建、交付和支持一个开源技术栈。让该开源技术栈成为你的基准系统。只有当你的开源技术栈无法满足组织记录在案的需求时，才使用商业软件。

-   **利用弹性配置。** 分析工作负载往往是临时和不可预测的，这使得它们成为弹性配置（无论是在云端还是本地）的理想候选。

采取行动回报：分析师效率更高，获取更多数据驱动洞察，做出更佳决策，并降低分析基础设施的总拥有成本。

无所作为的代价不会立刻显现。你的业务分析软件供应商会继续向你发送续费账单。那些未做出的决策、未产生的数据驱动洞察所带来的成本，将永远无法衡量。日子还会照常过。

然而，到了某个时候，会有人问：“你在这里做什么？”

你组织中的一些人可能会反对我们在本章中概述的举措。他们甚至可能称其为颠覆性。

如果他们这样做，请微笑。你走在正确的轨道上。

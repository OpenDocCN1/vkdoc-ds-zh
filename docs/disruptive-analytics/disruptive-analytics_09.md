# 3. 开源分析

免费的颠覆性力量

在各类软件领域中，自由与开源软件的影响力与日俱增。在本章中，我们将探讨以下问题：

* 什么是自由与开源软件？
* 自由与开源软件如何体现其商业价值？
* 分析领域有哪些领先的自由与开源软件项目？

自由与开源软件最显著的特质在于其缺失的部分：软件许可费。在本章中，我们将证明自由与开源软件是可行的，并且它正在颠覆分析软件行业中的现有企业。

## 开源基础

开源软件的精确定义存在一些争议。我们首先回顾各种相互竞争的定义，然后介绍开源软件项目的基础知识，包括治理、许可、代码管理与分发，以及软件捐赠问题。



### 定义

像“自由”和“开源”这样的词看似含义明确。然而，在软件领域，它们却有多重含义。

在标准的商业软件许可模式下，开发者提供软件使用许可，以换取许可费。许可可能是永久性的，也可能是有限期的。此外，还可能存在其他限制：例如指定用户、特定计算设备或特定应用。开发者以编译形式分发软件，通常附带一个许可密钥，用于防止超出软件许可范围的使用。这些措施保护了开发者对软件知识产权的经济利益。

自由及开源软件则运行在一种完全不同的模式下。开发者分发软件源代码本身，并附带一份授予检查、修改和重新分发代码权利的许可。开发者对软件知识产权不主张任何经济权利，并且放弃因使用软件而收取许可费。

有两个组织，即开放源代码促进会（OSI）和自由软件基金会（FSF），它们对“自由软件”和“开源软件”的定义略有不同：

-   自由软件基金会发布了《自由软件定义》，该定义规定，如果用户能够运行、研究、重新分发以及分发软件的修改版本，则该软件便是自由的。
-   开放源代码促进会发布了《开源定义》，该定义详细说明了开源软件的十项标准，包括访问源代码、重新分发的权利等等。

《自由软件定义》定义了一组权利；如果软件用户能够行使这些权利，该软件就是“自由的”。（“自由”指的是“被解放”的意义，而不仅仅是“免费”。）《开源定义》定义了一组特征；如果软件具备这些特征，它就是“开源的”。无论是《自由软件定义》还是《开源定义》，都没有明确说明开发者不得收取许可费；源代码的分发使得收费变得不可能。

假设玛丽根据某种开源许可发布了某款软件的源代码。乔拿到了玛丽的源代码，并以 100 美元的价格不加修改地重新分发。客户很快会发现，他们不需要为能从玛丽那里免费获得的东西向乔付费。如果乔通过以商业许可发布该软件来隐藏其来源，玛丽可以起诉乔侵犯了她的开源许可。

这两个组织之间的差异主要是哲学层面的。自由软件基金会源于自由软件运动，该运动主张专有软件和普遍的知识产权“不应该”存在，这是一种本质上的政治观点。自由软件基金会成立于 1985 年，赞助了大规模协作项目 GNU 项目。

与自由软件基金会相反，开放源代码促进会认为开源是一种更好、更实用的软件开发方式，并回避政治激进主义。撇开政治分歧不谈，两者之间几乎没有实际差异，并且大多数开源许可证都符合这两个组织的标准。

虽然所有开源软件都是“自由的”，因为任何人都可以在不支付许可费的情况下获取源代码，但并非所有“免费”软件都是开源的。商业软件供应商可以且确实会向用户免费提供闭源或专有软件。他们这样做可能是为了建立商业软件产品的知名度和试用机会，允许进行评估，或者采用双重许可模式（我们将在本章后面进一步讨论）。

类似地，并非所有标榜为“开放”的软件都是“开源”的。商业供应商有时会将软件标记为“开放”，因为它有公开的 API，或者因为它实现了如 ANSI SQL 这样的开放标准。定价和文档并不会使一个封闭的产品变得开放；当且仅当软件是根据自由及开源许可证分发时，它才是自由和开放的。

在尊重自由软件基金会和开放源代码促进会之间差异的同时，在本章及全书范围内，我们将使用术语“开源”来表示符合这两个组织定义的软件。

### 项目管理

开源软件项目，如同任何其他项目一样，需要一个职责明确的组织结构。它们还需要一个法律框架来拥有软件资产并向用户发放许可。像 `R` 和 `Python` 这样的大型项目，拥有自己的治理框架；我们将在本章后面单独讨论。在本节中，我们将介绍两个实体，即 Apache 软件基金会和 Eclipse 基金会，它们共同管理着许多广泛使用的开源项目。

Apache 软件基金会（ASF）是一个由个人和企业捐赠资助的 501(c)(3) 慈善组织，其使命是为公共利益提供软件。为了支持这一使命，ASF 提供了一个用于知识产权管理的法律框架，接受捐赠和贡献的软件，并根据自由及开源许可证分发软件。ASF 目前支持超过 350 个开源项目。根据其 2013 年（可获取其 IRS 备案的最新年份）的数据，ASF 报告了 110 万美元的捐赠和 65.3 万美元的运营费用。

每个 ASF 项目都在一个项目管理委员会（PMC）的指导下运作，其成员从项目的提交者中选举产生。PMC 负责监督项目，定义发布策略，设定社区和技术方向，并管理各个版本的发布。PMC 有责任确保项目遵循 ASF 设定的核心要求，例如关于法律方面和品牌形象的规则。

Apache 项目包括贡献者和提交者。贡献者以各种方式支持项目，但只有提交者才能在源代码仓库中创建新的修订版本。

Apache 项目通常作为孵化器项目开始。在孵化阶段，项目建立其 PMC，确保符合 Apache 的法律标准，并开始构建社区。当一个项目达到一组既定的项目目标时，它就会毕业并晋升为 Apache 顶级项目。截至 2016 年 4 月，有 56 个项目处于孵化状态；其中，20 个项目已在计划中超过一年。在孵化器计划的整个生命周期中，截至 2016 年 4 月，已有 159 个项目毕业成为顶级项目；42 个项目在毕业前退出，主要是由于不活跃。

Eclipse 基金会是一个 501(c)(6) 非营利性质的会员制支持公司，负责支持并维护 Eclipse——一个开源软件开发平台。该基金会还支持本章后面讨论的商业智能平台 BIRT。



### 开源许可证

在 1988 年《伯尔尼公约》实施之前，未经版权声明分发的软件即进入公有领域。根据《伯尔尼公约》，软件在创作完成时自动获得版权。《伯尔尼公约》还规定了较长的版权保护期限；自 1988 年以来，尚无已知的软件达到版权保护期结束并进入公有领域的案例。1988 年已处于公有领域的软件，例如 `BASIC` 编程语言，仍保留在公有领域。

由于版权自动附着于软件，因此需要开源许可证来明确放弃用户享有的版权特权。`开源促进会`（`OSI`）和`自由软件基金会`（`FSF`）分别针对开源和自由软件许可证发布了各自的指导方针。

根据追踪开源软件项目的私营公司 `Black Duck Software` 的数据，目前有超过 2,400 种独特的软件许可证在使用。最受欢迎的¹许可证包括 `MIT` 许可证、`GNU 通用公共许可证`（`GPL`）2.0 版和 3.0 版、`Apache 许可证 2.0` 以及 `BSD 许可证 2.0`。所有这些许可证均符合 `OSI` 和 `FSF` 的标准。

`MIT 许可证` ：一种由`麻省理工学院`（`MIT`）开发的自由且宽松的软件许可证。`MIT` 许可证明确授予最终用户使用、复制、修改、合并、出版、分发、再许可和销售其所附软件的权利。

宽松型软件许可证授予被许可方根据不同的许可证重新分发衍生软件的权利。换句话说，开发者可以修改根据宽松型许可证获得的软件，并根据商业许可证重新分发它。

`GNU 通用公共许可证` ：一种最初为`自由软件基金会`开发的自由但非宽松（即“著佐权”）的软件许可证。`GPL` 授予被许可方运行、研究、重新分发和改进其所附软件的权利。1991 年发布的 2.0 版与 2007 年发布的 3.0 版在知识产权法的具体细节上有所不同。

著佐权（或称限制性软件）许可证规定，任何基于该许可证分发的软件衍生的软件，都必须以相同的许可证进行分发。换句话说，如果开发者修改了根据 `GPL` 许可证分发的软件，那么修改后的软件也必须根据 `GPL` 许可证分发。

`Apache 软件许可证` ：一种由`阿帕奇软件基金会`（`ASF`）开发的自由且宽松的软件许可证。所有 `ASF` 项目以及许多其他非 `ASF` 项目均根据此许可证分发软件。该许可证授予用户使用、分发、修改和重新分发衍生软件的权利。虽然用户可以根据不同的许可证分发修改后的软件，但代码中未修改的部分必须保留在 `Apache` 许可证下。

`BSD 许可证` ：1989 年为操作系统`伯克利软件发行版`开发的一系列自由且宽松的软件许可证。有几种不同的版本（称为 2-条款、3-条款和 4-条款许可证），`BSD` 许可证的拥护者认为它比专有许可证更具兼容性。最初的 `BSD` 许可证不符合 `OSI` 标准，但修改后的版本符合。

### 代码管理与分发

每个开源项目都必须决定如何以及在何处存储源代码，如何维护版本和修订版，以及如何向潜在用户分发代码。

较大的项目运营自己的分发平台。例如，`R 项目`运营着`综合 R 档案网络`（`CRAN`），这是一个由全球超过 100 个 `FTP` 和网络服务器组成的网络，存储着 `R` 语言相同的最新版本代码和文档。同样，`Python 软件基金会`托管着一个包含 `Python` 参考实现的存储库。商业开源供应商通常运营自己的分发平台。

处于早期开发阶段的软件项目无力开发自己的代码管理系统。有两个开源项目是开源社区的关键推动者：`Subversion` 和 `Git`。

`Apache Subversion` 是一个软件版本和修订控制系统，被开源软件社区和企业用户广泛使用。私营的软件和应用生命周期代码管理公司 `Collabnet` 于 2000 年开发了 `Subversion` 的原始版本，并于 2009 年将其捐赠给`阿帕奇软件基金会`（`ASF`）。`ASF` 根据 `Apache` 许可证分发该软件。虽然 `Subversion` 本身缺乏用户界面，但许多商业和开源的客户端（即`集成开发环境`，`IDE`）都可以与 `Subversion` 协同工作。

`Git` 是一个免费且开源的分发式版本控制系统，由致力于 `Linux` 内核的一个团队从 2005 年开始开发；该软件在 `GPL` 许可证下可用。`Git` 本身通过命令行界面运行。`GitHub` 是一家成立于 2008 年的私营初创公司，它提供了基于 web 的 `Git` 版本，同时还具有访问控制、缺陷跟踪、功能请求和任务管理等其他功能。`GitHub` 声称拥有超过 1200 万用户和 3500 万个项目。



### 捐赠软件

很少有开源项目是从零开始的。大多数情况下，项目始于一个作为学术研究项目或商业项目开发的软件核心。版权所有者将源代码捐赠给致力于开源软件的实体，例如 Apache 软件基金会（ASF）。

此类捐赠的例子包括：

- `Spark`，一个分布式内存项目，于 2013 年由加州大学捐赠给 ASF。
- `Storm`，一个流式分析引擎，于 2011 年由 Twitter 捐赠²给 ASF。
- `Hawq`，一个基于 Hadoop 的 SQL 引擎，于 2015 年由 Pivotal Software 捐赠³给 ASF。
- `Impala`，一个分析型数据库，于 2015 年由 Cloudera 捐赠⁴给 ASF。
- `SystemML`，一种机器学习语言，于 2015 年由 IBM 捐赠⁵给 ASF。

这些捐赠背后的动机各不相同。在某些情况下，原始软件开发人员认为该项目作为商业企业不太可能成功。与其进一步投资，原始开发者会将项目捐赠给开源社区，获得开发成本的税收减免，并收获一些商誉。⁶

捐赠也可能是由战略方向的改变所驱动的。例如，当 Pivotal 将其商业模式从软件开发转向服务交付时，它将其大部分软件资产捐赠给了开源社区。在此转变之前的两年里，该公司从服务收入中获得的收益远高于软件许可收入。

当收购公司认定所收购的软件不属于其核心业务时，企业收购也可能触发软件捐赠。Twitter 在 2011 年收购 Backtype 时获得了 `Storm` 软件资产；此后不久，该公司就将该软件捐赠给了开源社区。

就学术软件项目而言，大学很少有意愿或基础设施来管理其核心使命之外的软件项目。加州大学伯克利分校 AMPLab 的研究人员将 `Spark` 作为一个研究项目进行开发；大学持有软件版权，但将其捐赠给了 ASF。

公司决定捐赠软件项目可能会或可能不会传递有关该项目潜在价值的信息。Apache `Hive`，一种用于 `Hadoop` 数据仓库的软件，是一个非常成功的项目。Facebook 开发了原始软件并于 2008 年将其捐赠⁷给 ASF；自那以后，许多其他贡献者对其进行了增强。Hortonworks 投资了 `Stinger` 项目来改进该软件，该软件被广泛使用并包含在每个商业 `Hadoop` 发行版中。

`Hadoop` 是一个用于分布式计算和存储的开源框架。我们将在第四章讨论 `Hadoop` 及其生态系统。

另一方面，已捐赠死亡项目的骨架遍布开源世界。例如，Apache `SAMOA`，一个由 Yahoo 于 2013 年捐赠⁸给 ASF 的流处理框架，至今仍处于孵化器状态，其整个生命周期内仅有七位贡献者。

## 开源商业模式

在专有许可模式下，软件开发者投入时间和金钱开发软件，期望未来的软件许可费收入能收回投资并带来利润。一旦开发完成，向新客户交付一份软件副本的边际成本极低；因此，成功的软件产品能带来非凡的投资回报。

版权法授予开发者复制软件的专有权；因此，开发者在该产品上拥有经济垄断权。开发者试图通过将产品定位为能为客户带来独特、无可替代的价值来最大化这些权利的价值。这种差异化可以通过软件特性、文档、技术支持、培训，或者通过品牌和营销来实现。

客户对软件的初始选择发生在竞争市场中。虽然开发者试图使软件独一无二，但客户通常有多个选项可供选择，并可以争取最优惠的价格。

然而，企业软件是复杂的，实施起来具有挑战性，并且可能需要大量的定制化；因此，选择标准化于某一专有软件产品的组织面临供应商锁定的风险，即由于高昂的转换成本，客户缺乏议价能力。

永久许可，即开发者授予客户永久使用该软件的权利，是对锁定问题的一种回应。在永久许可下，客户在最初选择软件（此时客户拥有最大的议价能力）时向开发者支付一次性费用；作为回报，开发者授予“永久”使用该软件的许可。

永久许可存在两个问题。首先，高昂的初始成本导致评估和购买周期非常长，并相应导致采用率低。第二个问题涉及持续的软件开发和维护。很少有软件产品在开发完成后能长期保持领先水平。客户期望软件能够持续改进；这需要与软件开发者建立持续的合作关系。永久许可非但没有使开发者和用户的利益一致，反而创造了一种激励，使软件供应商在产品售出后忽视客户需求。

除了采用速度较慢之外，专有软件许可还造成了另外三个抑制创新的问题。

首先，需要许可证密钥和其他必要机制，通过防止未经授权（例如，未授权）的使用来保护开发者在软件中的经济利益。这些不仅让用户感到烦恼，还可能使软件难以集成到企业中。

第二个问题是以编译形式分发软件的必要性，这样用户就无法检查源代码。这在分析领域是一个关键限制，用户依赖开发者来准确实现算法，而微小的编码错误可能产生虚假结果。

第三，专有许可关系使开发者和用户处于一种保持距离甚至对立的关系中。如果用户被软件锁定且转换成本高昂，开发者几乎没有动力去添加所请求的功能。当开发者设定增强功能的优先级时，尚未被锁定的潜在客户比现有客户拥有更大的影响力。

开源软件最显著的特点是免除了软件许可费。虽然这对用户来说是一个明显的好处，但它也引出了一个显而易见的问题：如果没有可能从许可费中获得收入，为什么还会有人一开始就创建软件呢？



### 开源软件的动机与商业模式

#### 动机分析

动机是多元的。在某些情况下，利他主义和政治因素显然是推动力。软件开发人员可能受到使命感或创造更美好世界的愿望所激励。至少，对开源项目的部分贡献正是出于这种动机。

另一种情况是，开发者可能相信，如果软件项目成功并获得广泛采纳，将会带来通过定制化、服务、培训等产生收入的辅助机会。我们将在本章后面讨论这些方法。

由于没有许可费用，试用、采纳和使用的障碍不复存在。开源软件的潜在用户无需经历漫长且充满对抗性的谈判——在这种谈判中，他们往往缺乏为自己争取最佳利益所需的信息。相反，潜在用户只需检查软件并进行试用。如果他们担心确保内部计算的正确性，只需检查代码即可。

与商业许可软件相比，开源软件拥有更高的采纳率和使用率，因此开源开发者能够受益于快速且丰富的用户反馈。此外，由于用户可以将增强功能回馈给项目，开源软件拥有潜在规模更大的贡献者群体。综合这两个因素，开源软件项目的发展速度通常远超专有软件项目。

#### 为何选择开源语言

出于多种原因，开源语言是定制开发的最佳选择。首先，开放且可自由获取的源代码使企业能够轻松地将分析应用程序与其他生产应用程序集成。其次，开源软件的商业模式确保企业能够充分实现其定制开发投资所创造的价值。

大多数商业分析软件包都包含专有编程语言，例如`SAS`编程语言（`SPL`）。虽然法院已宣布`SAS`编程语言属于公共领域，但使用`SPL`编写的代码需要商业运行时编译器才能执行，用户必须向`SAS`或第三方获得许可。这使得它成为开发者的糟糕选择，并且缺乏开源语言的颠覆性潜力。

#### 社区开源模型

在社区开发模型下，项目拥有广泛的贡献者基础，他们独立工作，几乎不受中央权威机构的指导。许多用户同时也是贡献者。项目本身设有管理代码提交的标准，以及限制恶意行为者提交恶意代码的测试协议。

社区项目通常选择两种组织模型之一：

- 在自上而下模型下，项目随每个版本分发源代码，但只有核心开发团队可以在版本之间访问和修改代码。
- 在自下而上模型下，所有开发者随时都可以访问源代码。

在折衷模型下，项目分为两个层级：一个核心平台和运行在该核心平台上的软件包。项目治理机构对核心平台的提交进行严格控制，但对软件包提交的直接控制极少。核心团队负责核心平台的增强，而软件包开发者则对其发布的软件包负责。

商业企业通常在社区开源项目的周边运营，提供支持、咨询、教育和培训。这些企业可能得到项目治理机构的认可，也可能没有。它们对项目的总体方向影响相对较小。

经验丰富的软件工程师和开源理论家`Eric S. Raymond`在《大教堂与集市》中倡导自下而上模型，认为更多的目光关注软件能加速开发、提高质量并加快问题解决速度。另一方面，缺乏强有力的中央权威机构来建立设计标准（例如）会导致解决类似问题的方法复杂且不一致，使得最终产品难以导航和使用。

分析领域社区开源的最佳例子是`R`项目和`Python`，我们将在本章后面深入讨论。虽然`Apache Hadoop`是一个社区开源项目，但大多数组织使用基于`Apache Hadoop`的商业支持产品，这些产品与开源核心有很大不同。

#### 商业与混合开源模型

在纯商业开源模型下，商业企业寻求在开源软件许可模型的约束内定义可持续的商业模式。该企业控制项目治理，并且大多数贡献者是该企业的员工。商业开源模型有两种不同的类型：开源核心模型和服务模型。

采用开源核心模型的公司提供多个软件版本，其中至少一个版本在开源许可下可用，至少一个版本在商业许可下可用。通常，商业版本具有开源版本中没有的额外功能。这种模式使潜在客户可以免费且不受限制地评估基础软件，并为选择功能更丰富版本的用户提供收入来源。

这种模式的例子包括：

- `Talend`将`Talend Open Studio`作为开源软件提供，并提供其他几个商业许可的软件产品。
- `Oracle`提供开源的`Oracle R Distribution`和商业许可的`Oracle R Enterprise`，后者包含额外功能。

采用服务模型的商业企业仅以开源许可分发软件，并向用户销售服务。服务可能包括云服务、技术支持订阅、培训以及实施或定制开发的专业咨询服务。

这种模式的例子包括：

- `H2O.ai`分发`H2O`（一个开源机器学习软件包），并向用户群销售订阅服务。
- `Google`分发`TensorFlow`（一个开源深度学习软件包），并在其云平台上销售该软件的托管服务。

在混合商业模式下，商业企业不控制项目治理，但通过在项目治理机构中担任角色来施加强大影响。商业企业的员工对开源项目做出重要贡献，但其他人也同样如此。

这方面最好的例子是`Apache`项目，其中`Apache`软件基金会的治理模型禁止任何商业企业进行独家控制：

- `Databricks`主导`Apache Spark`的开发，并提供云服务、培训、认证和会议。
- `Hortonworks`对`Apache Hadoop`项目的方向施加强大影响，并提供自己的开源`Hadoop`发行版以及服务与培训。

总的来说，商业企业在开源软件中扮演着关键角色，它们激发对项目的兴趣，并向企业提供推动价值所需的必要服务。然而，也有许多广泛使用的开源项目没有商业生态系统的例子。



## 开源分析

开源商业模式在新兴分析技术中非常普遍。因此，我们在其他章节中涵盖了特定的开源项目：

*   第四章：`Apache Hadoop`及其生态系统。
*   第五章：`Apache Spark`及其他内存平台。
*   第六章：流式分析，包括`Apache Flink`、`Apache Storm`及其他软件包。
*   第八章：机器学习与深度学习，包括`CNTK`、`DL4J`、`H2O`、`TensorFlow`、`Theano`及其他软件包。

在关系型数据库中，开源软件`MySQL`和`PostgreSQL`在 2016 年 4 月的 DB-Engines 排名中分别位列第二和第五。开源 NoSQL 数据库`MongoDB`、`Cassandra`和`Redis`则位列第四、第八和第九。总体而言，在最受欢迎的十大数据库中，开源数据库占据了其中五个席位。

`DB-Engines`通过追踪在 Google 和 Bing 上的提及次数、Google Trends 中的搜索热度、Stack Overflow 和 DBA Stack Exchange 上的技术讨论频率、Indeed 和 Simply Hired 上的职位数量、LinkedIn 个人资料中的提及次数以及 Twitter 上的提及次数来衡量数据库的受欢迎程度。

2013 年 1 月，开源数据库在`DB-Engines`衡量的总人气中占比 36%；到 2016 年 4 月，这一比例已升至 45%。在宽列存储、图数据库、文档存储、时序数据库、键值数据存储和搜索引擎等特定数据库类别中，开源占据了主导地位。

三个商业驱动的开源项目提供了集成的商业智能平台：`Jaspersoft`、`Pentaho`和`Talend`。这三个项目都采用开放核心模式运营，并提供包含额外功能的商业许可版本。

*   `Jaspersoft`社区版包含用于 ETL 和报表的工具（包括移动设备 BI 和 OLAP）。
*   `Pentaho`社区版提供商业分析、数据集成、报表、聚合、模式定义和元数据管理工具。
*   `Talend`开放工作室包含可扩展的 ETL、数据质量和主数据管理功能。

商业智能与报表工具项目（即`BIRT`）是一个社区开源项目，也是 Eclipse 基金会的一个顶级项目。`BIRT`的功能包括报表设计器和报表执行引擎。OpenText 的子公司 Actuate 提供技术支持和咨询，但`BIRT`是独立管理的。

有两个商业驱动的开源项目用于高级分析：`RapidMiner`和`KNIME`。这两个项目都起源于欧洲的学术项目，并为业务用户提供了可视化界面。`RapidMiner`对其最新版本的软件进行商业许可，并以免费开源许可方式分发先前版本。`KNIME`在开源许可下分发其基础平台，并以商业许可方式提供扩展功能。我们将在第九章自助分析中分别讨论这些项目。

在本章中，我们涵盖了三种分析编程语言：`R`、`Python`和`Scala`。`R`是统计学家和分析师专门为分析而开发的工具；`Python`是一种具有丰富分析能力的通用编程语言。`Scala`则是一种优雅的编程工具，以其强大的 Spark API 而闻名。

尽管`R`的分析功能目前仍超越`Python`，但`Python`正在迅速追赶。目前，在分析领域使用`R`的人数多于`Python`，但这种局面也在迅速改变。

许可协议是`R`和`Python`之间的一个关键区别。`R`的 GPL 许可对商业开发者来说是一颗“毒丸”，因为基于`R`开发的产品只能作为开源软件重新分发。这对于`Python`来说不是问题，因为`Python`的许可协议是宽松的。与`R`封闭的治理模式相比，`Python`的治理模式也更加开放和广泛。

对于以获取洞察为首要目标的分析师来说，`R`广泛的分析工具和可视化能力使其成为首选。另一方面，对于以构建嵌入分析功能的应用程序为目标的分析开发者来说，`Python`的通用功能使其成为最佳选择。

尽管具有软件工程背景的开发者和数据科学家对`Scala`的兴趣日益增长，但其原生分析能力仍然有限。我们在本章中包含`Scala`主要是因为它是指挥 Spark 分布式分析平台的主要接口之一。



### R 项目

R 项目（简称“R”）是一个流行的免费开源语言，专为统计分析、图形绘制和高级分析而设计。它可在多种平台上运行，并支持丰富的功能。尽管 R 存在一些限制，但它被研究人员和统计学家广泛使用，以至于许多人称其为高级分析领域的通用语言。

`Ross Ihaka` 和 `Robert Gentleman` 在 1993 年使用 S 编程语言的语法编写了 R 的原始代码库。1995 年，他们根据自由软件基金会的 GNU 许可证发布了源代码¹³。

随着贡献者将现有软件包移植到 R 并从头开发新功能，用户的兴趣稳步增长。`Ihaka` 和 `Gentleman` 于 1997 年成立了 R 核心开发团队，以领导核心软件环境的持续改进。R 核心开发团队负责开发 R 核心软件，而个人开发者则贡献具有特定功能的软件包。代码库是多样化的；截至 2.13.1 版本，22% 的代码是 R 本身，52% 是 C 语言，26% 是 Fortran。¹⁴

2002 年，`Ihaka` 和 `Gentleman` 将该软件捐赠给了位于奥地利维也纳的非营利性公益组织——R 统计计算基金会。该基金会持有并管理版权，并作为项目的官方发言机构。基金会的管理权归属一个自我遴选的正会员团体，他们因对项目的（非金钱）贡献而被选出；截至目前，有 29 位正会员来自美国、加拿大、英国、挪威、丹麦、德国、法国、瑞士、意大利、奥地利、印度、新西兰和澳大利亚。¹⁵

R 基金会在 GNU 许可证下分发 R。该许可证使得商业软件开发者难以向 R 增加价值，因为任何修改或增强都会成为免费分发的一部分。分发使用 R 构建的商业应用程序的开发者必须分发增强后的源代码。此要求不适用于仅为内部使用而使用 R 构建应用程序的企业。

R 支持从头到尾的分析项目，包括：

*   数据导入和导出，包括与大多数商业和开源数据库的接口
*   自定义编程，包括条件语句、循环和递归操作
*   数据管理和存储
*   数组和矩阵操作
*   探索性分析、发现和统计
*   图形和可视化
*   统计建模和机器学习
*   内容分析

R 发行版包含 14 个“基础”软件包，支持基本的统计、图形和有用的实用程序。用户可以有选择地从`CRAN`或其他存档中添加软件包。由于广泛的开发者社区和较低的贡献门槛，R 提供的功能广度远远超过商业分析软件。

截至 2016 年 4 月，全球所有主要存储库中共有 11,531 个 R 软件包，其中 8,239 个位于综合 R 存档网络（`CRAN`），这是使用最广泛的 R 存档¹⁶。虽然这些统计数据展示了 R 所包含功能的惊人广度，但它们作为实用性度量却具有误导性。由于软件包开发者彼此独立工作，功能上存在大量重叠；在一个存储库中搜索支持“线性回归”的软件包会返回 50 多个结果。软件包的质量、文档和开发者支持也不均衡；因此，普通用户倾向于依赖有限数量的软件包。

开源 R 完全在内存中运行。由于缺乏内存外操作能力，如果用户尝试处理大于内存的数据集，R 将会失败。

`plyr` 软件包为用户提供了一个框架，用于分割大型数据集、对每个数据子集应用函数，并组合结果。`dplyr` 软件包扩展了这个框架，并提供了一套高效的数据处理工具，以及连接到流行开源数据库（如 `PostgreSQL`、`MySQL` 和 `Google BigQuery`）的接口。

在 R 中还有其他几个用于处理大数据的开源软件包。这些包括：

*   R 中的大数据编程（`pbdR`），一套旨在支持多种高性能计算方法的软件包
*   简单工作站网络（`snow`）支持在使用 R 的工作站网络上进行并行计算
*   `Rdsm` 为 R 实现了一个线程编程环境，无论是在集群机器上还是在单个多核机器上

通常，这些软件包最适合于易并行任务。然而，预测分析中的许多任务并非易并行；对于这些任务，分布式平台是更好的工具。我们将在本章后面讨论这些。

大多数大数据平台都支持 R 接口，以便 R 用户可以向数据平台传递命令。这些接口并不会“让 R 在数据库中运行”；它们会将 R 命令转换为特定于平台的命令，然后将结果作为 R 对象返回给用户。这些接口的质量、实用性和支持水平因平台而异；大多数供应商不提供对 R 代码本身的支持或保证。

微软提供增强的开源 R 发行版和具有附加功能的商业许可版本，特别是分析超出计算机主内存大小数据的能力。微软为实施 R 的组织提供技术支持、培训和咨询服务。

甲骨文提供免费的增强型 R 发行版（`Oracle R Distribution`）。它还将增强版（`Oracle R Enterprise`）与 `Oracle Data Mining` 捆绑在 `Oracle Advanced Analytics Option` 中，用于 `Oracle Big Data Appliance`。甲骨文为那些获得了 `Advanced Analytics Option` 或 `Big Data Appliance` 许可的客户提供对 `Oracle R Enterprise` 的技术支持。

Tibco 提供 `Tibco Enterprise Runtime for R`（`TERR`），这是一个由专业程序员从头开始编写的商业 R 实现。因此，它通常速度更快，内存管理更好。特别是，其优化以其他语言风格编写的循环的能力比开源 R 更快。

R 核心发行版包含一个用于交互式使用和脚本开发的极简界面。大多数用户更喜欢使用集成开发环境（IDE）；其中最流行的是 `RStudio`。`RStudio` 提供其软件的开源版本和商业许可版本；商业版本包括用于企业部署的附加功能。

很难准确说出有多少人使用 R。2009 年，《纽约时报》报道¹⁷用户基数为 25 万；其他人估计用户基数达数百万。¹⁸

分析师的调查通常显示 R 是当今最流行的分析工具之一，但这些调查的抽样方法使得难以将其推广到总体人群。

数据挖掘网站 `KDnuggets.com` 定期对其读者进行投票；每年，它都会要求读者指出在过去 12 个月中“用于实际项目”的分析软件工具。在 2016 年的投票中，49% 的受访者表示他们使用 R 的频率高于其他任何工具。

`Rexer Analytics` 对在职数据挖掘人员进行年度调查。在 2013 年调查的分析师中，70% 表示他们使用 R，高于 2011 年的 48%。

`O'Reilly Media` 对数据科学家的追踪调查收集了在职数据科学家的薪资和工具使用信息。在截至 2015 年 9 月的 12 个月中，52% 的受访者报告使用 R，排名第三，仅次于 `SQL` 和 `Microsoft Excel`。

`R` 的主要劣势在于其类似市集的特性，这在新手看来表现为大量相互冲突且冗余的功能、松散的标准以及参差不齐的质量。虽然有经验的用户往往乐于享受 `R` 的多样性和社区开发，但习惯商业产品的用户可能会觉得它缺乏吸引力。  

## Python  

Python 是一种脚本语言，其语法使程序员能够编写高效简洁的代码。虽然它在分析功能上不如 `R` 丰富，但 Python 在科学计算方面的能力正在迅速扩展。  

1989 年，吉多·范罗苏姆在荷兰国家数学与计算机科学研究中心（CWI）工作期间，开始将 Python 作为业余项目进行开发。²³ 在 CWI 内部使用后，范罗苏姆于 1991 年在 `alt.sources` 发布了 0.9.0 版本。随着用户和贡献者群体的不断壮大，代码库稳步扩展²⁴，分别于 1994 年达到 1.0 版本，2000 年达到 2.0 版本，2008 年达到 3.0 版本。  

1995 年，麻省理工学院的吉姆·胡格宁基于 `matrix-sig` 兴趣小组的理念，开发了 Python 扩展模块 `Numeric`。在随后的几年里，来自科学和工程界的一群 Python 用户为 `Numeric` 做出了贡献，并开发了其他用于科学计算的包。2003 年，特拉维斯·奥利芬特、埃里克·琼斯和皮亚鲁·彼得森发布了 `SciPy` 包，该包提供了运行在 `Numeric` 之上的标准数值运算。大约在同一时间，费尔南多·佩雷斯发布了 `IPython` 的第一个版本，这是一个旨在服务科学界的交互式开发环境。²⁵  

Python 软件基金会（PSF）成立于 2001 年，拥有 Python 2.1 及以上版本的知识产权，并根据 Python 软件基金会许可证（PSFL）发布开源许可证。PSFL 已获得开放源代码促进会和自由软件基金会的批准；它允许开发者修改代码并制作衍生作品，而无需公开源代码。这使得 Python 成为一个具有吸引力的开发平台。  

PSF 负责生产用 C 语言编写的核心 Python 发行版（`CPython`），并促进 Python 用户和贡献者社区的发展。基金会董事会由 11 名董事组成，由社区投票成员每年选举产生。  

作为一种通用语言，Python 原生支持分析语言所需的核心功能，例如数据导入和程序控制。对于高级分析，两个包（`NumPy` 和 `SciPy`）提供了基础函数。`NumPy` 和 `SciPy` 共同提供了交互式 shell、数据处理工具、多维数组、稀疏矩阵处理、统计函数、线性代数、优化、空间分析以及与 `R` 的接口。  

在数据操作和分析方面，许多 Python 用户使用 `pandas`，这是一个设计用于处理结构化数据的包。`Pandas` 支持类似 SQL 的操作，例如连接、合并、分组、插入和删除。它还处理更复杂的操作，例如缺失值处理和时间序列功能。  

用于高级分析的最丰富且最广泛使用的 Python 包是 `scikit-learn`。该包包含用于分类、回归和聚类的算法，包括逻辑回归、朴素贝叶斯分类器、支持向量机、集成模型（梯度提升和随机森林）以及 K 均值。该包还包括用于降维、模型选择和预处理的工具。  

`Pybrain` 专为入门级 Python 用户设计。它支持有监督和无监督学习、强化学习以及黑箱优化等多种技术。该包侧重于网络架构。  

`Pattern` 明确设计用于支持网络挖掘。该包包括用于网络服务、网络爬虫和域名解析、自然语言处理、机器学习和网络分析的工具。  

许多 Python 包支持高度专业化和高级的分析。举例如下：  



*   `NuPic` 包支持层次时间记忆（HTM）算法，这是贝叶斯技术的一种扩展，可用于异常检测和流式分析。
*   `Nilearn` 包为神经影像数据提供多变量分析。
*   `Hebel` 支持通过`CUDA`（使用`PyCUDA`）进行 GPU 加速的深度学习神经网络。

Python 功能的发展速度惊人。2014 年 5 月底，Python 包索引（`PyPI`）中仅有超过 44,000 个包。一年后的 2015 年 5 月底，列出的包已超过 60,700 个。其中，有 4,007 个被标记为科学/工程类。

与 R 语言一样，Python 也受内存限制，无法处理大于内存的数据集。与 R 语言一样，专家级程序员可以绕过这一限制，但这会抵消使用高级语言的部分初衷。

`IPython.parallel` 提供了一种用于并行和分布式计算的架构，使用户能够：

*   使用`IPython`可视化大型分布式数据集
*   对易于并行化的任务（如模型评分）进行并行化执行
*   编写自定义代码以并行化并非易于并行化的算法

可扩展的机器学习平台（如 Apache Spark 和 H2O）消除了在后一种情况下编写自定义代码的需要。这些平台支持 Python API。

大多数大规模并行处理（MPP）数据库将 Python 脚本作为表函数运行。IBM PureData、Pivotal Greenplum 和 Teradata Aster 支持此功能；Teradata 数据库不支持。

Continuum Analytics 发布了 Anaconda，这是一个免费的 Python 发行版，包含多项针对科学计算和预测分析的增强功能。这些功能包括：

*   为科学、数学、工程和数据分析预选的 Python 包
*   一个包含每个包最新版本的在线仓库
*   一组用于 Microsoft Excel 的插件

Anaconda 的商业服务器版本包括技术支持、带有图形用户界面的私有安全包仓库、自定义安装程序和镜像，以及全面的许可。

Python 用户可用的集成开发环境（IDE）种类繁多。`IPython`项目（`ipython.org`）提供了一种用于交互式计算的架构，包括交互式 shell、基于浏览器的笔记本、可视化支持、可嵌入的 Python 解释器以及一个用于并行计算的框架。

Rodeo 是最近推出的一款专为数据科学设计的 IDE。

### Scala

为应对 Java 编程语言的局限性，Martin Odersky 在瑞士洛桑联邦理工学院（EPFL）工作期间开始了 Scala 的研究。²⁸ 2004 年，Scala 团队向公众发布了可在 Java 和 .NET 平台上运行的软件。Odersky 于 2011 年创办了 Typesafe 公司，提供商业支持与培训；2012 年，该公司从 Greylock Partners 和其他风险投资公司筹集了 1400 万美元。²⁹

EPFL 持有 2011 年之前所有 Scala 开发的版权；Typesafe 和 EPFL 共同持有 2011 年及之后增强功能的版权。最终用户许可证采用开源修改版 BSD 许可。

Scala 的原生分析能力尚不成熟。`ScalaNLP` 是科学计算和机器学习中最广泛使用的 Scala 包。该包包含几个相关的库：

*   `Breeze` 支持数值计算、线性代数、优化和信号处理
*   `Breeze-viz` 用于可视化
*   `Epic` 是一个自然语言处理组件，具有八种语言的解析能力：英语、巴斯克语、法语、德语、匈牙利语、韩语、波兰语和瑞典语
*   `Junto` 支持半监督学习，包括标签传播、吸附和改良吸附
*   `Nak` 是一个机器学习库，支持 k-means 聚类、逻辑回归、支持向量机、朴素贝叶斯和神经网络
*   `Puck` 支持在 GPU 芯片上进行自然语言处理

Scala 的其他包包括：

*   `Bioscala` 支持生物信息学，包括 DNA 和 RNA 测序
*   `Chalk` 是一个用于自然语言处理的库
*   `Figaro` 是一个用于开发概率模型的包

使用 Scala 的数据科学家可以处理 Apache Spark；对 Spark 的兴趣正推动着对 Scala 的兴趣。

截至 2016 年 5 月，Scala 在 TIOBE 编程社区指数中排名第 32 位，远低于 R 语言和 Python。在本章前面引用的 2016 年 KDnuggets 投票中，6%的受访者表示他们在过去一年中使用过 Scala。

作为一种分析编程语言，Scala 的主要优势在于其 Spark API，该 API 比其 Python API 更强大。Scala 的主要弱点是缺乏成熟的原生分析能力。



## 开源的力量：颠覆传统

开源商业模式通过两种方式颠覆了既有的软件市场。

首先，由于没有软件许可费用，开源软件在试用阶段不存在任何初始门槛。商业软件供应商倾向于开发日益复杂且功能丰富的产品，以证明其许可费用的合理性，而开源软件则以显著更低的总成本提供基础价值。这是一个典型的“低端颠覆”案例：现有产品的功能远超许多潜在客户的实际需求。

例如，大多数商业统计软件包都包含一系列令人眼花缭乱的统计和机器学习技术，其价格从几百到几千美元不等。但如果从业者只需要使用线性回归，开源的 `R` 语言就提供了一个绝佳的替代方案。

其次，由于开源软件开发节奏快且与用户互动密切，开发者往往首先在开源软件中引入最具创新性的技术。商业软件供应商通常会根据短期收入影响来设定功能增强的优先级；而针对小众市场的增强功能，或需要一段时间才能成熟的新方法，其优先级往往较低。相比之下，开源软件对创新者不设任何门槛。

以随机森林为例，这是一种当今非常流行且被广泛使用的机器学习技术。Leo Breiman 详细阐述该技术的原始论文首次发表于 2001 年³⁰。此后不久，在 2002 年 4 月，开发者就将 Breiman 的 Fortran 代码移植到 R 语言，并发布了 `randomForest` 软件包。而这距离业界领先的商业统计与机器学习软件供应商 `SAS` 在其任何产品中提供该技术，又过去了整整 10 年。

开源软件开发固有的创新特性，使其能够为那些行业巨头未能有效解决的问题提供方案。在下一章中，我们将讨论开源的 Hadoop 及其生态系统，以及它是如何永久性地颠覆了数据仓库行业。

# Hadoop 生态系统

## 自下而上的颠覆

2003 年，道格·卡廷和迈克·卡法雷拉致力于构建一个能够搜索并索引整个互联网的网络爬虫。他们需要一种将数据分布到多台机器上的方法，因为单台机器无法处理如此庞大的数据量。

为了控制成本，他们希望使用廉价的通用硬件。这意味着他们需要具备容错能力的软件，这样即使任意一台机器发生故障，系统也能继续运行。

在工作的早期阶段，他们排除了使用关系型数据库的可能性。他们的数据包含多种多样的数据结构和数据类型，没有预定义的数据模型。将这些数据映射到关系型数据结构中会耗费大量时间——即便这种映射在理论上可行。

借鉴谷歌工程师发表的两篇论文，卡廷和卡法雷拉开发了一个分布式文件系统和编程框架。这个文件系统如今被称为 Hadoop 分布式文件系统，即`HDFS`，它内置了冗余机制，因此如果集群中的任何一台机器发生故障，系统可以继续使用其他机器上的副本进行工作。

编程框架`MapReduce`为开发人员提供了一种将工作负载分发到集群节点并收集结果的方法。借助`MapReduce`，开发人员无需显式地并行化任务，这既节省了时间，又简化了编程任务。此外，它还将编码层与集群管理分离开来，使得可以在不更改程序的情况下修改集群配置。使用`MapReduce`编写、用于在一个集群上运行的程序，可以在具有不同配置的其他集群上无需修改即可运行。

卡廷和卡法雷拉将`HDFS`和`MapReduce`设计为一个协同工作的系统。2006 年，他们将代码贡献给了 Apache 软件基金会，作为 Apache Hadoop 的核心。

早期的 Hadoop 版本难以使用，分析师可用的工具很少。对于大多数企业而言，Hadoop 不过是令人好奇的新奇玩意。然而，互联网公司迅速采用了这项技术。2008 年，雅虎宣布¹其使用 Hadoop 进行 TB 级排序创下了纪录；此后不久，Facebook 披露²其每天将 15TB 数据摄入到其基于 Hadoop 的 2.5PB 数据仓库中。

2009 年，当 Cloudera 和 MapR 推出商业支持的发行版时，Hadoop 的通用适用性向前迈进了一步。2013 年，Hadoop 团队引入了`YARN`，这是一个资源管理器。此举意义重大，以至于社区创造了“**Hadoop 2.0**”一词来描述该项目的新阶段。

自此以后，企业采用率呈现爆炸式增长：

*   根据 Wikibon 的估计，所有拥有大数据的组织中，有三分之一已将 Hadoop 集群投入生产。³
*   Ovum 分析师托尼·贝尔估计⁴，到 2014 年初，已部署了 1000 个 Hadoop 集群。
*   领先的 Hadoop 发行商报告称每季度有 50 至 75 家新客户采购。
*   最成熟老练的用户拥有超过 1000 个节点的集群。⁵
*   Gartner 在 2015 年对其首席信息官小组进行的一项调查⁶显示，2016 年 Hadoop 用户群可能翻倍。
*   行业分析机构 Forrester 预测⁷，到 2017 年，100%的大型企业将采用 Hadoop。

在本章中，我们将涵盖 Hadoop 及其生态系统的基本原理；Hadoop 的经济性；NoSQL 数据存储简介；以及 Hadoop 中的分析技术回顾。

## Hadoop 及其生态系统

现代关系型数据库管理系统是一个复杂的技术组合：包含文件系统、查询引擎、备份与恢复工具、脚本语言、批量加载工具、安全系统以及管理与治理工具。Hadoop 将这些组件解耦为许多独立的软件组件，这些组件可以独立运行。

定义 Hadoop 有三种方式：

*   **Apache Hadoop**：Apache 软件基金会的一个用于分布式计算和存储的项目。
*   **“核心 Hadoop”**：一组广泛使用的、对 Apache Hadoop 功能进行补充的开源组件集合。
*   **Hadoop 生态系统**：围绕 Apache Hadoop 发展起来的、由开源项目、商业软件供应商和服务提供商组成的网络。

每个 Apache 项目都独立运作；这使得快速创新和发展成为可能。然而，每个项目只支持单一的功能，因此用户通常需要将来自多个项目的软件组合成一个可工作的系统。

商业供应商销售包含 Apache Hadoop 在内的开源和专有组件捆绑包。这些通常被称为 Hadoop 发行版，尽管 Apache 许可协议禁止供应商使用该术语。⁸

### Apache Hadoop

Apache Hadoop 是 Apache 软件基金会的一个顶级项目，基金会拥有其代码并以免费使用许可进行分发。Hadoop 遵循 Apache 的标准治理模型运作。项目团队由一个项目管理委员会（PMC）和若干提交者（均为志愿软件开发人员）组成。PMC 负责确定软件增强和缺陷修复的优先级。团队大约每三个月发布一个新版本，基于提交者的投票共识。

Hadoop 支持在通用硬件上进行大规模、容错的分布式计算。它包含三个主要组件：

*   **Hadoop 分布式文件系统（`HDFS`）**：一个用 Java 实现的分布式文件系统。
*   **`MapReduce`**：一个用于处理分布式数据集的处理框架。
*   **`YARN`**：一个资源管理和调度应用程序。

在 Hadoop 1.0 下，`HDFS`包含一个名称节点和一个或多个数据节点。名称节点充当目录，跟踪系统中存储的文件；数据节点则存储实际数据。在`HDFS`下，一个文件被分布存储在多个数据节点上。

`MapReduce` 1.0 引擎由一个作业跟踪节点和一个或多个任务跟踪节点组成。在标准配置中，集群中的每台服务器上都安装一个任务跟踪节点和一个数据节点，另外指定一台或多台服务器来支持名称节点和作业跟踪节点。

用户通过编写`MapReduce`程序（由映射器和化简器组成）来查询存储在`HDFS`中的数据。映射器负责执行如选择、过滤和排序等操作；化简器则对映射器的结果执行汇总操作。用户可以利用这些基本操作来支持广泛的业务应用。

### Hadoop 2.0

在 Hadoop 的第一代中，工作负载管理被硬编码到 `MapReduce` 中，这使得在集群中与其他处理模型共同部署软件变得困难。2013 年底 `YARN` 的引入标志着 Hadoop 的第二代，即 Hadoop 2.0。`YARN` 是代码重构的结果，它将 `JobTracker` 和 `TaskTracker` 的角色拆分为三个独立的实体：

-   `ResourceManager`：一个调度器，负责将集群中的计算资源分配给应用程序。
-   `NodeManager`：部署在 Hadoop 集群的每个节点上，该组件在 `ResourceManager` 的指导下管理其节点上的资源。
-   `ApplicationMaster`：在集群上运行特定作业，从 `ResourceManager` 获取计算资源，并与 `NodeManager` 协作管理该作业可用的资源。

`YARN` 和 Hadoop 2.0 对商业分析产生了巨大影响。在 Hadoop 1.0 下，分析应用程序部署在 Hadoop 旁边；用户要么物理地将数据从 Hadoop 中提取出来并移动到分析应用程序，要么将他们的命令转换为 `MapReduce` 以在 Hadoop 中直接执行。

移动非常大的数据集是不切实际的（有时也是不可能的）；此外，即使对于训练有素的分析师来说，`MapReduce` 的学习曲线也非常陡峭。一些软件供应商尝试构建工具，在后台自动转换为 `MapReduce`，但收效有限。

`YARN` 允许将分析应用程序直接部署在 Hadoop 集群上，与 `MapReduce` 共同部署。分析应用程序可以直接消费存储在 `HDFS` 中的数据，而无需通过 `MapReduce` 引擎传递命令。`YARN` 充当资源的“交通警察”，管理 `MapReduce` 作业与共同部署的软件之间的冲突。

### 基于 Hadoop 的解决方案

2009 年，初创公司 Cloudera 推出了第一个由 Hadoop 驱动的商业支持软件。Cloudera 将 Apache Hadoop 与其他几个组件捆绑在一起，形成了一个完整的数据管理包。他们将该捆绑包命名为 Cloudera Data Hub (`CDH`)，并提供技术支持和咨询服务。

同样成立于 2009 年的 `MapR` 提供了一个竞争的 Hadoop 捆绑包，其中包含许多旨在实现高可用性的修改。`MapR` 还提供了一个选项，可以用专有文件系统（`MapR-FS`）来代替，以获得更好的性能和易用性。

早期的 Hadoop 采用者雅虎（Yahoo）发布了其自有的捆绑包好几年，但没有提供技术支持。2011 年，雅虎将其 Hadoop 资产剥离给一家新公司 Hortonworks，该公司强调“纯粹的”开源 Hadoop 方法。Hortonworks 的软件中不包含任何专有组件，完全依靠技术支持和咨询服务来获得收入。

领先的 Hadoop 公司之间的竞争非常激烈；每家都试图通过服务、支持和产品增强来提高其捆绑包的价值。因此，核心 Hadoop 项目变得越来越稳定和功能丰富。

在实验室环境之外，很少有企业使用纯粹的 Apache Hadoop，而是依赖基于 Hadoop 的商业捆绑包之一。截至 2016 年 7 月，这些包括：

-   Amazon Elastic MapReduce
-   Cloudera Data Hub (`CDH`)
-   Hortonworks Data Platform
-   IBM Infosphere BigInsights
-   MapR

企业依赖商业捆绑包有几个原因。首先，商业捆绑包包含额外的组件，这些组件支持数据平台所需的功能：实施、维护、配置、安全等。

商业供应商会测试捆绑包中所有组件的互操作性，然后为客户提供技术支持和咨询服务。这些服务提供了巨大的价值，因为它们简化了部署并缩短了实现价值的时间。

与发布新版本频繁且不规律的 Apache Hadoop 相比，商业供应商还提供了更稳定的发布节奏。企业通常倾向于避免频繁升级软件所带来的成本和风险。

由于商业供应商相互竞争并寻求产品差异化，每个供应商都用不同的软件捆绑包来补充 Apache Hadoop。下面列出的九个组件包含在每个发行版中。

-   Apache Flume：用于收集、聚合和移动日志数据的分布式服务。
-   Apache HBase：分布式列式数据库。
-   Apache Hive：类 SQL 查询引擎。
-   Apache Oozie：工作流调度器。
-   Apache Parquet：列式存储格式。
-   Apache Pig：高级 MapReduce 脚本语言。
-   Apache Spark：分布式内存计算框架，包含用于 SQL、流处理、机器学习和图分析的库。
-   Apache Sqoop：用于在关系型数据库和 Hadoop 之间进行数据传输的工具。
-   Apache Zookeeper：分布式集群配置服务。

除了这些通用分发的组件之外，还有许多其他 Apache 开源项目支持数据管理所需的功能。下面列出的项目包含在部分（而非全部）商业 Hadoop 发行版中：

-   Accumulo：宽列数据存储。
-   Atlas：用于数据治理的元数据仓库。
-   Avro：远程过程调用和数据序列化框架。
-   Falcon：定义、调度和监控数据管理策略的数据治理引擎。
-   Knox：提供身份验证和安全访问的系统。
-   Ranger：全面的安全管理。
-   Sentry：提供基于角色的授权。
-   Slider：用于部署和监控在 `YARN` 下运行的应用程序的工具。
-   Storm：分布式实时计算系统。
-   Tez：加速 `MapReduce` 操作的软件。

商业供应商在其产品中混合使用 Apache 开源项目、非 Apache 开源软件和专有软件。Hortonworks 只捆绑开源软件。



### 性能改进

与高性能数据仓库设备相比，Hadoop 速度较慢，但正在快速改进。性能问题部分归因于该平台尚不成熟；数据仓库设备拥有复杂的查询优化器，能够加速每次操作的运行时间。Hadoop 的优化器仍处于早期开发阶段。

`MapReduce` 将高级任务（例如 SQL 操作）分解为多个步骤。每次处理数据后，它会将中间结果保存到磁盘；因此，复杂分析在 `MapReduce` 中的运行速度显著慢于数据仓库设备。对于迭代算法（例如 k-means 聚类或随机梯度下降算法）而言尤其如此。

领先的商业供应商对这一性能问题有着不同的处理方式。Cloudera 采纳了 `Apache Spark`，而 Hortonworks 则推崇 `Apache Tez`。

`Apache Spark` 是一个用于分布式内存处理的框架。类似任务在 `Spark` 中的运行速度远快于 `MapReduce`，因为 `Spark` 将中间结果保留在内存中，而不是持久化到磁盘。我们将在第五章详细讨论 `Spark`，该章节涵盖内存分析。

`Apache Tez` 采取了不同的方法。`Tez` 在后台运行，将程序逻辑建模为有向无环图（`DAG`），并动态重构和简化代码。因此，`Tez` 的工作方式类似于关系数据库中的查询优化器。虽然 `Tez` 减少了实现复杂分析所需的 `MapReduce` 步骤数量，但它并未改变 `MapReduce` 需要将中间结果持久化到磁盘的必要性。

Cloudera 在 2013 年认可了 `Spark`，并宣布将在其下一个版本中包含 `Spark`。其他供应商也纷纷效仿，因此到 2014 年 6 月，所有商业 Hadoop 供应商都已认可 `Spark` 并将其纳入其产品中。

2015 年 9 月，Cloudera 宣布了其所谓的“统一平台计划”，根据该计划，它打算让 `Spark` 成为其 Hadoop 版本中的主要计算平台，将 `MapReduce` 降级为针对新应用程序的次要地位。这并不意味着 `MapReduce` 已死；存在大量现有程序将继续在 `MapReduce` 中运行。

使用 `Tez`，Hortonworks 的 Stinger 项目提高了 `Hive` 的性能。然而，为机器学习规划的扩展尚未实现，并且 `Tez` 似乎是一条技术死胡同。

## Hadoop 的经济性

两个关键因素推动了 Hadoop 的采用。首先是灵活性——能够在未预先定义结构的情况下捕获和保留数据，使企业能够更快地采取行动。其次是成本：Hadoop 和 NoSQL 数据库每单位数据的成本远低于传统数据仓库。

Hadoop 和关系数据库就像苹果和橘子：它们做的事情非常不同。Hadoop 加载速度快，并且不需要预定义结构；因此，它非常适合支持新数字经济产生的大量非结构化数据。然而，Hadoop 相对难以查询，并且其对请求的运行时性能相对较慢。

关系数据库——以及基于它们的数据仓库——需要预定义的数据模型，这可能需要耗费大量时间和成本来构建。但它们相对易于查询，并且可以调优以获得极快的运行时性能。

Hadoop 提供了成本极低的存储；据一位分析师称，Hadoop 每 TB 的成本为 1000 到 2000 美元。与 Hadoop 相比，`Teradata` 数据仓库每 TB 的成本可能高达 69,000 美元。

`Apache Hadoop` 本身是免费且开源的；商业捆绑包需要许可，但每个分销商都提供免费版本，使用户能够以极低成本甚至零成本开始使用。Hadoop 的成本模型与用户需求平滑扩展。换句话说，向 Hadoop 集群添加另一个节点相对容易，并且这样做的增量成本很小。

来自领先供应商的数据仓库构建成本高昂，且成本是“前端加载”的——组织仅在起步阶段就需要支付高昂的费用。此外，数据仓库成本往往是“块状”的——扩展单元庞大且昂贵。

Hadoop 的颠覆源于 Hadoop 生态系统的商业模式。对于拥有快速扩展的非结构化数据量的组织而言，相对于传统数据仓库，Hadoop 的低成本、敏捷性和可扩展性极具吸引力。

基于设备、列式数据库或内存数据库构建的数据仓库对于高价值和频繁使用的数据仍然具有吸引力。对于组织愿意支付高溢价的高价值数据的高并发访问，高性能数据仓库仍然是最佳选择。

Hadoop 主要分销商中，只有 Hortonworks 是一家上市公司。Hortonworks 的财务披露显示了快速增长。2015 年第二季度，该公司增加了 119 名客户，比上一季度增长 27%；收入比 2015 年第一季度增长 35%，比 2014 年第二季度增长 154%。



## NoSQL 数据存储

NoSQL 意为“不仅是 SQL”。NoSQL 数据库不要求用户在加载数据之前定义逻辑结构；相反，用户可在分析数据时定义结构。这使得它们非常适合处理图像、音频、视频、机器生成的日志、文档、社交媒体文本以及其他格式多样的数据。

从技术上讲，Hadoop 是一种 NoSQL 数据存储，Hadoop 生态系统包含了像 HBase 这样流行的 NoSQL 数据存储。此外，一些 NoSQL 数据存储可以利用 HDFS 或 Hadoop 生态系统的其他组件。

NoSQL 数据存储主要有四种类型：

- **键值数据存储**：一种数据存储方法，其中表中的记录可以具有不同的字段结构，这与关系数据库中每条记录具有相同字段结构的情况相反。每条记录都有一个唯一的键。示例包括`Redis`、`Memcached`、`DynamoDB`和`Riak`。
- **宽列数据存储**：键值数据存储与列式数据存储的混合体；具有高度可扩展性。示例包括`Apache Cassandra`和`Apache HBase`。
- **文档数据存储**：专为存储和检索文档而设计的数据库，例如新闻文章、美国证券交易委员会文件或研究论文。示例包括`MongoDB`、`CouchDB`和`Couchbase`。
- **图数据库**：旨在以数学图的形式表示数据的数据存储，包含节点、边和属性。`Neo4j`是此类中的主要代表。

目前有许多 NoSQL 数据库在使用中。我们在此简要描述最流行的五种：

- **MongoDB**：最流行的文档数据库，广泛用作生产级网站和服务的后端。由 MongoDB 公司于 2007 年开发，该公司提供商业支持；该软件采用 GPU 和 Apache 许可证，是免费且开源的。
- **Apache Cassandra**：一种分布式宽列数据存储，由 Facebook 开发并于 2008 年捐赠给开源社区。Apache 软件基金会于 2009 年接纳 Cassandra 为孵化器项目，并于 2010 年将其提升为顶级项目。
- **Redis**：一种高性能内存键值数据存储。由 Redis Labs 开发和支持，该数据库采用 BSD 许可证，是免费且开源的。Redis Labs 提供`Redis Cloud`和`Memcached Cloud`作为数据库服务。
- **Apache HBase**：一种基于谷歌 BigTable 的高性能 NoSQL 列式数据存储。2006 年，Powerset 的开发人员使用谷歌 BigTable 框架构建了自家的海量可扩展列式数据存储，以支持自然语言搜索引擎。微软于 2008 年收购了 Powerset，并将该数据存储资产捐赠给了 Apache 软件基金会。起初，开发作为 Hadoop 的子项目进行；2010 年，Apache 将该项目提升为顶级项目，即`Apache HBase`。
- **Neo4j**：一种开源图数据库，由 Neo Technology 开发和支持。Neo 根据 GPL 和 AGPL 开源许可证以及商业许可证提供增强版软件。该产品的首个版本于 2010 年发布。

目前，NoSQL 数据存储最广泛地用于运营类应用程序，作为分析型数据存储的使用有限。这主要是由于缺乏与 SQL 等价的标准接口。像`Python`和`R`这样的分析编程语言可以与最流行的数据库交互，但这些工具的使用仅限于专业分析人员和开发人员。

行业分析师预计该类别将迎来洗牌，他们认为即使是最流行的 NoSQL 数据库也缺乏可持续的商业模式。

## Hadoop 中的分析

在 Hadoop 生态系统中，有许多支持分析的开源项目：用于 SQL 的`Hive`、`Impala`、`Spark`、`Drill`、`Presto`和`Phoenix`；用于 OLAP 的`Kylin`；用于机器学习的`Mahout`、`Spark`、`Flink`和`H2O`；用于图分析的`Giraph`和`Spark GraphX`；用于机器学习管道的`Zeppelin`；以及用于搜索和文本分析的`Lucene/Solr`。在 Hadoop 2.0 中，用于分析的商业软件包也越来越多。

我们将本章分为两部分。在第一部分中，我们介绍 Hadoop 1.0 中可用的分析功能，这些功能与当时 Hadoop 之外可用的功能相比是初级的。在第二部分中，我们介绍 Hadoop 2.0 中的分析功能。我们将该回顾的范围限制在 SQL 引擎上，将机器学习引擎的覆盖推迟到第八章，将自助式 BI 推迟到第九章。

### Hadoop 1.0

在 Apache Hadoop 团队于 2013 年引入 YARN 之前，分析工作负载运行在 MapReduce 中，因为无法在 Hadoop 中同时运行替代编程框架。因此，分析工具充当了代理，将更高级别的任务转换为 MapReduce 命令，提交这些命令执行并处理结果集。

在本节中，我们讨论四个开源项目和一个商业产品。我们还注意到本书其他部分讨论的三个开源分析项目——`Jaspersoft`、`Pentaho`和`Talend`——开创了与 Hadoop 的集成。

另外两个项目具有历史意义。由 Revolution Analytics 赞助的`rhadoop`项目支持与`HDFS`、`HBase`和`Avro`的连接，并为 R 用户在 MapReduce 中启用类似`dplyr`的操作。GitHub 统计数据显示，自 2013 年以来活动极少，自微软于 2015 年收购 Revolution Analytics 以来几乎没有任何活动。`RHIPE`项目为 R 用户提供了类似的功能。代码贡献是零星的。

本章前面讨论的 MapReduce 的局限性影响了这些早期将分析引入 Hadoop 的工作的性能和效用。随后，开发人员重新设计了`Apache Hive`以支持 Spark 和 Tez，从而有效地将其升级，以便在 Hadoop 2.0 下使用。



#### Apache Hive

`Hive` 是一个开源数据仓库环境，旨在支持在 `Hadoop` 中执行类似 SQL 的查询。最初设计为仅在 `MapReduce` 中运行，`Hive` 现在已能在 `Apache Tez` 中执行查询。`Hive` 是最成熟、分布最广的 SQL-on-Hadoop 项目。

Facebook 的开发者于 2007 年开始开发 `Hive`，并于 2008 年将代码捐赠给 Apache 软件基金会，作为 `Hadoop` 的一个贡献子项目²¹。2010 年 9 月，`Hive` 毕业²²晋升为 `Apache` 顶级项目。`Hive` 的提交者包括来自 `Cloudera`、`Dropbox`、`Facebook`、`Hortonworks`、`InMobi`、`Intel`、`LinkedIn`、`Microsoft`、`NexR`、`Nutanix`、`Qubole` 和 `Yahoo` 等科技领军企业的开发者。²³

2014 年之前，`Hive` 通过 `MapReduce` 执行查询。因此，`Hive` 的运行时性能相对较慢，使其最适合于批处理 SQL。在 `Stinger` 和 `Stinger.next` 项目下，`Hortonworks` 投入了大量资源用于改进 `Hive`，主要目标如下：

-   将性能提升至亚秒级响应时间。
-   将可扩展性扩展到 PB 级数据量。
-   将 SQL 支持增强至完整的 ANSI 标准。

`Stinger.next` 计划的其他增强功能包括：

-   流式数据摄入
-   跨地域查询，即能够查询跨地理区域分布的数据集
-   物化视图，即在内存中保存数据的多个视图
-   易用性增强
-   简化部署

为了提升性能，`Stinger` 团队重建了 `Hive`，使其利用 `Apache Tez`，这是一个能创建比通用 `MapReduce` 更高效执行计划的应用框架。`Tez` 将处理逻辑建模为有向无环图(DAG)，然后动态重构图以实现更高效的逻辑。根据 `Hortonworks` 的说法，对于`TPC-DS`基准测试，`Hive on Tez` 的平均运行速度比传统 `Hive` 快 52 倍。²⁴

与 `Stinger Initiative` 同期，`Cloudera Labs` 的一个团队将 `Hive` 移植到 `Apache Spark` 上运行。该团队于 2016 年 4 月发布了²⁵ `Hive-on-Spark` 的通用可用版本。

`Hive` 被分发并支持于每个由 `Hadoop` 驱动的商业产品中，包括 `Cloudera CDH`、`MapR`、`Hortonworks HDP` 和 `IBM Infosphere BigInsights`。`Hive` 的一个修改版本作为云服务在 Amazon Web Services 的 `Elastic MapReduce (EMR)` 中可用。该版本支持导入数据并写回 `Amazon S3`，以及指定外部元数据库。

`Hive Server` 是一个接口，使用户能够向 `Hive` 提交查询以执行并检索结果。（当前最新版本 `HiveServer2` 已在很大程度上取代了原始版的 `HiveServer1`。）`HiveServer2` 支持使用流行的安全协议进行身份验证，包括 `Kerberos`、`SASL`、`LDAP`、`可插拔自定义身份验证` 和 `可插拔身份验证模块`。

`Hive` 支持一种类似 SQL 的语言，称为 `QL`（“`HiveQL`”）。`HiveQL` 包含 `ANSI SQL` 功能的一个子集，外加对 `MapReduce`、`JSON` 和 `Thrift` 的额外支持。用户可以通过 `Java` 用户自定义函数（`UDF`）、用户自定义分析函数（`UDAF`）和用户自定义表函数（`UDTF`）来扩展 `Hive` 功能。

`Hive` 可处理位于 `HDFS`、`HBase` 以及兼容文件系统（包括 `Amazon S3`）中的数据。

根据 `OpenHub` 的统计²⁶，`Hive` 是一个非常活跃的项目，拥有 140 名贡献者和超过一百万行代码。代码库自 2013 年以来稳步扩展并显著加速。

`OpenHub` 数据库是 `Black Duck` 软件的一个项目，它会爬取开源代码仓库以生成关于贡献者和代码提交的统计数据。

#### Apache Pig

`Apache Pig` 是一个 `Apache` 顶级项目。它包含一种高级的类 SQL 分析语言（“`Pig Latin`”），并配有一个编译器，该编译器将此语言转换为 `MapReduce`。

`Yahoo` 的开发者于 2006 年夏天开始²⁷将 `Pig` 作为一个研究项目进行开发。`Yahoo` 将该软件捐赠给 Apache 软件基金会，基金会于 2007 年接受²⁸该项目进行孵育。一年后，`Pig` 毕业晋升为顶级项目。

在 `Pig` 团队内部，有正在进行中的项目计划将 `Pig` 移植到 `Tez` 和 `Spark`。

根据 `OpenHub` 的数据，`Pig` 远不如 `Hive` 活跃，拥有 28 名贡献者和 37.6 万行代码。代码库在 2011 年达到顶峰，此后几乎没有新活动。

#### Apache Mahout

`Apache Mahout` 是一个用于机器学习的开源项目，于 2008 年由 `Apache Lucene` 团队的几位开发者发起²⁹。该项目最初受斯坦福大学研究人员撰写的一篇论文³⁰启发而发展，但后来演变成——有些人认为退化成——包含多种方法的混合体。这种缺乏纪律性非但没有促进创新，反而导致项目沦为一系列开发和贡献的算法的松散集合。

`Mahout` 的某些算法使用 `MapReduce`，有些则不用；有些是分布式的，而另一些则运行在单节点上。许多贡献的算法后来因缺乏兴趣、用途和支持而被弃用并从项目中移除。

剩余的大部分算法使用 `MapReduce`，但自 2014 年起，所有新算法都必须使用 `Spark`。

从团队于 2015 年 11 月发布的版本 `0.11.1` 开始，该项目包含了 `Samsara`，这是一个运行在 `Spark` 或 `H2O` 上用于线性代数的数学环境。

`Mahout` 的代码库³¹直到 2012 年都增长缓慢，但此后就再无增长。该项目几乎已死亡，在截至 2016 年 5 月的 12 个月内没有任何代码贡献。

#### Apache Giraph

图引擎可对表示为数学图的数据进行大规模计算。`Apache Giraph` 是一个开源的迭代式图处理引擎，其灵感来源于一篇 2010 年论文³²中描述的 `Google Pregel` 图引擎；它使用了一种称为“批量同步并行”(BSP) 处理的并行化方法。`BSP` 提供了一个在分布式处理系统中管理进程和通信的框架。

`Giraph` 在 `MapReduce` 中实现了 `Pregel` 架构，并与 `HDFS` 文件或 `Hive` 表协同工作。`Giraph` 通过添加额外功能扩展了基本的 `Pregel` 模型，以实现更好的性能、可扩展性、实用性和容错能力。

Facebook 使用³³ `Giraph` 来分析其用户的社会化图谱；该图谱拥有超过一万亿条边。为了满足需求，Facebook 的开发团队修改了该软件，并将增强功能回馈给了开源项目。增强版的 `Giraph` 能够：

-   从不同数据源读取边和节点数据
-   处理任意数量的数据源
-   支持在 `Hadoop` 工作节点上进行多线程处理
-   充分利用每台机器的内存
-   在 `Hadoop` 集群中的多台机器间平衡聚合工作负载

2013 年，当 Facebook 首次公布³⁴其评估结果时，人们对 `Giraph` 的兴趣激增。自那时起，`Giraph` 的代码库一直缓慢³⁵但稳步地增长。



#### Datameer

`Datameer` 是一家商业软件公司，率先在 Hadoop 上实现了商业智能。2009 年，Ajay Anand 和 Stefan Groschupf 共同创立了 `Datameer`³⁶。当时，分析 Hadoop 中管理的数据只有寥寥几种选择：编写 `MapReduce` 表达式，用 `Pig` 编程，或者在一个早期版本的 `Hive` 中执行基本的 SQL。所有这些选项都需要编程和技术技能，而这些技能在商业分析师中并不普遍。`Datameer` 致力于让 Hadoop 数据变得易于访问。

自 2009 年以来，`Datameer` 的产品经历了重大演变，现已发布 6.0 版本（截至 2016 年 5 月）。该软件由一个驻留在 Hadoop 集群边缘节点上的应用服务器和数据库服务器组成。

`Datameer` 应用服务器接收来自终端用户的请求（这些用户使用基于浏览器的界面工作），并将用户请求转化为 Hadoop 操作。该应用评估用户请求，并通过以下四个执行框架之一提交请求：

* `MapReduce`：Hadoop 的默认计算框架，在没有其他替代方案时使用。
* `优化版 MapReduce`：当可用时，`Datameer` 会在 `Apache Tez` 上使用 `MapReduce`。（有关 `Tez` 的更多信息，请参见上一节关于 `Apache Hive` 的内容。）
* `Spark`：当 `Spark` 可用时使用。
* `单节点执行`：对于小任务，`Datameer` 在 Hadoop 集群的单个节点上运行该请求。

`Datameer` 全面支持主要的 Hadoop 发行版。它还支持从多种数据源导入数据，包括关系型数据库、NoSQL 数据库、`Hive`、Microsoft Office 格式、社交媒体文件、`HTML`、`JSON` 等等。数据导出功能则较为有限。同样重要的是，`Datameer` 必须物理提取数据并将其移动到 Hadoop 中进行处理，因为它缺乏将 SQL 透传到外部数据库的功能。

基于浏览器的 `Datameer` 用户界面以类似电子表格的形式显示结果，用户可以在其中添加函数和图表。

`Datameer` 已通过五轮风险投资筹集了 7650 万美元。其最新一轮融资是由总部位于新加坡的投资公司 `ST Telemedia` 领投的 4000 万美元“D 轮”融资。在融资公告发布时，`Datameer` 声称³⁷拥有 200 家客户。

### Hadoop 2.0

如前所述，我们将本次回顾的范围限定在 SQL 引擎，并将其他分析工具的讨论推迟到后续章节。

SQL 是分析领域的基础工具，几乎每个项目都需要用到它；许多项目只需要 SQL 即可。SQL 引擎是关系型数据库的内在组成部分；组织在将数据加载到数据库时，会将数据映射到 SQL 框架中。

相比之下，SQL 并未内建于 Apache Hadoop 中；而是由称为 SQL 引擎的独立组件提供 SQL 功能。SQL 引擎接收用户的 SQL 命令，生成一个或多个数据请求，将这些请求提交给一个或多个数据存储，并将结果集返回给用户。

虽然这些引擎常被称为 Hadoop 上的 SQL 引擎（SQL-on-Hadoop），但这个术语并不精确。一些引擎，如 `Hive` 和 `Impala`，仅在 Hadoop 内部、使用 Hadoop 数据源运行。其他引擎，如 `Spark`、`Drill` 和 `Presto`，则可以在 Hadoop 内部或外部运行，并能与多种不同的数据源协同工作。

将 SQL 引擎从数据存储中解耦出来具有许多潜在优势。首先是专业化：SQL 引擎开发者可以专注于 SQL 接口和查询解析器的开发，而其他开发者则可以增强数据存储本身。

将 SQL 引擎与文件系统分离也使用户能够在多个选项中进行选择。由于现代 SQL 引擎在商业上与特定的数据存储没有绑定关系，组织可以实现“同类最佳”架构，根据最终用户的需求混合搭配 SQL 引擎。独立于数据存储运行还提供了跨多个数据存储进行“联邦”查询的潜力。

Hadoop 在存储数据时，并不会事先将其映射到 SQL 框架中。因此，在 Hadoop 中，SQL 用户必须先*将数据映射到表结构中*，然后才能运行查询。

现代 SQL 引擎支持以下三种 SQL 处理模式中的一种或多种：

* `批处理`：SQL 脚本在无人监督或关注的情况下对静态数据运行。批处理模式适用于长时间运行的查询，或计划重复执行的查询。通常用于提取、转换和加载（ETL）处理、评分或定时报告。
* `交互式`：SQL 脚本在静态数据上运行，同时用户等待响应。此模式通常需要较低的延迟：最长可达 20 分钟。通常用于临时查询和探索，其中问题可能是嵌套的。
* `流式处理`：SQL 脚本在动态数据上连续运行，跨越一个滑动时间窗口。流式处理模式需要非常高的性能。通常用于算法交易、实时广告定向投放以及类似应用。

`Hive`、`Spark SQL` 和 `Impala` 支持 `HiveQL`；`Presto` 和 `Drill` 支持 ANSI SQL。所有引擎都支持用户自定义函数（UDF）。`Hive` 和 `Spark` 提供查询容错功能；其他引擎则没有。`Hive`、`Spark SQL` 和 `Impala` 是最成熟、功能最丰富的；`Presto` 和 `Drill` 则成熟度最低。

用户自定义函数（UDF）是由数据库用户提供的表达式、函数或代码片段，用于补充内置函数。UDF 的支持因平台而异，可能包括运行用 `C`、`Java`、`Python` 和 `R` 等语言编写的程序的能力。

现在 Hadoop 上的 SQL 引擎数量过多，无法逐一详述。我们将在本章介绍 `Impala`、`Drill` 和 `Presto`，并在第五章介绍 `Spark SQL`。此外，还有几个项目值得简要介绍：



#### SQL-on-Hadoop 引擎

- **Apache Tajo**：Tajo 是一款开源高性能 SQL 引擎。Apache 软件基金会于 2013 年 3 月接纳 Tajo 进行孵化，并于 2014 年 3 月将其提升为顶级项目。总部位于韩国的初创公司 Gruter 主导 Tajo 的开发并提供商业支持。
- **Apache Kylin**：Kylin 提供快速的交互式 ANSI SQL 和 MOLAP 立方体功能，并集成了 BI 工具和企业级安全特性。Kylin 最初由 eBay 开发，于 2014 年 11 月被接纳为 Apache 孵化器项目，并于 2015 年 11 月毕业成为顶级项目。
- **Apache Phoenix**：Phoenix 是一个旨在与 Apache HBase 集成的关系数据库框架；它包含一个查询引擎、元数据仓库和 JDBC 驱动程序。Phoenix 将用户请求转换为原生 HBase 调用，绕过了 MapReduce；这使其运行速度远快于早期版本的 Hive。`Salesforce.com` 的工程师为内部应用开发了 Phoenix；该公司于 2013 年将该项目捐赠给了开源社区。Apache 软件基金会于 2014 年 5 月将 Phoenix 提升为顶级项目。Hortonworks 在其产品中包含了 Phoenix。
- **Apache Trafodion**：Trafodion 是一个 SQL-on-HBase 引擎，为 BI 提供 ANSI SQL 支持以及 ODBC/JDBC 连接。惠普实验室于 2014 年 6 月将 Trafodion 作为开源项目发布，并于 2015 年 1 月发布生产版本。Apache 软件基金会于 2015 年 5 月接纳 Trafodion 为孵化器项目。
- **Apache HAWQ**：目前处于 Apache 孵化器状态，HAWQ 是一个源自 Pivotal Greenplum 数据库的 SQL on Hadoop 引擎。Pivotal Software 于 2015 年 6 月将该项目捐赠给了开源社区。
- **IBM Big SQL**：Big SQL 是 IBM 为其 Hadoop 发行版 InfoSphere BigInsights 提供的 SQL 接口；它可以查询 HDFS、HBase 以及 Big SQL 自身创建的特殊表。该产品包含一个将数据从关系数据库复制到 Big SQL 表的工具。
- **Oracle Big Data SQL**：Big Data SQL 是 Oracle 的产品，仅在 Oracle 大数据一体机上可用。它在单个查询中联合查询 Oracle 数据库、Oracle Hadoop 和 Oracle NoSQL 数据库。该产品通过 Oracle 数据库的外部表扩展运行，并提供一种称为“查询特许经营”（Query Franchising）的能力，通过该能力，数据子系统上的代理使用等效运算符执行查询。

许多不同的因素都会影响引擎的运行时性能。这些因素包括数据的数量和类型、存储格式、系统基础设施、部署特性以及所测试查询的性质。毫不意外的是，由于上述因素的差异，已发布的基准测试结果往往相互矛盾。

## Apache Spark

Apache Spark 是一个分布式内存计算框架，带有用于 SQL、流处理、机器学习和图分析的库。凭借超过 1000 名贡献者，它是 Apache 项目中最活跃的、Hadoop 生态系统中最活跃的，也是大数据领域中最活跃的项目。鉴于其重要性，我们在第五章中单独讨论 Spark，该章涵盖内存分析。

#### Apache Impala

Impala 是一个用于 Hadoop 的大规模并行处理 (MPP) SQL 平台。该软件由 Cloudera 开发和维护，采用 Apache 许可证，是免费且开源的。Cloudera 于 2012 年 10 月宣布该项目，并于 2013 年 5 月发布其通用版本。2015 年，Cloudera 将 Impala 捐赠给了 Apache 软件基金会。

Apache Impala 对以流行的 Apache Hadoop 文件格式存储的数据运行快速的交互式 SQL 查询。Impala 与 Apache Hive 元存储集成，以在各组件之间共享数据库和表。这使得用户能够自由选择使用 Impala 或 Hive，而无需移动或复制数据。

Impala 支持 HiveQL，并内置了用于数学运算、数据类型转换、日期和时间操作、条件表达式以及字符串处理的函数。对于更高级的操作，Impala 支持带有统计功能（如计数、求和、平均值和中位数）的聚合函数，以及用于有序和分组统计的窗口函数。最后，Impala 支持基本的用户定义函数 (UDF) 和用户定义聚合函数 (UDAF)，用于自定义操作。

使用 Impala 的用户通过 Impala Shell 或任何符合 ODBC 或 JDBC 标准的客户端提交命令。

Impala 直接对存储的数据进行操作，不使用中间计算层（例如 MapReduce 或 Spark）。它与 HBase 和 HDFS 协同工作，支持常见格式：文本、SequenceFiles、RCFiles、Apache Avro 和 Apache Parquet。Impala 也能与亚马逊 Web 服务的 S3 文件格式协同工作。

2014 年初，IBM 研究院发布了一项性能测试结果，该测试比较了 Hive、Hive on Tez 和 Impala 在不同文件格式和压缩编解码器下的性能。测试协议采用了事务处理性能委员会发布的标准测试协议。

在 IBM 的测试中，对于 TPC-H 基准测试，Impala 的运行速度比 Hive on MapReduce 快 3-4 倍，比 Hive on Tez 快 2-3 倍。对于 TPC-DS 基准测试，Impala 的运行速度比 Hive on MapReduce 快 8-10 倍，比 Hive on Tez 快约 4 倍。

TPC-H 和 TPC-DS 是事务处理性能委员会发布的标准决策支持基准测试。这些基准测试由一系列典型的即席查询组成，模拟了典型用户的工作负载。

2014 年晚些时候，Cloudera 发布了其自身的基准测试结果，比较了 Impala、Spark SQL、Facebook Presto 和 Hive on Tez 的性能。对于单用户查询，Impala 的性能优于所有替代方案，平均运行速度快 7 倍。对于多用户查询，Impala 进一步拉大了性能差距，平均运行速度快 13 倍。

Cloudera、MapR、Oracle 和亚马逊 Web 服务都分发 Impala；Cloudera、MapR 和 Oracle 提供商业构建和安装支持。



#### Apache Drill

Apache Drill 是一个用于交互式分析的开源分布式软件框架。

2010 年，一组谷歌工程师发表了一篇论文⁴⁴，描述了一个用于交互式即时查询分析的分布式系统，该系统旨在数秒内聚合万亿行的表。他们将这个系统命名为 `Dremel`。`Dremel` 启发了谷歌的 `BigQuery`，这是一个托管在谷歌云中的交互式即时查询系统。

由 MapR 公司的 Ted Dunning 领导的一组贡献者提议开发 `Dremel` 的开源版本，并更名为 `Drill`。2012 年 9 月，Apache 软件基金会接纳 `Drill` 作为孵化器项目。`Drill` 于 2014 年 12 月毕业，成为顶级项目。2015 年 6 月，团队发布了该软件的 1.0 版本。`Drill` 的开发者社区包括 MapR、Intuit、Hortonworks、Elastic、LinkedIn、Pentaho、Cisco 和威斯康星大学等机构的员工。

`Drill` 允许用户查询带有或不带预定义模式的数据，并且能够查询非结构化或嵌套数据。它提供完整的 ANSI 标准 SQL，并与广泛使用的 BI 工具集成。`Drill` 可以跨多个数据源联合查询。

潜在用户可以直接从项目网站下载并安装 `Drill`；MapR 也将 `Drill` 作为其 Hadoop 发行版的附加组件进行分发。

用户可以将 `Drill` 部署为独立应用程序，或部署在任何 Hadoop 集群上。

最终用户可以通过 ODBC 和 JDBC 驱动程序，使用 BI 工具（如 Tableau、MicroStrategy 或 Microsoft Excel）查询 `Drill`。`Drill` 还支持用于自定义应用程序的 REST API，以及 Java 和 C 应用程序。

`Drill` 目前支持以下数据源：

-   Hadoop：Apache Hadoop、MapR、Cloudera CDH 和 Amazon EMR
-   NoSQL：MongoDB 和 HBase
-   云存储：Amazon S3、Google Cloud Storage、Azure Blog Storage 和 Swift

尽管 Apache Drill 项目团队声称具备万亿行的可扩展性，但截至 2015 年 6 月，尚无公开的基准测试或参考用户。`Drill` 作为交互式查询工具潜力巨大，但目前商业应用有限。

`Drill` 拥有活跃的贡献者基础，其代码库自 2014 年中期以来稳步扩展⁴⁵。

#### Presto

Facebook 拥有最大之一的活跃数据仓库，在几个大型 Hadoop 集群中存储了超过 300 PB 的数据。为了满足对此资产进行 SQL 连接的需求，Facebook 工程师于 2007 年创建了 Hive 软件，用于查询这个庞大的数据存储。

如前所述，在其原始架构中，Hive 使用 `MapReduce` 作为计算引擎，这使其仅适用于批处理查询。2012 年，Facebook 工程师开发了一种更好的工具，用于快速交互式 SQL，称为 `Presto`。经过广泛的内部测试并在内部用户社区中推广后，Facebook 将代码分享给其他一些组织进行测试和反馈。2013 年底，Facebook 将 `Presto` 代码捐赠给开源社区，并根据 Apache 2.0 许可证向所有用户开放。

Facebook 报告称，它已成功将 `Presto` 集群扩展至 1000 个节点。该公司还报告⁴⁶称，超过 1000 名员工在 `Presto` 上运行查询，每天在超过 1 PB 的数据上执行超过 30,000 次查询。2015 年 5 月，开发者报告称，通过持续改进，新版本的速度显著提升。⁴⁷

`Presto` 支持跨多种数据源（包括 Hive、Cassandra、关系型数据库或专有文件系统（如 Amazon Web Services 的 S3））进行 ANSI SQL 查询。`Presto` 查询可以联合来自多个来源的数据。用户可以通过 C、Java、Node.js、PHP、Python、R 和 Ruby 提交查询。`Airpal` 是 Airbnb 开发的一个基于 Web 的查询执行工具，允许用户通过浏览器向 `Presto` 提交查询。

`Presto` 的用户群目前包括 Facebook、Airbnb 和 Dropbox。

组织可以通过 Qubole 在本地或云端部署 `Presto`。2015 年 6 月，Teradata 宣布⁴⁸计划开发并支持该项目。根据公布的三阶段计划，Teradata 提议将 `Presto` 集成到 Hadoop 生态系统中，使其能在 YARN 下运行，并通过 ODBC 和 JDBC 增强连接性⁴⁹。

OpenHub 统计数据显示⁵⁰，`Presto` 是一个非常活跃的项目，代码库稳步扩展。



## 摘要

尽管分析人士对于 Hadoop 的增长速度和企业渗透率存在一些争议，但毫无疑问，Hadoop 生态系统正在快速增长。我们从在生态系统中发挥关键作用的 Cloudera、Hortonworks、MapR、亚马逊云服务（Amazon Web Services）等公司的披露中了解到这一点。

这种增长有两个原因。第一个原因是如第二章所述，文本、图像、音频、视频以及其他不适用于关系型数据库的数据如海啸般涌现。第二个原因是经济因素。Hadoop 每 TB 的成本远低于其他数据管理工具。

在 2014 年之前的 Hadoop 1.0 版本下，Hadoop 处理非关系型数据的能力是其主要的应用理由。对于分析而言，它并不是数据仓库设备的可靠竞争对手，因为它太不成熟、不稳定、原始、缓慢且难以使用。

自 Hadoop 2.0 实施以来，面向 Hadoop 的商业和开源软件包数量呈爆炸式增长。将替代编程框架与`MapReduce`结合使用的能力，使得运行最复杂的分析成为可能。

与此同时，该平台本身也已成熟。得益于与企业客户打交道的商业供应商的贡献，Hadoop 变得越来越稳定和安全。诸如`Tez`和`Spark`等旨在提升性能的项目，使 Hadoop 成为交互式分析的可靠平台。我们将在第五章详细讨论`Spark`。

对于 SQL 分析而言，Hadoop 与关系型数据库的竞争力日益增强。在 Hadoop 1.0 下，`Hive`和`Pig`适用于高延迟的批处理程序；在语义上，它们支持 ANSI SQL 的一个子集。得益于`Stinger`项目，`Hive`现在在交互式分析方面与其他工具具有竞争力，`Impala`、`Spark SQL`、`Drill`和`Presto`也是如此。并且，它们正在迅速接近完全符合 ANSI SQL 标准。

此外，业务用户也越来越容易使用 Hadoop。得益于自助分析领域的多项创新，业务用户现在可以使用`Excel`和`Tableau`等工具直接操作 Hadoop。我们将在第九章介绍这些创新。

随着 Hadoop 的成熟，它与传统数据仓库展开竞争，其颇具吸引力的经济性至关重要。拥有现有数据仓库的企业，在其现有平台即将退役时，有强大的经济动机用 Hadoop 替代现有平台。

Hadoop 的经济性使其对无法承担传统数据仓库成本的应用场景具有吸引力。更重要的是，Hadoop 的边际“沉没”成本使其成为回报未知的应用场景的理想选择。因此，Hadoop 成为各类实验室、沙箱、臭鼬工厂以及创新的首选平台。

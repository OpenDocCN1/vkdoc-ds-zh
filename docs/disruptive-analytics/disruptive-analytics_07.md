# 7. 云端分析

弹性计算带来的颠覆性力量

几年前，领先的商业分析软件供应商之一 SAS 为其金融服务客户经理召开了一次年度销售会议。创始人兼 CEO 吉姆·古德奈特（Jim Goodnight）向在场的销售人员发表了讲话，并主持了问答环节。

“我们在云计算方面的战略是什么？”一位销售代表问道。

“关于云计算，你们只需要知道一点，”古德奈特慢吞吞地说道，“全是扯淡。”他将云计算比作 20 世纪 70 年代的大型机服务局，后者通常根据使用量提供按需计费。古德奈特在最近接受《华尔街日报》采访时再次重复了这一比喻。¹

当然，每个人都明白现代云计算与大型机分时共享并不相同，就像 2016 年的福特福克斯与 1976 年的福特平托并不相同，尽管它们都有四个轮子。不过，古德奈特指出了一些相似的原理——跨多个用户共享 IT 资源以及按需计费——这倒是没错。

无论云计算是全新的革命，还是像古德奈特所说的“全是扯淡”，有一点很清楚：云正在吞噬 IT 世界。一家领先的分析机构预测² ，2013 年至 2018 年间，云数据中心的工作负载将增长三倍；此外，到 2018 年，78% 的数据中心工作负载将运行在云端。

我们还注意到，在古德奈特最初发表此番言论后不久，SAS 便宣布³ 计划投资 7000 万美元建设云计算数据中心。

## 云计算基础

美国国家标准与技术研究院（`NIST`）将云计算定义为：

> ……一种模型，用于实现对可配置计算资源共享池的无所不在、便捷、按需的网络访问……这些资源能够以最少的管理工作或服务提供商交互的方式被快速配置和释放。⁴

云计算具有五个基本特征：

- `按需自助服务`：用户无需系统管理员的帮助，即可自行配置所需的计算资源，例如服务器时间和存储空间。

- `广泛网络访问`：用户可以通过网络从多样化的连接平台（包括手机、平板电脑、笔记本电脑和工作站）访问计算服务。

- `资源池化`：服务提供商将计算资源集中起来，服务于多个消费者，物理资源根据需求进行分配和再分配。用户对所分配的具体物理资源没有控制权或知情权。

- `快速弹性`：消费者可以根据需求获取和释放资源；对消费者而言，计算资源似乎是无限的，并且可以随时以任意数量获取和释放。

- `可计量服务`：云提供商在适当的维度上（例如服务器时间或存储容量及时间）对计算服务进行计量。资源使用情况以对用户和提供商都透明的方式进行监控和报告。

`NIST` 定义了四种云部署模型：私有云、社区云、公有云和混合云。

- `公有云`：云提供商拥有并维护一个云平台，并向普通公众提供服务。

- `私有云`：云提供商为自身独占使用而配置云。例如，一家公司构建并维护一个云计算平台，并为其自身员工和承包商提供服务。该云可由组织、第三方或其联合体拥有和管理，并可位于内部或外部。虚拟私有云（`VPC`）使用软件框架在公有云基础设施上提供等同于私有云的服务。`VPC` 非常适合中小型企业（`SMB`）的需求。

- `社区云`：多个组织（例如行业协会或兴趣团体）联合配置一个社区云，供成员组织独占使用。与私有云类似，社区云可由一个或多个关联组织、第三方或其联合体拥有，并可位于内部或外部。

- `混合云`：一个组织合并了来自多种部署模型（私有云、社区云或公有云）的基础设施。例如，一家公司运行自己的私有云，并在工作负载高峰期使用公有云作为补充。一个软件框架对混合云进行统一管理，因此用户不会知道某个作业是在私有基础设施还是公有基础设施上运行。`IDC` 调查的组织中，整整 70%报告采用了混合云方法。

咨询公司 `IDC` 预测⁵，全球公有云收入将从 2015 年的近 700 亿美元增长到 2019 年的超过 1410 亿美元。2016 年，亚马逊云服务（`AWS`）主导市场；微软排名第二且增长迅速。其他供应商包括谷歌、`VMware`、`IBM`、`DigitalOcean` 和甲骨文。⁶

`IDC` 估计⁷，2015 年私有云基础设施的总支出为 121 亿美元；而咨询公司 `Wikibon` 估计⁸的数额则低得多，为 70 亿美元。（私有云比公有云更难衡量。）该市场的领先供应商包括慧与（`HPE`）、甲骨文、`VMware`、`EMC` 和 `IBM`。私有云市场比公有云市场分散得多，排名前十的供应商仅控制了约 45%的支出。

一家咨询公司预测⁹，到 2022 年，`VPC` 的总支出将超过 400 亿美元。社区云在市场中的规模要小得多，预计到 2020 年总支出将达到 31 亿美元¹⁰。

在 `NIST` 的广泛部署模型下，云计算有三种不同的服务模型：

- `基础设施即服务（IaaS）`：最基本的云服务：提供商提供基础的计算、存储和网络服务以及虚拟资源管理器。最终用户安装并维护操作系统和应用软件。

- `平台即服务（PaaS）`：提供商提供完整的计算平台，包括操作系统、编程语言、数据库和 Web 服务器。最终用户在该计算平台上开发或部署应用程序，但云提供商负责支持组件的安装和维护。

- `软件即服务（SaaS）`：最终用户可以直接访问应用软件。`SaaS` 有两种不同的模型：直销模型和商场销售模型。在直销模型下，软件供应商处理软件应用和维护，并或在其自身基础设施上托管该软件，或与云提供商签订合同以获取`IaaS`或`PaaS`服务。在商场销售模型下，云提供商创建一个平台，最终用户可以在此选购来自多个供应商的软件；云提供商处理应用软件的安装和维护。

咨询公司 Technology Business Research（`TBR`）估计，`SaaS` 目前约占公有云市场的 60%；Salesforce 是`SaaS`领域的明确领导者。`PaaS` 市场相对较小，约占 2016 年市场的 10%；`TBR` 预计到 2020 年其增长率将达到 17%。微软在`PaaS`领域领先，其次是 `IBM`、Salesforce 和谷歌。

一般而言，`IaaS` 服务面向开发者和 IT 组织，他们为其最终用户的利益配置和管理平台。`PaaS` 服务面向开发者和高级用户，这些用户愿意且能够执行基本的软件配置任务。`SaaS` 服务面向业务用户。

在实践中，服务模型之间的区别往往模糊不清。例如，亚马逊云服务（`AWS`）通常被认为是`IaaS`提供商；但 `AWS` 也提供`PaaS`乃至`SaaS`服务。随着云提供商寻求扩大其产品的覆盖范围和盈利能力，我们可以预期他们将寻求向价值链上游移动，提供更高级别的服务和解决方案。

云计算带来的益处类似于托管软件服务，但其商业模式和技术有所不同。软件托管至少可以追溯到 20 世纪 60 年代的大型机服务局模式；到了 20 世纪 90 年代，服务局演变为应用服务提供商（`ASP`），并采用了更多样化的技术栈。

与云服务提供商不同，`ASP`根据合同为客户托管软件和应用程序。客户从软件供应商处获得软件许可；然而，托管提供商并非在本地部署软件，而是根据长期合同实施并管理该软件。`ASP`通常不会跨客户池化 IT 基础设施；相反，`ASP` 将专用基础设施的成本计入合同成本中。合同条款通常要求定期固定付款，并附有按使用计费的额外服务时间表。

`ASP`往往作为大型软件供应商的合作伙伴运营。软件供应商的营销能力有助于`ASP`的业务拓展，而`ASP`的托管模式则帮助软件供应商向 IT 技能和容量有限的公司销售产品。许多大型软件供应商，如 SAS 公司，都运营着自己的内部`ASP`业务。

云计算建立在三大创新之上：

### 虚拟化

硬件虚拟化是一种从单台物理机器创建一个或多个模拟计算环境（“虚拟机”或“实例”）的过程。虚拟化能够提升 IT 效率，因为单个应用程序很少能充分利用现代计算机硬件的全部性能。

虚拟化的主要目标是通过提高计算的可扩展性来管理工作负载。虚拟化并非新概念，但它已经持续演进了数十年。如今，它可以应用于广泛的系统层级，包括操作系统、应用程序、工作空间、服务以及硬件组件（包括内存、存储、文件系统和网络）。

除了提高硬件利用率之外，虚拟化还提供了其他优势。例如，IT 组织可以更轻松地管理虚拟实例上的安全性和访问控制，并且在需要维护或故障切换时，可以快速将实例从一台物理机器重新部署到另一台。

### 面向服务的架构（SOA）

面向服务的架构是一种计算机设计架构，其中应用程序组件通过通信协议向其他组件提供服务。服务是对可重复业务活动的自包含、松散耦合的表示形式。将复杂的应用程序分解为独立的服务，可以简化开发、维护、分发和集成。

### 自主计算

2001 年，`IBM` 创造了“自主计算”这一术语，指的是一种分布式计算方法，旨在构建具有自主组件的自调节系统。自主组件能够自行配置、修复、优化和保护。

支撑云的技术并非全新事物。像亚马逊、谷歌和 Facebook 这类公司的极速增长，及其对 IT 基础设施随之而来的巨大需求，催生了一场在虚拟化、资源调配、能耗、安全以及运营现代数据中心所需的其他学科领域中的技术与技能的完美风暴。

## 云的商业案例

在本节中，我们将讨论云的经济效益以及促使企业使用云的用例，同时涉及数据迁移和安全方面的考量。

### 云经济学

# 云计算的经济性与应用场景

云计算比本地计算更昂贵还是更便宜？这个问题存在一些争议。这个问题具有挑战性的一个原因是，许多企业并未准确衡量其 IT 基础设施的总成本；他们衡量设备和购买软件的“硬成本”，但未能衡量 IT 人员的“软成本”。另一方面，云计算成本是有形的；在计费周期结束时，供应商会发送发票，因此成本是清晰的。这往往会导致一些组织对云产生偏见，尤其是当 IT 高管认为云计算构成威胁时。

## 云计算供应商的经济优势

与本地 IT 组织相比，云计算供应商享有诸多优势。

### 规模经济

像亚马逊云服务和谷歌这样的供应商会大量采购硬件。他们拥有能力极强的采购团队，能够与硬件供应商进行艰难的议价。

### 技能经济

公有云供应商会雇佣最优秀、最聪明的人才来管理他们的数据中心。他们是能力极强的管理者，在运营大规模全球网络方面拥有深厚经验。在数据中心管理的各个方面，从虚拟化到能源消耗，他们都只是更擅长自己的工作。

### 利用率经济

通过整合资源并将其分散到庞大的全球用户群中，公有云供应商能够实现比单个企业高得多的 IT 基础设施利用率。这意味着云供应商可以以更低的单价提供计算资源。

得益于这些经济效应，再加上主要云供应商之间的激烈竞争，在 2016 年之前，公有云的费用每年都以两位数的百分比下降。

当然，这些经济效应并非普遍适用。一些大型组织拥有足够的规模和技能，能够提供与云价格相匹配甚至更低的单位计算成本。拥有精确总拥有成本（TCO）指标的组织可以自信地断言，将计算保留在本地是经济合理的。

## 使用云的合理场景

但是，即使对于单位计算成本较低的企业来说，也存在许多使用云的合理场景。

### 可预测的峰值工作负载

许多组织的工作负载具有可预测的峰值，这些峰值显著高于基准工作负载。例如，零售商在圣诞节旺季期间处理的交易量要高得多，而大多数组织在月末有大量的会计和财务应用程序处理需求。如果一个组织为满足其峰值工作负载而建设 IT 基础设施，那么该基础设施在大部分时间都将处于利用不足的状态。对于这些组织而言，采用混合方法（使用云处理峰值工作负载，使用本地系统处理基准工作负载）是最优方案。

### 意外的峰值工作负载

对于 IT 工作负载出现意外激增的组织，类似的考量也适用。与其匆忙增加更多基础设施来支持突然且意外的需求增长，不如使用云来支持增量工作负载，至少在完成根本原因分析之前这样做是合理的。

### 可变成本业务

服务行业的许多企业本质上是可变成本业务；它们资本薄弱，其运营模式是将成本转嫁给客户和项目。咨询公司、广告公司、营销服务提供商、分析精品店以及其他类似公司通常倾向于避免对任何形式的间接费用进行投资，包括 IT 基础设施。这类公司可能选择完全依赖云来支持项目工作。

### 实现价值的时间

在许多情况下，高管们对成本的关注度较低，更关心的是实现价值所需的时间。这在快速发展的企业中通常如此；对于 IT 组织已满负荷或接近满负荷运营的公司来说，情况也可能如此。对于这些公司，云提供了即时的容量和快速扩展的能力。速度和实现价值的时间是像`Salesforce`这样的 SaaS 供应商所强调的关键价值主张，以满足企业对快速获得能力的需求。

### 业务单元自主权

业务单元有时会选择独立于 IT 组织工作。这可能是由于 IT 有效支持业务能力的实际或感知缺陷、高管之间的政治冲突，或与其他业务单元争夺稀缺的 IT 资源所致。无论如何，转向云端为业务单元高管提供了控制关键任务计划所需 IT 资源的机会。

### 试点和概念验证

某些业务分析用例对云非常有吸引力。其中包括试点项目和概念验证（POC）：旨在确定特定解决方案可行性的项目。云计算对这些项目具有吸引力，因为组织可以快速配置一个临时环境，而无需承担基础设施沉没成本的风险。如果项目被证明可行，组织可以将应用程序保留在云端或迁移到本地平台。如果试点或 POC 不成功，组织只需将其关闭即可。

### 临时分析

战略性的临时项目也是云的一个有吸引力的用例。为高管执行的许多分析是不可重复的；分析将执行一次，此后不再执行。传统的数据仓库方法不适用于临时分析，而临时分析在大多数企业中出奇地普遍。云使分析师能够快速创建一个临时的数据存储，并根据需要提供足够的存储和计算能力。

### 模型训练

机器学习的模型训练阶段特别适合云中的弹性计算，原因如下：
- 模型训练是面向项目的，而不是重复的生产活动。（另一方面，模型评分是面向生产的。）
- 机器学习算法需要大量的计算能力，但持续时间很短。
- 机器学习项目通常支持在 IT 基础设施投资之前进行的开发项目。
- 在市场营销等领域，项目通常启动时间很短，需要快速配置。
- 为了交付机器学习项目，组织经常聘用分析服务提供商（ASP），他们必须考虑基础设施成本。

许多企业将临时分析外包给咨询公司和分析服务提供商。云计算对这些公司尤其重要，因为云的低成本和按量计费服务使他们能够将计算成本明确地与客户项目匹配，并在无需资本投资的情况下快速扩展。

## 数据移动

在处理大数据时，数据移动始终是一个需要考虑的问题。对于小数据集只需几分钟的过程，当我们的数据以 PB（拍字节）计量时，可能需要数小时或数天。在大数据时代，最小化数据移动是一个关键的管理原则。

然而，在业务分析中，至少部分数据移动是不可避免的。IT 组织很少允许充当数据源的生产系统被用于分析；无论如何，这些系统通常缺乏必要的工具。因此，在大多数情况下，每部分数据在从源系统传输到分析存储库时，至少会被复制和移动一次。

将数据移入和移出云比在内部移动数据更令人担忧。公共网络可能成为瓶颈，而安全考虑要求在两端进行加密/解密操作，以避免数据泄露。为缓解这个问题，云提供商及其联盟伙伴提供了许多产品和服务。

### 专用物理连接

云提供商为客户提供通过专用私有网络连接直接连接到提供商数据中心的能力。像这样的服务对于寻求将常规更新移至基于云的环境进行分析的组织来说是一个不错的选择。

### 数据传输加速器

领先的云提供商运营着全球数据中心网络，并将与客户合作优化数据传输。例如，一个在多个国家运营的组织可能能够通过在每个国家本地传输数据，然后在云提供商的网络内整合数据，从而最小化数据传输成本。

### 便携式存储设备

安全可移动的存储设备现在可以存储高达 80 太字节（TB）的数据；更大的文件可以跨多个设备拆分。寻求将数据移入或移出云的组织，可以将数据复制到安全设备，然后通过隔夜快递发送到目标数据中心。这种方法在需要一次性移动大量数据的场景中非常出色，例如在数据库迁移或分析项目的早期阶段。

### 存储网关

对于寻求实现混合本地和云平台架构的组织，存储网关可能是合适的解决方案。存储网关（来自诸如`Aspera` (IBM)、`CloudBerry`、`NetApp`和`Zerto`等公司）驻留在客户本地，并在本地和云存储之间进行协调，维护一个数据及其位置的目录。存储网关处理压缩和加密。

### 数据库迁移服务

当组织寻求将数据从本地关系数据库迁移或更新到云中的数据库时，保持结构和元数据是高度可取的。提取和重新加载操作需要时间，因为数据库管理员必须将源数据库的结构映射到目标数据库；而且映射过程中容易出现人为错误。来自像`Attunity`这样的供应商的工具使组织能够直接在数据库之间复制数据，无论是在本地、云端，还是两者兼有。

当然，当源数据已在云端且无需传输时，云平台是业务分析的合理选择。一些企业已围绕云计算构建了其运营；对于这些组织来说，数据进出云平台的移动根本不是问题。

## 安全性

本地部署软件的供应商常营造一种印象，认为云环境不如本地数据管理安全。在许多组织中，部分高管认为数据保留在本地最为安全，因而反对将数据迁移至云端。

但数据揭示的情况恰恰相反。2015 年十大最严重的数据泄露事件均发生在本地设施中。企业法律顾问协会发布的一份网络安全报告指出，员工失误是数据泄露的主要原因；而隐私与数据保护专业机构贝克·霍斯泰特勒律师事务所进行的另一项分析则发现，员工疏忽是泄露的最大诱因。

有效安全措施的关键在于良好的管理策略与实践，而非数据的物理存储位置。主流公共云供应商在数据中心安全管理方面表现卓越，他们竭力确保自身符合 ISO 和 NIST 发布的安全标准，并满足 HIPAA 及其他监管法规的要求。在十年的服务历程中，主要云供应商尚未有过已知的安全泄露记录。

咨询公司技术商业研究（TBR）对高管的调查显示，安全因素是他们在云决策中的首要考量。然而，受访者也表示，他们认为由专业第三方存储和管理数据能提升整体安全性。同一项调查中，受访者指出，安全是选择私有云的主要考量因素；而在其他所有维度上，受访者对公共云的评价与私有云持平或更高。

个人可识别信息（PII）属于高度敏感数据，其未经授权的披露会直接影响消费者隐私，并使组织面临严重后果。PII 的定义范围出奇地宽泛，因为不法分子可通过整合多个来源的 PII，建立起潜在受害者的详细画像。个人的社会安全号码（SSN）显然是 PII；但欺诈者能从出生日期和出生地推测出受害者的 SSN。

个人可识别信息是指可用于识别、联系或定位个人的信息。在美国，国家标准与技术研究院发布了关于何种信息构成 PII 以及如何管理 PII 的标准。

虽然运营系统必须采集并保留 PII，但在业务分析中通常并不需要这些信息。这一概括也存在例外情况：分析师可能希望运用机器学习技术处理客户姓氏以识别种族，或对客户地址进行地理编码以执行空间分析。当必须处理 PII 时，良好的工作方法能最小化安全风险；我们将在第十章中讨论这些方法。

## 公共云中的分析

在本节中，我们将考察亚马逊云服务、微软和谷歌提供的与业务分析相关的云服务。我们重点关注存储、计算、Hadoop、关系型数据库、商业智能和机器学习领域的托管服务；这三大供应商还提供许多其他服务，这些服务可能适用于某些项目。本节旨在涵盖最广泛使用的服务。

我们提供定价信息以供参考和比较，但读者应牢记，云供应商会且确实频繁调整价格。

虽然我们重点关注托管服务，但三大供应商均提供基本的计算和存储服务，这使得组织能够在云端部署任何许可软件。

### 亚马逊云服务

亚马逊云服务（AWS）提供超过 50 种托管服务。其中，与业务分析最相关的服务包括：存储服务、计算服务、Hadoop 服务、数据库服务、商业智能服务和机器学习服务。

#### 存储服务

对于任何云平台而言，数据存储都是最基础的服务，原因有二：首先，数据首次上传到云端时，它可作为初始的暂存区域；其次，在应用程序处理完毕后，它可作为持久化存储使用。

在 AWS 中，大多数计算实例都包含部分本地存储，只要实例可用，这些存储就可供使用。然而，当用户对计算实例的租约到期时，保存在本地存储中的任何数据都将丢失。因此，将长期文件存储与计算实例（用户可能仅短期租用后便释放）分离开来是合理的。

亚马逊简单存储服务（`S3`）是 AWS 于 2006 年 3 月推出的第一项服务。它是一种低成本、可扩展的存储服务，可存储高达 5TB 的计算机文件，文件格式不限。

应用程序通过流行的 Web 服务接口（如 REST、SOAP 和 BitTorrent）与 `S3` 交互；这使得 `S3` 能够作为 Web 应用程序的后端存储。据 AWS 称，`S3` 服务使用的技术与 Amazon.com 在其电子商务平台上使用的技术相同。

AWS 提供三种不同价位的存储类别：标准存储、低频访问存储和 Glacier 存储。

- **标准存储**提供即时访问，无最小文件大小限制、无最短存储时长要求，且无检索费用。

- **低频访问存储**提供即时访问，但会产生检索费用、有最小文件大小限制，且要求最短存储时长 30 天。只要用户不频繁检索文件，月度成本会更低。

- **Glacier 存储**提供最长四小时延迟的访问，会产生检索费用，且要求最短存储时长 90 天。

AWS 对 `S3` 的使用按月按千兆字节（GB）收费。定价取决于存储类别和使用的总存储量。例如，在美国东部地区，标准存储每月每 GB 的价格（1TB 以内）为 0.03 美元；低频访问存储为每月每 GB 0.0125 美元；Glacier 存储则为 0.007 美元。这三类服务的价格均随使用量增加而递减。与所有 AWS 服务一样，价格可能因地区而异。

#### 计算服务

Amazon 弹性计算云（`EC2`）是 AWS 最早提供的服务之一，至今仍是其云平台的基石。`EC2` 使用户能够租用虚拟机来部署自己的应用程序，并按小时支付机器使用费用。

用户可以根据需要启动和结束服务器会话，从种类繁多的实例中进行选择，并根据计算能力定价。AWS 可用的服务器类型不断变化，主要分为以下五类：

-   **通用型**实例在计算、内存和网络资源之间取得平衡。此类别中的某些实例具有可突发性能，这意味着它们提供了一个基准容量，并能够临时“突发”超过该基准。

-   **计算优化型**实例拥有性能最高的处理器（以 CPU 速度衡量）。

-   **内存优化型**实例为每个 CPU 配备了更大容量的随机存取存储器（`RAM`）。

-   **GPU 实例**包含一个或多个 NVIDIA GPU。

-   **存储优化型**实例包括具有 SSD 存储的高 I/O 实例和每个 CPU 配备超大硬盘的高密度存储实例。

在每个类别中，AWS 提供了从小型（相当于笔记本电脑）到超大型（拥有数千个核心）的各种尺寸。实例预配置了操作系统镜像；用户可以从 Linux（Amazon、Red Hat、SUSE 或 CentOS）、Windows（带或不带 SQL Server）、Debian 及其他操作系统中进行选择。

`EC2` 用户可以预定义虚拟设备，称为 Amazon 机器镜像（`AMI`）。这些镜像包括一个操作系统以及运行应用程序所需的任何其他软件。`AMI` 使得在 `EC2` 上运行复杂的软件栈具有成本效益，因为用户无需花费宝贵的实例时间来安装和配置软件。

AWS 为 `EC2` 提供了三种主要的定价模式：按需、预留和竞价。按需定价下，用户按小时付费，无任何承诺。定价因区域和操作系统而异；2016 年 4 月，美国东部地区 Amazon Linux 的价格范围为每小时 0.0065 美元至 6.82 美元。

预留实例定价为用户提供折扣，条件是用户承诺使用该实例一至三年。折扣幅度很大。例如，对于一个大型通用实例（`M4`），用户需为三年期预付 1,173 美元，相当于每小时 0.0446 美元；相比之下，按需的小时费率为 0.12 美元，几乎是前者的三倍。（定价基于 2016 年 4 月美国东部地区的 Amazon Linux。）当然，这个比较仅在用户在合同期内持续运行该实例上的应用程序时才有效。

按需实例和预留实例定价之间的差异，类似于租酒店和租公寓之间的区别。一个到访城市的旅行者只需住几个晚上，愿意为短期住宿支付相对较高的每晚价格。在其他晚上，酒店将房间租给其他旅行者。另一方面，一个居住在城市里的人需要一个常年居住的地方，并且愿意做出长期承诺，以换取在租期内对公寓的独占使用权。

竞价定价模式就像一个拍卖市场。用户对未使用的 Amazon `EC2` 容量进行竞价；实例按竞价价格收费，该价格由 AWS 设定，并随供需关系波动。

#### Hadoop 服务

在第四章中，我们介绍了 Hadoop 生态系统。Amazon Elastic MapReduce（`EMR`）是 AWS 针对 Hadoop 提供的托管服务。AWS 于 2009 年 4 月首次提供 `EMR` 服务。

`EMR` 在两个层面上具有弹性。用户可以不受限制地部署多个集群；集群可以进行不同的配置，使用不同的实例类型，同时仍能共享存储。用户还可以调整现有集群的大小，甚至在集群中运行作业时添加或删除节点。

AWS 为 `EMR` 用户提供了使用不同文件系统的能力，包括 `S3`、`HDFS`（“原生”Hadoop 文件系统）、Amazon DynamoDB（一种 NoSQL 数据库服务）、Amazon `RDS` 和 Amazon `Redshift`。`EMR` 包含了 Hadoop 生态系统中的常用组件，包括`HBase`、`Hive`、`Hue`、`Impala`、`Pig`、`Presto`、`Spark` 和 `Zeppelin`。

AWS 按实例小时为 `EMR` 定价，每个集群一个实例，无论集群中有多少个节点。定价根据用于集群的实例类型而有所不同。用户还需支付 `EC2` 费用。因此，一个在大型通用实例上运行的 10 节点 `EMR` 集群的总费用将是 10 个 `EC2` 实例的费用加上 `EMR` 实例的费用。

#### 数据库服务

Amazon 关系型数据库服务（`RDS`）是一种分布式数据库服务，于 2009 年 10 月首次提供。截至 2016 年 4 月，AWS 为 MySQL、Oracle 数据库、Microsoft SQL Server、PostgreSQL、MariaDB 以及 Amazon Aurora（MySQL 的高可用版本）提供托管服务。

Amazon `Redshift` 是一个基于数据仓库厂商 Actian 技术授权的 PB 级列式数据仓库。`Redshift` 适用于对海量数据进行 SQL 分析。

理论上，用户可以在租用的 `EC2` 实例上搭建自己的数据库。而 AWS 的这些服务免除了用户安装、配置、预置和修补数据库软件的需求，并简化了扩展计算和存储的过程。AWS 还提供自动备份和数据库快照。

#### 商业智能服务

AWS 用户可以在 `EC2` 中设置任何 BI 工具，并查询 `RDS` 或 `Redshift` 中的数据库。2015 年 10 月，AWS 宣布了其自有商业智能服务的公开预览版，品牌名为 Amazon QuickSight。QuickSight 使用户能够连接到 `Redshift`、`RDS`、`EMR`、`S3` 以及许多其他数据源中的数据，并使用分布式内存计算引擎提供快速的交互式可视化。AWS 预计于 2016 年将该服务投入生产，定价为每用户每月费用。

#### 机器学习服务

Amazon 机器学习（`ML`）是一项托管服务，可与存储在 Amazon `S3` 文件、Amazon `Redshift` 或 Amazon 关系型数据库服务中的 MySQL 数据库中的数据配合使用。该服务包括数据可视化、探索和转换工具，以及数量有限的机器学习算法。

对于预测，该服务支持用于批量或实时评分的 API。该服务不支持模型导入或导出。

AWS 按固定的小时费率对该服务定价，用于分析数据和构建模型，并针对批量预测和实时预测分别收取基于使用量的费用。

#### 市场

AWS 还运营着一个市场平台，使软件供应商和其他卖家能够提供其能力。供应商以`Amazon 机器镜像`、`AWS CloudFormation`堆栈或软件即服务的形式提供软件。

`AWS CloudFormation`是一项帮助用户建模和设置`AWS`资源的服务。它提供比`Amazon 机器镜像`更广泛的功能。

在大多数情况下，供应商提供其软件的试用版，免收许可费。其他供应商则按小时、按月或按年收取许可费，由`AWS`负责计量和计费。还有一些情况，用户必须通过其他渠道单独为软件获取许可。在所有情况下，用户均需承担`AWS`的存储和计算费用。

## Microsoft Azure

微软对云计算有着独特的方法，这反映了其在本地计算和企业桌面软件方面的优势。微软云服务的核心是`Microsoft Azure`，一个管理计算和存储资源的专用操作系统。（`Microsoft Azure`品牌既适用于整个云平台，也适用于该云操作系统。）

### 存储服务

`Microsoft`为不同类型的数据提供了多种存储服务：

-   用于结构化数据的`Azure Table Storage`（Azure 表存储）

-   用于文档、视频、备份和其他非结构化文本或二进制数据的`Azure Blob Storage`（Azure Blob 存储）

-   用于消息的`Azure Queue Storage`（Azure 队列存储）

-   用于服务器消息块 (SMB) 文件的`Azure File Storage`（Azure 文件存储）

这些存储类型有四种不同的数据冗余选项可供选择。最便宜的选项在一个数据中心内保留三份数据副本；最贵的选项将六份副本分发到两个地理上分离的数据中心，并提供读取访问以实现高可用性。

这四种存储类型各有独立的价目表。`Blob`存储最便宜，而文件存储最昂贵。

`Microsoft`还提供基于固态硬盘 (SSD) 的高级存储服务，适用于 I/O 密集型工作负载。

### 计算服务

与`AWS`类似，`Microsoft`提供各种实例类型和操作系统的虚拟计算平台。`Microsoft`还区分了用于开发和测试环境的 Basic 实例以及用于生产环境的 Standard 实例。

计算平台并不仅限于 Windows 操作系统。`Microsoft Azure`提供包含 Linux、Red Hat Linux、SUSE Linux、CentOS Linux 和 Canonical Ubuntu 的实例。毫不奇怪，`Microsoft`还提供了预配置了`Microsoft`应用程序（如`SQL Server`和`SharePoint`）的实例。

### Hadoop 服务

`Microsoft Azure HDInsight`是一项基于`Hortonworks HDP`发行版的托管 Hadoop 服务，并做了一些修改以体现`Microsoft`的标准和架构。`HDInsight`的弹性与`AWS`的`EMR`类似；用户可以添加或删除集群，也可以为现有集群添加或删除节点。

`HDInsight`包含标准`Hortonworks`发行版中捆绑的分析组件：`HBase`、`Hive`、`Pig`、`Phoenix`、`Spark`和`Storm`。用户需额外付费才能访问`Microsoft R Server`，这是一个带有 R 语言接口的分布式机器学习引擎。

`Microsoft`按节点对`HDInsight`进行定价。价格因每个节点使用的计算实例类型而异。

### 数据库服务

`Microsoft Azure SQL Database`是一项基于`Microsoft SQL Server`的托管式数据库即服务产品。该服务与`AWS`的关系型数据库服务类似，但限于单一的核心数据库产品。其数据库功能是`Microsoft SQL Server`功能的一个子集。

该服务的定价分为三个不同的服务层级。其度量单位是数据库事务单位 (`DTU`)，用于衡量数据库实例处理事务的能力。

对于 PB 级别的 SQL 处理，`Microsoft Azure`提供了 SQL 数据仓库，这是一个与`AWS Redshift`类似的列式数据库。与`Redshift`不同，SQL 数据仓库将计算和存储分离，因此用户可以在不丢失已存储数据的情况下关闭查询引擎。SQL 数据仓库还包括查询非关系型数据源（如分隔文件、ORC 存储、HDFS 和`Azure Blob`存储）的能力。

`Microsoft`以数据仓库单位 (`DWU`) 对 SQL 数据仓库的计算资源进行计费，`DWU`是衡量查询性能的指标。存储则按`Azure Blob`存储费率单独计费。

### 商业智能服务

`Microsoft`广受欢迎的 BI 工具，如 Excel 和`PowerBI`，可以轻松地将`Azure`数据管理服务用作后端。用户可以在本地部署这些工具，并将其配置为使用`Azure`数据源；应用程序在云端执行复杂计算，并将结果集传输给本地用户。

### 机器学习服务

`Microsoft Azure Machine Learning`是`Microsoft`提供的一项产品，包括基于浏览器的客户端、云端的机器学习算法、Python 和 R 的 API 以及一个应用程序市场。

`Azure Machine Learning Studio`（Azure 机器学习工作室）是一个交互式的拖放式开发环境，使用户能够构建、测试和部署机器学习应用程序。该服务支持多种格式的数据，包括文本文件、`Hive`表、SQL 表、R 对象等。`Azure Machine Learning`（Azure 机器学习）支持特征工程以及用于回归、分类、聚类和异常检测的各种算法。用户可以将自定义的 Python 和 R 模块嵌入到机器学习管道中，并将模型部署为 Web 服务。

`Microsoft`对`Azure Machine Learning`的定价方式为：每席位固定月费，外加使用`Machine Learning Studio`和`Machine Learning API`的按小时计费。

## Google 云平台

Google 云平台 (`GCP`) 是公有云市场中相对较晚的参与者，于 2010 年首次向公众提供存储服务，2012 年提供计算服务。然而，自那时起，Google 逐步增加了服务，现在提供了一个近乎完整的业务分析平台。

Google 目前不提供针对 BI 和可视化的托管服务。然而，许多此类工具可以连接到`Google BigQuery`（本章稍后讨论）并将其用作数据源。

### 存储服务

Google 云存储 (`GS`) 是一项与`AWS S3`和`Azure`存储服务类似的存储服务。`GS`可存储最大 5 TB 的对象。

与`AWS`类似，`GS`提供三种按可用性定价的存储选项。标准存储最贵，提供即时访问且无需检索费用。持久低可用性存储比标准存储略便宜，但保证的可用性较低。近线存储每 GB 的月费最低，但 Google 对每次检索都收费，并且以最低水平保证可用性。

与`Microsoft`不同，Google 不区分存储对象的类型。

### 计算服务

Google 计算引擎 (`GCE`) 提供虚拟机（“实例”），其底层基础设施与运行 Google 品牌服务（如 Gmail 和 YouTube）的全球基础设施相同。

`GCE`将实例分为预定义实例和自定义实例。预定义实例具有预设的虚拟化硬件属性和固定价格。预定义实例有四种类型：标准、共享核心、高内存和高 CPU。标准实例有 1 到 32 个核心；高内存和高 CPU 实例有 2 到 32 个核心。

用户可以指定自定义实例，包括偶数个虚拟核心（最多 16 或 32 个，取决于用户所在区域），以及每个虚拟核心 0.9 GB 到 6.5 GB 的内存（以 256 MB 为增量）。定价取决于虚拟 CPU 数量和内存量。

Google 以大幅折扣提供抢占式实例。Google 会提前 30 秒向用户发出警告，以便用户能够优雅地关闭实例。

`GCE`提供包含 Debian、CentOS、CoreOS、SUSE Linux、Ubuntu、Red Hat Linux (`RHEL`)、Free BSD 和 Windows 的实例。使用`RHEL`、`SUSE`和 Windows 需要额外付费。

虽然`AWS`和`Microsoft`按小时对计算服务计费，但 Google 按分钟计费，最低计费时长为 10 分钟。持续使用折扣适用于在计费月度内使用时间达到指定百分比的实例。Google 在所有区域的收费相同。

### Hadoop 服务

Google Cloud Dataproc 是一项针对 Hadoop 和 Spark 的托管服务。Google 于 2015 年 9 月首次以 Beta 版提供该服务，并于 2016 年 2 月正式推出。

`Cloud Dataproc` 包含核心 Apache Hadoop（`MapReduce`、`HDFS` 和 `YARN`）、`Spark`、`Hive`、`Pig`，以及连接至其他 GCP 服务（包括 `Cloud Storage`、`BigQuery`（本章稍后讨论）和 `BigTable`（本章稍后讨论））的连接器，所有这些都部署在 Debian 上。Google 将这些组件整合到一个镜像中，并通过发布主要或次要版本来更新镜像版本，以反映任何组件的版本发布和补丁。用户可以在版本发布后的 18 个月内选择较旧的版本来创建新集群。

与 `AWS EMR` 和 `Azure HDInsight` 一样，`Cloud Dataproc` 是完全弹性的。用户可以根据需要添加、删除集群或调整其大小。

Google 对 `Cloud Dataproc` 集群中的每个虚拟 CPU 收取每小时一美分的费用。

## 数据库服务

对于相对较小的关系型数据库应用，Google 提供 `Cloud SQL`，这是一项以 `MySQL` 数据库为特色的托管服务。该服务与 `AWS Relational Database Service` 和 `Microsoft Azure SQL Database` 类似。Google 按每个数据库实例的小时费率收费，该费率根据部署数据库的实例大小进行缩放。存储空间按月额外收费，并且出站（离开实例的流量）会产生网络费用。

`Google BigTable` 是一个 PB 级的高性能数据管理系统。它不是关系型数据库，而是一个可大规模扩展的超表或多维数据存储。`BigTable` 支持 `HBase` 和 Google 的 `Go` 编程语言的 API，并且提供一个连接器用于 `Google Cloud Dataflow`（Google 的通用编程框架）。

`BigTable` 不支持 `SQL`，因此无法与 `AWS Redshift` 或 `Microsoft Azure SQL Data Warehouse` 相媲美。对于可扩展的 `SQL`，Google 推荐使用 `Google BigQuery`，这是一个直接与 `Google Storage` 配合使用的 `SQL` 引擎。`BigQuery` 是 Google 核心技术 `Dremel` 的一个实现。Google 于 2006 年首次将 `Dremel` 投入生产，并至今仍将其用于许多应用程序。

`BigQuery` 使用列式存储和树状架构来分发查询。（我们在第一章中讨论过列式序列化。）列式存储能够实现非常高的数据压缩比，并最大限度地减少分析查询的扫描时间。Google 的查询树状架构使 `BigQuery` 能够在数千台机器上分发查询并收集结果。

Google 向用户收取存储费用（费率与 `Google Cloud Storage` 相同）以及查询的标准费用（每兆兆字节 5 美元）；第一个兆兆字节免费。某些计算密集型查询不符合标准费率；Google 将这些归类为高计算查询并单独定价。Google 未披露标准定价的计算限制。如果查询超过阈值，Google 会通知用户并提供成本估算；用户必须明确选择加入才能运行该查询。

虽然 `BigQuery` 在许多方面提供了与 `Redshift` 和 `SQL Data Warehouse` 类似的功能，但 Google 的定价模式却大不相同。AWS 和 Microsoft 服务的用户自行决定要使用的计算资源，并为他们请求的资源付费。`Google BigQuery` 用户为实际的查询处理量付费，而 Google 则决定用于该查询的计算资源。

## 机器学习服务

`Google Cloud Machine Learning` 是一项用于深度学习的托管服务。用户使用 Google 于 2015 年开源的 `TensorFlow` 框架来定义模型。（我们将在第八章讨论 `TensorFlow`。）

`Cloud Machine Learning` 与 `Cloud Dataflow` 集成用于预处理，并处理存储在 `Google Cloud Storage`、`BigQuery` 和其他数据源中的数据。

截至 2016 年 4 月，该服务处于 `Limited Preview` 阶段，Google 尚未公布定价。

`Google Cloud Vision API` 是一项托管服务，支持标签检测、光学字符识别、显式内容检测、面部检测、地标检测、徽标检测和图像属性。前 1,000 个单位免费；超过该数量后，Google 按每 1,000 个单位收费。一个单位是指应用于一张图像的一项功能或服务。

`Google Cloud Speech API` 使用深度学习将音频转换为文本。该 API 可识别超过 80 种语言和方言，并可处理直接上传或存储在 `Google Cloud Storage` 中的数据。该服务处于 `Limited Preview` 阶段。

`Google Translate API` 提供了一个简单的编程接口，可将任何文本快速翻译成 90 多种支持的语言中的一种。当源文本语言未知时，翻译引擎会自动检测。定价为每百万字符 20 美元。

Google 还提供 `Google Prediction API`，该服务可处理以 `CSV` 格式上传的训练数据。用户可以选择使用 Google 的“黑盒”训练算法，或从托管模型库中选择一种技术。该服务在最初六个月内免费使用，但有使用限制。免费期过后，Google 会按每个 `Google Cloud Platform Console` 项目收取基本月费，外加模型训练和预测的单独费用。定价不包括用于存储训练数据的 `Google Cloud Storage` 服务的费用。

# 云的颠覆性力量

支撑云计算的技术并非新鲜事物。真正颠覆科技行业，并由此波及领先的商业分析提供商的是云计算的商业模式——一种弹性、"按用量付费"的计算模式。

显而易见，云计算正在颠覆计算机硬件行业。2014 年，美国自然资源保护委员会委托进行了一项关于数据中心能效的研究。研究发现，云端服务器的运行容量利用率约为 65%，而本地部署的服务器容量利用率仅为 12%至 18%。本地服务器利用率较低，是因为运营这些服务器的组织会按峰值需求来建设容量，导致服务器大部分时间处于闲置状态。

如果企业将峰值工作负载迁移至云端，它们所需购买的服务器数量就会减少。这种情况已然发生，而那些依赖向其他企业销售计算机硬件来维持业务的公司正举步维艰：

- IBM 报告其服务器系统销售额下降了 22%。

- 芯片制造商英特尔因销售业绩不佳，计划裁减 12,000 个职位。

- 存储供应商 EMC 报告其产品销售额下降。

有趣的是，虽然英特尔的其他业务疲软，但其面向云计算供应商的销售额却增长了 9%。

云计算同样也在颠覆商业软件行业，原因有二。首先，许多组织并非忠于其软件供应商，而是被套牢了。云服务提供商通常在每个类别中都提供多种软件选择，包括开源软件以及它们自有品牌的低成本"贴牌"软件。选择迁移到云端往往会使组织的软件选择权重新被激活，从而鼓励用户更换供应商。

第二个颠覆因素在于弹性计算，以及用户只需按用量付费的理念。传统的软件许可模式要求客户购买永久许可，或者最低也要购买年度许可；无论客户是否充分利用该许可，其成本都已沉没。许多软件供应商的收入模式要求它们通过向客户加载他们只会部分使用的软件来"塞满渠道"。如果客户只为实际使用量（且仅为实际使用量）付费，那么他们的支出将大大减少。

许多商业软件供应商现在都支持其软件在三大云服务中的某一个上运行。然而，很少有供应商提供弹性定价，恰恰是因为他们担心这会侵蚀他们主要的收入模式。换句话说，商业软件供应商知道自己对客户过度授权了。

借助云计算，现在完全可以仅使用三大云计算供应商提供的服务来构建一个完整的商业分析平台。凭借一定的技术能力，分析团队可以用开源软件来补充供应商的托管服务，从而创建一个定制化的平台，以满足任何项目的需求。此外，这个平台还可以根据需要横向扩展，以应对需求变化。

在第十章，我们将更详细地讨论这样一个平台，并提供关于增值托管服务提供商的信息，这些提供商在云端提供完整的商业分析"技术栈"。

## 第 6 章 元编程与宏

*元编程* 是程序员使用的一种技术，用于编写代码（计算机指令），这些代码不会被直接求值和执行，而是生成不同的代码，这些代码随后再由机器进行求值和运行。

例如，以下 C++ 宏在广义上就是一种元编程：

```cpp
#define LOOPS(a,b,c) \
for (uint i=0; i<a; i++){ \
  for (uint j=0;j<b; j++){ \
    for (uint z=0;z<c; z++){ \
```

在这里，程序员无需编写三个 `for` 循环（假设在程序的多处都需要用到），只需编写 `LOOPS(1,2,3)`，这将在代码运行前被展开并替换为实际的循环结构。

在这种情况下，与大多数编程语言一样，“元编程”的用法仍然相当基础。首先，它需要一个与主构建步骤不同的构建步骤（在 C++ 中，这由预处理器完成）。其次，或许也是最重要的，替换是在文本层面的“搜索并替换”上进行的，而不涉及将代码作为计算机指令进行任何语法解释。

## 第 6 章 元编程与宏

在 `Julia` 和其他少数语言（尤其是那些派生或受 `Lisp` 编程语言启发的语言）中，程序员编写的代码会被解析并翻译成计算机指令，这一过程的结果称为抽象语法树（或 `AST`）。此时，代码呈现为一种数据结构，可以在语言内部进行遍历、创建和操作（无需借助第三方工具或单独的构建步骤）。这意味着“代码替换”（后来被称为 *宏*）可以拥有更强的表达能力和更强大的功能，因为你可以直接操作计算机指令，而不是操作文本。

本章将介绍*符号*和*表达式*的概念，然后解释宏的工作原理。

### 6.1 符号

符号与 `Julia` 将自身语言代码表示为数据结构的能力紧密相关。*符号*本质上是一种引用数据对象，同时使其保持未求值状态的方式。例如，在处理变量时，你可以使用符号来引用实际的标识符，而不是变量的值。符号也可以引用运算符和（已解析的）计算机指令的任何其他部分。例如，`:myVar`、`:+` 和 `:call` 都是有效的符号。

要创建一个符号，请使用冒号 `:` 前缀运算符或 `symbol()` 函数。例如：

```julia
a = :foo10
```

等价于：

```julia
a = Symbol("foo10")
```

`symbol()` 函数可以有选择地连接其参数来组成符号，如下所示：

```julia
a = Symbol("foo",10)
```

要将符号转换回字符串，请使用 `string(mysymbol)`。

### 6.2 表达式

表达式是未经求值的计算机指令。在 `Julia` 中，它们同样也是对象。具体来说，它们是 `expr` 类型的实例，其字段包括 `head`（用于定义表达式的类型）和 `args`（用于定义元素数组）。这些元素可以是符号、原始（不可修改）值（如字符串和数字），或者其他子表达式（树形数据结构由此形成）。

作为对象，表达式在 `Julia` 中是“一等公民”。它们支持通常可用于其他实体的所有操作，例如作为参数传递、从函数返回、被修改或赋值给变量。

表达式通常通过解析计算机代码来创建，其最终命运是被求值。

例如，字符串 `"b = a+1"` 在解析后会变成一个表达式。在 `AST`中，它看起来像这样：

```julia
julia> expr = Meta.parse("b = a+1 # 这是一个注释")
julia> typeof(expr)
Expr
julia> dump(expr)
Expr
  head: Symbol =
  args: Array{Any}((2,))
    1: Symbol b
    2: Expr
      head: Symbol call
      args: Array{Any}((3,))
        1: Symbol +
        2: Symbol a
        3: Int64 1
```

在脚本的第一行，你开始通过解析字符串 `"b=a+1 # 这是一个注释"` 来创建一个表达式对象，并将其保存在 `expr` 变量中。然后你使用 `dump` 来检查其内部结构。

请注意，注释已被剥离，并且这个简单的表达式被解释为一个分支。主节点是等号，两个参数分别是变量 `b` 和一个更低层级的表达式，该表达式本身是对 `+` 运算符的调用，其参数为 `a` 和 `1`。

这表明在内部，`b = a+1` 被视为 `b = +(a,1)`，即加法运算符的行为就像一个接受参数的普通函数。

#### 6.2.1 创建表达式

有多种创建表达式的方法，下面将逐一介绍。

**解析字符串**

创建表达式的第一种方法就是你刚刚看到的——使用 `Meta.parse()` 解析一个字符串。这就是 `Julia` 在解析 `.jl` 脚本或 `REPL` 输入时所采用的方法。

**冒号前缀运算符**

可以使用你之前看到的应用于单个符号的同一个冒号 `:` 前缀运算符来创建表达式，这次它应用于整个表达式（用括号括起来）：

```julia
expr = :(a+1)
```

**引用块**

`:([...])` 运算符的一个替代方案是 `quote [...] end` 块：

```julia
expr = quote
    b = a+1
end
```

**使用树形结构配合 `Expr` 构造器**

也可以直接从给定的树结构直接构建表达式。因此：

```julia
expr2 = Expr(:(=), :b, Expr(:call, :+, :a, 1))
```

等价于：

```julia
expr = Meta.parse("b = a+1")
```

或：

```julia
expr = :(b = a+1)
```

#### 6.2.2 对符号和表达式求值

要对表达式或符号求值，请使用 `eval()` 函数：

```julia
expr = Meta.parse("3+2")
eval(expr) # 5
```

即使 `eval()` 调用发生在函数内部，求值也是在全局作用域中进行的。也就是说，被求值的表达式可以访问全局变量，但无法访问局部变量。

这段代码很简单，因为它只包含字面量，即编译时已知的不可变值。但如果表达式中包含变量会发生什么？计算会考虑表达式组合时绑定到变量的值，还是求值时的值？

事实证明，你可以在组合表达式时做出选择，如以下代码片段所示：

```julia
a = 1
expr1 = Meta.parse("$a + b + 3")
expr2 = :($a + b + 3) # 等价于 expr1
expr3 = quote $a + b + 3 end # 等价于 expr1
expr4 = Expr(:call, :+, a, :b, 3) # 等价于 expr1

eval(expr1) # UndefVarError: b not defined
b = 10
eval(expr1) # 14
a = 100
eval(expr1) # 仍然是 14
b = 100
eval(expr1) # 104
```

在第一行，你定义了变量 `a` 并为其赋予了一个初始值。在表达式 1 到 3 中，你使用了美元 `$` 运算符来插值（“取消引用”）变量 `a`。这表明你想将它的值存储到表达式中，而不是变量本身。这就是为什么 `a` 必须事先存在的原因。

相反，对于 `b`，你指明存储在表达式中的是标识符 `b`，而不是其值。此时甚至不需要定义这个变量。

请注意，当你使用 `Expr` 构造器方法定义 `expr4` 时，你直接处理的是取消引用的实体。当你指明 `a` 时，你指的是*绑定到它的值*；而要指明一个标识符，你需要使用一个符号（如 `:b`）。

当你尝试对表达式求值时，此时 `Julia` 会尝试查找 `b` 符号，如果找不到，就会抛出错误。你必须在表达式能够被求值之前定义 `b` 并为其赋值。

最后，请注意，无论变量 `a` 发生什么变化，都不会影响表达式的求值结果，但修改 `b` 的值会影响它。

**与 C/C++ 指针的粗略比较**

在 `C/C++` 中，`&` 运算符应用于变量时，返回其内存地址。相反，`*` 运算符应用于内存地址时，返回存储在该地址的变量的值。

在 `Julia` 中，你可以将变量名本身视为地址。这意味着 `:var`（如同 `&var`）返回变量名，而 `$var`（如同 `*var`）返回绑定到该变量的值。

### 6.3 宏

将代码表示为表达式的可能性是宏强大能力的核心。在 `Julia` 中，宏接受一个或多个输入表达式（以及可选的字面量和符号），并在解析时返回一个修改后的表达式。

这与普通函数形成对比，普通函数在运行时接受输入值（参数）并返回计算出的值。宏将计算从运行时移到编译时，因为表达式是直接生成并编译的，而不是像函数那样需要在运行时调用 `eval`。

#### 6.3.1 宏定义

# 定义宏

定义宏与定义普通函数类似。区别在于，需要使用 `macro` 关键字代替 `function` 关键字，并构建宏应返回的表达式。例如，使用引号块（quote block）时，作为参数的变量需通过美元符号（`$`）进行解引用。这很合理，因为宏的参数是表达式，对绑定到参数的变量使用美元符号，意味着将其内容（一个表达式）注入到引号块中定义的整个表达式的更广泛上下文中。

让我们看一个示例：

```julia
macro customLoop(controlExpr,workExpr)
    return quote
        for i in $controlExpr
            $workExpr
        end
    end
end
```

这里，你使用一个宏来定义通用循环，该循环包含应用于 `for` 循环的控制表达式以及在循环内部求值的一个或多个表达式。

# 宏调用

宏定义完成后，可以使用其名称调用它，名称前需要加上 `@` 符号。宏后跟上它接受的表达式，这些表达式在同一行中，用空格分隔（可使用 `begin` 块语法将多个表达式组合在一起）。

例如：

```julia
a = 5
@customLoop 1:4 println(i)
@customLoop 1:a println(i)
@customLoop 1:a if i > 3 println(i) end
@customLoop ["apple", "orange", "banana"] println(i)
@customLoop ["apple", "orange", "banana"] begin print("i: "); println(i) end
```

你可以使用另一个名为 `@macroexpand` 的宏来查看“展开”后的宏看起来是什么样：

```julia
julia> @macroexpand @customLoop 1:4 println(i)
quote
    #= /path/to/source/file/metaprogramming.jl:65 =#
    for #92#i = 1:4
        #= /path/to/source/file/metaprogramming.jl:66 =#
        (Main.println)(#92#i)
    end
end
```

请注意，宏不会创建新的作用域，在宏内部声明或赋值的变量可能会与实际调用宏的位置所在作用域中的变量发生冲突。

# 字符串宏

最后，一种便捷的宏类型（其冗长但技术上准确的名称是“非标准字符串字面量”）允许开发者对以 `xxx"...text..."` 形式输入的文本执行编译时的自定义操作。这是一个自定义前缀，直接附加到待处理的文本上，并以字符串形式输入（也可以使用三重引号，例如 `xxx"""...多行文本..."""`）。

例如，以下宏定义了将输入文本按自定义的八列格式显示：

```julia
macro print8_str(mystr)
    limits = collect(1:8:length(mystr))
    for (i,j) in enumerate(limits)
        st = j
        en = i==length(limits) ? length(mystr) : j+7
        println(mystr[st:en])
    end
end
```

这些名称以 `_str` 结尾的特殊宏，随后可以使用非标准字符串字面量进行调用，其中前缀与宏名称去掉 `_str` 部分后匹配：

```julia
julia> print8"123456789012345678"
```

你将在下一章“Julia 与其他语言交互”中看到这些宏的应用，其中字符串宏将用于处理代表外语言（C++、Python 或 R）代码的文本。

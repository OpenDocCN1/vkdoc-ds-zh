# 1. Swift 入门

> *Swift 是一种通用编程语言，采用现代方法构建，注重安全性、性能和软件设计模式。*

苹果公司在 2014 年全球开发者大会上推出了 Swift 编程语言，旨在取代 C、C++ 和 Objective-C 等其他基于 C 的语言。自那时起，Swift 通过力求在性能、安全性和易用性之间取得完美平衡，发展了一个充满激情的开发者社区。

## Swift 概览

在深入探讨统计分析之前，我们需要问自己几个问题：Swift 是否是合适的技术选择。其他语言也支持此类计算，其中许多语言还拥有优秀的第三方库，进一步扩展了标准库的功能。为了说服自己 Swift 是完成这些任务的理想工具，让我们来看看该语言及其生态系统的一些优势特性。

### 性能

现代计算中的一个瓶颈是，它通常涉及处理大量数据。例如，微软的恶意软件分类数据集大小接近半 TB，而谷歌的地标识别数据则由超过 120 万个数据点组成。处理如此庞大的数据量需要强大的硬件支持，同时也要求我们所使用的编程语言足够高效。

自 2014 年以来，性能一直是 Swift 营销中的一个重要关键词。与 C 和 C++ 竞争的愿景为速度和效率设定了高标准，许多基准测试表明，Swift 在追赶方面表现得相当不错。与如今已成为数据科学家黄金标准的 Python 相比，基准测试表明，相应的 Swift 程序可能会实现显著的加速。既然我们知道有大量数据需要处理，那么高性能的语言总是受欢迎的。然而，大量复杂数据对我们的工具如何安全、正确地操作这些数据提出了新的要求。

### 安全性

安全性是 Swift 发展过程中的指路明灯。在此背景下，安全性意味着该语言主动尝试保护开发者，避免其编写导致未定义行为的代码。这些安全特性包括一些简单的措施，比如鼓励使用不可变变量。然而，它们也包含更加复杂的方案和要求。

Swift 采取的最突出的安全措施之一是使用 `Optional` 类型。如果我们需要表示某个值的缺失，我们必须使用空的 `Optional`，而不是裸空值。有些人认为这是一种不必要的僵化设计，会导致更多的样板代码。然而，这迫使开发者明确标记数据可能缺失的实例，并安全地处理这些情况。

另一个重要的安全特性是要求对修改操作进行独占内存访问。设想一个场景：两个不同的方法调用同时访问同一个内存位置。只要两个方法都只是读取内容然后继续，我们就可以认为这是安全的操作。然而，一旦其中一个（或两个）方法想要修改存储的值，问题就会变得棘手。内存位置中的最终内容将取决于哪个方法最后执行写操作。Swift 通过要求修改操作独占访问权限，即只允许单个调用在任意时刻注册修改某个内存位置，从而帮助指出不安全的代码。

### 正确性

一旦我们开始处理大量复杂数据，确保产生正确的结果就变得更具挑战性。我们可以通过融入大量可靠的软件工程实践来解决其中的许多问题。然而，我们也应该充分利用开发工具提供的任何帮助。

Swift 从函数式编程的世界中汲取了大量灵感。开发者被积极鼓励考虑`值类型`，并且仅当引用语义至关重要时才使用`引用类型`。在可能的情况下，我们应该优先使用`值类型`，这有很多原因，但我们只关注那些在处理大数据集时对我们直接有益的原因。

使用`值类型`的第一个真正优势在于，它们在内存分配方面通常性能更高。Swift 通常将`引用类型`分配在堆上，而`值类型`通常位于栈上。当然，总有例外，但这可以作为一个很好的经验法则。在栈上分配对象的过程只需系统递增一个指针，这是一个非常快速的操作。然而，在堆上分配对象时，系统需要在该内存区域中搜索一个足够大的空位。这个过程要慢得多，并且如果我们需要分配大量对象时，这种差异会非常明显。

第二个优势是，`值类型`在不同变量之间共享时会进行自我复制。这一特性意味着我们可以确信，没有其他变量能够在我们背后更改我们当前正在处理的数据。这种局部性使得我们更容易推断结果，并对单独的代码部分进行完整性检查。一旦我们需要并行化工作，它也能简化事情。

## 硬件加速

在处理大量数据时，使用硬件加速可以带来巨大的好处。并行处理信息的能力能够加快程序执行速度，最终减少空闲时间。Swift 提供了多个框架，让开发者能够利用多核 CPU 和 GPU。

我们在本书中解决的问题大多将依赖 `Accelerate` 框架，主要使用其线性代数功能。阅读本书后，若想更深入探究并行计算，`Metal` 框架可提供对图形处理器的访问，并能实现计算并行化与加速。前述两种框架均默认预装在每台苹果电脑上。然而，我们有时也会发现系统库不足以胜任相关工作。

## Swift 包管理器

在进行任何数据科学任务时，便捷地获取优质外部库是一个重要方面。得益于 Swift 包管理器的发展，收集和管理此类项目依赖项的任务已变得简单得多。例如，该工具允许开发者将第三方库纳入项目并直接开始使用。

其他工具也曾提供过类似功能，例如 CocoaPods 和 Carthage。但它们从未像如今的 Swift 包管理器一样与 Xcode 环境紧密结合。我们将借助这一点，导入能够帮助我们操作和可视化数据的库。

## 结论

回顾上述特性，我们可以得出结论：在处理统计分析数据时，Swift 及其生态系统拥有许多理想特质。有理由相信，一旦开始使用这门语言，它将会为我们提供良好支持。同样现实的是，使用 Swift 可能会带来其他工具难以甚至无法实现的优势。带着这些结论，是时候深入了解本书将用到的一些语言细节了。

#### Decodable 协议

Swift 标准库提供了相当多与编码、解码和数据处理相关的优秀特性。在本书中，我们将大量使用其中的许多特性，但其中一个对于启动工作尤为重要——那就是 `Decodable` 协议。

`Decodable` 协议本身（如代码清单 1-1 所示）既简单又强大。它只要求遵循该协议的类型实现一个能够从 `Decoder` 实例化对象的初始化器。

```swift
protocol Decodable {
    init(from decoder: Decoder) throws
}
```
**代码清单 1-1 来自 Swift 标准库的 Decodable 协议**

如我们所见，这个初始化器接受一个 `Decoder` 类型的对象作为参数。`Decoder` 是另一个由能够从原生数据格式读取值的类型所实现的协议。例如，一个 `Decoder` 类型可以读取一个 CSV 文件，解析其中的行和数据值，然后将这些值提供给 `Decodable` 的初始化器来创建新的 Swift 对象。为了直观理解这在实际中是如何工作的，我们将逐步演练如何解码一个小的 CSV 文件。代码清单 1-2 展示了一个包含两位人士（Anna 和 Keith）信息的 CSV 文件示例，而代码清单 1-3 则展示了一个名为 `Person` 的 Swift 类型，我们打算用它来存储解码后的值。

# Swift 数据解码与 KeyPath 类型

```swift
struct Person: Decodable {
    let name: String
    let age: Int
    enum CodingKeys: String, CodingKey {
        case name = "name"
        case age = "age"
    }
    init(from decoder: Decoder) throws {
        let container = try decoder
            .container(keyedBy: CodingKeys.self)
        self.name = try container
            .decode(String.self, forKey: .name)
        self.age = try container
            .decode(Int.self, forKey: .age)
    }
}
```


查看 `Person` 类型，我们看到它声明遵循 `Decodable` 协议。为了满足协议要求，我们定义了初始化器，并请求 `Decoder` 解包我们想要使用的值。我们还定义了一个名为 `CodingKeys` 的枚举，它提供了我们请求的值与 CSV 中对应键之间的映射。通过这种方式，我们告诉 `Decoder` 在请求不同值时应该使用哪些键。

> **注意**
>
> 在许多情况下，我们无需手动实现代码清单 1-3 中的初始化器和 `CodingKeys` 枚举。只要我们的结构体只包含其他遵循 `Decodable` 的类型，并且属性名与数据文件中的键名相同，Swift 就能自动为我们合成这些代码。

#### `KeyPath` 类型

Swift 标准库中最强大的特性之一就是 `KeyPath` 类型。它让开发者能够在运行时动态访问对象属性，同时又不牺牲类型安全。在本节中，我们将通过几个代码示例，探索 `KeyPath` 类型的概念及其在编写灵活且可维护代码中的应用。

首先，我们来看如何使用 `KeyPath` 访问对象属性。下一页的代码清单 1-5 展示了用 `KeyPath` 打印每个 `Person` 对象姓名的示例。同时，该示例还介绍了 `DataLoader` 的使用，它是 `StatisticalSwift` 模块的一部分。为了从数据集中获取所有人的数组，我们调用了 `load(_:from:)` 方法，并指定期望返回的类型。

```swift
let people = DataLoader.load(
    Person.self,
    from: .people
)
let nameKey = \Person.name
for person in people {
    let name = person[keyPath: nameKey]
    print("Name: \(name)")
}
// 输出:
// Name: Anna
// Name: Keith
```
代码清单 1-5
使用 `KeyPath` 从人员 CSV 文件中打印姓名

我们使用 `\` 操作符，后跟要引用的属性，来创建一个 `KeyPath` 实例。新实例的类型是 `KeyPath<Person, String>`，这明确表示我们引用的是 `Person` 对象中存储的一个 `String` 属性。这个特定示例相较于熟悉的点语法并没有增加多少价值，它的目的是介绍这种类型及其最基本的用法。要探索一个更实际（且更贴近真实场景）的用例，请看下一页的代码清单 1-6。

```swift
let names = people
    .map(\.name)
    .joined(separator: " and ")
let ages = people
    .map(\.age)
    .map(String.init)
    .joined(separator: " and ")
let totalAge = people
    .sum(over: \.age)
print(
    """
    We have \(names) with us today!
    They are aged \(ages), respectively,
    totaling \(totalAge) years together!
    """
)
// 输出:
// We have Anna and Keith with us today!
// They are aged 34 and 36, respectively,
// totaling 70 years together!
```
代码清单 1-6

在这个例子中，`KeyPath` 类型将不同的属性转换为新的数据类型。在创建 `names` 和 `ages` 变量时，`KeyPath` 将相应的属性值映射到数组中，然后这些数组可以进一步处理并格式化为 `String` 对象。请注意，这个示例使用了隐式成员语法来引用属性。只要编译器能推断出我们正在处理 `Person` 类型，就可以使用 `\.name` 这个简写形式，而不是 `\Person.name` 来引用 `name` 属性。

`totalAge` 变量提供了一个稍微复杂且更有趣的用例。方法 `sum(over:)` 来自 `StatKit` 模块，它不要求 `KeyPath` 引用特定类型的属性，而是要求被引用的类型遵循 `AdditiveArithmetic` 协议。这意味着我们可以自由指向任何属性，只要该属性存储的类型支持 `+` 操作符即可。

最后，我们快速了解一下 `PartialKeyPath`。这种类型将动态行为发挥到了极致，因为它对被引用的属性没有任何类型要求。这一特性使得编写高度灵活的代码成为可能，前提是我们能够对类型擦除的对象执行预期的操作。代码清单 1-7 展示了这一示例。

```swift
let partialkeys: [PartialKeyPath] = [
    \Person.name,
    \Person.age
]
for _ in 1 ... 5 {
    guard
        let randomKey = partialkeys.randomElement(),
        let person = people.randomElement()
    else { continue }
    let value = person[keyPath: randomKey]
    print(value)
}
// 输出 5 个随机属性值，
// 例如 Anna、Keith 或 36
```

#### 高阶函数

在构建数据转换管道时，使用高阶函数通常十分有用。高阶函数是指至少满足以下条件之一的函数：

- 它接受一个或多个其他函数作为输入。

- 它返回另一个函数作为输出。

如前所述，我们在一些示例中已经使用过高阶函数。在代码清单 1-4 中，我们将一个尾随闭包（即一个函数）传入了 `CSVDecoder` 的初始化器来配置解析策略。在代码清单 1-6 中，我们使用了 `map(_:)` 方法，通过 `KeyPath` 对部分数据进行了转换。

# 高阶函数在Swift中的应用

高阶函数在 Swift 标准库和第三方库中很常见。我们中的许多人可能已经使用过它们，甚至自己都未曾意识到。除了 `map(_:)`，Swift 标准库还提供了 `filter(_:)`、`reduce(_:_:)` 和 `sorted(by:)` 等方法，仅举几例。为了深入理解这些方法的运作方式，我们将实现一个新的高阶函数，作为 `MutableCollection` 协议的扩展。这样做可以让我们看到其底层实现，并理解高阶函数在操作数据时能有多么强大。

我们的高阶函数名为 `apply(to:_:)`。其概念相对简单——对于数据集中的每一个数据点，它计算一次转换并将结果写回该数据点。你可以使用这类方法在数据送入统计计算管道之前，对其进行即时整理或优化。例如，此类操作可能包括对数值数据进行重新缩放、量化或归一化。代码清单 1-8 展示了该函数的实现及其使用示例。

## 代码实现与解析

```swift
extension MutableCollection {
    mutating func apply(
        to key: WritableKeyPath,
        _ transform: (T) -> T
    ) {
        for index in self.indices {
            let newValue = transform(
                self[index][keyPath: key]
            )
            self[index][keyPath: key] = newValue
        }
    }
}

var points = [
    CGPoint(x: 1, y: 1),
    CGPoint(x: 2, y: 2),
    CGPoint(x: 3, y: 3)
]

print("Before: \(points)")
points.apply(to: \.y) { value in
    value * value
}
print("After:  \(points)")
// 输出:
// Before: [(1.0, 1.0), (2.0, 2.0), (3.0, 3.0)]
// After:  [(1.0, 1.0), (2.0, 4.0), (3.0, 9.0)]
```

代码清单 1-8 中的代码相当复杂。让我们简单过一遍其中的一些关键部分，以了解发生了什么：

- 我们对 `MutableCollection` 协议进行扩展。这使得该实现可用于所有支持可变操作的集合类型。这种功能的传播得益于 Swift 面向协议的特性，但我们在本书中不再进一步探讨该机制。

- 方法 `apply(to:_:)` 接受两个参数。第一个参数是 `KeyPath` 类型，它可以引用数据元素的任何泛型属性。这种特定类型的 `KeyPath` 也支持写操作，而不仅仅是读操作。

- 第二个参数是另一个函数。它使用泛型类型 `T` 同时作为输入和输出，这与 `KeyPath` 引用的 `T` 相同。该函数应将数据属性的当前值转换为某种更易于使用或更适合其他计算的新值。

- 在方法体中，`apply(to:_:)` 遍历集合中的所有数据点。它应用转换函数，并将新值写回到数据集中。当函数返回时，数据集不再包含旧值，而是包含了指定的转换结果。值得注意的是，`apply(to:_:)` 对如何转换值一无所知。该函数由开发者在调用点指定，这使得该方法非常灵活。

当然，这个函数内部还有更多微妙之处，我们或许可以用一整章来讨论它们。不过，这几个要点应该足以让你理解我们想传达的主要思想。高阶函数是强大的工具，能提供高度可定制的方式来操作数据，我们将在解决本书中的问题时频繁使用它们。

# 8. 最佳实践与常见问题解答

在每个编程和技术平台中，产品所有者都有一套推荐的方法。同样，SAP MII 也有需要遵循的注意事项。SAP MII 是一个平台，因此 SAP 提供了一些建议。应遵循此处解释的最佳实践，以获得最佳性能并确保解决方案的有效性。

## 最佳实践

建议您遵循以下章节中解释的最佳方法。

### 项目处理

从 SAP MII 中项目创建的角度来看，始终建议最好使用`NWDI（NetWeaver 开发基础架构）`来实现适当的版本控制机制，为整个开发组件使用中央存储库功能，并实现零代码覆盖风险。如果使用`NWDI`，则会创建一个共享项目，并且必须在该项目中进行代码的签入和签出。如果您创建一个本地项目并将其存储在本地服务器上，那么任何有权访问该服务器的人都可以访问该代码。由于多个开发人员可以编辑和保存代码，因此代码被覆盖的可能性很大。代码更改的最新实例将被保存。

### 项目文件夹结构

创建项目时，建议您使用特定的、易于理解的结构。例如，在“项目”下的“目录”选项卡中，应有单独的文件夹来定义项目的不同功能，例如报告名称。在每个功能下，应为不同的对象类型（如查询模板和 BLS）设置单独的文件夹。在“对象”和“Web”选项卡中需要遵循完全相同的结构，但将查询模板和 BLS 替换为`MDO`、`KPI`对象等，以及 Web 文件 HTML (`.irpt`)、JavaScript 等。

### 命名约定

作为最佳实践的一部分，还应遵循某些命名约定。以下是一些示例：

*   调度器：`<项目名称>_<功能>_<工厂（如果有）>`
*   数据服务器：`DS_<项目名称>_<服务器名称>`
*   凭据存储：`<项目名称>_<连接名称>`
*   BLS：`BLS_<功能>`
*   查询：`SQL_<功能>`、`[MDOQry/KPIQry/AlertQry]_<功能>`、`PCO_<功能>`、`XCT_<BLS 名称>` 等。
*   显示模板：`LineChrt_<功能>`、`iGrd_<功能>` 等。
*   对象：`MDOObj_<表名称>`、`KPIObj_<KPI 名称>`

请注意，如果客户根据公司政策有一些预定义的命名约定，则应优先考虑这些约定。

### 开发

在开发期间，请遵循以下建议来编写干净的代码并获得更好、更有效的性能：

*   只有`BLS`中使用的输入和输出属性才应声明为事务变量。`BLS`中临时使用的所有其他变量应声明为局部变量。
*   始终使用`异常启用器`和`捕捉`操作块来捕获逻辑中的任何异常。
*   避免在一个重复器下使用另一个重复器。尽可能避免逻辑中的循环。相反，使用 XSLT 以获得良好的性能。
*   使用`XPath`和`XQueries`避免循环。
*   开发最终确定后（即迁移前），移除所有跟踪器和日志记录器；否则，性能将非常差，有时由于日志记录过多可能导致内存崩溃问题。
*   尽可能避免写入文件和加载器操作块，因为它们在执行时会消耗大量内存。
*   避免使用终止操作块。
*   调试完成后，必须移除断点和监视点；否则，`BLS`的执行将停在这些断点处。
*   如果任何`BLS`以调试模式执行，请使用“调试关闭”按钮将其关闭。不要直接点击交叉（X）按钮关闭。即使`BLS`已关闭，每当`BLS`执行时，缓存内存也会继续缓存调试日志，并可能导致 Java 堆空间错误。
*   避免再次将大的输入存储在局部变量中，即使它已从源端传入，因为一旦值进入`BLS`，它将一直存在直到`BLS`执行结束。
*   如果可以通过 MII 输出 XML 操作块实现相同的效果，请避免创建本地 XML 结构作为局部变量并在其中附加值。
*   如果适合逻辑，请尝试尽可能多地使用异步事务调用。同步事务调用会保持主`BLS`的执行，直到被调用的`BLS`执行完成，从而对性能产生不利影响。
*   为所有操作块使用有意义的命名约定，并采用驼峰式命名。如果可能，请提供操作块描述。
*   避免从调度器调用`BLS`，如果该`BLS`中存在同步事务调用。这会保持调度器实例的执行，并使调度器长时间处于运行状态。在这种情况下，尝试使用包装器`BLS`，它将异步调用主`BLS`，并将包装器`BLS`放入调度器中。调度器实例将不会排队等待下一次执行，因为它是异步工作的。
*   不要在操作块中硬编码用户名和密码。尝试使用凭据别名并在操作块中引用它们。类似地，这也适用于连接别名。
*   避免在操作块配置中硬编码，并尽可能地动态使用它。
*   如果不需要，不要在 SQL 查询中使用 `select *`。尝试在查询时定义特定列。
*   不要在 UI 中使用硬编码的超时。尝试使用逻辑处理超时。
*   不要在 UI 中使用的 URL 中硬编码用户名和密码。
*   不要在`BLS`和 UI 中重复任何逻辑部分。在 UI 中，尝试在多个位置调用该功能。
*   建议在使用`JCO`、`JRA`进行 ECC 调用以及类似地用于查询模板时使用会话。这有助于提交和回滚调用。
*   建议对 UI 使用 MVC 模型，这有助于保持代码整洁，并易于其他开发人员理解。
*   尝试在 Web 选项卡中为不同的用户区域设置使用单独的属性文件。
*   尝试开发一个实用程序文件，其中包含不同模块的通用功能代码，以便在其他对象开发设置中重用。
*   在注释部分说明 UI 前端编码中使用的代码和功能。这将有助于其他开发人员以后理解代码。

## 常见问题解答

以下是一些 SAP MII 专业人士和从业者常问的问题：

1. 什么是 SAP MII ？`SAP MII` 是一个由 Lighthammer 使用 `Java` 开发、后被 `SAP` 收购的平台。`SAP MII` 可以作为具有实时集成和高端智能能力的中间件运行。`SAP MII` 非常先进，利用 `IOT` 可以实现众多创新。
2. 如何安装 `SAP MII`？ `SAP MII` 可以安装在 `NetWeaver` 或 `SAP HANA` Web 应用服务器之上。
3. `SAP MII` 有哪些可用版本？ `SAP MII` 由 `SAP` 以 `SAP xMII 11.5` 版本推出。其后，依次发布了 `SAP MII 12.0`、`SAP MII 12.1`、`SAP MII 12.2`、`SAP MII 14.0` 和 `SAP MII 15.0`。最新版本是 `SAP MII 15.1`。
4. `SAP MII` 是否支持 `SAP HANA`？ 是的，从 `SAP MII 15.1` 版本开始，可以使用 `OData` 服务将 `MII` 数据暴露到 `HANA` 中。
5. `SAP MII` 的基础组件是什么？ `SAP MII` 是使用 `Java Swing` 开发的，并且 `SAP MII` 支持使用 `XML` 进行所有内部处理和操作。
6. 使用 `SAP MII` 可以实现哪些类型的集成？ `SAP MII` 可以连接 `SAP ERP`、任何类型的数据库、支持任何类型 `REST` 服务（如 `HTTP Post`、`Web service`、`JMS` 等）的系统，以及任何支持 `UDC connector` 的车间层系统。
7. `SAP MII` 具备哪些智能功能？ `SAP MII` 可以使用各种图表展示丰富且高端的报表，并且也可以使用 `SAP MII` 开发用户交互界面。
8. 使用 `SAP MII` 可以开发哪些类型的应用？ 基于 `SAP MII` 的应用始终是基于 Web 的应用，因为 `SAP MII` 运行在 `Web Application Server` 上。
9. `SAP MII` 提供实时数据吗？ 是的，`SAP MII` 完全能够提供接近实时的数据。然而，由于基于 `SAP MII` 开发的应用是基于 Web 的，因此很难期望在基于 `SAP MII` 的应用中获得精确的实时数据，因为数据流依赖于网络速度。
10. 基于 `SAP MII` 的应用的灵活性如何？ 从集成角度来看，`SAP MII` 可以双向连接并从大多数系统获取数据。从 UI 角度来看，`SAP MII` 现在使用 `SAP UI5` 进行用户界面开发。`SAP UI5` 与浏览器无关，这有助于应用程序在任何类型的窗口或任何移动浏览器上运行，无论操作系统是什么。
11. `SAP MII` 支持哪些操作系统服务器？ `SAP MII` 可以在 `Windows`、`Linux` 和 `SAP PCo` 上运行，`SAP PCo` 是 `SAP MII` 中可自由分发的组件之一。它也是与车间层集成的重要工具，但仅支持 `Windows Server`，因为 `SAP PCo` 是使用 `Microsoft .NET` 技术开发的。
12. `MDO` 与数据库有何不同？ `MDO` 代表 `Manufacturing Data Object`。它是 `SAP MII` 应用的内部数据库或缓存。数据可以存储在 `MDO` 中并在本地查询以更快地获取数据，而不是直接查询数据库。`MDO` 有两种类型——`persistent`（持久化）和 `on-demand`（按需）。它们在数据存储方式上有所不同。

### `SAP MII` 是如何与 `HANA` 集成的？
可以使用 `SAP MII Smart Data Adapter (SDI)` 从 `SAP HANA` 中获取来自工厂或制造系统的数据。通过使用该适配器，来自 `PCo` 的数据、`SAP MII` 中的查询将在 `SAP HANA` 的虚拟表中可用，并且这些表可用于 `SAP HANA` 中的各种分析和计算视图。

### 什么是共享内存？
它是一种持久性内存，可用于存储有限的值，并可在开发逻辑时作为持久性变量在事务中使用。用户可以通过 `SAP MII` 菜单页面访问共享内存。更改共享内存中的值无需修改代码。

### 什么是自定义动作块？
自定义动作块是在 `Java` 平台上开发的定制代码，用于处理 `SAP MII` 中未作为标准功能提供的特定功能。使用用于自定义动作块的标准 `SDK`，可以创建包含具有特殊处理功能的 `Java` 代码的 `.JAR` 文件，然后将其上传并在 `SAP MII` 工作台中以动作块的形式使用。

### 是否可以访问 `Excel` 文件？
是的，可以通过两种方式实现。如果 `Excel` 文件名是固定的，即使其内容定期刷新，也可以通过 `PCo`、文件系统连接器和 `SAP MII` 中的 `OLEDB` 连接器来集成该文件。另一种方法是通过 `Java` 开发一个自定义动作块进行集成。

### `SAP MII` 事务是否可以远程调用？
是的，可以使用 `runner` 服务调用 `SAP MII Transaction`。Runner 服务是一种 `illuminator` 服务，可以使用以下 URL 格式从外部调用 `MII` 事务：
```
http://<server>:<port>/XMII/Runner/Transaction=<folder>/<TransactionName>&<InputParamName1>=<value1>&<InputParamNameN>=<valueN>&OutputParameter=<OutputParamName>&Content-Type=<content-type>&isBinary=<true|false>&XacuteLoginName= <username>&XacuteLoginPassword=<password>
```

### 是否可以将 `SAP MII Transaction` 暴露为 `REST` 服务？
是的，在 `SAP MII` 中可以将任何 `SAP Transaction` 暴露为 `SOAP web service`。`MII` 事务可以使用以下 URL 转换为 `WSDL`：
```
http://<server>:<port>/XMII/WSDLGen/<projectName>/<folderName>/<transactionname>
```
要将 `SAP MII` 事务作为 `Web Service` 运行，请使用以下 URL：
```
http://<server>:<port>/XMII/SOAPRunner/<projectName>/<folderName><transactionname>
```

### `SAP MII` 支持同步和异步调用吗？
是的，它同时支持同步和异步调用。在一个 `SAP MII Transaction` 内部，可以根据需求调用其他事务。事务可以以异步和同步两种方式调用。在同步调用中，父事务调用子事务并等待子事务执行完成。根据执行结果，父事务完成逻辑并关闭会话。在异步调用中，父事务触发子事务，然后父事务完成其全部逻辑并关闭会话。它不等待被触发的子事务完成，因此子事务始终独立执行。

### 共享属性的默认内存和活动内存有什么区别？
`SAP MII` 中的共享属性同时具有默认内存和活动内存。默认内存拥有默认值，而活动内存拥有活动值。活动值可以从工作台的 `Tools` 选项卡或 `SAP MII` 管理页面的 `Data Servers` 部分进行检查。在事务执行时，值总是从活动内存中获取。最初为任何变量创建默认内存时，相同的值会在第一次立即自动复制到活动内存中。

### 迭代器和重复器有什么区别？
`SAP MII Transaction` 为我们提供了多种用于逻辑赋值的作用块。用于循环的主要有两个作用块——迭代器和重复器。迭代器用于遍历列表，因为其输入源是一个列表。重复器用于遍历 `XML` 节点。

### 什么是计划事务？
计划事务是指能够按照定义的调度计划执行为所需逻辑设计的 `MII Transaction` 的事务。它们可以根据需要随时启用或禁用。

### 是否存在可以直接维护工厂层次结构的平台？
是的，从 `SAP MII` 15+ 版本开始，`SAP MII` 提供了 `PIC (Plant Information Catalog)`。使用该功能，可以在 `SAP MII` 中定义工厂层次结构以及相关的标签和详细信息。

### `PCo` 如何在 `SAP MII` 中使用？
`SAP Plant Connectivity (PCo)` 是一个软件组件，用于实现车间层和 `SAP MII` 之间的数据交换。在 `PCo` 中，可以定义车间层标签，以直接从机器获取实时时间序列数据；它也可以维护历史数据。从 `PCo` 交换数据有两种方式：一种是推送方法，即创建包含标签组的代理，并定义特定条件，当条件满足时触发通知到 `SAP MII` 中指定的 `BLS`。第二种是拉取机制，即通过从 `SAP MII` 使用 `PCo` 连接器执行 `PCo` 查询来直接从标签获取数据。

### `SAP MII` 是否有支持其他 `SAP` 制造产品？
是的，它支持 `SAP` 制造产品——`SAP ME` 和 `SAP OEE`，通过它们的集成组件 `MEINT` 和 `OEEINT`。由于这两个产品都是在 `SAP MII` 之上开发的，因此也可以借助标准解决方案通过 `SAP MII` 进行自定义逻辑挂接（活动钩子）和自定义仪表盘（`ME` 的 `POD` 和 `OEE` 的操作员仪表盘）的开发。因此，总结来说，`SAP MII` 与这两个制造产品紧密耦合。

### 什么是启动（Bootstrapping）？
要启动 UI 中的任何应用程序，必须首先加载并初始化它。这个加载和初始化的过程被称为启动。

### `SAP UI5` 开发支持哪些数据模型？
`SAP UI5` 支持 `XML` 模型、`JSON` 模型、`OData` 模型和 `JS` 模型视图。

### 基于 Applet 的 UI 编码（`.irpt`）和 `UI5` 编码有什么区别？
在基于 Applet 的 UI 编码中，要加载任何类型的显示模板（如图表、网格等），需要首先加载 `Java JRE`，这在执行期间会消耗大量时间，并可能导致缓存问题。有时 `JRE` 版本也会给 applet 版本带来问题。`UI5` 是一种独立于 `Java` 的编码方式，用于所有 UI 组件（如 `HTML5`），因为它遵循 `MVC` 模型。这意味着 `UI5` 的处理时间比 `.irpt` 文件快得多，并且在 `UI5` 中没有缓存问题。

### `i5` 显示模板和普通显示模板有什么区别？
`SAP MII` 引入了基于 `UI5` 的新显示模板，并命名为 `i5` 模板，而现有的模板是基于 Applet 的模板。

### 什么是 `IRPT` 页面？
`IRPT` 页面，也称为 `SAP MII` 报表，是一种使用 `SAP MII` 的 `.irpt` 文件扩展名（而非标准的 `.html` 文件扩展名）的网页。`IRPT` 页面通过服务器端处理促进网页的动态生成。Web 服务器将 `.irpt` 页面发送给一个名为 `ReportServlet` 的专用 servlet 进行处理。`IRPT` 使用一些特殊功能，例如会话变量和在网页中动态插入内容。这使得它不同于 `HTML`。

### `SAP MII` 中是否有用于跟踪和记录活动的功能？
可以在 `SAP MII` 中通过 `NWA` 日志进行日志记录，需要在 `NetWeaver` 中进行一些配置，然后即可启动此跟踪过程。`Event Logger` 动作块也可以在日志中从 `SAP MII Transaction` 跟踪自定义消息。

### 什么是 `illuminator` 服务？
`Illuminator` 服务是 `SAP MII` 的支柱。使用此 Web 服务，可以调用、修改和更新任何 `SAP MII` 标准组件。除此之外，`SAP MII` 的组件，如查询模板、显示模板和 UI 组件，可以直接调用来访问它们。这是处理存储在内部表中的 `SAP` 标准数据的唯一途径。

### 如何使用 `illuminator` 服务？
`Illuminator` 服务包含两个主要参数——一个是服务（`service`），另一个是模式（`mode`）。有多个可用的服务，包括 `admin`、`systemInfo`、`scheduler`、`BLS` 管理器服务等。每种服务也有多种可用模式。其编写方式如下：
```
http://<server>:<port>/XMII/Illuminator?service=<service name>&mode=<mode name>&content-type=text/xml
```

# 6. 管道：magrittr

数据分析由几个步骤组成，在最终进入模型构建之前，你的数据会经历不同阶段的转换和清洗。实际上，这意味着你的 `R` 代码将包含一系列函数调用，其中一个函数的输出是下一个函数的输入。这种模式很典型，但直接实现它有几个缺点。Tidyverse 多年来一直提供“管道运算符”来缓解这个问题，从 R 4.1 开始，该语言本身也内置了一个运算符。虽然本章主要介绍 `magrittr` 管道运算符 `%>%`，但我也将介绍原生运算符 `|>`，并指出它们在行为上的一些不同之处。

原生运算符 `|>` 在任何大于 4.1.0 的 R 版本中都可以直接使用。如果你加载 `tidyverse` 包，就可以获得 `magrittr` 包中实现的管道运算符：

```r
library(tidyverse)
```

或显式加载包：

```r
library(magrittr)
```

如果你通过 `tidyverse` 包加载 `magrittr`，你将获得最常见的管道运算符 `%>%`，但不会获得其他替代运算符——请参见下一节。要使用那些替代运算符，你需要加载 `magrittr`。

## 管道的问题

考虑来自第 5 章的数据。

```r
write_csv(
  tribble(
    ~country,  ~`2002`, ~`2003`, ~`2004`, ~`2005`,
    "Numenor",  123456,  132654,      NA,  324156,
    "Westeros", 314256,  NA,          NA,  465321,
    "Narnia",   432156,  NA,          NA,      NA,
    "Gondor",   531426,  321465,  235461,  463521,
    "Laputa",    14235,   34125,   45123,   51234,
  ),
  "data/income.csv"
)
```

我已将其写入文件 `data/income.csv`，以使以下示例更易于阅读。

在第 5 章中，我们使用 `pivot_longer()` 和 `drop_na()` 对这个数据进行了重新格式化并清除了缺失值：

```r
mydata <- read_csv("data/income.csv",
  col_types = "cdddd")
mydata <- pivot_longer(
  data = mydata,
  names_to = "year",
  values_to = "mean_income",
  !country
)
mydata <- drop_na(mydata)
```

这是一个典型的管道，尽管很短。它包含三个步骤：(1) 将数据读入 R，(2) 整理数据，(3) 清洗数据。

这种代码本身并没有什么问题。每一步都很容易阅读；它是一个将数据从一种形式转换为另一种形式的函数调用。然而，代码的管道特性并不明确。我们可以阅读代码并看到，一个函数的输出是下一个函数的输入，但如果不是呢？

考虑以下情况：

```r
mydata <- read_csv("data/income.csv",
  col_types = "cdddd")
data <- pivot_longer(...) # 我们赋值给正确的变量名了吗？
mydata <- drop_na(mydata) # 输入来自 read_csv() 而不是 pivot_longer()
```

`pivot_longer()` 的结果被赋值给了变量 `data`，然后 `drop_na()` 在 `mydata` 上被调用。如果我们的意图是前面的管道，这将是一个错误。但也许我们想要 `pivot_longer()` 的结果作为后续分析所需的单独数据表。

一系列构成管道的转换步骤只能通过遵循编程约定来识别，除非代码有良好的文档且易于理解，否则我们无法从代码中立即看出将结果赋值给 `data` 而不是 `mydata` 是否是一个错误。

我们可以使管道更加明确。如果一个函数的输出应该是下一个函数的输入，我们可以嵌套函数调用：

```r
mydata <- drop_na(
  pivot_longer(
    data = read_csv("data/income.csv",
      col_types = "cdddd"),
    names_to = "year",
    values_to = "mean_income",
    !country
  )
)
```

这使得管道的意图变得明确，但代码很难阅读；你必须从最内层的函数调用到最外层的函数调用来理清管道。

`magrittr` 包为我们提供了一种符号，用于明确地描述可读的管道。

## 管道符号

管道操作符 `|>` 和 `%>%` 为函数调用引入了语法糖。^(¹⁴) 代码

```r
x %>% f()
```

或

```r
x |> f()
```

等同于

```r
f(x)
```

以及

```r
x %>% f() %>% g() %>% h()
```

或

```r
x |> f() |> g() |> h()
```

等同于

```r
h(g(f(x)))
```

同样地，以下写法也等价：

```r
x %>% f %>% g %>% h
```

但以下写法不等价：

```r
x |> f |> g |> h
```

原生操作符需要在操作符右侧有一个函数*调用* `f()`，而 `magrittr` 既可以接受函数*调用* `f()`，也可以仅接受函数*名称* `x %>% f`。你也可以为 `%>%` 提供一个匿名函数：

```r
"hello, "%>% (\(y){ paste(y, "world!")})
## [1] "hello, world!"
```

但 `|>` 仍然需要一个函数*调用*，因此如果你给它一个匿名函数，也必须同时调用该函数（在函数定义后添加 `()`）。

```r
"hello," |> (\(y){ paste(y, "world!")})()
## [1] "hello, world!"
```

无论哪种情况，你*必须*将函数定义放在括号中。以下写法将会报错：

```r
x |> \(y) { ... }
```

这是因为两个操作符都是语法糖，会将 `x %>% f()`、`x %>% f` 或 `x |> f()` 转换为 `f(x)`，而函数定义 `function(y) { ... }` 或 `\(y) { ... }` *就是*一个函数调用。管道左侧的内容会被放入函数定义中：

```r
x |> \(y) { ... }
```

对于两个操作符，都会被转换为：

```r
\(x, f) { ... }
```

将函数定义放在括号中可以避免这种情况；虽然 `function(y) { ... }` 是一个函数调用（对名为 `function` 的函数的调用），但 `(function(y) { ... })` 则不是。也就是说，当函数定义放在括号中时，它在语法上就不再是一个函数调用（而是一个括号内的表达式）。如果它不是调用，`|>` 就不会将其接受为右侧内容，但 `%>%` 会。对于 `%>%`，它仍然不是一个调用，只是一个会被求值成调用的表达式，因此函数定义不会被修改，但结果会将左侧内容作为参数传入。

不管怎样，这变得有些技术化了，但如果你在管道中使用匿名函数，这是你需要了解的内容。

使用 `%>%` 操作符时，你不需要为函数调用添加括号，但大多数人都倾向于加上括号以明确我们是在处理函数，并且即使你将代码改为 `|>` 操作符，语法仍然有效。此外，如果你的函数需要多个参数，括号就是必需的，因此如果你始终包含括号，就能保持符号的一致性。

之前提到的嵌套函数调用管道：

```r
mydata <- drop_na(pivot_longer(read_csv(. . . )))
```

因此可以重写为管道形式：

```r
mydata %>% pivot_longer(. . . ) %>% drop_na()
```

或者，包含所有参数后，写成：

```r
mydata %>%
  pivot_longer(names_to = "year", values_to = "mean_income", !country) %>%
  drop_na()
```

管道符号将单一步骤函数调用的可读性与数据处理管道的显式符号结合在了一起。

## 管道与函数参数

管道操作符是左结合的，即它从左到右求值，表达式 `lhs %>% rhs` 期望左侧（`lhs`）是数据，右侧（`rhs`）是一个函数或函数调用（对于 `|>` 则始终是函数调用）。结果将是 `rhs(lhs)`。该函数调用的输出会成为管道中下一个管道操作符的左侧内容，或者整个管道的结果。如果右侧函数需要多个参数，你可以在 `rhs` 表达式中提供这些参数。表达式

```r
lhs %>% rhs(x, y, z)
```

将被求值为函数调用：

```r
rhs(lhs, x, y, z)
```

默认情况下，左侧内容作为右侧函数的第一个参数。你在右侧表达式中显式写入的参数是额外的函数参数。

# 使用`magrittr`操作符`%>%`

使用`magrittr`操作符`%>%`（而非`|>`操作符）时，你可以通过特殊变量`.`（点）来改变默认的输入位置。如果右侧表达式中将`.`作为一个参数，那么左侧内容的值就会被放入该位置。以下四个管道都是等价的：

```r
mydata %>%
  pivot_longer(names_to = "year", values_to = "mean_income", !country) %>%
  drop_na()

mydata %>%
  pivot_longer(names_to = "year", values_to = "mean_income", !country) %>%
  drop_na()

mydata %>%
  pivot_longer(data = ., names_to = "year", values_to = "mean_income", !country) %>%
  drop_na()

mydata %>%
  pivot_longer(names_to = "year", values_to = "mean_income", !country, data = .) %>%
  drop_na()
```

你可以在右侧多次使用点：

```r
rnorm(5) %>% tibble(x = ., y = .)
## # A tibble: 5 × 2
##         x       y
##       
## 1 -0.951  -0.951
## 2  0.0206  0.0206
## 3  1.14    1.14
## 4 -0.172  -0.172
## 5  0.0795  0.0795
```

你也可以在嵌套函数调用中使用它。

```r
rnorm(5) %>% tibble(x = ., y = abs(.))
## # A tibble: 5 × 2
##          x       y
##        
## 1  1.61    1.61
## 2  1.86    1.86
## 3 -0.211   0.211
## 4 -0.00352 0.00352
## 5 -0.522   0.522
```

但是，如果点*仅*出现在嵌套函数调用中，`magrittr`仍然会将其作为第一个参数添加到右侧函数中。

```r
rnorm(5) %>% tibble(x = sin(.), y = abs(.))
## # A tibble: 5 × 3
##        .      x     y
##      
## 1  1.10   0.893 1.10
## 2 -0.155 -0.155 0.155
## 3  0.102  0.102 0.102
## 4  0.627  0.587 0.627
## 5  0.280  0.276 0.280
```

为避免这种情况，你可以将右侧表达式放在花括号中：

```r
rnorm(5) %>% { tibble(x = sin(.), y = abs(.)) }
## # A tibble: 5 × 2
##         x      y
##      
## 1  0.661  0.723
## 2  0.0588 0.0588
## 3  0.960  1.86
## 4  0.820  0.961
## 5 -0.366  0.375
```

一般来说，你可以将表达式放在花括号中作为管道操作符的右侧，并让`magrittr`对其进行求值。可以将其视为编写单参数匿名函数的一种方式。输入变量是点，花括号内的表达式是函数体。

## 函数组合

编写与你自己的管道配合良好的函数是轻而易举的。所有函数都将输入映射到输出（理想情况下没有副作用），因此所有函数都可以在管道中使用。如果关键输入是你所编写函数的第一个参数，那么左侧内容的默认位置就会起效——因此这是更好的做法——但否则你可以显式地使用点。

然而，在编写管道时，你通常不需要从头编写一个函数。如果一个函数仅仅是由其他函数调用组合而成——它本身就是一个管道函数——我们可以将其定义为这种形式。

在数学中，函数组合操作符`°`将函数`f`和`g`的组合`g` `°` `f`定义为函数：

（`g` `°` `f`）（`x`）=`g`（`f`（`x`））

许多函数式编程语言鼓励你通过组合其他函数来编写函数，并为此提供操作符。这在R中并不常见，虽然你可以实现函数组合，但没有内置的操作符。不过，`magrittr`包为你提供了这种语法：

```r
h <- . %>% f() %>% g()
```

这定义了函数`h`，使得`h(x) = g(f(x))`。

如果我们沿用之前看到的整理再清洗管道，并假设我们需要对多个输入文件执行相同操作，我们可以为此定义一个管道函数：

```r
pipeline <- . %>%
  pivot_longer(names_to = "year", values_to = "mean_income", !country) %>%
  drop_na()

pipeline
## Functional sequence with the following components:
##
##  1\. pivot_longer(., names_to = "year", values_to = "mean_income", !country)
##  2\. drop_na(.)
##
## Use 'functions' to extract the individual functions.
```

## 其他管道操作

`magrittr`包中还有另外三个管道操作符。当你导入`tidyverse`包时，这些操作符并不会被自动导入，因此若要使用它们，你需要显式地导入`magrittr`。

```r
library(magrittr)
```

`%<>%`操作符用于执行一个以变量开头，并以将该变量的处理结果重新赋值给该变量为结尾的管道操作。以下代码：

```r
mydata %<>% pipeline()
```

等价于：

```r
mydata <- mydata %>% pipeline()
```

这个重新赋值操作符的行为与我们在本章开头讨论的逐步赋值管道约定类似，但它明确表示我们正在更新一个已有的变量。这样你就不会意外地将结果赋值给另一个不同的变量。

如果你的右侧是一个花括号包围的表达式，你可以通过点变量（`.`）来引用输入：

```r
mydata %<>% { .$x - .$y }
## [1] 0.3597903 1.8108120 2.3444173 3.1367824
## [5] 0.2507438
```

如果像此处这样，输入是一个数据框，并且你想访问其列，你需要使用`.$`符号来访问它们。`%$%`管道操作符为你打开了数据框，因此你可以直接通过列名来引用它们。

```r
mydata %$% { x - y }
## [1] 0.3597903 1.8108120 2.3444173 3.1367824
## [5] 0.2507438
```

*三通*管道操作符`%T>%`的行为与常规管道操作符`%>%`类似，不同之处在于它返回的是其输入，而不是调用其右侧函数的结果。常规管道操作`x %>% f()`会返回`f(x)`，但三通管道操作`x %T>% f()`会调用`f(x)`但返回`x`。这对于在管道内部调用具有副作用的函数非常有用，例如将中间结果保存到文件或绘制数据图表。

如果你在常规管道中调用一个函数，你会将该函数调用的结果传递给管道中的下一个函数。例如，如果你想绘制中间数据，但绘图函数可能不会返回该数据，那就不太走运了。`ggplot2`函数就不会（参见第13章）。

如果你想绘制中间值，你需要将数据保存到一个变量中，保存它，然后以该数据作为输入开始一个新的管道。

```r
tidy_income %>% 
  pivot_longer(names_to = "year", values_to = "mean_income", !country)
## 在继续处理之前汇总和可视化数据
summary(tidy_income)
ggplot(tidy_income, aes(x = year, y = mean_income)) + geom_point()
## 继续处理
tidy_income |>
  drop_na() |>
  write_csv("data/tidy-income.csv")
```

使用三通操作符，你可以在调用绘图函数后继续管道操作。


```
mydata %>%
  pivot_longer(names_to = "year", values_to = "mean_income", !country) %T>%
  # 汇总然后继续
  { print(summary(.)) } %T>%
  # 绘图然后继续
  { print(ggplot(., aes(x = year, y = mean_income)) + geom_point()) } %>%
  drop_na() %>% write_csv("data/tidy-income.csv")
```

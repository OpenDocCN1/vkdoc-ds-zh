# 前言

几十年来，应用世界一直遵循一个简单的规则：程序员比任何人都更了解用户的需求。如果沿着这条轨迹发展，当开发者向用户提供新程序或现有程序的更新版本时，用户只能被动接受所得到的一切。结果，数百万用户与不需要的功能苦苦斗争，并自行实施变通办法来跨越障碍、拼凑功能，以使程序满足自身需求。开发者为何必须牢牢掌控自己的产品？历史表明，移除这一障碍对双方都有益。

## 历史的轨迹

汽车的黄金时代始于福特等制造商开始向客户提供可以随时随地驾驶的汽车。汽车制造商提供了工具，但最终由客户决定何时以及如何使用该工具。这种方式完美运行，直至今日。

当牛顿和莱布尼茨独立发明微积分时，科学和工程（无论是研究还是实践）都获得了巨大推动。创造者并未指示科学家必须如何使用新方法才能解决问题。每位科学家或工程师都必须自己判断，是否值得投入时间深入理解微积分。科学家必须思考如何将这一新的数学工具应用于自己的特定研究工作。这种方式已经运行了 300 年。

几十年前，我的一位同事完美地概括了大型编程公司的座右铭：“用户必须接受给予他们的一切。”程序世界中的贸易珠时代已经结束。用户变得更加挑剔，要求产品能够帮助他们解决特定任务。

用户比任何开发者都更了解自己的专业领域。在科学和工程领域，这一点最为明显；在这些领域，用户比任何其他领域都更受“一刀切”程序之苦。必须赋予用户对程序的完全控制权，才能使其发挥作用。本书解释了此类程序的设计，并展示了新型程序——用户驱动型应用的运作方式。

## 软件危机与演变

五十年前，当无法在要求时间内开发出大型高效程序时，发生了软件危机。当时程序数量相对较少；其中最大、最重要的程序用于工业和国防的关键领域，因此任何此类程序的灾难都影响巨大。艾兹格·迪科斯彻在解决该问题中发挥了关键作用¹。那场危机纯属技术性危机，解决方案在于应用新的编程技术。自那时起，结构化编程和新语言使得编写任何复杂程度、几乎无错误的程序成为可能。几十年前，任何程序最重要的部分都是某种计算算法，一切围绕它构建，而界面则毫无作用。当时，开发者和用户数量都很少且规模相当。如果对程序结果有疑问，就意味着对所使用的算法有疑问。这些疑问在程序开发者与用户之间进行讨论。讨论后的结果，经过一段时间，用户会得到新版本。开发者对程序拥有绝对控制权，这种控制权从未被质疑过。

## 个人计算机时代

个人计算机的引入对计算和程序世界产生了深远影响。给定应用的开发者和用户数量相差三到四个（有时是五到六个）数量级已不再罕见。任何复杂程度的程序都应无故障运行；无错误工作符合应用程序目标，这是理所当然的，甚至无需讨论。界面，而非计算，成为了程序的关键部分。无错误程序的问题从一个完全意想不到的方面出现了。面对海量用户，期望所有用户都对单一界面设计（即使是出色的设计）感到满意是不现实的。更可能出现的是各种各样的需求。为了回应用户需求，开发者转向了自适应界面。它被宣称是使程序适应用户需求的一种方式；每个用户都必须使任务适应开发者提供的任何内容。三十多年来，无数种自适应界面变体的使用既未解决也未缓解这个问题。世界各地数百万人与程序苦苦斗争，试图让程序做他们想做的事。通常，用户会失败，但仍在继续抗争。考虑到受此问题影响的人数，这与其说是一个技术问题，不如说是一场哲学危机，而这样的危机无法通过技术调整来解决。

## 解决方案：用户驱动型应用

这场危机的根源在于开发者对应用的控制权，只能通过将应用完全控制权交给用户来解决。开发者仍负责程序的默认视图和无差错运行，但必须允许用户进行任何所需操作。将应用完全控制权交给用户的想法对大多数开发者来说可能听起来很疯狂，但请想一想，我们作为开发者也是许多不同程序的用户。开始使用一个新工具或平台，不久你就会放弃那些由别人规定你如何使用它们的旧程序。当应用的完全控制权掌握在你手中时，一切就只取决于你的能力了。

# 为了将应用的控制权交还给用户，需要做出哪些改变？

有一个必要且充分的条件：每一个屏幕对象都必须变得可由用户移动和调整大小。如果用户能在任何时刻轻松地对任何对象执行这些操作，那么应用的全部控制权就自动移交给了用户。因此，我们需要一种易于使用的可移动性算法，该算法能够应用于任意形状和复杂度的对象。

全球范围内，技术娴熟且富有想象力的开发者们正在创造出无限多样的屏幕对象。用户不会为了使用一个新程序而去阅读冗长的手册，因此可移动性算法必须提供一种处理任意对象的简便方法。同时，这种算法必须易于实现，否则它将毫无用处。

本书描述了一种完全可移动性算法，并展示了它在多种不同场景下的实现——从最简单的例子到现实世界中高度复杂的应用。所提出的算法仅仅是开发用户驱动型应用的一种工具。如果你决定使用自己的算法来代替它，你最终会得到完全相同的结果。程序可以基于任何可移动性算法，但所有程序都将遵循用户驱动型应用的相同规则。

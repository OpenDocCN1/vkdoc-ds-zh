# 最新的云基础大数据技术

传统上，构建大数据应用意味着将数据存储在昂贵的本地数据仓库中，并安装和维护复杂的软件。两大发展使得这种情况不复存在。

首先，高速宽带的大范围普及使得数据在不同地点之间的移动变得更加容易。本地产生的数据不再必须由本地进行分析，它可以被转移到云端进行分析。

其次，如今越来越多的应用是基于云的。这意味着更多的数据正在云端产生和存储。越来越多的创业者正在构建新的大数据应用，以帮助公司分析诸如电子商务交易和 Web 应用性能数据等基于云的数据。

最新的云基础大数据技术已在三个不同的层面演进：基础设施层、平台层和应用层。

## 基础设施

在最底层，基础设施即服务（IaaS），如亚马逊弹性计算云（EC2）和简单存储服务（S3），以及谷歌云存储，使得在云端存储数据变得简单。

基于云的基础设施服务实现了巨大的可扩展性，而无需通常所需的在存储和计算基础设施上的相应前期投资。或许与其他任何公司相比，亚马逊通过其亚马逊网络服务（AWS）产品开创了公有云领域，你将在下一节读到更多关于它的详细内容。

AT&T、谷歌、IBM、微软和 Rackspace 等提供商一直在扩展其云基础设施服务。IBM 最近变得更具进取心，或许是对 AWS 的快速增长感到担忧。2013 年，IBM 以 20 亿美元收购了 SoftLayer Technologies，以扩展其云服务产品。在被收购前，SoftLayer 的年收入估计在 8 亿至 10 亿美元之间。¹

亚马逊、谷歌、微软和 Rackspace 在基础设施层面的竞争尤为激烈，多次下调计算和存储服务的价格。根据云管理公司 RightScale 的数据，2013 年这四家公司总共降价约 26 次，其中亚马逊的降价次数最多。这对大数据来说是个好兆头，因为这意味着在云端存储和分析大量数据的成本持续下降。在许多情况下，在云端处理大数据比在本地处理更便宜。

## 平台

在中间层，平台即服务（PaaS）解决方案在提供更多应用特定能力的同时，提供了存储和计算服务的组合。这些能力意味着应用开发人员可以花更少的时间担心底层基础设施如何扩展的细节，而将更多时间专注于其应用的独特方面。

在经历了一个稍晚的开端后，微软一直在扩展其 Microsoft Azure 云产品。Microsoft Azure HDInsight 是云端的 Apache Hadoop 产品，它使大数据用户能够按需启动和关闭 Hadoop 集群。

谷歌提供谷歌计算引擎和谷歌应用引擎，此外还有 Google Fusion——一种基于云的存储、分析和演示解决方案，用于在云端快速处理海量的基于表格的数据。最近，谷歌推出了 Google Cloud DataFlow，并将其定位为 MapReduce 方法的继任者。与采用批处理方式处理数据的 MapReduce 不同，Cloud DataFlow 既能处理批处理数据，也能处理流式数据。

较新的进入者，如由 Facebook 前大数据主管创立的 Qubole，以及提供 CloudFoundry 产品的 VMWare，将现有云基础设施服务的优势与更先进的数据和存储管理能力结合了起来。`Salesforce.com`也值得一提，因为该公司早在 1999 年就开创了基于云的应用领域。该公司提供其`Force.com`平台。尽管该平台非常适合与客户关系管理（CRM）相关的应用，但它目前尚未提供专为大数据应用设计的功能。

## 应用

软件即服务（SaaS）大数据应用存在于云堆栈的最高层。它们是开箱即用的，无需设置复杂且昂贵的基础设施，也无需安装和管理软件。在这一领域，`Salesforce.com`通过一系列收购（包括 Radian⁶和 Buddy Media）扩展了其产品线。它现在提供基于云的社交、数据和分析应用。

较新的进入者，如 AppDynamics、BloomReach、Content Analytics、New Relic 和 Rocket Fuel，都处理大量基于云的数据。AppDynamics 和 New Relic 都从基于云的应用中获取数据，并提供洞察以改善应用性能。BloomReach 和 Content Analytics 利用大数据来提高电子商务网站的搜索可发现性。Rocket Fuel 则利用大数据来优化其向消费者展示的广告。



未来几年，随着企业努力让更广泛的用户群体能够接触大数据，应用层很可能将持续增长。对于终端用户而言，基于云的 BDA 提供了一种强大的方式，能够让他们在特定垂直领域或业务领域收获大数据的益处，而无需承担传统上从头开始建设所需的时间和成本。

![Image](img/sq.jpg) **提示** 采用基于云的应用程序是一种经济且强大的方式，能够在业务层面和终端用户层面收获大数据摄取与分析的好处。

但由于当今 BDA 尚未覆盖许多领域，仍有大量技术可以帮助你快速开始构建自己的 BDA。在这方面，或许没有比 `AWS` 更知名的产品了。

## Amazon Web Services (AWS)

几乎没有哪个基于云的平台能比 `AWS` 更成功。直到最近，普遍的看法是，本地产生的数据会使用现场计算机基础设施在本地进行分析，而云端产生的数据则会在云端存储和分析。这在很大程度上是因为将海量数据从现场基础设施迁移到云端（以便进行分析）非常耗时。

但这一切都在改变。连接到云端的高带宽连接的可获得性，以及在云端弹性伸缩计算资源的便利性，意味着越来越多的大数据应用正在迁移到云端，或者至少在本地系统容量不足时使用云端。

但在你探索企业如何利用 Amazon Web Services 满足其大数据需求的具体方式之前，先退一步，看看 `AWS` 是如何变得如此受欢迎的。尽管 `AWS` 似乎在一夜之间就成为了巨头，但亚马逊实际上在 2003 年就推出了这项服务。到 2006 年，亚马逊已经将其商业化，并逐步发展成为今天这样的行业巨头。据一些分析师估计，`AWS` 在 2013 年为亚马逊贡献了约 38 亿美元的收入，并预计在 2014 年将达到惊人的 62 亿美元。²

一家在线书商是如何转变成领先的公共云服务提供商之一的？亚马逊开发了一种基础设施，可以按需弹性伸缩虚拟服务器和存储资源，这是应对公司在假日购物季期间出现的巨大需求高峰的关键能力。亚马逊将其最初为支持消费者对其零售网站的需求而构建的存储和计算能力（通常是过剩容量）提供给了企业用户。

当然，基于云的基础设施之前已经存在，形式是来自 `GoDaddy`、`Verio` 等提供商的主机托管服务。但亚马逊使得用户只需使用信用卡在线注册帐户即可轻松上手。亚马逊同样简化了增加更多存储（称为 `S3`，即简单存储服务）和计算能力（称为 `EC2`，即弹性计算云）的过程。

值得注意的是，亚马逊的产品以公用事业模式提供存储和计算。用户只需为他们实际消耗的资源付费。这使得用户可以在必要时购买几个小时的处理器时间，而无需承诺购买整台服务器数月或数年。用户可以试用一台服务器（称为实例），在其所需的时间内运行，并在不需要时将其关闭。他们可以根据自己的计算需求启动更大或更小的实例。所有这些操作都可以在几分钟甚至几秒钟内完成。

亚马逊无锁定限制的产品，加上易于上手的特性，真正使其与之前的托管服务提供商区别开来。更重要的是，用户认为，如果这些基础设施足以支撑亚马逊庞大的电子商务网站，那么它当然也足以支撑他们自己的应用程序。

而且亚马逊的定价很难被超越。由于其基础设施的规模，亚马逊采购了海量的硬件和带宽。因此，它拥有巨大的购买力，这反过来又使其能够一再降低价格。`AWS` 的用户不仅能利用灵活云基础设施的能力，还能享受亚马逊的购买力，就好像这是他们自己的购买力一样。此外，他们无需担心通常伴随维护物理服务器而来的所有基础设施需求：电源、冷却、网络容量、物理安全以及处理硬盘和系统故障。使用 `AWS`，所有这些都由服务提供。

由于这种灵活性，`AWS` 获得了巨大的采用率。像 `Netflix` 和 `Dropbox` 这样的领先科技公司都运行在 `AWS` 之上。但 `AWS` 的采用远不止于此。制药公司 `辉瑞` 在其对高性能计算（`HPC`）服务的需求超过其现场可用容量时，会使用 `AWS`。这是云端大数据服务实际应用的一个绝佳例子，因为用于药物发现和分析的 `HPC` 工作负载本质上通常是波动性的。有时，制药分析需要巨大的计算能力；云是支持这种需求高峰的理想方式，而无需长期购买计算资源。

在另一个例子中，娱乐公司 `Ticketmaster` 使用 `AWS` 进行门票定价优化。`Ticketmaster` 需要能够调整票价，但不想为支持此类应用而预先投入通常所需的昂贵成本。此外，与 `辉瑞` 一样，`Ticketmaster` 的需求波动性很大。通过使用 `AWS`，该公司能够部署基于云的 `MapReduce` 和存储能力。据亚马逊称，采用基于云的方法减少了每天三小时的基础设施管理时间，并降低了约 80% 的成本。

随着时间的推移，亚马逊为其云产品增加了越来越多的服务，尤其是对 BDA 有用的服务。Amazon Elastic `MapReduce` (`EMR`) 是一项基于云的服务，用于在云端运行 `MapReduce` 作业。

`MapReduce` 是一种著名的大数据处理方法，用于将大型数据集处理成结果，通常将数据分割成多个块，分布在多个服务器或实例上进行处理，然后将结果重新组合以产生最终见解。`MapReduce` 最初由谷歌于 2004 年设计。Apache 通过其开源的 Hadoop `MapReduce` 产品推广了这种方法，而像 `Cloudera`、`HortonWorks` 和 `MapR` 这样的公司则通过商业产品使其更加可行。Hadoop 和 `MapReduce` 方法已成为大数据的中坚力量，因为它们能够存储、分发和处理海量数据。

使用 `EMR`，用户无需执行创建 `MapReduce` 基础设施所需的通常费力且耗时的设置任务。此外，如果需要在规定时间内完成 `MapReduce` 作业而需要额外的计算资源，用户可以简单地启动更多实例。也许最重要的是，用户无需预先投入巨资即可拥有自己的 `MapReduce` 基础设施。用户无需购买典型的 50 或 100 节点计算集群所需的硬件和网络基础设施，只需启动任意所需数量的实例，然后在分析完成后将其关闭即可。

亚马逊的解决方案不止于此。在过去几年中，该公司还推出了一种名为 `Glacier` 的超低成本数据归档解决方案。虽然 `Glacier` 无法实时访问数据，但其价格仅为传统归档解决方案的十分之一或更低。这为那些还在观望的人提供了又一个将其数据迁移到云端的理由。



为了进一步扩展其服务，亚马逊推出了`Kinesis`，这是一种用于处理海量流式数据的托管云服务。与基于批处理的`EMR`和`MapReduce`不同，`Kinesis`可以实时处理流式数据，例如推文流、应用程序事件、库存数据，甚至是股票交易数据。

![Image](img/sq.jpg) **注意** 亚马逊正在持续为`Amazon Web Services`引入新的大数据和云相关功能。`Kinesis`是其最新的服务，旨在处理海量流式数据，如推文、股票报价和应用程序事件。

现在，不再只是云中产生的数据才适合在云中分析。如今乃至未来，低成本存储、灵活且可扩展的计算能力，以及`EMR`和`Kinesis`等预构建服务，结合对`AWS`等公共云基础设施的高带宽访问，将提供更具说服力的理由，促使我们在云中执行大数据分析。

`AWS`最初客户支持有限，且缺乏企业级的服务等级可用性（`SLA`）选项。现在，该公司提供了企业级的可用性。像`Netflix`、`Dropbox`、`Pfizer`、`Ticketmaster`等公司都依赖`AWS`来运行其关键任务应用程序。一些分析人士预测，在未来短短几年内，亚马逊`AWS`的年收入将从几十亿美元增长到 150 至 200 亿美元。为了实现这一目标，该公司极有可能将继续扩展其企业云和大数据产品。

`AWS`为传统基础设施提供了一种极具吸引力的替代方案，能够快速启动新的大数据服务，并提供按需扩展能力。在支持大规模分析应用的需求方面，它也是用于处理溢出容量的一个不错选择。到目前为止，我们在所提供的服务以及近乎持续的价格下调方面所看到的，仅仅是个开始。未来还将有更多基于云的大数据服务，它们都将具备固有的经济性和可扩展性优势。

## 大数据公有云与私有云方案

云服务有多种形式——公有云、私有云和混合云。私有云提供与公有云相同的按需扩展能力，但其设计目的是供单个组织使用。私有云本质上隔离了基础设施，因此存储在该基础设施上的数据与其他组织的数据是分开的。

组织可以在其内部物理硬件和软件上运行自己的私有云。他们也可以使用部署在`AWS`等主要云服务之上的私有云。这种组合通常能提供两全其美的优势——云的灵活性、可扩展性和降低的前期投入，结合组织保护其最敏感数据所需的安全性。

![Image](img/sq.jpg) **注意** 在`AWS`等主要服务之上运行私有云，能提供灵活性、低成本以及公有云的所有好处，而且还增加了当今许多企业所要求的安全性。

一些组织选择在内部硬件和软件上部署私有云服务组合，同时使用公有云服务来应对需求高峰。这种混合云方法特别适合大数据应用。组织既能拥有在自有基础设施上运行核心分析应用所带来的控制权和安心感，又能确保在需要时可以从公有云提供商那里立即获得额外的容量。

许多大数据应用（如定价优化、路线规划和药物研究）的计算密集型部分并不需要一直运行。相反，它们需要在相对较短的时间内使用巨大的计算能力，以便从海量数据中产生结果。因此，这些应用程序非常适合采用混合云方法。

更重要的是，这类应用程序通常可以利用最低的计算能力价格。以`AWS`为例，竞价型实例是根据市场供需定价的。竞价型实例买家出价一个每小时的价格，如果市场能够接受这个价格，买家就能获得该实例。竞价型实例的价格通常远低于按需实例的同等价格。

竞价型实例的缺点是，如果实例的市场价格上涨，它们可能会在没有通知的情况下被收回。当云服务提供商遇到需求显著增长时（例如在节假日期间），就可能发生这种情况。但大数据处理的瞬时性，结合`MapReduce`方法的分布式特性，意味着因实例被收回而丢失的任何结果，都可以简单地在另一个实例上重新生成。

处理大数据所分布的实例越多，任一特定实例上涉及的数据就越少。通过将分布式架构方法与竞价型实例的低成本特性相结合，公司通常可以显著降低其大数据相关成本。通过在公有云服务之上叠加虚拟私有云，组织可以同时为其大数据应用获得所需的安全性。

## 大数据如何改变移动领域

或许没有哪个领域比大数据与移动领域的交汇更令人感兴趣了。移动意味着大数据可以随时随地访问。过去需要安装在台式电脑上的软件，现在可以通过平板电脑或智能手机访问。更重要的是，过去需要昂贵定制硬件和复杂软件的大数据应用，现在也已触手可及。你可以使用智能手机、一些附加硬件以及一个易于安装的移动应用程序，来监测你的心率、睡眠模式，甚至是心电图。你可以将其与云相结合，上传并分享你收集的所有数据。

大数据和移动技术不仅在数据展示和分析方面，还在数据收集方面正在融合。在一个被称为物联网（`IoT`）的知名技术潮流中，智能手机和其他低成本设备正在迅速扩大可用于收集数据的传感器数量。即使是像交通信息这类过去需要复杂、昂贵传感器网络的数据，现在也可以通过智能手机和移动应用程序来收集和显示。

健身是大数据改变移动领域的另一个领域。过去，我们（如果曾经记录过的话）是通过桌面软件应用来追踪健身活动的，而现在，像`Fitbit`这样的可穿戴设备让我们可以轻松地追踪一天走路的步数。结合移动应用程序和分析功能，我们现在可以在活动量不足时收到提醒。我们甚至可以使用`Strava`等应用程序结合低成本的`GPS`设备来与他人进行虚拟竞赛。`Strava`会识别出骑行路线中的热门路段，并让骑行爱好者比较他们在这些路段上的表现。这使得骑行者即使无法一起骑行，也能与朋友甚至知名的职业车手进行社交化的骑行体验。然后，这些骑行者可以分析自己的表现，并利用数据来提升自己。


在医生的办公室里，像`PracticeFusion`这样的应用程序使医生能够收集和查看患者数据以用于电子健康记录（EHR），并直接在可以随身携带的平板电脑上分析这些数据。数据收集不再需要经历记笔记或将其录制为音频文件，然后再将笔记转换或转录为数字形式的多步骤过程。现在，医生可以“即时”记录和查看患者信息，并将这些信息与历史患者数据或基准数据进行比较。不再需要等待——大数据与移动计算的交汇意味着实时已成为现实。

但实时移动大数据的应用并不仅限于此。`Google Glass`是一款外观未来主义的可穿戴设备，既能记录信息也能呈现信息，它正在改变我们看待世界的方式。你不再需要查阅智能手机来获取关于产品的更多信息或查看地图上的位置。`Glass`集成了实时信息、可视化和云服务，所有这些都作为你观察世界的增强手段。

在商业世界中，当涉及到车队路线规划、包裹递送、销售、营销和运营等应用时，大数据正在改变移动计算。专门为移动设备优化的分析应用程序使得在旅途中评估运营绩效变得容易。财务数据、网站性能数据、供应链数据以及许多其他来源的数据，都可以轻松地从平板电脑和智能手机上访问和可视化。这些设备不仅拥有极强的图形处理能力，其触摸屏界面也使得与可视化数据交互变得简单。计算密集型的数据处理可以在云端完成，结果可以随时随地显示。

大数据也在物流和运输领域产生了巨大影响。飞机引擎数据被实时下载以监控性能。像福特这样的主要汽车制造商已经创建了车联网计划，使得汽车数据易于访问。因此，开发者将能够构建利用汽车数据的新移动应用程序。

这类曾经只属于最先进赛车队的汽车应用程序，如今已开始广泛可用。开放汽车产生的大量信息意味着，有趣的汽车新应用程序的开发者不必仅限于汽车制造商本身。那些对引人注目的汽车相关应用有想法的企业家将能够直接创建这些应用程序。

这种平台方法当然不仅限于汽车。对于任何拥有丰富数据源并希望开放它，以便其他人可以利用这些数据创建引人注目的新应用程序的组织来说，这都很有意义。

健身、医疗、销售和物流只是移动、云和大数据汇聚在一起，产生各种引人注目的新应用的众多领域中的几个。大数据正在改变移动——而移动也正在改变大数据。

## 如何构建你自己的大数据应用程序

你已经了解了可以用大数据构建的各种应用程序以及可用于支持你工作的基础设施。现在，你将深入研究构建自己的`BDA`的细节，包括如何识别你的业务需求。

构建`BDA`不必困难。从历史上看，启动一个新的大数据项目所需的投资、专业知识和时间，曾阻止了许多公司和企业家进入大数据领域。然而，现在大数据几乎对任何人都可及，构建`BDA`完全触手可及。

要构建你自己的`BDA`，你需要五样东西：

*   一个业务需求
*   一个或多个数据源
*   正确的技术，用于存储、计算和可视化
*   一种向用户呈现洞察的引人注目的方式
*   一个能够处理大规模数据的工程团队

## 定义业务需求

在我与客户的合作中，我经常发现公司是从大数据技术开始的，而不是首先确定他们的业务需求。结果，他们花费数月甚至数年的时间纯粹为了技术而构建技术，而不是为了解决特定的业务问题。

解决这种常见陷阱的一种方法是让业务用户和技术人员在流程的早期就聚在一起。很多时候，这些人各自为政；通过打破这些壁垒并让他们尽早聚在一起，你解决问题的可能性会大得多。

对于企业家——无论是独立工作还是在大型组织中工作——大数据带来了一些惊人的新机遇。你可以专注于某个特定的垂直领域，如医疗、教育、交通或金融，或者你可以构建一个使大数据更易访问的通用分析应用程序。`Uber`就是一家利用大数据和移动技术颠覆运输和物流市场的公司例子。同时，`Platfora`是一个基于云的新可视化应用程序。随着对大数据的兴趣日益增长，现在是构建你自己引人注目的应用程序的最佳时机。

![Image](img/sq.jpg) **提示** 现在是时候构建你自己的大数据应用程序了。首先，你会学到很多东西。其次，你可以肯定你的顶级竞争对手正在努力构建他们自己的应用程序。

## 识别数据源

根据你构建的应用程序类型，数据可以有多种形式。例如，我的公司`Content Analytics`开发了一种分析整个网站的产品。数据来自对数千万个网页的爬取，就像`Google`所做的那样。该公司的产品随后从每个网页中提取相关数据，例如定价、品牌细分和内容丰富度信息。

在识别数据源的同时，确定这些数据源是非结构化、结构化还是半结构化的也很重要。例如，一些网页几乎只包含文本和图像。这被认为是非结构化数据。

许多电子商务网站包含定价、产品和品牌信息。然而，页面上呈现的这类数据并非以数据库中众所周知的结构化形式提供。因此，该数据具有一定的结构，但并非真正良好的结构化，这使得解析它相对困难。这被认为是半结构化数据。

最后，像存储在数据库中的客户联系信息这样的数据是结构化数据的一个很好的例子。你将处理的数据类型将对你选择如何存储该数据以及在对数据进行分析之前需要处理多少数据产生重大影响。

数据也可能来自内部来源。我们合作过的一个电信客户提出了开发一个新的`Big Data`现场管理应用程序的想法。该应用程序将汇集关于客户支持请求的数据、现场技术人员可用性甚至客户账户价值，以确定技术人员下一步应该去哪里。它还可以整合移动/位置信息，提醒技术人员在到达每次服务呼叫时携带合适的设备。大型电信公司拥有超过 75，000 名或更多的现场技术人员。因此，利用数据来高效地部署这些技术人员，每年可能为公司节省数亿美元。


另一个例子是，数据可以来自公司网站。网站性能数据和访客信息都可用，但需要以引人注目的方式进行存储、分析和展示。仅仅存储网站生成的日志文件是不够的。像 AppDynamics 和 New Relic 这样的公司，围绕应用性能监控开创了全新的业务；而 Adobe Marketing Cloud 和 Google Analytics 等产品，则将海量的网站流量数据转化为关于谁在访问你的网站、何时访问以及停留时长的深刻见解。

最后，别忘了公共数据源。从经济数据到人口数据、就业数字和监管文件，有海量的数据可用。挑战在于，这些数据往往难以获取。

房地产信息网站 Zillow 就是从难以获取的房地产销售价格信息中建立起整个业务的。这些信息存在于公共记录中，但这些记录通常以纸质形式存放在当地镇书记办公室。即使这些记录以电子方式存储，也往往无法在线访问。Zillow 将这些难以获取的数据转化为标准化的中央存储库，并通过易于使用的网络界面提供访问。消费者可以输入地址，并根据周边地区的销售数据获得估算价格。公共数据可以成为无价的资源。有时，你只需要付出必要的努力去获取、整理并展示它。

一旦你确定了业务需求以及数据的来源和类型，就可以开始设计你的大数据应用了。一个典型的大数据应用会有三层结构：用于存储数据的基础设施层、用于从数据中提取含义的分析层，以及展示层。

## 选择合适的基础设施

对于如今的大多数初创公司来说，决定在云端存储和处理大数据是一个轻松的选择。云服务提供了极低的前期时间和成本投入，以及按需扩展的能力。在如何存储数据方面，通常有三种选择。你可以使用传统的 SQL（结构化查询语言）数据库基础设施。这包括 MySQL、Oracle、PostgreSQL 和 DB2 等产品。在一定规模内，MySQL 表现出色，并且提供了无与伦比的价格——它是免费的。它还有一个优点，就是可以运行在通用硬件上。这些数据库也有基于云的版本。例如，Amazon 提供了其 RDS 服务，这是一种预构建的、基于云的数据存储服务，内置了冗余等功能。

然而，将数据存储在传统数据库中会带来一系列挑战，其中最重要的一点是，数据在存储前必须具有良好的结构。对于许多应用来说，数据库往往会很快成为瓶颈。过多的表、不断增长的过多行、纵向扩展（即在单台机器上增加处理能力、存储和内存容量，而不是将数据分散到多台机器上）的倾向，以及编写糟糕的 SQL 查询，都可能导致即使是中等规模的数据库也运行停滞。在处理大数据时，应用程序本身往往是最不复杂的部分——数据存储及其访问方式通常才是最关键的方面。

在另一个极端，则是 NoSQL 数据库。NoSQL 数据库克服了传统数据库的许多限制——例如跨多台服务器拆分数据的复杂性，以及需要预先定义数据结构。然而，它们也存在一些严重的局限性。具体来说，它们对基于传统 SQL 查询的存储和检索数据的方式支持有限。最近，NoSQL 数据库增加了更多类似 SQL 的功能来解决这些限制，并且它们在存储大量非结构化数据（如文档和其他形式的文本）方面确实表现出色。这方面有许多可用的产品，但最著名（且资金最充足）的是 MongoDB。

最后，还有 Hadoop，它已成为主流的大数据解决方案。Apache Hadoop 发行版是免费提供的，其技术设计使得将数据分布到多台机器上进行分析变得容易。这意味着，无需依赖位于一台或几台机器上的单个数据库，数据可以分散到集群中数十台甚至成百上千台机器上进行分析。对于那些需要商业支持、更高级的管理功能以及更快或近乎实时的分析能力的用户，可以从 Cloudera、HortonWorks、MapR 和其他供应商处获得商业解决方案。

如果你的应用是基于云的，你可以为 Hadoop 和 MapReduce 配置你的服务器，或者根据你的供应商选择，使用预构建的基于云的解决方案。Amazon MapReduce (EMR) 就是这样一种易于使用的服务。Amazon 还提供 AWS Data Pipeline 服务，该服务有助于管理进出不同位置的数据流。例如，Data Pipeline 可以自动将日志文件从服务器实例集群移动到 Amazon S3 存储服务，然后启动 EMR 作业来处理数据。

使用这种预构建的、特定于平台的解决方案的缺点在于，如果你以后想迁移到另一个云平台或采用自定义配置，会变得相对困难。但在许多情况下，使用此类解决方案的好处（例如快速上手的速度和降低的维护开销）往往超过潜在的缺点。

![图表](img/sq.jpg) **注意**  请记住，当你选择某个特定平台（例如 Amazon 的 MapReduce 版本 EMR）时，你可能会在迁移数据以及为创建解决方案所做的所有工作时遇到困难。通常，收益是大于风险的，但在投入大量资源之前，请仔细考虑一下。

## 向客户展示洞察

一旦你有了收集、存储和分析数据的方法，就需要一种方式向你的用户、客户或委托人展示结果，使他们能够看到结果并与数据进行交互。在许多情况下，他们最初的问题会引发更多问题，因此他们需要一种方式来迭代他们的分析。

就你的应用而言，你可以从头开始设计一切，但利用大量现成的模块、工具和服务更有意义。假设你的应用需要支持在地图上显示数据，并允许用户与这些数据交互。你可以从头构建一个完整的地图解决方案，但利用现成的解决方案会更高效。

如果你正在构建一个基于网络的数据分析服务，CartoDB、BatchGeo 和 Google Fusion 是基于云的数据展示和地图解决方案，它们能让你轻松地将地理可视化集成到你的应用中。无需编写大量自定义可视化支持代码，你只需将数据以支持的格式上传到这些服务之一，并在你的应用中集成少量代码，就能让所选服务显示出最终的可视化结果。



此类基于云的地图可视化解决方案对移动应用尤为实用。例如，若您正在构建车队路由应用，使用预构建模块意味着您可以专注于为车队设计最优路由算法，并为司机打造最易用的应用界面，而无需操心如何显示详细地图数据。

使用此类服务的弊端在于您的数据会被这些服务获取。尽管根据合同约定，除在您的网站上显示可视化内容外，他们不得将您的数据挪作他用，但当涉及机密数据时仍会增加安全风险。因此在决定使用任何第三方基于云的可视化解决方案时，必须权衡易用性与安全性之间的取舍。

如果您的应用场景有特殊需求，也可以直接将开源或专有地理可视化软件集成到应用中。例如 `CartoDB` 即提供开源解决方案。

预构建模块还可支持多种其他可视化功能。`HighCharts` 便是能让您在应用中轻松添加精美图表的解决方案之一。

根据应用的性质差异，需要不同程度的定制化呈现开发工作。我所在的公司 `Content Analytics` 结合了自定义可视化功能与 `HighCharts` 等预构建方案，在其产品中提供完整的可视化支持。这种方法让应用用户能兼得两者之长：既可查看在线营销效果数据的专用界面，又能通过优雅的可视化图表以引人入胜且简明易懂的方式展示数据。

另一种可视化思路是专注于应用中的数据分析，而将呈现工作交给专注于可视化的产品，如 `Tableau`、`QlikView` 及 `Spotfire`。这些产品专为可视化设计，功能极为丰富。如果您应用的核心竞争力来自数据及/或您开发的算法和分析方法，那么最合理的做法可能是专注于这些领域，让应用便于导出数据，再使用上述工具进行数据呈现。然而，随着越来越多用户（尤其是缺乏传统数据科学和分析背景的人）将大数据融入日常工作，他们自然会期望大数据应用内置可视化功能。

## 组建工程团队

构建引人入胜的大数据应用需要多方面的技能。您的团队需要包含：

- 后端软件开发人员：能构建支持超大量数据的可扩展应用。
- 前端工程师：能构建注重细节、富有吸引力的用户界面。
- 数据分析师：负责评估数据，开发用于关联、总结并从数据中获取洞察的算法。他们还可根据处理复杂数据集的经验，推荐最合适的可视化方案。
- 用户界面设计师：设计应用界面。可能需要一名负责应用整体外观和体验的设计主管，配合熟悉特定桌面、平板及移动设备界面规范的设计师。例如，若您正在为应用构建 iPhone 界面，则需要一位不仅熟悉移动应用设计，还通晓 iPhone 特有的图标、窗口、按钮等通用应用元素设计风格的设计师。
- DevOps（开发运营）工程师：能衔接软件编码与 IT 运维两个领域。他们负责配置和维护应用及其基础设施（无论是基于云还是本地部署）。DevOps 工程师通常兼具系统管理和开发专长，既能在必要时直接修改应用代码，又能构建运维应用所需的脚本及其他系统配置。
- 产品或项目经理：使命是聚焦客户需求。在大数据应用中，人们极易迷失在技术和数据中，而忽视客户和用户真正需要的洞察。

将合适的团队与正确的数据源和技术相结合，您就能构建出极具吸引力的大数据应用。从车队管理到营销分析，从教育到医疗，大数据应用的新可能性几乎是无限的。

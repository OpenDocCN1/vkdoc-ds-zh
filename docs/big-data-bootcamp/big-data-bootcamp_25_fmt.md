# 排版后的内容

在某些情况下，解读数据几乎不需要或完全不需要人工干预。对于在线广告、金融交易和定价而言，结合了算法的软件可以帮助你解读结果并尝试新的实验。计算机程序解读复杂的数据集，根据有效和无效的部分来投放新广告、交易股票以及提高或降低价格。随着数据集的体量持续增长，并且需要以前所未有的速度和规模做出决策，这类自动化解读很可能会扮演越来越重要的角色。在这些系统中，人工监督至关重要——能够显示系统行为变化、突出异常并允许人工干预的仪表盘是关键。

## 我应该抛弃我的关系型数据库管理系统（RDBMS）吗？

实际上，自从数据库首次被发明以来，人们就一直在试图摆脱它们。简单的答案是：你不应该抛弃你的`RDBMS`。这是因为每项大数据技术都有其用武之地，这取决于你需要存储的数据类型以及你需要对该数据进行访问的方式。

关系型数据库系统是由 IBM 公司的埃德加·科德在 20 世纪 60 年代末至 70 年代初发明的。与其前身——信息管理系统（`IMS`）不同，`RDBMS` 由各种表组成。相比之下，`IMS` 系统采用层级结构组织，常用于记录高速交易数据，例如金融服务交易。就像收音机在电视机出现后并未消失一样，`IMS` 系统在 `RDBMS` 出现后也并未消失。同样，随着像 `Hadoop` 和 `MapReduce` 这样的新技术出现，`RDBMS` 也不会消失。

首先，简单地抛弃像 `Oracle`、`IBM DB2`、`MySQL` 等经典结构化数据库系统是不切实际的。软件工程师对这些系统非常熟悉，并且已经使用它们多年。他们编写了大量应用程序，使用广为人知的结构化查询语言（`SQL`）与这些系统进行交互。而且，这类系统随着时间的推移已经不断发展，以支持数据复制、冗余、备份和其他企业级需求。

其次，`RDBMS` 继续服务于非常实际的目的。正如用于存储数据和从数据库中检索数据的 `SQL` 语言所暗示的那样，`RDBMS` 最适合存储结构化数据。账户信息、客户记录、订单信息等通常都存储在 `RDBMS` 中。

但是，当涉及到存储非结构化信息（如文档、网页、文本、图像和视频）时，使用 `RDBMS` 可能不是最佳方法。如果你需要存储的数据结构频繁变化，`RDBMS` 系统也不是理想的选择。

与传统数据库系统相比，近期引入的大数据技术——虽然擅长存储海量非结构化数据——但在处理高度结构化数据方面表现不佳。它们缺乏结构化查询语言那种优雅的简洁性。因此，虽然存储数据很容易，但以你需要的格式取回数据却很困难。

这就是为什么当今的大数据系统开始具备更多传统数据库系统的能力，而传统数据库系统也在吸收当今大数据技术的特征。这两类处于技术谱系两端的系统正变得越来越相似，因为客户有此需求。

当今的用户不愿意放弃他们在过去 40 年中已经习以为常的那些能力。相反，他们想要两全其美——既能处理结构化数据也能处理非结构化数据的系统，并且能够将这些数据分布到许多不同的机器上进行存储和处理。

## 大数据硬件

大数据的一大承诺是，它可以在通用硬件上处理海量数据。这意味着公司能够以比以往更低的成本存储和处理更多的数据。但重要的是要记住，像 `Facebook`、`Google` 和 `Amazon` 这样数据密集型程度最高的公司，正在设计自己的定制服务器，以运行当今数据密集型最高的应用程序。

因此，在设计你的大数据路线图时，你可以对底层基础设施（即运行所有软件，将数据转化为可行洞察的硬件）采取几种不同的方法。

一种选择是使用通用硬件构建你自己的基础设施。这通常适用于内部 `Hadoop` 集群，在这种情况下，公司希望维护从裸机到应用程序的整个自有基础设施。这种方法意味着可以很容易地向集群添加更多计算能力——只需添加更多服务器。但隐藏成本会随着时间的推移而显现。虽然这类集群相对容易搭建，但你需要负责管理底层硬件和应用软件。

这种方法还要求你内部拥有硬件、软件和分析方面的专业知识。如果你有资源，在将大数据作为更大规模应用程序的原型进行试验时，这种方法可能是最合理的。它能让你获得关于搭建和运营大数据系统所需条件的第一手知识，并让你对那些经常对应用程序性能产生巨大影响的底层硬件拥有最大程度的控制。

另一种选择是使用托管服务提供商。在这种情况下，你的硬件可以位于内部，也可以位于提供商的数据中心。在大多数情况下，提供商负责管理硬件故障、电力、冷却以及其他与硬件相关的基础设施需求。

还有一种选择是在云端完成所有大数据处理。这种方法允许你根据需要快速启动和关闭服务器，而无需预先投资来从零开始构建自己的大数据基础设施。其缺点是，你的应用程序和底层硬件之间通常存在一层虚拟化软件，这可能会降低应用程序的性能。

![Image](img/sq.jpg) **注意** 云技术允许你根据需要设置服务器并快速扩展系统——而且无需投资自己的硬件。然而，许多基于云的系统中所使用的虚拟化软件会稍微拖慢处理速度。

在过去，`IBM`、`Sun Microsystems`、戴尔、惠普等公司相互竞争，提供各种不同的硬件解决方案。现在情况已不再如此。如今，更重要的是运行在硬件上的软件，而非硬件本身。

有几件事情已经发生了变化。首先，设计和制造定制硬件的成本极其高昂，而且利润率很薄。其次，当今许多应用程序的横向扩展（而非纵向扩展）特性意味着，当客户需要更多处理能力或存储空间时，只需添加另一台服务器即可。此外，由于摩尔定律，更多的计算能力可以集成到越来越小的空间中。通过在每个处理器中集成多个核心（处理器），每个处理器的性能更强劲。每台服务器拥有更多内存，每个驱动器存储更多数据。

不过，毫无疑问的是，当今的大数据应用程序对内存和存储的消耗极大。在大多数情况下，无论你的服务器是本地部署还是基于云端，都应该尽可能多地加载内存。相对于内存而言，磁盘仍然相对较慢。因此，每当计算机必须访问磁盘来获取数据时，性能就会受到影响。能够缓存到内存中的数据越多，你的应用程序（以及你的数据处理）速度就越快。

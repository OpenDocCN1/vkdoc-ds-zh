# 大数据面临的挑战与解决方案

处理大数据时最常见的难题之一是数据格式问题。例如，不同厂商生产的网络和计算机系统生成的日志文件包含相似的信息，但格式却各不相同。比如，所有日志文件都可能包含有关发生了哪些错误、错误何时发生以及发生在哪个设备上的信息。

但每个厂商输出的错误信息格式都略有不同。标识设备名称的文字在一个日志文件中可能是`DeviceName`，而在另一个文件中则可能是`device_name`。时间的存储格式也可能不同；有些系统以协调世界时（UTC）存储时间，而另一些系统则以本地时间记录，例如太平洋标准时间（PST），前提是该时区是特定服务器或设备运行所在的时区。

像 Informatica 这样的公司历来都开发工具和服务来解决这个问题。然而，这类方法要求用户定义复杂的规则来将数据转换为一致的格式。最近，由加州大学伯克利分校计算机科学教授乔·赫勒斯坦创立的 Trifacta 等公司，正试图通过建模和机器学习软件来简化数据转换这一挑战。

## 查询数据

一旦数据处于可用状态，下一步就是查询数据，以便获取你需要的信息。对于存储在 Oracle、DB2、MySQL、PostgreSQL 以及其他结构化数据库中的结构化数据，你将使用 SQL。像`SELECT`这样的简单命令允许你从表中检索数据。当你需要组合多个表中的数据时，可以使用`JOIN`命令。当处理多个表和列时，SQL 查询可能会变得相当复杂，而经验丰富的数据库管理员通常可以优化查询，使其运行更高效。在数据密集型应用中，数据存储以及用于访问其中存储数据的查询，往往会成为系统最关键的部分。

虽然 SQL 查询有时执行速度较慢，但通常比大多数基于 Hadoop 的批处理大数据任务要快。Hadoop 及其 MapReduce 因其能够将海量大数据工作负载分布到众多商用服务器上，已成为大数据的代名词。但对于习惯使用 SQL 的数据分析师来说，问题在于 Hadoop 不支持 SQL 风格的查询，并且由于其面向批处理的特性，获取结果需要很长时间。

![Image](img/sq.jpg)

**注意** 虽然直到最近，传统的 SQL 数据库仍提供了最简便的数据查询方式，但 NoSQL 技术正在迅速追赶。例如，Apache Hive 为 Hadoop 提供了一个类似 SQL 的接口。

已有几种技术发展来解决这个问题。首先，Hive 本质上是适用于 Hadoop 的 SQL。如果你正在使用 Hadoop 并需要一个查询接口来访问数据，最初由 Facebook 开发的 Hive 可以提供该接口。虽然它和 SQL 不完全相同，但查询方法是相似的。

## 数据可视化

在开发完查询之后，你最终会希望以可视化的形式展示数据。仪表盘和数据可视化就是答案。一些数据分析和展示可以在像 Excel 这样的经典电子表格应用中完成。但对于交互式及更高级的可视化，值得看看来自 Tableau 和 Qliktech 等厂商的产品。他们的产品与查询语言、数据库以及结构化和非结构化数据源协同工作，将原始分析结果转化为有意义的洞察。

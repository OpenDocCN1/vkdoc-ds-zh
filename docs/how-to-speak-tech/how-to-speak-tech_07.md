# 4. 前端：呈现层

知道使用哪种语言很有帮助，但如果没有前端，用户什么都做不了。回想一下，前端是用户与后端交互的界面。它指的是你在特定网页上看到的内容以及你可以执行的一系列交互操作。你开始思考 `MyAppoly` 看起来会是什么样子，你想要哪些页面，以及它们之间如何连接（例如，页面 1 上的按钮 A 带你到页面 9）。然后，你最终确定了一组你想要包含在 `MyAppoly` 中的功能，并为每个网页开发线框图。

线框图是屏幕的简单蓝图。拼装线框图会迫使你思考信息设计和交互设计。*信息设计*涉及如何呈现你想要传达给用户的所有内容或消息。*交互设计*指的是你希望用户为完成某项整体任务而执行的一系列操作。例如，在像亚马逊这样的网站上，产品描述和评论的放置属于信息设计，而用户查看商品、将其添加到购物车并最终购买商品的流程则与交互设计有关。

在设计前端时，你还需要考虑用户界面和用户体验。*用户界面*，通常缩写为 `UI`，指的是应用程序的外观。一个好的 `UI` 能让应用程序直观易用，而一个糟糕的 `UI` 可能杂乱无章或让用户感到困惑。*用户体验*（`UX`）指的是用户对于使用你的应用程序的感受；你应该始终争取积极的用户体验，这通常来自于运行良好的后端、易于理解的 `UI` 以及经过深思熟虑的信息和交互设计。

你与 CTO 一起审查了 `MyAppoly` 的模拟图。实际上，你已经创建了一个网站纸质版。太棒了！那么，你如何让你的网站看起来像这样呢？你将如何创建大多数现代网页上都能看到的交互效果？某些语言和工具已经变得如此普遍，以至于值得学习它们的基础知识，因为它们共同构成了呈现层，并定义了你的用户将获得的体验。

## 前端技术

用于创建呈现层的标准前端工具包括 `HTML/XHTML`、`CSS`、`JavaScript` 和 `Ajax`。



### HTML

HTML 是一种标记语言，它定义了网页的内容和结构。如第 3 章所述，标记语言使用标签和特殊字符来赋予文档结构。标签分为两种类型：**容器标签**和**独立标签**。容器标签包裹你想要格式化或赋予上下文的文本。以`<h1>Read my book</h1>`为例。当浏览器将标记代码翻译为你所看到的网页时——这个过程称为*渲染*——它会识别起始的`<h1>`标签，并知道对其后的文本进行加粗和放大。因此，“Read my book”看起来会像一个标题。`</h1>`是结束标签，它告诉浏览器不再对任何文本加粗，并继续读取代码，直到遇到下一个标签。这类标签也可以嵌套，例如，如果你希望标题为斜体，可以写成`<h1><i>Italicized Heading</i></h1>`。容器标签通过开始和结束标签描述格式，而独立标签则是你放入代码中以产生某种效果的标签。例如，当浏览器在 HTML 中读取到`<br>`时，它知道在继续读取其余代码前，需要在网页中创建一个换行。

因此，标记语言使用标签的组合来定义文档的结构。样式表（将在 CSS 中讨论）为标签添加样式，使得渲染后的文档不会显得那么简陋。没有这种样式，网页看起来都会一样，使用相同的字体、字号和颜色。样式表告诉浏览器诸如“让所有`<h1>`标签使用不同的字体！”之类的信息。因此，标记文档和样式表共同构成了网页的基本要素。

有了这个介绍，让我们回到 HTML。在 20 世纪 80 年代，蒂姆·伯纳斯-李使用一种称为*标准通用标记语言*（SGML）的*元语言*创建了 HTML，这是用于在互联网上显示网页的主要标记语言。与其他标记语言一样，HTML 使用分层嵌套的标签来赋予构成网页的文本以结构。回想一下，元素可以嵌套，就像之前描述的斜体元素被包含在`<h1>`标签内一样。用户访问网页时，本质上是打开一个 HTML 文件，浏览器随后将其渲染为更易读的格式。

HTML 页面的结构通常由以下六个部分组成：

- *DOCTYPE*：随着时间的推移，HTML 和 XHTML（稍后讨论）的新版本不断被开发出来。因此，我们面临一个问题：网页是用多种可用标记语言的版本和类型之一编写的。当你访问最喜欢的网站时，浏览器如何知道该网页是由哪种标记语言创建的？如果它不知道，它可能会错误地解释某个标签，或者根本无法呈现页面。因此，DOCTYPE（文档类型定义/声明）告诉浏览器文件是用哪种标记语言编写的。
- *HTML*：`<html>`标签包含文档中除了 DOCTYPE 之外的所有标签或元素。它定义了浏览器应渲染的区域。
- *Head*：`<head>`元素包含浏览器用于读取文档其余部分的信息。除了文档的标题，`<head>`元素还包括其他脚本、元信息和样式表——这些都将稍后讨论。
- *Title*：这定义了网页的标题。除了向用户传递信息外，一个好的标题是*搜索引擎优化*（SEO）的关键之一，SEO 是提升你在搜索引擎结果中排名的过程（第 10 章）。
- *Meta*：元标签用于向浏览器传递信息，例如页面的关键词或页面内容的描述。这些标签对于 SEO 也很重要。
- *Body*：`<body>`元素包含要阅读的实际页面，包括所有文本、图像、链接等等。

还存在许多其他类型的标签，用于引入图形图像、表格、列表以及几乎你能想到的任何东西。标签可以具有属性，这些属性提供关于元素的更多描述，例如用于样式设置的信息。最新版本 HTML5 还支持动画、地理定位、触摸屏支持和内容处理等新特性。

以下两节将讨论你在讨论标记语言和网页设计时可能遇到的其他术语。

### XML 和 XHTML

XML 是一种标记元语言，这意味着它用于定义其他标记语言，因此在某些方面它与 SGML 类似。然而，它比 SGML 简单得多，而 HTML 正是从 SGML 技术发展而来的。XML 由两部分组成：文档和样式表。文档包含如前所述的标签或元素，而样式表则为各个元素提供样式。

为什么我们需要 XML？SGML 包含许多复杂且常常不必要的方面。因此，HTML 经常对错误很宽容，对规则也较为宽松，导致同一 HTML 文档在不同浏览器或设备上产生不同的渲染效果。如果每个浏览器对你的代码理解不同，那么作为开发人员，你将难以控制用户界面。XML 更为严格，并具有需要遵守的指南。因此，如果我们能够用 XML 重写 HTML，我们就能创建一种可能不会像 HTML 那样遇到许多问题的标记语言。这一想法启发了名为 XHTML 的标记语言。凭借更严格的编码指南，XHTML 页面可以在不同设备和浏览器上具有更好的可访问性，尽管 XHTML 并非*向后兼容*，这意味着旧版浏览器可能无法读取较新版本的标记语言。



### CSS

**层叠样式表**（CSS）是一种告诉浏览器如何对各类 HTML/XHTML 元素进行样式设置和定位的语言。CSS 语法简洁，包含一个选择器（告诉浏览器要对哪些 HTML 标签设置样式）和一个声明（告诉浏览器如何设置这些元素的样式）。

CSS 样式可以存在于三个位置。首先，它可以内联放置，例如 `<h1 style="color:blue">我的蓝色标题</h1>` 告诉浏览器将标题设为蓝色。其次，所有样式代码可以集中放在页面顶部的 `<head>` 标签内。浏览器足够智能，能够将样式代码与其对应的 HTML 标签匹配。最后，所有 CSS 可以放入一个外部样式表中，并在 HTML 页面中链接该样式表。你只需指定想要设置样式的 HTML 标签，浏览器即可处理其余部分。在这三种方式中，外部 CSS 文件因以下原因被视为最佳实践：

-   *可读性*：将结构与样式分离更好。
-   *速度*：加载速度更快。
-   *维护性*：假设你想更新整个网站的样式。如果 CSS 是内联的，你必须遍历所有 HTML 来更新所有样式；但如果所有样式都在一个外部文件中，你可以轻松进行更新。你甚至可以创建一个全新的文件，比如名为“`styleversion2`”，然后更改 HTML 文档中的链接。根据你的心情，你可以将链接从 `styleversion1.css` 改为 `styleversion2.css`，整个网站的风格就会改变。这种强大的能力类似于*抽象*（第 3 章）。

第 3 章讨论的*继承*在 CSS 中同样存在，即*父*元素的样式会传递给*子*元素。换句话说，一个包含在另一个元素中的元素会继承其所在容器的样式。我们将这种继承概念称为*层叠*，这就是 CSS 中字母 C 的由来。

CSS 包含以下八种通用样式类别，并附有示例：

-   *类型*：字体、颜色
-   *背景*：颜色、图像
-   *块*：字间距、行间距
-   *盒*：宽度、高度、浮动
-   *边框*：样式、颜色
-   *列表*：样式、位置
-   *定位*：位置、高度、可见性
-   *扩展*：分页、光标

CSS 中的定位基于盒模型，即每个元素都可被描述为位于一个嵌套区域中，从中心的*内容*向外延伸，经过*内边距*，再到*边框*和*外边距*。从某种程度上说，用 CSS 设计网页无非就是在屏幕上排列盒子。

### JavaScript

利用 HTML 和 CSS，你可以创建内容排版精美的漂亮网站，但它们缺乏交互性。下拉菜单、鼠标悬停时出现的信息框等等，都可以归功于 JavaScript——一种基于对象的脚本语言（还记得第 3 章的定义吗？）。它存在于 HTML 文档中，并由你的浏览器（试图访问网站的*客户端*）解释执行；因此我们说 JavaScript 需要*客户端*处理。这就是为什么 JavaScript 与我们讨论过的其他脚本语言不同，它被认为是前端而非后端。它不由服务器执行。

JavaScript 最初由网景公司推出，如今在网络上无处不在，并将使 MyAppoly 具有交互性和动效。假设你想让用户在点击 MyAppoly 标志后显示一个信息弹出窗口。如何实现呢？包含该标志的 HTML 元素将包含对一段称为*事件处理程序*的 JavaScript 代码的引用。事件处理程序“等待”某些“事件”——即用户完成的操作——此时计算机开始执行相应的 JavaScript 指令。在这种情况下，当标志被点击时，JavaScript 事件处理程序将创建一个弹出窗口并将其添加到用户的显示屏上。因此，事件、事件处理程序和函数在很大程度上定义了如何使用 JavaScript 为网页增添交互性。

与 CSS 一样，JavaScript 可以直接放置在 HTML 文档的 `<head>` 元素中，也可以放在一个外部的 `.js` 文件中，并在 HTML 文档中建立链接。

#### 文档对象模型与动态 HTML

如果你希望在用户点击 MyAppoly 标志并弹出窗口的同时，改变背景颜色，该怎么办？这稍微复杂一些，因为 JavaScript 不仅要创建弹出窗口，还要更改定义页面背景颜色的 HTML/CSS 代码。这种静态 HTML 与 JavaScript 的*动态 HTML*（DHTML）组合是通过*文档对象模型*（DOM）实现的。*万维网联盟*（W3C）将 DOM 定义为“一种平台与语言无关的接口，它允许程序和脚本动态访问和更新文档的内容、结构和样式”。DOM 本质上是将 HTML 页面上的所有元素定义为对象，根据元素的嵌套关系将它们放置在一个树状结构中，以便你轻松引用它们，并使页面上的每个元素都具有交互性。从理论上讲，你可以通过从树顶追溯到该元素的路径来引用文档中的任何元素。一旦定位到该元素，你就可以操作它来达到期望的效果。DOM 为页面上的每个元素增添了交互性。

### Ajax

Ajax 与 DHTML 类似，也是一种技术的融合。创建于 2005 年的*异步 JavaScript 与 XML*——简称 *Ajax*——结合了 CSS、HTML、DOM、XML 和 `XMLHttpRequest`，允许网页在后台执行功能。让我们来分解一下。想象一下，MyAppoly 有一个供个人填写的表单，需要用户输入他们所在的州。大多数现代网站会在一个动态下拉菜单中为你建议几个选项，因此当你输入“M”时，以 M 开头的州列表会自动出现在搜索框下方。当你输入“A”时，马萨诸塞州就会出现供你选择。如果没有 Ajax，另一种方式是这样的：每次你输入一个新字母，页面都会完全刷新，以便获取一份新的、可能有效的候选州列表。你每输入一个字母，页面就会获取该字母并用它在数据库中进行搜索。在找到所有满足该字母的州之后，页面会刷新以显示更新后的信息。假设页面刷新需要 0.5 秒，用户就会对你的网站感到不耐烦和厌烦——这是一种糟糕的用户体验。

那么 Ajax 是做什么的呢？Ajax 并没有用新内容刷新页面，而是将用户请求的数据从服务器传输到客户端。Ajax 使用 XML 来格式化这些数据，然后使用 XHTML、CSS、DOM 和 JavaScript 来获取数据并仅更新网页中受影响的部分。关键点是所有这些操作都是异步完成的，这意味着用户并不知道它在后台进行。实际上，当 Ajax 在后台从服务器获取最新信息时，用户可以继续与网页进行交互。Ajax 很复杂，通常难以使用，但许多工具包让 Ajax 的使用变得简单得多。

Ajax 仅在现代浏览器中有效，因此这项技术也同样缺乏向后兼容性。



## 可移植性与可访问性

浏览器的渲染并无强制标准，因此所有浏览器对 HTML 和 CSS 的呈现方式都略有差异。在 `Safari` 上显示正常的页面，在 `Internet Explorer` 上可能看起来很怪异。在 PC 版浏览器上看上去不错的内容，在 Mac 上可能就不合适。由于技术不断变化，今天能在某个版本 `Chrome` 上运行的功能，可能无法在旧版本上运行。这一切都意味着，作为开发者，你无法以完全相同的方式触达所有受众。你的最佳选择要么是确保你的网站在所有潜在设备的每一个屏幕上都能美观呈现——但这并不现实——要么是寄希望于网络标准或某种其他解决方案的出现。

### 网络标准

想象一下，如果每家汽车公司都要求使用一种独特的汽油。那么加油站几乎不可能储备客户可能需要的每一种汽油。汽车制造商从一开始就认识到，让他们的车辆只使用少数几种行业标准的汽油等级运行是最优解决方案。

目前，互联网就像一个没有汽油标准的世界。针对可访问性和可移植性问题，一个更好的解决方案是建立针对编码和渲染的网络标准。`W3C` 是一个“由成员组织、全职员工和公众共同协作开发网络标准的国际社区”。它制定和推广的不是严格的规则，而是建议性的指南。许多人注意到，近来业界正逐渐趋向于采用这些建议，这对开发者和用户都极为有利。

存在多种验证工具可以确保你的网页符合 `W3C` 的指南。进行验证大有益处，因为它有助于确保你的网页能被最广泛地访问，通常能改善显示时间，并可能有助于搜索引擎优化（详见第 10 章）。

### 响应式设计

如果你能识别人们访问你网站时正在使用哪种设备，会怎样？如果这成为可能，你就可以向他们展示为他们的设备特别调整过的网站版本。这种技术被称为*响应式设计*。由于可以识别用户来自何处以及他们正在使用何种设备，你可以选择显示特定的 `CSS` 样式表，或者使用不同版本的代码，为用户提供更优化的体验。然而，正如你可以想象的，覆盖所有浏览器和设备的组合是十分困难的。

## 结论

你现在已经理解了在概念上将 `MyAppoly` 的纸质版本转化为可工作的前端需要什么。此时，你可以告诉你的首席技术官，你理解了用户如何访问网站、如何与你的功能交互，以及哪种编程语言处理用户的操作。但是，你的后端如何记住并组织信息，比如用户的姓名或他们的好友列表？要回答这个问题，你需要了解数据库，这是下一章的主题。

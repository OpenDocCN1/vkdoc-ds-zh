# 12. 安全

特别感谢 Ashi Agrawal 贡献本章内容。

2017 年 7 月下旬，信用报告巨头 Equifax 披露，一群不明身份的黑客入侵了超过 1.45 亿客户的个人信息——包括驾驶证号码和社会安全号码。^((13)) 此次攻击是日益增多的公开泄露和黑客攻击浪潮中的最新一起，此前 Target、Ashley Madison 和花旗银行等机构已遭受过此类攻击。

尽管 Equifax 的数据泄露因其数据的敏感性而尤为令人震惊，但此类攻击可能发生在*任何*公司。黑客——即寻找网络安全漏洞的人——可能出于各种原因将组织机构的数字资产作为攻击目标，甚至为了实施个人报复或博取名声。有些人想将数据卖给出价最高者，而另一些人则享受其中的刺激和挑战。并非所有黑客都怀有恶意；道德黑客（也称为白帽黑客）会寻找这些漏洞，以便公司修复。即便如此，数字世界依然充斥着恶意的攻击。

无论你的应用是做什么的，一次攻击都可能导致你丢失宝贵的计算能力和数据，或导致业务中断。即使数据泄露不会导致消费者身份被盗用，它仍然可能暴露敏感数据，并导致消费者的信任消失殆尽。除了实施安全防范措施的业务原因外，组织在道德和法律上也有义务保持安全。网络安全对你和你的公司而言应至关重要，本章将讨论如何保护你和你的用户的安全。



## 什么是网络安全？

网络安全是信息安全（保护电子与物理数据的实践）的一个分支。^(¹⁴) 正如《*牛津英语词典*》所定义的那样，网络安全侧重于保护电子数据，但这一定义具有局限性，因为它忽略了保护不属于数据范畴的计算机资源。^(¹⁵) 该领域还涉及非数据驱动的数字攻击：比如破坏电网的黑客行为。此类攻击并不危及数据，但却利用数字工具造成严重破坏。因此，本文定义网络安全为：研究并实践保护电子资源（如数据和计算能力）免受未经授权方侵害的学科。本章将使用“安全”一词来替代“网络安全”，以反映该领域专业人士的实际用语习惯。

某些网络安全技术源于密码学，即研究在存在恶意第三方的情况下进行安全通信的学科。作为一门学科，密码学历经数个世纪的发展，从简单的技术——如颠倒消息中的字母顺序或使用儿童语言游戏“猪拉丁语”——演变为基于数学的复杂系统。这些系统对于后续我们将深入探讨的某些网络安全技术至关重要。

互联网兴起之后，密码学和安全在数字空间中迅速被证明不可或缺。公认的第一个计算机病毒是 1988 年的莫里斯蠕虫。^(¹⁶) 该程序利用各种网络协议中的漏洞迅速传播并嵌入到机器中。尽管莫里斯最初旨在无害地测量互联网的规模，但它最终因消耗并压垮计算机的处理能力而摧毁了数千台计算机。由此引发的计算机故障造成了数十万美元的损失。自那以后，攻击手段变得愈发复杂，并且随着互联网上用户和设备数量空前增长，潜在影响规模也急剧膨胀。

## CIA 三元组

CIA 三元组为理解攻击态势提供了一个框架。这一经典的信息安全模型概述了三个主要的安全关注点：机密性、完整性和可用性。想象以下情景：爱丽丝希望将一则信息传递给鲍勃，并保护它免受对手查理的侵害^(¹⁷)。让我们思考爱丽丝和鲍勃可以对其交易感到安全的三种方式。

- **机密性**：由于消息属于秘密，我们希望它保持秘密。它仅对爱丽丝和鲍勃可见，对像查理这样的任何第三方都不可见。
- **完整性**：消息的内容很重要，因此我们希望确保查理无法篡改或破坏该消息。当鲍勃收到消息时，他可以相信这与爱丽丝发送的是同一条消息。
- **可用性**：消息具有时效性，爱丽丝希望确保鲍勃能够收到并阅读它。查理不能阻止鲍勃访问该消息。

以下各节将使用这一机密性、完整性和可用性模型讨论常见的攻击及缓解措施。这种结构既有助于对过去的攻击进行分类以了解系统中的漏洞，也有助于未雨绸缪，将最佳安全实践融入您的应用程序。请记住，此列表并非详尽无遗，也并非所有攻击都能如此清晰地归类。然而，此讨论是利用 CIA 三元组在应用程序背景下思考安全性的一个有益示例。

### 机密性

每个人都有秘密，无论是令人尴尬的绰号还是个人的感情史。和人一样，所有应用程序都有它们希望保密的秘密。应用程序最明显的秘密是密码和用户数据。当一条数据（例如社会安全号码或出生日期）可用于识别个人身份时，它被称为个人身份信息（PII）。保护 PII 及其他用户信息免受窥探是应用程序的职责。简而言之，机密性就是保守秘密——这一点我们在年少时都体会到了其难度。

攻击者破坏机密性的一种方式是通过社会工程攻击，这类攻击利用基于人类心理学的技术来操纵用户泄露机密信息。最普遍的社会工程攻击类型是网络钓鱼，即通过在线伪装成可信实体来诱骗敏感信息或诱使用户下载恶意软件的做法。本节重点介绍三种类型的网络钓鱼：广撒网式钓鱼、鱼叉式钓鱼和克隆式钓鱼。

广撒网式钓鱼攻击通过利用大规模电子邮件方案，将目标锁定在广大用户群体上。攻击者冒充某种权威机构（例如美国国税局），向大量用户发送相同、看似有效的电子邮件。然而，该电子邮件包含一个恶意链接，会将用户引至一个看起来像官方网站或与实际网站（例如美国国税局官方网站）完全相同的页面，但实际并非如此。用户陷入陷阱，在该网站上输入个人详细信息（例如其社会安全号码），从而使攻击者能够进行身份欺诈。一些钓鱼电子邮件还（或另外）将破坏性病毒伪装成看似无害的附件。下载并打开此文件的用户无意中导致病毒运行，从而让攻击者可以访问他们的计算机。最著名的广撒网式钓鱼攻击是“尼日利亚王子”骗局，攻击者伪装成需要帮助转移财富的王子。攻击者的电子邮件要求收件人向一个银行账户汇出一笔看似微不足道的费用，并承诺如果他们提供帮助将获得更大的财富。当然，根本没有王子，受害者也无法追回他们汇往该银行账户的资金。虽然这种攻击并不总是涉及敏感信息的交换，但攻击者使用的策略与许多其他广撒网式钓鱼攻击相同。

另一方面，鱼叉式钓鱼攻击则针对特定受害者。攻击者冒充受害者认识或信任的人，并向其发送一封包含个性化信息的电子邮件，例如提及受害者的姓名或职务。一种常见的鱼叉式钓鱼策略是向特定服务提供商的用户发送电子邮件——这里我们以 Gmail 为例。攻击者使用一个看似官方 Gmail 账户的账号，通过电子邮件告诉用户他们的账户已被黑。然后，该邮件将用户重定向到一个收集其凭证的虚假页面。由于用户认为自己是在与 Gmail 交互，他们愿意输入密码。2016 年初，针对克林顿竞选团队高级官员约翰·波德斯塔的电子邮件泄露事件正是基于这种攻击手法。^(¹⁸)

克隆式钓鱼则将这种个性化更进一步，并利用用户之前的电子邮件来对付他们。攻击者以用户之前收到的一封合法电子邮件为模板，发送一封几乎一模一样的邮件给受害者，只是替换了一个新的恶意链接或附件。由于这些邮件与用户实际收到过的电子邮件非常相似，因此更难区分其是钓鱼邮件还是合法邮件。



#### 电子邮件提供商的反钓鱼策略

电子邮件提供商不断将新的反钓鱼策略整合到其服务中。自然语言处理、机器学习和其它模式匹配技术已被成功用于查找钓鱼邮件并将其标记为垃圾邮件。虽然我们目前讨论的钓鱼攻击需要一定程度的技术知识，但许多攻击者会使用非技术途径。其中一个例子是语音钓鱼（也称为`vishing`），这是一种通过电话进行的钓鱼形式。在一种极为成功的攻击手法中，攻击者冒充国税局（IRS）工作人员通过电话威胁收件人，声称除非他们在所谓的官方 IRS 网站上进行付款，否则将被逮捕。当然，这笔钱最终落入了攻击者手中，而非 IRS。

要保护自己免受钓鱼攻击，你必须保持警惕。不要打开来自未知发件人的电子邮件或带有可疑主题行的电子邮件；虽然垃圾邮件过滤器已经取得了很大进步，但它们并非完美无缺。此外，良好的做法是避免在电话或电子邮件中透露个人信息。如果必须向他人提供此类信息，请完全确认你正在与真正的权威人士进行通信。

在本节中，我们探讨了攻击者如何通过社会工程和钓鱼攻击来获取访问用户数据的权限。其他常见的机密性攻击包括数据包嗅探（`packet sniffing`）、端口扫描（`port scanning`）和键盘记录（`keylogging`）。在考虑保护你的机密性时，请考虑锁定访问你信息的入口点（最直接的方式是在不使用时锁定你的电脑或手机），包括锁定你自己。接下来，我们将研究针对消息完整性的攻击。

### 完整性

在小学游戏“电话”中，一条消息通过耳语在人与人之间传递。正如你可能想象的那样，随着人们传播他们自己的误解（然后这些误解又被进一步误解），消息很快会变得面目全非。虽然这不是故意的，但这个游戏经常损害原始消息的完整性。这里的完整性指的是消息的可信度：消息接收者可以相信他们收到的消息未经篡改，并且来自他们所期望的发送者。由于冒充另一个安全用户存在难度，完整性攻击通常在技术上较为复杂。本节我们将讨论三种类型的攻击：中间人攻击、注入攻击和伪造攻击。

#### 中间人攻击

中间人攻击（即`man-in-the-middle`）发生在攻击者拦截了发送者和接收者之间的消息时。一个例子是重放攻击（`replay attack`），攻击者查理（Charlie）窃听爱丽丝（Alice）和鲍勃（Bob）之间的通信以窃取秘密（例如密码）。然后，在后续的交易中，查理可以利用这个秘密来冒充爱丽丝。在那次交易中，鲍勃认为消息来自爱丽丝，但消息的完整性已不复存在，因为它实际上是来自查理的不同消息。重放攻击展示了攻击如何可能同时属于多个 CIA 类别；虽然重放攻击针对的是消息的完整性，但查理知道爱丽丝的秘密也使其成为一种机密性攻击。

#### 注入攻击

注入攻击涉及攻击者通过提供恶意输入，经由应用程序运行破坏性代码。例如，考虑一个使用用户输入来执行 SQL 数据库查询的 Web 应用程序。攻击者可能能够输入有害代码，导致应用程序运行一个破坏性查询。这个查询可能会摧毁整个数据库。注入攻击非常普遍且破坏性极大，以至于在开放 Web 应用程序安全项目（OWASP）2017 年十大最关键的 Web 应用程序安全风险列表中，该类别被列在首位。^(¹⁹)

跨站脚本攻击（`XSS`）是另一种类型的注入攻击。在`XSS`中，攻击者在网站上插入代码以捕获敏感信息，通常是`cookie`。请记住，`cookie`是一种基于字符串的令牌，网站用其保存用户特定的设置和认证信息。想象一下，你的网站渲染了用户提交的 HTML 格式评论的最后一条结果。该评论可能包含一个带有 JavaScript 脚本的`<script>`标签，该脚本会窃取访问该页面的任何用户的`cookie`。当新用户加载页面时，这个脚本会自动运行，攻击者随后便能够利用这些窃取到的`cookie`冒充受害者，进行身份盗窃。

#### 伪造攻击

伪造攻击包括攻击者冒充用户的攻击。虽然中间人攻击中也存在冒充行为，但那些攻击针对的是两方之间正在进行的交换，而伪造攻击则侧重于单向通信渠道。例如，跨站请求伪造（`CSRF`）利用了用户到网站的单向通信。`CSRF`利用了`cookie`在你离开网站后仍然保持活跃、允许网站在你返回时识别你的这一事实。假设你最近访问了你最喜欢的购物网站；即使你已经离开该网站，它仍保留着一个`cookie`。攻击者可能诱使你点击钓鱼邮件中的链接，或通过`XSS`运行一个脚本，该脚本向购物网站发送一个恶意请求（例如删除你的账户）。由于`cookie`尚未过期，网站可能允许此请求执行。防止此类攻击的一种标准方法是发放一个隐藏的、会话特定的令牌（称为`CSRF token`），该令牌仅允许当用户（而非其他任何人）当前正在该网站上时才允许请求执行。

#### 总结与防御

作为要点，永远不要信任用户，尤其是他们的输入。你应该通过要求输入符合特定模式（例如，银行会检查请求的存款和取款金额是否为合法的非负十进制数）来验证他们的输入。通过验证输入，你可以降低黑客向应用程序注入代码或以其他方式造成有害结果的风险。对于许多完整性攻击，深入了解你所用的特定技术栈（即你的应用程序所使用的编程语言和框架）对于理解攻击者可能注入代码的漏洞至关重要。

本节讨论了可能是技术上最复杂的安全攻击——完整性攻击。我们研究了中间人攻击、注入攻击和伪造攻击，这些攻击试图注入攻击者的代码并造成破坏性后果。其他完整性攻击包括数据篡改（`data diddling`）和切片攻击（`salami attack`）。为了保护自己，我们学会了严格验证用户的输入，并确保我们所做的任何假设都是真实的。我们的最后一节将讨论针对数据可用性的攻击。



### 可用性

每个举步维艰的小公司都梦想着他们的应用程序能有朝一日大受欢迎，流量暴增 100 倍。恭喜——这一幕正在你身上发生！不幸的是，你的服务器并没有为应对如此巨大的流量做好准备。它们崩溃了，你的网站随之瘫痪。2013 年，[healthcare.​gov](http://healthcare.gov) 就曾发生过这种灾难性的情况：在数百万美国人试图注册《平价医疗法案》的巨大压力下，该网站不堪重负。幸运的是，一群工程师拯救了这个网站，并成功为数百万美国人办理了医疗保险，但其底层基础设施引发的全国性沮丧与痛苦早已蔓延开来。当应用程序无法处理此类流量时，就称为**拒绝服务**。在这种情况下，由于资源无法被访问，就称资源的可用性受到了损害。

有些攻击者会故意造成拒绝服务，他们向你的应用程序发送伪造请求，直到其崩溃，导致合法用户无法访问。这种攻击被称为拒绝服务攻击。虽然应对合法的拒绝服务的唯一方法是扩展你的应用程序所能处理的流量规模，但你可以通过拦截破坏性请求来预防或反击拒绝服务攻击。一个成功的反拒绝服务（DoS）计划包含两个主要部分。首先是定义一组预期的流量模式，其次是移除不符合这些模式的流量。

一个直接的方法是追踪发起攻击者请求的服务器，并阻断来自这些服务器的所有流量。然而，在拒绝服务攻击最常见的形式——分布式拒绝服务攻击中，这变得困难重重。在分布式拒绝服务（DDoS）攻击中，恶意请求来自许多不同的服务器，使得创建能成功过滤掉它们的模式变得更加棘手。诸如 Cloudflare 之类的服务会使用诸如机器学习之类的高级模式创建技术，来保护你的应用程序免受阻止服务（DoS）和分布式拒绝服务（DDoS）攻击。

攻击者还会利用勒索软件来针对数据的可用性。勒索软件是一种拒绝用户访问其数据的软件，有时仅仅是通过锁定他们的电脑（这很烦人，但对安全专家来说相对容易处理）。然而，更常见的情况是，勒索软件会提取并加密用户的数据，然后攻击者索要赎金，以换取返还解密后的数据。正如我们将在下一节中了解到的，没有解密密钥，几乎不可能破解设计良好的加密，因此受害用户往往不得不支付赎金来恢复数据。

对于包含代码或连接互联网的硬件设备来说，可用性攻击尤其危险。震网病毒是一种计算机蠕虫，它通过针对运行特定软件的机器，迫使相应的离心机超速旋转直至报废，从而摧毁了数十万台离心机（实验室设备）。像震网这样的攻击属于控制系统安全范畴，该领域主要关注工业系统。虽然损坏的离心机可以更换，但对控制系统的攻击可能会摧毁诸如液压系统或水坝等大型系统，造成深远的后果。

本节探讨的攻击不会访问或篡改数据，而是阻止预期的接收者查看和使用数据。其他的可用性攻击包括物理电源攻击和会话劫持攻击。验证我们收到的请求并过滤掉任何可疑的请求，对于阻止可用性攻击至关重要。

虽然 CIA 三元组是发现漏洞和集思广益，揣测黑客可能想如何窃取你信息的有用框架，但它无法穷尽所有攻击方式。因此，通过参加诸如黑帽大会或 Defcon 等会议、阅读论文，并持续了解你所使用服务的技术能力与缺陷来掌握最佳安全实践的最新动态，至关重要。美国国家标准与技术研究院（NIST）和欧盟网络与信息安全局（ENISA）也是获取网络安全防护信息的优质资源。

#### 预防措施

幸运的是，有一些预防措施可以帮助你保护你的应用程序。虽然这些被广泛接受的安全实践大有裨益，但它们并不全面，本节内容更多是作为概述。你应该设立一个专门的安全团队来加强你的安全实践并处理攻击事件。



#### 加密技术

加密是我们最强的防御手段之一，它通过将信息从"明文"转换为"密文"，使得第三方无法从密文中推导出明文。加密的本质只是改变数据的呈现方式，这意味着所有数据类型（包括音频和图像）都可以被加密。一种简单但安全性不高的明文加密方法是反转字符顺序。例如，我们可以将明文"the quick brown fox jumps over the lazy dog"转换为密文"god yzal eht revo spmuj xof nworb kciuq eht。"这看起来像一串乱码，但敏锐的观察者可能会注意到两处"eht"，将其与常见单词"the"联系起来，从而同时推断出加密算法和秘密信息。

这个例子说明了简单加密方案的不安全性。由于数学和语言学模型可以破解较简单的加密协议，你应该使用经过严格测试的知名加密协议和系统。虽然更复杂的加密方法理论上可能被破解，但破解所需的大量资源和时间使其在实际上无法被攻破。

许多加密系统和协议的基础是公钥密码学，它使用两个辅助信息：**公钥**和**私钥**。私钥必须由其所有者保密，而公钥则可供任何人访问。如果爱丽丝想使用公钥密码学（也称为非对称加密）向鲍勃发送加密的明文消息，她将消息和鲍勃的公钥输入加密算法，该算法会生成密文。收到密文后，鲍勃将密文和他自己的私钥输入解密算法来解密消息。以既安全又高效的方式创建公钥和私钥是困难的。密钥生成密码系统（其中最著名的是 RSA）通常利用数学方法生成充当密钥的大数字。

`TLS`（传输层安全协议）是用于保护互联网通信安全的加密协议，它基于公钥密码学。它包含两个部分：第一部分对通信双方（客户端和服务器）进行身份验证，并创建一个安全通道用于交换消息；第二部分为从客户端到服务器或服务器到客户端的数据提供安全保障。`TLS`在互联网上被广泛用于保护网站、API 等。

加密对于确保数据安全至关重要。所有数据，包括客户数据和公司数据，都应进行加密，仅在必要时才解密。数据的生命周期包含三个阶段：**使用中的数据**（从永久存储中提取的数据）、**静态数据**（存储在持久化存储器中的数据）和**传输中的数据**（在两个系统之间流转的数据）。我们使用加密来保护静态和传输中的数据——例如，`TLS`可以保护传输中的数据。

在通信和消息传递领域，一些产品已经实现了数据在整个生命周期中的加密保护，这一特性被称为**端到端加密**。让我们以爱丽丝和鲍勃的场景来思考。如果爱丽丝发送给鲍勃的消息是端到端加密的，那么原始消息只有爱丽丝和鲍勃两人可见。即使爱丽丝使用第三方客户端发送消息，应用程序在加密完成后也会立即丢弃明文。

我们主要在点对点通信（如电子邮件和即时通讯服务）的背景下讨论端到端加密。端到端加密在电子邮件中的使用率相对较低，主要有两个原因。第一个问题是我们依赖电子邮件提供商过滤垃圾邮件，这意味着提供商必须能够读取邮件内容。第二个原因是电子邮件提供商的碎片化以及缺乏端到端加密的行业标准。例如，从 Gmail 账户向 Yahoo 账户发送加密邮件，需要两个提供商就同一加密方案达成一致，或者用户自行协商加密方案并交换公钥，这很麻烦。不过，端到端加密正在即时通讯领域逐渐普及。为了保持真正的安全性，你应该使用 Signal 消息应用，它既支持端到端加密，又是开源的（这意味着任何人，包括安全专家，都可以通过阅读其源代码来验证其安全性）。该平台非常安全，以至于其他（闭源的）消息应用如 Facebook Messenger 和 WhatsApp 也使用 Signal 协议来实现其端到端加密。

#### 密码保护

在个人层面，最重要的防范措施是使用强密码。创建安全密码有许多最佳实践：使用特殊字符和数字、增加密码长度、使用密码短语、绝不重复使用密码等。虽然这些最佳实践确实容易被忽视，但遵循它们至关重要：2016 年 Verizon 数据泄露报告发现，63%的数据泄露是由于密码薄弱或被盗所致。^(²⁰)

密码管理器`LastPass`在 2017 年发布的《密码曝光》报告显示，平均每个`LastPass`企业用户拥有 191 个密码，数量之多远超任何人的记忆能力。^(²¹)像`LastPass`和`1Password`这样的密码管理器将所有密码存储在一个受主密码保护的"保险库"中，极大地简化了密码的组织和使用。密码管理器还具备自动填充功能，可在网站上填写你的凭证，以及密码生成功能，可自动为你创建强密码。这样一来，你唯一需要记住的密码就是一个主密码。其理念是，记住一个复杂的密码比记住多个密码（无论它们多么好记）要容易得多。因此，你所有的密码都能变得更难猜测，从而更强。

虽然密码管理器并非对黑客免疫，但其数据存储在一个由多层加密保护的保险库中。即使黑客窃取了密码管理器的保险库，他们也无法访问你的数据，因为这些数据受到加密保护，并且你的主密码作为钥匙将其锁定。要解密保险库，他们需要你的主密码（由于哈希处理，主密码并不存储在任何地方）。只要你的主密码选择得当，黑客就无法猜出它。简而言之——虽然切换到密码管理器可能看起来令人不安，但大多数安全研究人员都认为，这是创建、存储和使用密码最安全的方式。

一旦用户创建了密码，确保密码永不泄露至关重要。如上所述，我们使用哈希处理来保护密码。与加密类似，哈希将数据转换为另一种形式，这里称为**哈希值**。与加密后的密文不同，哈希值是不可逆的。哈希处理在验证信息方面效果很好，因为对同一个明文的相同副本（例如，用户首次选择密码时和在网站上输入密码时）运行相同的哈希函数会产生相同的结果。然而，我们并不存储明文，因此也无法从哈希副本中还原出明文。



#### 身份验证方式

身份验证要素是用户必须持有的、用以证明其声称身份的物品。身份验证要素共有三类：知识要素（“你知道的东西”）、持有要素（“你拥有的东西”）和固有要素（“你本身的特征”）。

知识要素是最常见的身份验证方式。例如，密码是用户必须*知道*的一条信息。另一个知识要素的例子是安全问题（“你母亲的娘家姓是什么？你的第一辆车是什么品牌和型号？”）。正如任何看过电影《盗梦空间》的人所知，知识要素相对容易被破解，原因有三：(a) 它们通常很简单；(b) 它们的信息可能是固定的，意味着从不改变；(c) 它们遵循常见的格式。由于人类必须记住自己的密码，他们往往倾向于以个人信息为基础（如生日或宠物名），而这些信息很容易被猜到。安全问题可能会暴露一些通过侦察就能发现的信息，即使攻击者找不到你第一辆车的品牌和型号，需要他们尝试的可能的答案也相当有限。尽管知识要素目前是最普遍的身份验证形式，但它们无法提供日益必要的安全性。

因此，许多系统正转向使用双因素认证，这要求在基于知识的身份验证之上再加一层验证。第二层通常是持有要素，它根据用户拥有的某个物品来验证其身份。想想你用来开家门和车门的钥匙。对于许多网络应用程序而言，持有要素就是用户的手机。应用程序通过短信或移动应用程序（如 `Authy` 或 `Duo`）向手机提供一次性密码。由于短信与你的手机号码绑定，所以更容易被黑客攻击。攻击者会使用网络钓鱼攻击，冒充手机丢失致电移动服务提供商。服务提供商会允许他们将号码切换到新手机，从而让他们能够窃取 OTP。最安全的持有要素被认为是专门为此目的而构建的独立硬件令牌，例如 `Yubikey`。`Yubikey` 是一种小型设备，可直接插入用户的电脑，并在不使用互联网的情况下生成 OTP。

有时，额外的一层会改用固有要素。固有要素是一种生物识别测量方式，利用用户的物理属性。iPhone 上允许用户使用指纹登录的 Touch ID 就是一种固有要素，视网膜扫描和人脸识别也是如此。虽然固有要素使用起来很方便（扫描指纹可能比输入 OTP 更方便），但它们不如其他身份验证方案流行，因为被破解的生物特征信息无法替换。例如，如果黑客成功窃取了你的指纹数据，你无法合理地更改你的指纹，而密码则很容易更改。在大多数使用场景中，这种风险通过将生物特征数据本地加密存储（例如，直接在你的手机上）来缓解。由于数据不在不同地点之间传输，攻击面（攻击者可以瞄准应用程序的不同位置的数量）更小，这意味着攻击者入侵应用程序的方式更少。因此，固有要素通常只对与设备绑定、且无需将生物特征信息存储在云端的应用程序有意义。

多因素认证可以保护你免受那些窃取了你凭证的攻击者的侵害，例如来自重放攻击的威胁。如果黑客试图用你的密码登录，由于他们没有第二层身份验证，将无法登录。请记住，如果你怀疑有人窃取了你的凭证，仍应轮换你的凭证。对于个人使用而言，最安全的做法是在所有支持 MFA 的应用程序上启用多因素认证，从你的银行账户到你的社交媒体账户。然而，要求你的用户使用 MFA 可能并非正确的决定。虽然 MFA 提供了额外的安全性，但并非所有消费者都优先考虑安全，他们可能会认为 MFA 很麻烦。无论如何，支持 MFA 总是一个好主意，即使你不强制要求。

#### 网络安全

网络安全指的是保护访问和传输信息的网络的安全，这既包括用户端的网络，也包括企业环境中的网络。本节概述了你可以作为个人用户使用的工具，以及为你互联网网络上的所有人（无论是与家人共享的家庭网络，还是与公司共享的企业网络）可用的工具。

从个人角度来看，你在浏览互联网时能采取的最简单的保护措施是使用 HTTPS。HTTPS 代表超文本传输安全协议，它使用 TLS 来安全地传输流量。在浏览网页时，请确保在 URL 开头使用 HTTPS 协议，而不是 HTTP，因为 HTTP 不包含 HTTPS 所提供的加密。在某些浏览器（如 Firefox 和一些版本的 Chrome）中，你还可以通过在 URL 栏中查找绿色挂锁图标来验证你是否在使用 HTTPS 进行浏览。浏览器也可能会自然地阻止连接到使用过时或不安全 TLS 设置的网站。

除了使用 HTTPS，还要确保在网络中保持谨慎。只从可信来源下载软件，并留意那些可能包含恶意软件的带广告的流媒体网站。对抗此类广告的一个简单方法是安装广告拦截器，例如 `uBlock`。由于攻击者经常创建声称链接到某个域（例如“`google.com`”）但实际将你引导至不同危险网站的超级链接，一个良好的做法是将 URL 输入到浏览器中，而不是点击链接，以防止我们之前概述的网络钓鱼攻击。

为了进一步保护你的网络流量，你可以使用虚拟专用网络，通常是通过使用第三方 VPN 服务。VPN 通过加密隧道将网络请求（最常见的是网站导航）发送到远程服务器，然后由该服务器将请求发送到公共网络。在通过公共网络（如在咖啡店）浏览时，这非常有用，因为你的流量是加密的，并且看起来像是来自 VPN 服务拥有的不同 IP 地址。即使公共网络不安全，你的数据仍然是安全的，因为 VPN 隧道对其进行了加密。

许多工作场所，尤其是那些有远程员工的工作场所，会使用 VPN，以便使用不同本地网络（例如，他们的家庭 Wi-Fi 网络）的员工看起来处于同一个专用网络上。这样，VPN 上的计算机可以识别哪些其他计算机在同一 VPN 上，因此是可信的。本质上，VPN 可以作为一个单一的认证点，就像在办公场所刷门禁卡一样。

你可以采取的最后一项保护任何网络安全的预防措施是使用防火墙或代理。防火墙会阻止来自用户指定站点的流量到达你的 IP 地址，反之亦然，以保护你免受恶意站点和攻击者的侵害。代理充当用户和外部网络之间的中介，可以执行多种功能，例如阻止恶意站点以及向任何窥探者或潜在攻击者隐藏你的 IP 地址。

## 在你的应用程序中实施安全实践

考虑到所有这些攻击、工具和预防措施，下一步就是运用这些知识，将其用于在你的团队开发流程中构建安全性。我们将概述三个步骤，指导你思考与应用程序相关的安全性：(a) 保护你的应用程序，(b) 保持安全，以及 (c) 最小化损害。



### 保护应用程序安全

考虑如何保护应用程序安全可能会让人感到不知所措。幸运的是，有许多开源库和包已经为你实现了相关协议和最佳实践。使用库至关重要，因为安全措施很难实现——而实现不当的安全方案会使你的应用程序极易受到攻击。流行的开源库往往拥有健壮的实现，因为任何人都可以审查代码并指出漏洞。请寻找那些维护良好、开发者能及时响应问题的库。

我们讨论过的许多攻击和缓解措施都归结于同一个教训：永远不要信任用户。特别是，一些完整性攻击（如 SQL 注入）依赖于恶意行为者提供输入，导致应用程序执行有害操作。如前所述，验证用户输入是防御此类攻击的一个环节。

另一个环节是访问控制，即建立权限机制，使每个用户只能访问他们所需的内容。考虑一个银行为每个用户提供主页`mybank.com/username/home`。通过猜测用户名，攻击者可以找到其他用户的主页并访问敏感信息，这明显违反了保密性原则。取而代之的是，银行可以在加载内容前，检查登录用户的用户名是否与他们试图访问的页面所关联的用户名匹配。正确的访问控制意味着，应用程序在用户查看内容（例如其银行主页）或执行操作（例如从账户取款）之前，会确保该用户拥有相应的权限。

### 维持安全状态

既然你已经构建了应用程序的安全初始版本，你可能会希望将所有精力都集中在产品营销上。不幸的是，俗话说“好人不得安生”——恶意行为者不会停止攻击你的资源。即使你没有积极开发新功能，也必须采取预防措施，确保应用程序保持安全——两项关键措施是测试和安装更新。

安全测试建立在开发应用程序时进行的测试之上。例行测试不一定能捕获所有错误。发现安全漏洞异常重要，因为它们可能导致严重后果，而逻辑错误或渲染错误充其量只会导致用户体验不佳。为了捕获这些高风险错误，开发者会使用渗透测试，这是一种模拟对应用程序进行安全攻击的模型。渗透测试通常采用模糊测试，即随机生成应用程序输入，并确认输出既有效又符合预期。模糊测试有助于模拟其他测试可能无法发现的边缘情况。许多公司还聘请白帽黑客来寻找系统中的缺陷，以便在恶意行为者发现并利用这些缺陷之前进行修复。

你的应用程序中的错误并非唯一需要担忧的问题。你的工作不可避免地会依赖于他人构建的平台、框架和库。有时，这些第三方中的一方会发现一个安全漏洞，并发布更新来修复它，这也称为补丁。及时安装更新至关重要；在安装补丁之前，你的应用程序仍容易受到该补丁本应修复的安全漏洞的攻击。以 Equifax 数据泄露事件为例，黑客利用了 Equifax 忽视更新、已存在数月之久的旧版第三方库漏洞。^(²²) 这些漏洞甚至存在于最成熟的库中——Heartbleed 漏洞，它曾为有史以来最具破坏性的攻击之一开辟道路，就存在于广泛用于执行 TLS 协议的 OpenSSL 库中。正如我们所讨论的，TLS 是计算机之间通信的一个环节。利用 Heartbleed 协议的黑客可以操纵请求，诱骗计算机发送超出其访问权限的信息；有时，这些数据包括用户名和密码等个人信息。在此案例中，黑客的关键发现是意识到接收信息的计算机并未验证它们所请求的信息量。这个例子再次说明了验证用户输入的必要性。

### 最小化损害

即使你遵循了上述所有最佳实践，黑客仍可能攻破你的系统。新的攻击方法层出不穷，因此应用程序永远无法达到 100%的安全。遭受攻击后，你必须努力保护资源并尽快恢复。第一步是检查系统日志。日志是对某个操作、事务或事件的报告。计算机日志很有用，因为它们可以持续监控系统，并且你可以选择在日志中记录哪些内容。例如，你可以记录用户登录的时间，或你的应用程序进行 API 调用的时间。大多数这些日志应该是无害的，而且理应如此，因为你的站点上的大部分活动应该是合法的。然而，当出现可疑活动时，日志可以更容易地发现恶意行为或欺诈。以信用卡公司注意到某个用户的凭证在世界各地出现为例。这可能是一位环球旅行者——也可能是身份被盗用。无论哪种情况，日志都能提供对情况的洞察以及如何最好地推进。你可能需要修复一个错误或构筑更多预防措施，比如将违规网站加入黑名单。

在遭受可用性攻击并失去对数据的访问权限后，你需要尽快恢复服务。因此，最佳实践是在不同的物理位置维护数据的加密备份。即使你意外丢失了数据（比如将手机掉进水里），备份也能确保你在一定程度上安全地恢复数据，而不是丢失一切。将备份存储在不同位置可以保护数据免受物理攻击。

备份数据至关重要，尤其是在提供敏感服务时。让我们来看看 WannaCry 勒索软件事件，该软件攻击了英国国家医疗服务体系（NHS）的 60 多个组织。^(²³) 尽管 NHS 存在宽松的安全实践，使得 WannaCry 得以入侵其系统，但其备份系统使大多数组织能够从攻击中恢复过来，没有数据丢失，也无需支付要求的赎金。对于服务危重病人的医疗系统来说，快速恢复的能力至关重要。由于拥有强大的企业备份系统，WannaCry 与其他勒索软件相比在财务上远不成功，因为受影响的业务只是丢失了它们数据的一份副本。



## 结论

在本章中，我们探讨了网络安全领域一些广为人知的攻击手段及防御措施。我们将**CIA 三元组**确立为思考安全的模型，并审视了攻击者可能突破你防护屏障的方式。此外，我们讨论了诸如加密、多因素认证和防火墙等可能的保护措施。最后，我们将安全概述为一个过程，从初始阶段构建安全开始，到最终最小化攻击造成的损害结束。不幸的是，你的应用程序是不法分子的目标，保护你和你的公司免受其害是你的责任。祝你在构建防御时好运！

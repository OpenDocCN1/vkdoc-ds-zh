# 1. 互联网

世界上大多数人都通过一个名为互联网的全球网络相互连接。它的前身是美国国防部资助的高级研究计划局网络（`ARPANET`），旨在让大学和研究实验室的计算机能够共享信息。`ARPANET` 于 1969 年首次部署，1975 年全面投入运行。`ARPANET` 针对计算机之间共享信息所固有的困难提出的解决方案，构成了全球互联网的骨干。

`ARPANET` 是如何做到的呢？请考虑以下类比。地方城镇通常由公路紧密连接。主要公路连接城镇，而更大的高速公路则连接各州。要融入更大的国家公路网络，一个城镇只需修建一条连接该镇与高速公路的道路即可。这条道路会将城镇居民与全国其他地区连接起来。类似地，`ARPANET` 利用通信线路、卫星和无线电传输进行通信，通过 `WAN` *骨干网*（相当于中央高速公路）将所有*局域网*（`LANs`，相当于城镇道路）和*广域网*（`WANs`，相当于州际系统）连接在一起。

从概念上讲，我们看到互联网是一个网络的网络——但这些网络是如何连接的呢？要创建一个原始的本地区域网络，可以用电线、电话系统或光纤电缆（使用光而非电）将几台计算机连接在一起。要将多个本地网络连接起来，可以使用一种称为*路由器*的“连接”计算机，它可以扩展子网络的规模。如果我们将这些本地子网络中的每一个都连接到一条中心电缆上，那么所有本地网络便连接起来了，从而构成了互联网。

既然互联网本质上是计算机集群的物理连接，那么它究竟是如何作为一个运行顺畅的单通信线路网络来运作的呢？这个问题的答案正是互联网真正技术创新的所在。

## 分组交换、TCP 与 IP

请记住，研究人员开始研究网络的整个原因是他们需要一种在计算机之间共享信息的方法。就像高速公路有出口标志和限速一样，也需要有规则来指导互联网上的信息流。为了解决这个问题，美国高级研究计划局（`ARPA`）通过两种软件定义了信息的传输方式：传输控制协议（`TCP`）和互联网协议（`IP`）。互联网软件层的这两个组件运行在硬件层之上，硬件层即构成互联网物理实体的电缆和设备。

历史上，当两台计算机用电缆连接时，通信是单向且独占的。如果计算机 A 向计算机 B 发送了某些内容，数据就沿着电线传输；如果此时有任何其他通信尝试，数据就会发生冲突，谁都无法获得他们想要的信息。要创建一个允许数百万人同时、即时互动的网络，当时的技术将需要数量惊人的电缆。减少布线需求的唯一方法，是开发一种让数据能在同一通信线路上从多个源头发送到多个目的地的技术。

这是通过*分组交换*实现的。研究人员发现，他们可以将任何信息（例如文本、音乐或图像文件）分解成小的“数据包”；这样做可以使单根电线同时承载来自多个文件的信息。存在两个明显的挑战：所有数据包如何到达正确的目的地，以及接收方如何将它们重新组合起来？

退一步讲，互联网上的每一个页面都是某人编写的文档，它存放在某处的一台计算机上。当你用浏览器访问一个网页时，你本质上是在请求查看某台计算机上的某个文档的权限。为了让你能查看它，这个文档必须发送给你——而 `TCP`/`IP` 正好有助于完成这项工作。

`TCP` 将文档分解成小的数据包，并为每个数据包分配一些标签。首先，`TCP` 为数据包编号，以便它们能够按正确的顺序重新组装。其次，它为每个数据包提供一个称为*校验和*的东西，用于判定到达的数据是否遭到任何篡改。最后，数据包会被赋予其目的地和源地址，以便能够正确路由。`谷歌地图`在这里帮不上忙，但 `IP` 可以。`IP` 为互联网上的每台设备定义一个唯一的地址。

因此，这些数据包都带有你计算机的 `IP` 地址。`IP` 帮助将这些数据包路由到它们的目的地，其过程很像美国邮政服务投递邮件的方法。数据包从其起点被路由到下一个最靠近目的地的路由器。在每一步，它们都会被分类并推送到下一个最近的路由器。这个过程一直持续到它们到达目的地。通过这种方式，`IP` 软件使得一组相互连接的网络和路由器能够像一个单一的网络一样运行。

`IP` 的一个宝贵特性是网络冗余所带来的稳定性。如果整个网络的某个特定部分发生故障，数据包可以被重新定向到另一个路由器。当数据包到达你这里时，`TCP` 会验证所有数据包是否都已到达，然后再将它们重新组装以供查看。

实际上，几家计算机公司早就针对计算机间通信问题开发了各自的解决方案，但他们要求人们付费使用，而且这些方案互不兼容。如果买了 A 公司的解决方案却不能连接买了 B 公司方案的人，那又何必买呢？`ARPANET` 的与众不同之处在于，`ARPA` 免费公布了其成果，使得 `TCP`/`IP` 可以公开访问。当美国军方分支于 1982 年采用 `TCP`/`IP` 时，`ARPA` 这种开放且免费的方式得到了合法化和制度化。从此以后，计算机只有安装了 `TCP`/`IP` 软件，才能通过互联网发送或接收信息。

因此，从 1982 年开始，研究人员可以在全球范围内共享信息，但如何显示和查看这些数据的问题依然存在。1990 年，蒂姆·伯纳斯-李和欧洲核子研究组织（`CERN`）的其他人开发了超文本标记语言（`HTML`）和超文本传输协议（`HTTP`）的前身，两者共同促成了格式化且具有视觉吸引力的信息的在线交换。1991 年之后，第一批图形化浏览器——允许你在互联网上查看网页的程序——发布了。这为在网络上共享和消费信息创造了一种有吸引力且高效的方式。

大约在同一时期，个人电脑成本下降，诸如 `AOL` 之类的在线服务提供商出现，提供了廉价的互联网接入。这些因素的共同作用，使得互联网迅速发展成为我们今天使用的网络。

## HTTP 与互联网的使用

数据在物理层面如何传输是相当直接的，并且由 `ARPA` 开发的协议所定义——但是，你首先如何告诉别人发送数据呢？当有人——比如说你——访问你的心血结晶 `MyAppoly` 时，幕后究竟发生了什么？

## MyAppoly

如果你跳过了序言，那么需要知道的是，本书以松散叙事的方式展开，主角是*你*。故事的前提是你正在构建一个名为 MyAppoly 的 Web 应用程序。这个名字只是一个统称；我鼓励你将自己感兴趣的任何场景想象成 MyAppoly。如果你是一位杀手级应用的企业家或天使投资人，MyAppoly 将成为你实现 10 亿美元退出策略的门票。如果你是非营利组织的高管，MyAppoly 将帮助你筹集资金并连接志愿者。如果你在《财富》500 强公司工作，MyAppoly 将帮助你的公司保持竞争力，并领先于不断变化的消费者期望。

你打开浏览器访问 MyAppoly 网站上的某张图片。此时，你的计算机成为了*客户端*，负责请求信息。你访问的实体网页通常是用一种叫做 HTML 的语言编码的文档，它们存储在名为*服务器*的计算机上。你的应用程序的所有文件，包括图片和视频，都存放在服务器上。这些文件被称为*资源*。由于*客户端*（用户）在访问*服务器*，因此可以说互联网遵循*客户端-服务器架构*。

接着，你在浏览器中键入网址——*统一资源定位符*（URL），即 [`www.MyAppoly.com`](http://www.myappoly.com)。从技术上讲，你也可以直接键入 MyAppoly 服务器特定的 IP 地址，但谁能记住每个网站对应的 IP 地址呢？*域名系统*（DNS）将像 [`MyAppoly.com`](http://myappoly.com) 这样对人类友好的域名转换为计算机友好的 IP 地址。

你访问 [`MyAppoly.com`](http://myappoly.com) 并点击一个链接来查看网站上的图片库。请记住，所有这些图片也都存放在服务器上。假设它们都在一个名为“Pictures”的文件夹中。如果你点击第一张图片，你将被定向到 `http://www.MyAppoly.com/Pictures/pic1.jpg`。该 URL 的组成部分表明，我们正在使用 HTTP 协议，指定了正确的服务器（通过域名），并指出了文件在服务器上的位置（用技术术语来说，就是文件的*层级位置*）。换句话说，URL 就是一个资源的文本地址。

那么，你究竟是如何收到这些网页的呢？首先，客户端（你的浏览器）访问 DNS 以获取对应 MyAppoly 的 IP 地址，这样它就知道服务器在哪里。你的浏览器不会物理移动到 MyAppoly 服务器去获取图片，因此它必须通过互联网发送一条消息，告诉服务器发送文件。HTTP 请求正是完成这一工作的。HTTP 是一组用于在互联网上交换资源（文本、图像、音频等）的规则。

你的请求可以是多种不同的方法之一，最常见的是 `GET` 或 `POST`。`GET` 方法告知服务器，客户端想要从服务器获取文件。收到 `GET` 请求后，服务器会检索相应的文件并将其发送回你的浏览器。另一种请求类型是 `POST`，当你向服务器发送数据时，浏览器会使用此方法。在某些情况下，这两种方法都可以处理请求，但它们在数据实际通过互联网发送的方式上有所不同。使用 `GET` 方法时，你发送给服务器的信息会被添加到 URL 中。例如，如果你在 MyAppoly 上搜索“mediterranean”这个词，`GET` 请求会将你重定向到 URL `www.MyAppoly.com/search?q=mediterranean`。如果搜索词通过 `POST` 发送，则搜索词会包含在 HTTP 消息中，并在 URL 中不可见。通常认为，仅在需要更改服务器端某些内容时使用 `POST` 请求是一种良好实践。

于是，客户端发出了一个请求，该请求找到了 MyAppoly 服务器，并告知它执行 `GET` 操作以获取包含“pic1”文件的页面。服务器获取该资源，并通过 TCP/IP 将其作为*响应*发送回来。浏览器可以利用头部信息来显示（即*渲染*）该资源。然而，这个过程并不一定就此结束，因为客户端可能还需要发送更多请求。由于服务器一次只能向浏览器发送一个资源，因此可能需要多个请求来检索构建一个网页所需的所有资源。如果你想查看包含 pic1 图片的页面，你实际上是在请求两个资源：包含文本内容和页面布局的 HTML 页面，以及 pic1 图像。因此，浏览器至少需要发送两个请求。

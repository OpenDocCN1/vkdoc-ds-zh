# 典型应用

在本节中，你将了解一些典型应用的若干跟踪指标，以便快速概览。表 2-10 列出了一些典型应用，其中仅提供了块大小、读写百分比以及随机/顺序百分比的粗略值。主导因素 `IOPS` 或 `MBPS`（吞吐量）实际上表明了工作负载是以随机请求为主还是以顺序请求为主。

**表 2-10** 典型应用 IO 工作负载概况

| 应用 | 大小（字节） | 读/写 | 随机/顺序 | 主导因素 |
| --- | --- | --- | --- | --- |
| Web 文件服务器 | 4KB, 8KB, 64KB | 95%/5% | 75%/25% | IOPS |
| 数据库在线事务处理 (OLTP) | 8KB | 70%/30% | 100%/0% | IOPS |
| Exchange 邮件 | 4KB | 67%/33% | 100%/0% | IOPS |
| 操作系统驱动器 | 8KB | 70%/30% | 100%/0% | IOPS |
| 决策支持系统 (DSS) | 1MB | 100%/0% | 100%/0% | IOPS |
| 文件服务器 | 8KB | 90%/10% | 75%/25% | IOPS |
| 视频点播 | 512KB | 100%/0% | 100%/0% | IOPS |
| Web 服务器日志记录 | 8KB | 0%/100% | 0%/100% | MBPS |
| SQL 服务器日志记录 | 64KB | 0%/100% | 0%/100% | MBPS |
| 操作系统分页 | 64KB | 90%/10% | 0%/100% | MBPS |
| 媒体流 | 64KB | 98%/2% | 0%/100% | MBPS |

IO 工作负载特性通常与应用本身相关。许多访问模式，例如读写比例和处理写入的方式，因具体应用而异。然而，大多数特性仅随环境（运行条件）而变化。与环境相关的特性包括空闲间隔长度、请求到达率、工作负载随机性与顺序性、读写性能、磁盘服务时间和请求响应时间、请求大小等。更重要的是，存在一些在整个 IO 工作负载中跨应用和环境保持一致的特性。这里特别指出的是工作负载的突发性（即长程依赖性）。特别是块级工作负载，请求到达间隔时间和请求寻道距离，通常是长程依赖的。作为时间序列中时间局部性的一种度量，长程依赖性会产生多种后果，尤其是在预测整个系统和特定资源饱和度方面。因此，在设计新的存储系统以及 IO 路径各层的资源管理策略时，必须考虑突发性。因此，由于各种应用之间存在巨大差异，不存在适用于所有工作负载的通用良好配置 [42]。

对于文件系统性能，保持文件系统块大小接近工作负载的 I/O 大小可以显著提高系统效率 [43]。

Web 流量正在快速增长。一些研究人员认为，在过去 10 年中，Web 服务器工作负载特性并未发生显著变化 [44]。这些特性包括一次性引用行为、重尾文件大小分布、非泊松聚合请求流、高度集中的引用、每个文档的泊松请求流以及远程请求的主导地位。

数据库通常具有显著的跨事务局部性，这表明实际工作负载中的事务通常是相互依赖的。另一个观察结果是，大量使用顺序访问使得可以应用预取策略。顺序性是长时间运行查询（例如连接操作）检查大量记录的结果。

OLTP（在线事务处理）工作负载的特点是内存占用大，关键工作集小，并且从微架构优化中获益较少。此外，OLTP 工作负载中的索引搜索需要不同的缓存设计。

让我们进一步详细研究两个工作负载。^(³⁵) 表 2-11 显示了这两个跟踪的指标值。你可以看到它们的属性差异很大。有时，在简单的合成跟踪生成器中仅使用两三个主要指标，尽管应用的实际跟踪要复杂得多。

**表 2-11** 两种典型工作负载的基本指标

| 跟踪 | 持续时间（秒） | 流量（GB） | 总请求数（*×*10⁶） | 平均读/写大小（KB） | 读/写流量比 | 随机读（*×*10⁶） | 随机写（*×*10⁶） |
| --- | --- | --- | --- | --- | --- | --- | --- |
| OLTP | 43712 | 18.491 | 5.335 | 3.466 | 0.1820 | 0.955 | 2.99 |
| 搜索引擎 | 3151.3 | 16.369 | 1.055 | 15.509 | 8762.9 | 0.994 | 2.08e-4 |

## 文件和对象级别的跟踪

另外两种类型的跟踪通常与块级跟踪共享许多共同属性。然而，在某些场景下，它们具有独特的特征。表 2-12 给出了一些文件级跟踪的指标，这些指标与块级跟踪的指标不同。

**表 2-12** 文件级跟踪的一些指标

| 指标 | 说明 |
| --- | --- |
| **文件类型** | 文件系统以多种方式之一被使用：作为持久数据的长期存储，作为存放因过大而无法放入主内存的数据的仓库，作为可执行文件的存储位置，以及用于存储系统使用日志以进行记账和监控。元数据与用户数据的比率是一个重要指标。 |
| **文件年龄** | 年龄定义为自上次引用以来的时间。 |
| **文件访问持续时间** | 从打开到关闭的时间。 |
| **用户行为模型** | 用户生成构成工作负载的引用。 |
| **进程和状态模型** | 包含多个方面，例如进程在其生命周期内如何发出文件服务请求；访问依赖的条件激活表；以及不同操作（如 `open`、`close`、`write`、`read`、`seek` 等）的比率。它可以被建模为一个封闭的马尔可夫链。 |
| **引用模型** | 请求如何在系统中的文件之间分布。 |

如前所述，基于不同的抽象级别，需要考虑的指标可能不同。例如，在系统级别，我们通常考虑表 2-13 中列出的属性，其中大部分属性可能存在于文件或对象级别。

**表 2-13** 系统级别的工作负载

| 系统视图中的工作负载 | 负载到达模式 | 数据访问模式 | 计算模式 |
| --- | --- | --- | --- |
| MapReduce | 作业序列的到达时间 | HDFS 输入和输出路径，输入、混洗和输出存储的数据大小 | 输入数据大小、混洗数据大小、输出数据大小、作业持续时间、映射任务时间、归约任务时间 |
| 企业网络存储 | 应用实例或用户会话的到达时间序列 | 读/写、顺序/随机、单次/重复访问、文件大小、文件类型 | 不适用 |

在本章中，我介绍了一些用于存储系统性能评估和设计的跟踪指标。给出了一些典型应用，以便对这些指标有一个快速印象。事实上，由于某些应用之间存在巨大差异，通常不存在通用的系统设计。我将在后续章节中讨论更多细节。

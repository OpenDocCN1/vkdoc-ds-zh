### 数据科学技术栈

数据科学技术栈覆盖了快速信息工厂生态系统中的数据处理需求。在本书中，我将把该技术栈作为指导模式进行讨论。

在本章中，我将帮助你认识数据科学工具的基础知识及其对现代数据湖开发的影响。你将发现将数据仓库转换为数据仓库总线矩阵的技术。我将解释如何使用 `Spark`、`Mesos`、`Akka`、`Cassandra` 和 `Kafka` 来驯服你的数据科学需求。

我将指导你使用 `Elasticsearch` 和 `MQTT`（MQ Telemetry Transport）来增强你的数据科学解决方案。我将帮助你认识 `R` 作为一种创造性可视化解决方案的影响力。我还将介绍诸如 `R`、`Python` 和 `Scala` 等编程语言对数据科学生态系统的影响和作用。

### 快速信息工厂生态系统

快速信息工厂生态系统是我用于个人处理开发的一套技术惯例。本书的处理路线将基于此制定，但你并非必须专门使用它。我在本章讨论的工具对你来说是免费可用的。这些工具可以以任何适合你特定生态系统的配置或排列组合方式使用。

我建议你开始构建自己的生态系统，或者直接采用我的。作为前提条件，你必须习惯于一套你熟悉并能熟练部署的工具。

> **注意**  
> 请记住：你的数据湖将拥有其自身的属性和特性，因此请调整你的工具以适应这些特定特征。

## 数据科学存储工具

这个数据科学生态系统包含一系列用于构建解决方案的工具。该环境的能力正在快速发展，新的进展每天都在发生。

我将解释我日常工作中用于执行实用数据科学的工具。接下来，我将讨论以下基本数据方法论。

### 写时模式与读时模式

数据处理工具支持两种基本方法论。以下是每种方法论及其优缺点的简要概述。

#### 写时模式生态系统

传统的关系型数据库管理系统（RDBMS）要求在加载数据之前定义模式。为了从我的结构化数据模式中检索数据，你可能多年来一直在运行标准的 SQL 查询。

其优势包括：

*   在传统数据生态系统中，工具假定存在模式，并且只有在模式被描述后才能工作，因此对数据只有一种视图。
*   该方法在阐明数据点之间的关系方面极具价值，因为关系已经预先配置好。
*   这是存储“密集”数据的一种高效方式。
*   所有数据都位于同一个数据存储中。

另一方面，写时模式并非所有数据科学问题的答案。该方法的缺点包括：

*   其模式通常是为特定目的构建的，这使得它们难以更改和维护。
*   它通常会丢失作为未来分析源的原始/原子数据。
*   在处理数据之前，需要大量的建模/实现工作。
*   如果某种特定类型的数据无法存储在模式中，则无法有效地从模式中处理该数据。

目前，写时模式是一种广泛采用的数据存储方法论。

#### 读时模式生态系统

这种替代性的数据存储方法不要求在加载数据之前定义模式。从根本上说，你以最小结构存储数据。基本的模式在查询阶段应用。

其优势包括：

*   提供了存储非结构化、半结构化和杂乱数据的灵活性。
*   在从结构中查询数据时允许无限的灵活性。
*   底层数据保持完整且未经转换，以供将来参考和使用。
*   该方法鼓励实验和探索。
*   它提高了生成新鲜可行知识的速度。
*   它缩短了从数据生成到可行知识可用的周期时间。

读时模式方法论将在第 6 章中进一步阐述。

我建议采用读时模式与写时模式生态系统的混合方案，以实现高效的数据科学和工程。在讨论功能层在数据科学处理中的用途时，我将详细解释为什么这个特定生态系统是最佳解决方案。

### 数据湖

数据湖是一个存储海量原始数据的存储库。它以原生格式存储数据，以备未来需求之需。你将通过本书了解为什么这对于实用的数据科学和工程解决方案至关重要。写时模式数据仓库将数据存储在预定义的数据库、表和记录结构中，而数据湖则使用限制较少的基于读时模式的架构来存储数据。数据湖中的每个数据元素都被分配一个独特的标识符，并用一组全面的元数据标签进行标记。

数据湖通常使用分布式数据对象存储来部署，以实现读时模式结构。这意味着业务分析和数据挖掘工具无需复杂的模式即可访问数据。使用读时模式方法，你可以按原样加载数据并立即开始从中获取价值。

我将在第 6 至 11 章中讨论并提供更多关于使用读时模式存储方法原因的具体细节。

对于云上的部署，使用亚马逊简单存储服务（Amazon S3）存储数据湖的基础数据是一种经济高效的解决方案。我将展示使用云技术来配置你的数据科学工作的可行性。不过，完成本书示例并不需要访问云，因为它们可以很容易地使用笔记本电脑进行处理。

### 数据仓库

由 Dan Linstedt 设计的数据仓库建模是一种数据库建模方法，其结构旨在控制来自多个运营系统的数据的长期历史存储。数据仓库处理过程将读时模式数据湖转换为写时模式数据仓库。数据仓库被设计成读时模式查询请求，然后针对数据湖执行。

我还看到结果以写时模式格式存储，以便为将来的查询持久化结果。这两种方法的技术将在第 9 章中讨论。此时，我希望你只理解构建数据仓库所需的基本结构。

该结构由三种基本数据结构构建而成：集线器、链接和卫星。让我们检查一下具体的数据结构，以阐明它们为何是必需的。

### 集线器

集线器包含一个独特的业务键列表，这些键具有较低的变化倾向。它们包含每个集线器项目的代理键以及业务键来源的元数据分类。

集线器是你的数据仓库的核心主干，在第 9 章中，我将更详细地讨论为何以及如何使用此结构。

### 链接

业务键之间的关联或交易使用链接表进行建模。这些表本质上是多对多的连接表，带有特定的额外元数据。

链接是集线器之间的单一关系，以确保业务关系被准确记录，从而为真实的业务完成数据模型。在第 9 章中，我将解释为何以及如何需要特定的关系。



### 卫星表

中心点（Hubs）和链接（Links）构成了模型的结构，但不存储数据的时序特征或描述性特征。这些特征存储在被称为卫星表（Satellites）的专用表中。

卫星表是存储业务特征综合信息层次的结构，通常是完整数据仓库数据结构中体量最大的部分。在第[9]章(#A435693_1_En_9_Chapter.html)中，我将解释这些结构为何以及如何出色地模拟现实世界的业务特征。

中心点、链接和卫星表的恰当组合，能够帮助数据科学家构建并存储必备的业务关系。这是数据建模人员一项非常抢手的技能。

这种写时模式（Schema-on-Write）数据结构的转换将在第[9]章(#A435693_1_En_9_Chapter.html)详细讨论，以阐明为何特定结构能够支持该处理方法。我将在那一章解释为何需要特定的中心点、链接和卫星表。

### 数据仓库总线矩阵

企业总线矩阵（Enterprise Bus Matrix）是由 Ralph Kimball 创建的数据仓库规划工具和模型，在过去 40 多年里被全球众多人士使用。总线矩阵和架构建立在通过事实表相互关联的一致性维度这一概念之上。

数据仓库是将数据转化为可操作知识所需解决方案的主要组成部分。这种写时模式方法支持基于可操作知识的商业智能。在第[10]章(#A435693_1_En_10_Chapter.html)中，我将提供关于此数据工具的更多细节，并给出其使用指导。

## 数据处理科学工具

既然我已经介绍了数据存储，下一步就是介绍用于将数据湖转化为数据仓库，再转化为数据仓库的处理工具。这些工具是数据科学和工程生态系统的主力军。以下是我使用的数据工具的推荐基础。

### Spark

Apache Spark 是一个开源的集群计算框架。它最初在加州大学伯克利分校的 AMP 实验室开发，Spark 代码库随后被捐赠给 Apache 软件基金会，该基金会现将其作为一个开源项目进行维护。这个工具正在以惊人的速度发展。

IBM 投入超过 3500 名开发人员和研究人员从事与 Spark 相关的项目，并在旧金山成立了一个专门的 Spark 技术中心，以追求基于 Spark 的创新。

SAP、Tableau 和 Talend 现在将 Spark 作为其核心软件栈的一部分进行支持。Cloudera、Hortonworks 和 MapR 的发行版都将 Spark 作为原生接口支持。

Spark 提供了一个用于编程分布式集群的接口，具有隐式数据并行性和容错能力。Spark 正逐渐成为众多企业级处理应用的事实标准。

在我的技术工具包中，我发现使用该工具的以下模块。

### Spark Core

Spark Core 是整个开发工作的基础。它提供分布式任务调度、任务分派和基本 I/O 功能。

这使您能够将复杂且综合的运行环境卸载给 Spark Core。这保证了您提交的任务能够按预期完成。Spark 生态系统的分布式特性使您能够在小型 Spark 集群上，然后在拥有数千个节点的集群上，使用相同的处理请求，而无需更改任何代码。在第[10]章(#A435693_1_En_10_Chapter.html)中，我将讨论如何实现这一点。

### Spark SQL

Spark SQL 是 Spark Core 之上的一个组件，它提供了一种称为数据帧（Data Frames）的数据抽象。Spark SQL 提供了一种领域特定语言（DSL）来操作数据帧。Spark 的这一特性使得从传统的 SQL 环境轻松过渡到 Spark 环境成为可能。当您希望让遗留应用程序将其数据从传统的纯关系型数据存储卸载到数据湖生态系统时，我认识到了它的优势。

### Spark Streaming

Spark Streaming 利用 Spark Core 的快速调度能力来执行流式分析。Spark Streaming 内置支持从 Kafka、Flume、Twitter、ZeroMQ、Kinesis 和 TCP/IP 套接字消费数据。流处理是从数据源导入数据到数据湖的主要技术。

流处理正成为从多个数据源加载数据的领先技术。我发现许多数据源都有可用的连接器。目前有强大的驱动力来构建更多连接器的改进，这将在未来进一步改善这个生态系统。

在第[7]章(#A435693_1_En_7_Chapter.html)和第[11]章(#A435693_1_En_11_Chapter.html)中，我将讨论使用流处理技术通过各处理层移动数据的使用。

### MLlib 机器学习库

Spark MLlib 是一个分布式机器学习框架，通过基于分布式内存的 Spark 架构在 Spark Core 之上使用。

在 Spark 2.0 中，引入了一个新的库 `spark.mk`，用于用基于 DataFrame 的模型取代基于 RDD 的数据处理。计划到 Spark 3.0 发布时，将只存在基于 DataFrame 的模型。

常见的机器学习和统计算法已被实现并随 MLlib 提供，这简化了大规模机器学习流水线，包括：

*   降维技术，例如奇异值分解（SVD）和主成分分析（PCA）。
*   摘要统计、相关性分析、分层抽样、假设检验和随机数据生成。
*   协同过滤技术，包括交替最小二乘法（ALS）。
*   分类与回归：支持向量机、逻辑回归、线性回归、决策树和朴素贝叶斯分类。
*   聚类分析方法，包括 k-均值聚类和潜在狄利克雷分配（LDA）。
*   优化算法，例如随机梯度下降法和有限内存 BFGS（L-BFGS）。
*   特征提取与变换函数。

在第[10]章(#A435693_1_En_10_Chapter.html)中，我将讨论如何运用机器学习能力来支持跨各层的自动化处理。

### GraphX

GraphX 是 Apache Spark 分析引擎的一个强大的图处理应用程序编程接口（API），能够从大型数据集中挖掘见解。GraphX 为运行大规模并行和机器学习算法提供了卓越的速度和能力。

图处理能力的引入使得数据条目之间的关系处理变得轻而易举。在第[9]章(#A435693_1_En_9_Chapter.html)和第[10]章(#A435693_1_En_10_Chapter.html)中，我将讨论使用图数据库来支持跨各层的处理交互。

### Mesos

Apache Mesos 是一个开源的集群管理器，由加州大学伯克利分校开发。它在分布式应用程序之间提供高效的资源隔离和共享。该软件以细粒度的方式实现资源共享，提高了集群利用率。

Mesos 的企业版是 Mesosphere Enterprise DC/OS。它弹性地运行容器，并且数据服务支持 Kafka、Cassandra、Spark 和 Akka。

在微服务架构中，我的目标是构建一个能够跨各层生成细粒度处理单元和轻量级协议的服务。在第[6]章(#A435693_1_En_6_Chapter.html)中，我将讨论如何使用细粒度微服务技术来支持通过该框架的数据处理。



### Akka

该工具包与运行时方法能够缩短大规模数据密集型应用的处理开发周期。`Akka` 是一个基于 Actor 的消息驱动运行时，用于运行并发、弹性及可恢复性进程。通过使用 Actor、流和 Future 等高阶抽象，有助于构建数据科学与工程中的细粒度处理单元。

使用 Actor 使数据科学家能够通过一种简单的处理模型生成一系列并发进程，该模型为每个 Actor 采用消息传递技术和特定的预定义操作/行为。通过这种方式，Actor 可以被控制并限制为仅执行预期的任务。在第 7 章至第 11 章中，我将讨论如何使用不同的细粒度进程来支持整个框架中的数据处理。

### Cassandra

`Apache Cassandra` 是一个大规模分布式数据库，支持多数据中心复制，以实现高可用性、持久性和性能。

我主要使用 `DataStax Enterprise (DSE)`，它通过提供全面且运维简单的数据管理层（其独特的始终在线架构内置于 [Apache Cassandra](http://www.planetcassandra.org/%23_blank)），极大地提升了我以史诗级规模交付实时价值的能力。标准的 `Apache Cassandra` 开源版本同样运行良好，只是缺少一些其标准版未提供的额外管理功能。在此需指出，对于图数据库，作为 `GraphX` 的替代方案，我目前也正在使用 `DataStax Enterprise Graph`。在第 7 章至第 11 章中，我将讨论如何使用这些大规模分布式数据库模型，通过数据科学结构来处理数据。

### Kafka

这是一个高吞吐量的消息传输骨干网，能够实现数据处理实体之间的通信。`Apache Kafka` 流处理平台由 `Kafka Core`、`Kafka Streams` 和 `Kafka Connect` 组成，是 Confluent 平台的基础。

`Confluent Platform` 是 `Kafka` 的主要商业支持方（参见 [`www.confluent.io/`](http://www.confluent.io/)）。我目前参与的大多数 `Kafka` 项目都使用这个平台。`Kafka` 的各个组件能够以分布式、容错的方式，在整个组织内实时实现数据流的捕获、传输、处理和存储。

#### Kafka Core

`Confluent Platform` 的核心是 `Apache Kafka`。`Confluent` 扩展了该核心，使得 `Kafka` 的配置、部署和管理不再那么复杂。

#### Kafka Streams

`Kafka Streams` 是一个开源解决方案，您可以将其集成到您的应用程序中，以构建和执行强大的流处理功能。

#### Kafka Connect

这确保了针对众多标准数据系统的、经过 Confluent 测试且安全的连接器。这些连接器使得快速、无压力地建立一致的数据管道成为可能。这些连接器通过模式注册表与平台完全集成。

`Kafka Connect` 提供了数据处理能力，实现了从业务生态系统边缘向数据解决方案核心的数据迁移。在第 7 章至第 11 章中，我将讨论如何使用此消息传输管道通过配置来流式传输数据。

### Elastic Search

`Elastic search` 是一个分布式、开源搜索与分析引擎，专为水平可扩展性、可靠性和无压力管理而设计。它通过一种精良且对开发者友好的查询语言，结合了搜索的速度与分析的能力，覆盖结构化、非结构化和时间序列数据。在第 11 章中，我将讨论如何使用此弹性搜索在框架内对数据进行分类。

### R

`R` 是一种用于统计计算和图形的编程语言及软件环境。`R` 语言被数据科学家、统计学家、数据挖掘者和数据工程师广泛用于开发统计软件和执行数据分析。

`R` 的功能通过用户创建的使用专门统计技术和图形程序的包得到扩展。`R` 的核心安装中包含一组核心包，其他包可从综合 R 存档网络（`CRAN`）获取。

必须了解以下包：

*   `sqldf`（使用 SQL 的数据框）：此函数将文件读入 `R`，同时使用 `sql` 语句过滤数据。只有过滤后的部分由 `R` 处理，因此大于 `R` 原生可导入的文件也可以用作数据源。
*   `forecast`（时间序列预测）：此包提供时间序列和线性模型的预测函数。
*   `dplyr`（数据聚合）：在 `R` 内对数据进行拆分、应用和组合的工具。
*   `stringr`（字符串操作）：用于常见字符串操作的简单、一致的封装器。
*   `RODBC`、`RSQLite` 和 `RCassandra` 数据库连接包：用于连接数据库，在 `R` 外部操作数据，并实现与源系统的交互。
*   `lubridate`（时间与日期操作）：使 `R` 中的日期处理更加简便。
*   `ggplot2`（数据可视化）：使用图形语法创建优雅的数据可视化。这是一种超级可视化能力。
*   `reshape2`（数据重构）：仅使用 `melt` 和 `dcast`（或 `acast`）两个函数，灵活地重构和聚合数据。
*   `randomForest`（随机森林预测模型）：Leo Breiman 和 Adele Cutler 的用于分类和回归的随机森林。
*   `gbm`（广义提升回归模型）：Yoav Freund 和 Robert Schapire 的 AdaBoost 算法以及 Jerome Friedman 的梯度提升机。

在本书的指导过程中，我将逐一讨论这些包。在第 6 章中，我将讨论如何使用 `R` 处理示例框架内的样本数据。我将提供示例，以演示该框架及其工具背后的基本理念和工程原理。

请注意，`CRAN` 中还有许多其他包，并且每天都在增长。花时间研究不同的包以提升您在 `R` 环境中的能力是非常值得的。

### Scala

`Scala` 是一种通用编程语言。`Scala` 支持函数式编程和强静态类型系统。许多高性能数据科学框架都是用 `Scala` 构建的，因为它具有出色的并发能力。对于来自数据湖的大规模数据集，并行化海量处理是一个关键需求。`Scala` 正逐渐成为数据处理工具使用的事实标准编程语言。在本书中，我将提供如何使用它的指导。`Scala` 也是 `Spark` 的原生语言，掌握这门语言非常有用。

### Python

`Python` 是一种高级通用编程语言，由 Guido van Rossum 创建并于 1991 年发布。值得注意的是，它是一种解释型语言：`Python` 的设计哲学强调代码可读性。`Python` 使用动态类型系统和自动内存管理，并支持多种编程范式（面向对象、命令式、函数式编程和面向过程）。

得益于其在全球的成功，它拥有一个庞大而全面的标准库。Python 包索引（`PyPI`）（[`https://pypi.python.org/pypi`](https://pypi.python.org/pypi)）提供了数千个可供您的数据科学项目使用的第三方模块。在本书中，我将提供如何使用它的指导。

我建议您也安装 `Anaconda`。它是一个 `Python` 的开源发行版，简化了包管理和功能部署（参见 [`www.continuum.io/downloads`](http://www.continuum.io/downloads)）。

# 摘要

本章阐述了如何利用 BW/4HANA 和 HANA 原生对象，实现从 HANA 物理表和虚拟表消费数据的敏捷数据模型。表 2-1 总结了本章涵盖的每种建模概念的优缺点和用法。

表 2-1. 建模概念对比

| 传统数据模型 |
| --- |
| **优点** | • 高水平的数据稳定性、质量和一致性• 可使用 SAP 业务内容• 通过安全模型管理访问权限 |
| **缺点** | • 灵活性低，开发规则严格• 主要适用于 SAP 数据• 开发和维护工作量大• 始终需要数据持久化 |
| **用途** | • SAP 数据模型 |
| **虚拟数据供应** |
| **优点** | • 高灵活性• 开发工作量非常低• 易于实施和维护• 无需创建信息对象• 不需要数据持久化 |
| **缺点** | • 无主数据• 仅提供特定信息片段• 安全模型不适用（除非维护了对信息对象的关联） |
| **用途** | • 简单的数据供应/提取• 临时分析• 直接访问虚拟表 |
| **基于字段的数据模型** |
| **优点** | • 高灵活性• 易于实施和维护• 无需创建信息对象• 数据持久化可选• 可实现授权模型 |
| **缺点** | • 开放式 ODS 视图对象不支持所有信息对象功能（例如层次结构）• 复杂数据模型性能较低 |
| **用途** | • 非 SAP 数据模型 |
| **混合数据模型** |
| **优点** | • 高灵活性• 无需创建新的信息对象• 可在适用处利用现有主数据对象• 通过安全模型管理访问权限 |
| **缺点** | • 如果没有严格的建模指南，混合来自不同区域的多个对象，模型可能变得复杂且难以维护• 对于复杂数据模型，性能可能不足 |
| **用途** | • 维度与 SAP 主数据对应的非 SAP 数据模型 |
| **组合数据模型** |
| **优点** | • 使用户能够在全局数据（SAP 和非 SAP）上运行数据分析和报表• 可实现授权模型 |
| **缺点** | • 组合模型的设计需要详细且耗时的分析• 实施复杂• 通过外部 SAP HANA 视图产生大量依赖关系，可能对 SAP 模型产生负面影响• 维护工作量相当高 |
| **用途** | • 将 SAP 和非 SAP 数据集成到单个模型中 |

本章描述的概念让您了解如何将外部表数据供应到 BW/4HANA，如何基于非 SAP 表实现报表和数据模型，以及如何将 SAP 和非 SAP 数据集成到单个数据模型中。在接下来的章节中，您将通过示例学习如何在 BW/4HANA 系统中实施这些概念。

# Kotlin/S2 数值方法简介

2009 年的一个晚上，我在伦敦公寓的阁楼里编写了矩阵乘法算法的第一行代码——经典的 `O(n³)` 版本——当时这不过是一种业余爱好。我正在用 Java 编写一个交易策略，但找不到一个合适的 Java 数学库（即，一个专业维护、文档详尽、面向对象设计完善且具有广泛开放数据结构的库）。策略代码的大部分是用 R 或 MATLAB 开发的，而交易/订单执行系统是 Java 的。然而，让 Java 与 R/MATLAB 相互通信简直是一场噩梦，更不用说其他许多 IT 烦恼了（例如，多线程安全、多实例、调试、R/MATLAB 速度极慢，以及那些莫名其妙的“谁知道为什么不行”的问题）。

我曾以为，如果有一个类似于当年无处不在的《C 语言数值算法》那样的 Java 数学库，世界将会受益。创建一个这样的库的一个简单方法是将 C 代码（自动）翻译成 Java。然而，这样做得到的只是一堆只能做各自本职工作的函数（过程）。我无法复用其中的数据结构、模块或（子）算法来构建自己的新数据结构或算法。一个向量不应该仅仅是一堆数字或一个数组。向量是一个数学概念，它具有明确定义的属性和运算。任何处理向量的算法都应该理解这些属性和运算，而不是重新编码它们。

虽然当时有一些 Java 数值库，最著名的是 `Apache Commons Math`，但没有任何一个被设计为高性能的。自 FORTRAN/C 时代以来，现代计算已经取得了长足的进步。我们现在有了并发编程、更高效的算法（例如用于矩阵乘法）、像 GPU 这样的新硬件等等。简单移植 FORTRAN/C 代码或者照搬教科书上的算法实现，无法利用这些进步。性能会非常慢。我们需要多线程、高度优化的数据结构以及高效的算法。例如，我们没有使用简单的 `O(n³)` 矩阵乘法算法，而是实现了 Strassen 算法的并行化版本。由于团队在过去十年中付出了大量的努力进行扭曲、实验和测试，最终的结果是，我们现在拥有了可以说是 Java 中最快的线性代数实现。

我对现有 Java 数学库的另一个问题是它们的范围非常有限。一个量化交易策略可以像移动平均线交叉一样简单，但也可以非常复杂，涉及求解随机微分方程。它当然也包含大量的统计分析。最后但同样重要的是，它还需要一套求解器来优化策略参数之类的东西。几乎所有的统计过程都涉及某种优化，例如回归和最大似然估计。Java 中没有免费或廉价且效果良好的优化器。像 `Gurobi` 和 `Mosek` 这样的专业优化器非常昂贵。

# 前言

当我还是个孩子时，我喜欢整理数学笔记。我原本并不真正喜欢数学（或任何功课），直到遇见第一位数学老师，他启迪了我。正是**何斌**教授让我看到数学可以如此有趣，并在初中暑假期间于中山大学教我数学。我永远感激他。数学训练塑造了我的思维方式，并为我打开了学习物理等其他科学学科的大门。那些暑假改变了我的命运，使我从一名平庸的学生变成了尖子生。

我觉得数学有趣，是因为数字之间存在结构。例如，质数构成了所有数字；实数轴上没有“空洞”。证明同一件事有如此多的方法，比如勾股定理。几何图形之间、图形与数字之间同样存在结构和关系。*为什么*如此迷人。我曾以为自己擅长数学，直到大学一年级选修了实分析的荣誉课程。班上有些同学的水平远超于我。我意识到自己成不了数学家，于是在研究生阶段转向了计算机科学，心想这可能会容易些。

学习计算机科学绝非仅仅学习编程。在高校用 C++编程近十年后，我发现自己还算是个不错的程序员——至少当时这么认为。我有种特殊天赋，能花上数小时甚至数天，除了调试段错误、修复内存泄漏或比较数字到小数点后最后一位之外什么都不做。（我至今记得在瑞银曾花三天时间找出一个极其隐蔽的 Bug。）结果，当我的第一位导师向我介绍设计模式时，我才发现自己原来是盲目自信。**阿尼尔·库马尔**博士在求职面试中让我设计一个单例模式，并引导我设计了双重检查锁定模式。幸运的是，他仍然录用了我，让我加入了他的团队，这是我第一份工作。我感激他的培养、指导和 mentorship，这开启了我成为专业量化交易员的职业生涯。

我在数学与计算机科学领域的训练（专攻人工智能），一直支撑着我作为量化交易员的职业生涯，并运用数学解决商业问题。这是一种罕见的技能组合：大多数数学家不会编程（Excel/MATLAB/R 并非真正的专业编程），而大多数程序员不读数学。我们经常需要将 R 代码翻译成 Java 代码，在创建交易模型的数学家与负责在订单执行系统中实现这些模型的程序员之间来回转换。于是有一天，我决定利用自己的两种技能，创建一个数学编程库，让自己变得更有用。这某种程度上延续了我儿时整理数学笔记的爱好，因为现在我将数学算法组织成了更有用的形式。目标是让量化程序员能用构建应用程序的同一种语言来编写数学代码。从此不再有“翻译丢失”的问题。

2007 年，我有幸聘请了**姚健文**博士，他起初是实习生，后来转为全职员工，也是这家初创公司的联合创始人。姚是我见过最优秀的软件工程师。他聪明、机敏、细致，最重要的是有责任心。我感激不尽的是，他陪伴我走过了学习与构建数学库、交易策略和系统的冒险之旅。他教会了我许多关于计算机科学和编程的知识。

2008 年，**孙凯文**博士以实习生身份加入团队。我有幸让凯文后来以另一位联合创始人的身份加入初创公司。他现在是我们团队的智囊，也是创建交易和赌博领域众多数学模型的关键人物。他拥有出色的数学思维和问题解决能力。我至今仍惊叹于他当时（以及现在）能优雅而美妙地解决我们抛给他的几乎所有问题。他总能凭借惊人的数学和 R 语言技能在截止日期前拯救团队。他教会了我许多数学和统计学知识。

此外，我永远感激我的兄弟凯文，感谢他在我们共同经历的起伏、欢笑与泪水、希望与挑战中，给予我的所有精神支持、团队协作、贡献、鼓励、建议、人脉、宝贵时间以及经济援助。没有他巨大的付出和资源，一切都不可能实现。我感谢上帝，让我生命中有他相伴。

这就是 NM Dev 数学库的诞生故事。如今，该库已被知名商业机构和学术机构所采用。NM Dev 是我们所有工作的基石。我们基于这个 Java 数值编程库构建了交易策略、金融分析平台（AlgoQuant）、固定收益分析平台（SuperCurve）、数据驱动决策系统（NM Optim）以及高性能求解器与优化器（NM Solver）。

# Kotlin/S2 数值方法简介

2009 年的一个晚上，我在伦敦公寓的阁楼里编写了矩阵乘法算法的第一行代码——经典的 `O(n³)` 版本——当时这不过是一种业余爱好。我正在用 Java 编写一个交易策略，但找不到一个合适的 Java 数学库（即，一个专业维护、文档详尽、面向对象设计完善且具有广泛开放数据结构的库）。策略代码的大部分是用 R 或 MATLAB 开发的，而交易/订单执行系统是 Java 的。然而，让 Java 与 R/MATLAB 相互通信简直是一场噩梦，更不用说其他许多 IT 烦恼了（例如，多线程安全、多实例、调试、R/MATLAB 速度极慢，以及那些莫名其妙的“谁知道为什么不行”的问题）。

我曾以为，如果有一个类似于当年无处不在的《C 语言数值算法》那样的 Java 数学库，世界将会受益。创建一个这样的库的一个简单方法是将 C 代码（自动）翻译成 Java。然而，这样做得到的只是一堆只能做各自本职工作的函数（过程）。我无法复用其中的数据结构、模块或（子）算法来构建自己的新数据结构或算法。一个向量不应该仅仅是一堆数字或一个数组。向量是一个数学概念，它具有明确定义的属性和运算。任何处理向量的算法都应该理解这些属性和运算，而不是重新编码它们。

虽然当时有一些 Java 数值库，最著名的是 `Apache Commons Math`，但没有任何一个被设计为高性能的。自 FORTRAN/C 时代以来，现代计算已经取得了长足的进步。我们现在有了并发编程、更高效的算法（例如用于矩阵乘法）、像 GPU 这样的新硬件等等。简单移植 FORTRAN/C 代码或者照搬教科书上的算法实现，无法利用这些进步。性能会非常慢。我们需要多线程、高度优化的数据结构以及高效的算法。例如，我们没有使用简单的 `O(n³)` 矩阵乘法算法，而是实现了 Strassen 算法的并行化版本。由于团队在过去十年中付出了大量的努力进行扭曲、实验和测试，最终的结果是，我们现在拥有了可以说是 Java 中最快的线性代数实现。

我对现有 Java 数学库的另一个问题是它们的范围非常有限。一个量化交易策略可以像移动平均线交叉一样简单，但也可以非常复杂，涉及求解随机微分方程。它当然也包含大量的统计分析。最后但同样重要的是，它还需要一套求解器来优化策略参数之类的东西。几乎所有的统计过程都涉及某种优化，例如回归和最大似然估计。Java 中没有免费或廉价且效果良好的优化器。像 `Gurobi` 和 `Mosek` 这样的专业优化器非常昂贵。

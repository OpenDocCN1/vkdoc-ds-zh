# Tungsten 项目

自 2015 年起，Spark 设计者观察到 Spark 工作负载的瓶颈日益集中在 CPU 和内存上，而非 I/O 和网络通信。这虽然有些反直觉，但考虑到硬件方面的进步（如 10Gbps 网络链路和高速 SSD），也并不令人意外。Tungsten 项目旨在提升 Spark 应用中内存和 CPU 的使用效率，使性能更接近现代硬件的极限。Tungsten 项目包含三项举措。

-   通过使用堆外内存管理技术来显式管理内存，以消除 JVM 对象模型的开销并最小化垃圾回收。
-   使用智能的缓存感知算法和数据结构来利用内存层级结构。
-   使用全阶段代码生成，通过将多个算子合并为单个 `Java` 函数来最小化虚函数调用。

Tungsten 项目所付出的艰苦而有趣的工作，自 Spark 2.0 以来极大地改进了 Spark 执行引擎。Tungsten 项目中的大部分工作都在执行引擎的后台进行。以下示例通过检查物理计划，让我们得以一窥全阶段代码生成举措。在以下输出中，每当算子前出现星号（`*`）时，表示启用了全阶段代码生成。清单 5-58 展示了在 `DataFrame` 中过滤并对整数求和的物理计划。

```
spark.range(1000).filter("id > 100").selectExpr("sum(id)").explain()
== Physical Plan ==
*HashAggregate(keys=[], functions=[sum(id#13L)], output=[sum(id)#23L])
+- Exchange SinglePartition
+- *HashAggregate(keys=[], functions=[partial_sum(id#13L)], output=[sum#25L])
+- *Filter (id#13L > 100)
+- *Range (0, 1000, step=1, splits=8)
清单 5-58
通过查看物理计划演示全阶段代码生成
```

全阶段代码生成将过滤和整数求和的逻辑合并到单个 `Java` 函数中。

## 总结

本章涵盖了 Spark SQL 模块中许多有用且强大的特性。

-   聚合是大数据分析领域最常用的特性之一。Spark SQL 提供了许多常用的聚合函数，例如 `sum`、`count`、`avg` 等。带透视的聚合提供了一种很好的数据汇总方式，同时也能将列转置为行。
-   进行任何有用且有意义的数处理通常需要连接两个或多个数据集。Spark SQL 支持 SQL 世界中存在的许多标准连接类型。
-   Spark SQL 拥有丰富的内置函数集，应能覆盖处理字符串、数学、日期和时间等大部分常见需求。如果这些函数都无法满足特定用例的需求，那么编写一个用户自定义函数也相当容易，该函数既可用于 `DataFrame` API，也可用于 SQL 查询。
-   窗口函数是强大且高级的分析函数，因为它们可以为输入组中的每一行计算一个值。它们特别适用于计算移动平均值、累计总和或每一行的排名。
-   `Catalyst` 优化器使您能够编写高效的数据处理应用程序，而无需过多考虑其内部机制。基于成本的优化器在 Spark 2.2 中引入，使 `Catalyst` 能够根据所处理数据的收集统计信息，更智能地选择正确的连接实现类型。
-   `Tungsten` 项目是幕后的主力，它通过采用几种先进技术来提高内存和 CPU 的使用效率，从而加速数据处理应用程序的执行。

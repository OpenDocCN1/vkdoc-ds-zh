## 第 6 章：过滤、映射与归约

上一章介绍了一些可能难以理解的函数式编程概念，但本章会简单得多。

我们将学习函数式编程中用于替代循环和显式递归函数的三种通用方法。它们实际上是处理序列计算的三种不同模式，虽然不同函数的具体实现各异，但仅凭这三种模式就能完成几乎全部原本需要用循环实现的操作。

请注意前面提到的“几乎”二字。这三种函数并不能替代*所有*循环操作。它们可以替代已知迭代次数的 for 循环，但无法替代 while 循环和 repeat 循环。不过，在 R 语言中，绝大多数循环都是 for 循环，因此通常情况下可以用这些函数来替代。

这三种函数（或模式）分别是 `Filter`、`Map` 和 `Reduce`。第一个函数接收一个序列和一个谓词（返回布尔值的函数），返回的序列包含所有谓词为真的元素，其余元素被移除。第二个函数 `Map` 对序列中的每个元素求值一个函数，并返回包含函数结果的新序列，类似于上一章简要介绍的 `sapply` 函数。最后一个函数 `Reduce` 接收一个序列和一个函数，通过反复求值将序列归约为单一值。这种模式在某些编程语言中也被称为“折叠”（fold）。

### R 中通用的序列对象是列表

在 R 中，序列主要有两种形式：向量和列表。向量只能包含基本类型，且所有元素必须类型相同。

列表可以包含任意类型的序列，元素之间可以类型不同。因此列表比向量更通用，通常用作数据结构的基础构件，例如本书之前使用的“邻接列表”和树结构。

因此，通用序列处理函数能对列表进行操作也就不足为奇了。`Filter`、`Map` 和 `Reduce` 这三个函数也可以处理向量，但处理时会将其视为先显式转换为列表后的结果。`Reduce` 函数返回的值类型取决于输入（非序列类型），而 `Filter` 和 `Map` 返回的序列均为列表形式。

从编程角度看，操作列表与操作向量的难度相当，但某些函数（如图形绘制函数和数据框操作函数）要求输入为向量，因此有时需要将 `Filter` 或 `Map` 返回的列表转换为向量。

使用 `unlist` 函数即可实现转换。该函数会在所有元素类型相同（基本类型）时将列表转换为向量，否则原样返回列表。本章中我会大量使用 `unlist`，因为它能让输出结果更美观，但在实际编程中，我通常只在确实需要向量时才进行转换——列表本身已足够存储序列。

区别仅在于

```r
list(1, 2, 3, 4)
```

的输出篇幅比

```r
1:4
```

更长。如果读者在电脑前跟随操作，可以尝试对比 `unlist` 使用前后的输出差异。

将向量转换为列表的情况很少见。虽然操作列表的函数通常也支持向量，但若确需转换，应使用 `as.list` 而非 `list` 函数。

前者会为向量的每个元素创建一个列表元素：

```r
as.list(1:4)
```

而后者会创建一个包含整个向量的单元素列表：

```r
list(1:4)
```

### 序列过滤

`Filter` 函数是本章三个主要函数中最简单的一个。它通过谓词从序列中选取子集。

谓词是返回布尔值的函数，`Filter` 会返回谓词为 `TRUE` 的元素构成的列表，并丢弃谓词为 `FALSE` 的元素。

```r
is_even <- \(x) x %% 2 == 0
unlist(Filter(is_even, 1:10))
```

该函数常与闭包配合使用，使谓词能够依赖局部变量：

```r
larger_than <- \(x) \(y) y > x
unlist(Filter(larger_than(5), 1:10))
```

当然，实际编程中不会写出上述代码，因为更简单的写法同样有效：

```r
unlist(Filter(\(y) y > 5, 1:10))
```

但闭包确实可行，并且在更复杂的情况下非常有用。

此处我们使用向量作为 `Filter` 的输入，但任何列表类型都可以，也不必限制为相同类型的序列：

```r
s <- list(a = 1:10,          # 向量
          b = list(1,2,3,4,5,6),  # 列表
          c = y ~ x1 + x2 + x3,   # 公式
          d = vector("numeric"))  # 空向量
Filter(function(x) length(x) > 5, s)
```

打印结果可能不够美观，但此处无法用 `unlist` 解决。使用 `unlist` *会*得到向量，但无法反映结果的原始结构；向量 `a` 和列表 `b` 会被展平为单一向量。

### 序列映射

`Map` 函数会对列表中的每个元素求值一个函数，并返回包含结果的新列表：

```r
unlist(Map(is_even, 1:5))
```

与 `Filter` 类似，`Map` 也常与闭包结合使用：

```r
add <- function(x) function(y) x + y
unlist(Map(add(2), 1:5))
unlist(Map(add(3), 1:5))
```

并且可以应用于不同类型的列表：

```r
s <- list(a = 1:10, b = list(1,2,3,4,5,6),
          c = y ~ x1 + x2 + x3, d = vector("numeric"))
unlist(Map(length, s))
```

如果提供的函数参数数量与序列数量匹配，`Map` 还可以同时处理多个序列：

```r
unlist(Map(`+`, 1:5, 1:5))
```

在此示例中，我们使用了接受两个参数的 `+` 函数，并为 `Map` 提供了两个序列，结果实现了对应元素的加法运算。

可以为 `Map` 调用传递额外参数，既可以直接使用命名参数

```r
x <- 1:10
y <- c(NA, x)
s <- list(x = x, y = y)
unlist(Map(mean, s))
unlist(Map(mean, s, na.rm = TRUE))
```

也可以通过 `MoreArgs` 参数传入列表：

```r
unlist(Map(mean, s, MoreArgs = list(na.rm = TRUE)))
```

对于单个值，这两种方法的工作原理相同，但它们的语义略有不同，这在提供序列作为参数时会体现出来。将命名参数直接提供给 `Map` 与提供未命名参数的作用相同（区别在于你可以按名称而不是按位置选择特定变量），因此 `Map` 会假定你想要将函数应用于参数的每个元素。这在单个参数下有效的原因是，正如 R 的常规做法，较短的序列会根据需要重复多次。对于单个参数，这正是我们想要的，但对于序列则不一定。

如果我们想要这种行为，我们可以直接使用 `Map` 的命名参数，但如果我们希望每次调用函数时都使用整个序列，则必须将该序列作为 `MoreArgs` 参数的一个参数。

作为一个例子，我们可以考虑我们信赖的朋友 `scale` 函数，并创建一个版本，其中向量 `x` 通过另一个向量 `y` 的均值和标准差进行缩放：

```r
scale <- function(x, y) (x - mean(y))/sd(y)
```

如果我们只为 `scale` 提供两个参数，`Map` 会独立地评估所有配对，我们会得到很多 `NA` 值，因为我们在单个值上调用了 `sd` 函数：

```r
unlist(Map(scale, 1:10, 1:5))
## [1] NA NA NA NA NA NA NA NA NA NA
```

如果我们命名参数 `y`，也会发生同样的情况：

```r
unlist(Map(scale, 1:10, y = 1:5))
## [1] NA NA NA NA NA NA NA NA NA NA
```

但是如果我们使用 `MoreArgs`，整个向量 `y` 会在每次调用时提供给 `scale`：

```r
unlist(Map(scale, 1:10, MoreArgs = list(y = 1:5)))
## [1] -1.2649111 -0.6324555  0.0000000  0.6324555
## [5]  1.2649111  1.8973666  2.5298221  3.1622777
## [9]  3.7947332  4.4271887
```

与 `Filter` 一样，只要我们的函数可以处理不同类型的列表，`Map` 就可以处理任意类型的列表：

```r
s <- list(a = 1:10, b = list(1,2,3,4,5,6),
          c = y ~ x1 + x2 + x3, d = vector("numeric"))
unlist(Map(length, s))
##  a  b  c  d
## 10  6  3  0
```

## 缩减序列

`Filter` 和 `Map` 生成列表，而 `Reduce` 函数则将列表转换为一个值。当然，这个值也可以是一个列表——列表也是值——但 `Reduce` 并非简单地独立处理其输入列表中的每个元素。相反，它通过迭代地将一个函数应用于成对的元素来对列表进行汇总。你提供一个接受两个元素的函数 `f`，它首先会对列表中的前两个元素调用 `f`。然后，它将获取这个结果，并用此结果与下一个元素调用 `f`，并继续在整个列表中执行此操作。

所以调用 `Reduce(f, 1:5)` 等同于调用 `f(f(f(f(1, 2), 3), 4), 5)`。写 `Reduce(f, 1:5)` 只是更易读，至少在你习惯了之后。

我们可以使用 `+` 作为函数来观察它的实际应用：

```r
Reduce(`+`, 1:5)
## [1] 15
```

如果你使用参数 `accumulate`，还可以获得逐步结果。这将返回一个包含对 `f` 的所有调用结果的列表，并且列表中包含第一个值，因此 `Reduce(f, 1:5, accumulate = TRUE)` 将返回列表：

```
c(1, f(1, 2), f(f(1 ,2), 3), f(f(f(1, 2), 3), 4),
  f(f(f(f(1, 2), 3), 4), 5))
```

所以，对于加法，我们得到：

```r
Reduce(`+`, 1:5, accumulate = TRUE)
## [1]  1  3  6 10 15
```

默认情况下，`Reduce` 从左到右进行计算，但是通过将选项 `right` 设置为 `TRUE`，你将得到从右到左的结果：

```r
Reduce(`+`, 1:5, right = TRUE, accumulate = TRUE)
## [1] 15 14 12  9  5
```

对于像 `+` 这样的结合性操作，如果我们不要求累积的函数调用，结果显然是相同的。

在许多函数式编程语言中（所有这些语言都有这个函数，尽管有时它被称为 `fold` 或 `accumulate`），你需要为计算提供一个初始值。然后，这个初始值会在对 `f` 的首次调用中使用，因此如果 `init` 指的是初始值，`x` 是序列，则折叠从 `f(init, x[1])` 开始。在 R 中，你也可以通过参数 `init` 为 `Reduce` 显式提供一个初始值来获得相同的行为：

```r
Reduce(`+`, 1:5, init = 10, accumulate = TRUE)
## [1] 10 11 13 16 20 25
```

你只是通常不需要指定这个初始值。在需要它的语言中，它用于在累积结果时获得正确的起点。对于加法，如果我们希望 `Reduce` 计算总和，我们会使用零作为初始值，因为将零加到序列中的第一个值只会得到第一个元素。对于乘法，我们则必须使用 1 作为初始值，因为这样第一个函数应用就会得到初始值。

在 R 中，如果我们满足于让第一个函数调用作用于列表中的前两个元素，则不需要提供这些初始值，因此乘法与加法一样有效，无需提供 `init`：

```r
Reduce(`*`, 1:5)
## [1] 120

Reduce(`*`, 1:5, accumulate = TRUE)
## [1]   1   2   6  24 120

Reduce(`*`, 1:5, right = TRUE, accumulate = TRUE)
## [1] 120 120  60  20   5
```

你通常不会使用 `Reduce` 来汇总值（如求和或乘积），R 中已经有了用于此目的的函数（分别是 `sum` 和 `prod`），而且它们作为用 C 实现的底层函数要快得多，而 `Reduce` 必须是高级函数才能处理任意函数。对于我们已经没有现成函数来汇总列表的更复杂数据，`Reduce` 通常是首选方法。

下面是一个例子，来自 Hadley Wickham 的 *Advanced R* 一书：

```r
samples <- replicate(3, sample(1:10, replace = TRUE), simplify = FALSE)
str(samples)
## List of 3
## $ : int [1:10] 1 3 7 8 9 5 9 1 6 4
## $ : int [1:10] 4 5 8 3 1 6 9 10 5 3
## $ : int [1:10] 9 9 2 10 9 2 9 8 7 10

Reduce(intersect, samples)
## [1] 8 9
```

我们有一个包含三个向量的列表，每个向量都有从 1 到 10 的十个样本，我们想要获取这三个列表的交集。这意味着取前两个的交集，然后取该结果与第三个列表的交集。非常适合使用 `Reduce`。我们只需将其与 `intersect` 函数结合使用。

或者我们可以在对树应用 `Map` 之前，显式检查树是否包含节点“B”：

```
has_B <- function(node) {
  if (node$name == "B") return(TRUE)
  if (is.null(node$left) && is.null(node$right)) return(FALSE)
  has_B(node$left) || has_B(node$right)
}
```

`unlist(Map(node_depth_B, Filter(has_B, trees)), use.names = FALSE)`

### Apply 函数族

`Map` 函数是对列表元素进行映射的通用解决方案，但 R 有一整套类似 `Map` 的函数族，它们适用于不同类型的输入。这些函数均以“something-apply”命名，我们已在上一章中见过 `sapply`。`Map` 函数实际上只是其中一个函数 `mapply` 的包装器，鉴于我们已经了解 `Map` 的用法，这里不再讨论 `mapply`，但我会简要介绍 `apply` 族中的其他函数。

### sapply、vapply 和 lapply

`sapply`、`vapply` 和 `lapply` 都作用于序列。区别在于：`sapply` 尝试*简化*其输出；`vapply` 接受一个值作为参数，并将输出强制转换为该值的类型，若无法转换则报错；`lapply` 则对列表进行映射。

## 第 6 章 Filter、Map 和 Reduce

在交互式会话中使用 `sapply` 很方便，因为当映射结果可以转换为向量时，它本质上类似于 `Map` 与 `unlist` 的组合。与 `unlist` 不同，它不会展平列表，因此如果映射结果比向量更复杂，`sapply` 仍会返回列表。正因如此，在程序中使用 `sapply` 可能存在风险：你无法预先知道输出类型，因此必须防御性编程，检查得到的是向量还是列表。

`sapply(trees, size_of_tree)`

`A` `C` `E`

1 3 5

`sapply(trees, identity)`

`A` `C` `E`

left NULL list,3 list,3

right NULL list,3 list,3

使用 `vapply` 时，如果结果可以转换为向量，你会得到与 `sapply` 相同的简化效果，但必须向函数告知输出应为何种类型。这通过提供一个期望输出的示例来实现。如果 `vapply` 无法将结果转换为该类型，你会得到错误而非不同类型的意外结果，这使得该函数在程序中使用更安全。毕竟，相比因类型混淆导致的意外结果，得到错误要好得多。

`vapply(trees, size_of_tree, 1)`

`A` `C` `E`

1 3 5

## purrr 包中的函数式编程

Filter、Map 和 Reduce 函数是许多函数式算法的构建模块。然而，许多常见操作需要这三种函数的各种组合，以及与 `unlist` 的组合，因此本章内容众多。

第 6 章 Filter、Map 和 Reduce

如果*只*使用这三/四个函数来编写函数，意味着从最基本的构建模块开始构建函数。这样做效率低下，因此你需要一个包含更具体函数的工具箱来处理常见操作。

`purrr` 包实现了一些此类函数，用于更高效的函数式编程，并提供了它自己版本的 Filter、Map 和 Reduce。完整介绍 `purrr` 包超出了这本小书的范围，但我将快速概述该包中可用的函数，并敦促你，如果你认真对待在 R 中使用函数式编程，请进一步探索该包。

```
library(purrr)
```

`purrr` 中的所有函数都将它们操作的序列作为第一个参数——这与 `apply` 函数族类似，但与 Filter、Map 和 Reduce 函数不同。

### 类似 Filter 的函数

`purrr` 中与 Filter 对应的函数叫做 `keep`，其工作方式与 Filter 完全相同。它接受一个谓词函数，并返回序列中所有使该谓词返回 `TRUE` 的元素组成的列表。函数 `discard` 的工作方式类似，但返回谓词返回 `FALSE` 的元素：

```
keep(1:5, \(x) x > 3)
## [1] 4 5

discard(1:5, \(x) x > 3)
## [1] 1 2 3
```

如果你向这些函数提供一个向量，你将得到一个相同类型的向量作为返回值；如果提供一个列表，你将得到一个列表：

```
keep(as.list(1:5), \(x) x > 3)
## [[1]]
## [1] 4
##
## [[2]]
## [1] 5
```

有两个便捷函数 `every` 和 `some`，你可以通过检查 Filter 返回的列表长度来实现它们。它们分别检查序列中*所有*元素是否都满足谓词，或者*某些*元素是否满足谓词：

```
every(1:5, \(x) x > 0)
## [1] TRUE

every(1:5, \(x) x > 3)
## [1] FALSE

some(1:5, \(x) x > 3)
## [1] TRUE

some(1:5, \(x) x > 6)
## [1] FALSE
```

在此处的示例中，我使用了 R 4.0 引入的 `\(x) ...` 语法，但对于在此语法出现之前开发的 `purrr`，你也可以使用公式来定义简短的函数。你可以使用“公式符号”，通过编写 `~` 后跟函数体来定义一个匿名函数，其中函数参数由变量 `.x` 引用：

```
keep(1:5, ~ .x > 3)
## [1] 4 5

discard(1:5, ~ .x > 3)
## [1] 1 2 3
```

不过，这种匿名函数的简写形式仅在 `purrr` 包内的函数中可用。仅仅导入了 `purrr` 包，并不能使该功能在其他函数中生效。

函数 `map_if` 提供了 `map` 的一个变体，它仅在谓词为 `TRUE` 时才应用正在映射的函数。如果某个元素的谓词返回 `FALSE`，则该元素保持不变。

# 无点编程

在最后一章中，我们不会过多讨论实际的编程，而是一种被称为无点编程（并非无意义编程）的编程风格，其特点是通过组合其他函数来构造新函数，而非直接编写新函数。

许多计算都可以表达为数据流经的步骤以及数据在此过程中如何被转换。我们编写函数来处理所有最基本的步骤，即程序的原子，然后通过组合更基础的变换来构造用于更复杂操作的函数，从而从程序原子构建程序分子。

术语无点指的是在计算一系列变换时数据可能所处的中间状态。它所指点是数据在每次变换后所处的状态，而无点意味着我们不以任何方式关注这些点。在使用无点编程编写的代码中，这些点根本不会被提及。

这听起来可能有点抽象，但如果你习惯于在 shell 脚本中编写管道，那么很快就会感到非常熟悉，因为无点编程正是你在编写管道时所做的事情。在那里，数据流经一系列串联在一起的程序。一个程序的输出成为管道中下一个程序的输入，你从不引用中间数据，只引用数据在管道处理过程中所经历的变换步骤。

## 函数组合

从更基础的函数构造新函数的最简单方法就是函数组合。在数学中，如果我们有一个函数`f`将定义域`A`映射到值域`B`，我们可以将其记为`f : A → B`，另一个函数`g`记为`g : A → C`，那么我们可以通过组合这两个函数来创建一个新函数`h : A → C`：`h(x) = g(f(x))`。

我们可以在 R 中做完全相同的事情，并像这样用函数`f`和`g`来定义`h`：

```r
h <- function(x) g(f(x))
```

仅仅为了组合两个函数而显式编写一个新函数，其中包含大量额外的冗余内容。在数学符号中，我们不会那样写两个函数的组合。我们将函数组合写成`h = g ° f`。通过组合函数来定义新函数，而不是定义那些仅仅显式调用其他函数的函数，这就是我们所说的无点编程，并且在 R 中很容易实现。

你可以编写一个组合函数，它是一个高阶函数，接受两个函数作为参数并返回它们的组合：

```r
compose <- function(g, f) function(...) g(f(...))
```

然后我们可以用这个函数来处理一个常见情况：当我们使用`Map`并经常想要对结果进行`unlist`时。当然，我们可以显式地调用它们来使用`Map`和`unlist`：

```r
xs <- 1:4
unlist(Map(\(x) x + 2, xs))  # 显式调用 Map + unlist
## [1] 3 4 5 6
```

但我们也可以组合`Map`和`unlist`，从它们的组合中创建一个新的映射函数：

```r
umap <- compose(unlist, Map)  # 组合 Map 和 unlist
umap(\(x) x + 2, xs)          # 使用新函数
## [1] 3 4 5 6
```

为了得到类似于数学记法的东西，我们希望它是一个中缀运算符，但 `pryr` 包已经为我们定义了它，所以我们可以像这样编写相同的代码：

```r
library(pryr)
umap <- unlist %.% Map
umap(\(x) x + 2, xs)
## [1] 3 4 5 6
```

我们不仅限于组合两个函数，由于函数组合是可结合的，我们无需担心组合的顺序，因此不需要在组合周围使用括号。我们也可以组合三个或更多函数，并且如果我们需要一些尚未作为命名函数实现的额外功能，我们还可以将函数与匿名函数组合。例如，我们可以像这样定义一个计算均方根误差的函数：

```r
rmse <- sqrt %.% mean %.% \(x, y) (x - y)**2
rmse(1:4, 2:5)
## [1] 1
```

我们需要一个新函数来计算`x`和`y`之间的平方距离，所以为此我们添加了一个匿名函数，然后我们可以直接使用`mean`和`sqrt`来获得其余的功能。

在函数组合的数学记法中，你总是按照显式调用它们的顺序来书写要组合的函数，因此`h ° g ° f`会在值`x`上被评估为`h(g(f(x)))`。如果你习惯从右向左阅读，这很好；但如果你习惯从左向右阅读，那就有点反过来了。

当然，没有什么能阻止我们编写一个反转函数顺序的函数组合运算符。为了避免与函数组合的数学记法混淆，我们会使用一个不同的运算符，这样我们可以定义`;`使得`f ; g = g ° f`，并在 R 中将其用于函数组合：

```r
`%;%` <- function(f, g) function(...) g(f(...))
rmse <- (\(x, y) (x - y)**2) %;% mean %;% sqrt
rmse(1:4, 2:5)
## [1] 1
```

在这里，我需要用括号将匿名函数括起来，以防止 R 将组合视为函数体的一部分，但除此之外，功能与之前相同；我们可以从左到右阅读组合。

## 管道

`magrittr` 包引入了一种“从左到右”的函数组合，作为运算符`%>%`，而在 R 4.1 中，我们有了一个内置的具有相同目的的运算符`|>`。尽管它们在语法和灵活性上略有差异，但两者都旨在通过指定从左到右的管道语法中的变换，使数据分析管道更易于阅读和编写。两者都允许你以与在 shell 管道中串联命令行工具非常相似的方式，将各种数据转换和分析链接在一起。

各种操作都是函数调用，这些函数通过`%>%`或`|>`运算符链接在一起，将一个函数的输出传递到下一个函数的输入。

例如，要获取向量`1:4`，计算其均值，然后计算`sqrt`，你可以像这样编写一个管道：

```r
library(magrittr)
1:4 %>% mean %>% sqrt
## [1] 1.581139
```

或者使用`|>`：

```r
1:4 |> mean() |> sqrt()
```

# 管道操作符：`%>%` 与 `|>`

使用 `%>%` 时，你可以通过函数名来组合函数，例如 `mean %>% sqrt`；但使用 `|>` 时，你必须组合函数调用，例如 `mean() |> sqrt()`。`%>%` 运算符也支持后一种语法。

默认情况下，管道中上一步的输出会作为第一个参数传递给下一步的函数。若要编写适合此模式的自定义函数，你只需让通过管道传输的数据成为函数的第一个参数即可。

由于管道现在在 R 中频繁使用，大多数函数都遵循这一模式，并且在 `dplyr` 和 `tidyr` 等流行包中也是如此。`purrr` 包也设计为与 `magrittr` 管道良好配合。它的所有函数都将要操作的数据作为第一个参数，因此使用 `%>%` 或 `|>` 将多个转换串联起来非常直接。

并非所有函数都遵循此模式，主要是较旧的函数不遵循，但你可以使用变量 `.` 来引用在管道中传递的数据，当你需要将其放在非第一个参数的位置时：`data.frame(x = 1:4, y = 2:5) %>% plot(y ~ x, data = .)`。不过，这仅受 `%>%` 运算符支持，`|>` 则不支持。

如果输入是数据框，你可以像使用任何其他数据框一样，通过列名来访问其列。参数依然是 `.`，你只需使用该参数来引用数据：`data.frame(x = 1:4, y = 2:5) %>% plot(.$x, .$y)`。

`. ` 参数可以在管道中的函数调用中多次使用，并且可以与管道中的函数调用一起使用，例如：

```
rnorm(4) %>% data.frame(x = ., y = cos(.))
```

虽然 `%>%` 运算符主要用于编写此类数据处理管道，但它也可以用于通过组合其他函数来定义新函数，此时函数按从左到右的顺序编写。编写此类函数就像编写数据处理管道一样，但让管道的第一步是 `.`，因此这是一个数据管道：

```
mean_sqrt <- 1:4 %>% mean %>% sqrt
mean_sqrt
## [1] 1.581139
```

而这是一个函数：

```
mean_sqrt <- . %>% mean %>% sqrt
mean_sqrt(1:4)
## [1] 1.581139
```

并且你可以在管道中使用这个函数：

```
1:4 %>% mean_sqrt
## [1] 1.581139
```

`|>` 运算符不支持这种编写函数的方式；你可以用它来组合函数调用，但它只是调用函数的语法糖，不能用于定义函数。在定义函数方面，`%>%` 运算符更加灵活。

你只能使用这种方法定义接受单个参数作为输入的函数。如果你需要多个参数，则需要显式定义你的函数。整个管道模式的工作原理是假设在函数调用之间传递的是单条数据。尽管如此，这并不妨碍你拥有复杂的数据（例如数据框），并以此方式模拟拥有多个参数。

例如，以我们之前编写的均方根误差函数为例：`rmse <- (\(x, y) (x - y)**2) %>% mean %>% sqrt`

这个函数接受两个参数，因此我们不能使用 `.` 来创建它。我们可以改为让它接受一个参数，例如一个数据框，并从中获取两个值：

```
rmse <- . %>% { (.$x - .$y)**2 } %>% mean %>% sqrt
data.frame(x = 1:4, y = 2:5) %>% rmse
## [1] 1
```

这里，我们还使用了 `magrittr` 的另一个特性，一种更简洁的编写匿名函数的语法。通过将表达式 `{(.$x - .$y)**2}` 写在花括号中，我们创建了一个函数，在其中可以将参数引用为 `.`。

当数据需要稍微调整以匹配上一个函数的输出和下一个函数的预期输入时，能够通过将表达式放在花括号中来编写匿名函数是非常方便的。

匿名函数还可以防止 `.` 参数在仅用于函数调用时被隐式地作为第一个参数传递给函数。如果表达式被包裹在花括号中，那么函数调用就不会以任何方式被修改，因此 `.` 不会作为第一个参数被隐式添加：

```
rnorm(4) %>% { data.frame(x = sin(.), y = cos(.)) }
```

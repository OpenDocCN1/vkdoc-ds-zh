# 第 8 章：结论

本书关于 R 语言函数式编程的内容到此结束。你现在已经了解了日常函数式编程中使用的所有基本编程模式，以及如何在 R 编程语言中使用它们。

如果你只习惯于命令式或面向对象编程，那么适应编写函数式程序可能需要一些努力，但高阶函数和闭包的组合是一种非常强大的高效编程范式，并且尽可能编写纯函数可以使代码更容易推理。

不过，R 语言并非纯粹的函数式编程语言，因此你的代码通常会混合命令式编程（在大多数情况下，出于便利和效率的考虑，使用循环而非递归）和函数式模式。通过谨慎编程，你仍然可以将程序的变化状态降至最低，并保持程序大部分是纯粹的。

R 中数据的不可变性有助于你保持编程的纯粹性。每当你“修改”数据时，你会隐式地创建数据的副本，然后修改该副本。这对程序推理来说是个好消息。函数很难产生副作用。然而，它也有一些缺点。许多经典的数据结构假设你可以修改数据。由于在 R 中无法做到这一点，你将不得不构建你的数据结构，使得更新它们意味着创建新的、修改过的数据结构。

我们已经了解了如何在计算数据时，使用带有修改数据功能的链表（本书中我使用的术语是“next lists”）和树。列表和树构成了函数式程序中数据结构的基本构造，但高效的函数式数据结构超出了本书的范围。我计划在本系列后续的书中再讨论这个话题。

本书到此结束，但我希望这不是你探索 R 语言函数式编程的终点。

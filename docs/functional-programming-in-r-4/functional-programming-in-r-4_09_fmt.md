# R 语言中的函数

下一章将简要介绍 R 语言中的函数。你可能已经熟悉其中部分内容，因此可以跳过直接阅读后续章节，但我会详细描述函数的定义与使用方法，以确保大家步调一致。后续章节会进一步探讨更复杂的问题。

## 第二章：R 语言中的函数

本章将介绍如何在 R 中编写函数。如果你对大部分内容已有所了解，可以放心跳过。我们将讨论参数如何作为"承诺"传递给函数——这种参数传递方式被称为惰性求值。如果你不熟悉这个概念但会编写函数，可以直接跳到该部分。我们还会介绍如何编写中缀运算符和替换函数，如果你不清楚这些是什么以及如何编写，也可以直接跳转到相关章节。如果你是 R 函数的新手，请从这里开始阅读。

## 在 R 中编写函数

你可以使用 `function` 关键字来创建 R 函数，或者从 R 4.1 开始，也可以使用 `\()` 语法。例如，我们可以这样编写一个计算平方的函数：

```
square <- function(x) x**2
```

或者这样写：

```
square <- \(x) x**2
```

然后这样使用：

```
square(1:5)
## [1] 1 4 9 16 25
```

T. Mailund, *R 4 中的函数式编程*, https://doi.org/10.1007/978-1-4842-9487-1_2

较短的语法 `\(x) x**2` 专为所谓的"lambda 表达式"设计，反斜杠符号旨在模仿希腊字母 lambda（λ）。当我们需要将简短函数作为参数传递给其他函数时，lambda 表达式非常有用——我们将在后续章节中讨论这一点。通常，在定义可复用的函数时，我们使用 `function()` 语法，在定义并命名函数时（如之前的 `square`），我将坚持使用这种写法。

我们编写的函数接受一个参数 `x`，并返回结果 `x**2`。函数的返回值始终是函数体内最后一个表达式的值。如果函数只有一个表达式，你可以像之前那样编写；但对于更复杂的函数，通常需要多条语句。这时，你可以将函数体放入花括号中，如下所示：

```
square <- function(x) {
  x**2
}
```

下面的函数需要花括号，因为它需要三条独立的语句来计算返回值：第一条计算输入的均值，第二条获取标准差，最后一条返回以均值为中心、标准差为单位的缩放后输入值。

```
rescale <- function(x) {
  m <- mean(x)
  s <- sd(x)
  (x - m) / s
}
```

前两条语句仅用于定义一些可在最后一条表达式中使用的变量。这是编写短函数的典型做法。

在函数内部赋值的变量仅在函数内部可见。当函数执行完毕后，这些变量将不复存在。从函数内部，你可以看到所谓的*局部*变量（函数参数和在函数体内赋值的变量），以及所谓的*全局*变量（在函数外部赋值的变量）。然而，在函数外部，你只能看到全局变量。至少在我们深入探讨[第 4 章](https://doi.org/10.1007/978-1-4842-9487-1_4)的细节之前，这是一种理解程序中任意时刻可见变量的好方法。目前，我们暂且从全局变量和局部变量的角度思考：在函数外部编写的任何内容都属于第一类，所有人都能看到；而函数参数和在函数内部赋值的变量则属于第二类；参见图 2-1。如果全局变量和局部变量同名（如图中全局变量 `x` 和函数参数 `x`），那么该名称始终指向局部变量。

**图 2-1.** 局部变量与全局变量

赋值操作实际上也是表达式。它们会返回一个对象（即被赋的值），只是以静默方式返回。R 认为某些表达式是"不可见的"——虽然它们会像所有表达式一样求值得到某个值，但 R 不会打印结果。赋值操作正是以这种方式不可见；它们确实会返回赋值运算符右侧的值，但 R 使结果不可见。你可以将赋值语句放在括号中，从而移除这种不可见性。括号会让 R 移除表达式结果的不可见性，因此你能看到实际的值：

```
(x <- 1:5)
## [1] 1 2 3 4 5
```

你也可以反其道而行之，使值变为不可见。通常，当你求值一个表达式时，R 会打印它：

```
x**2
## [1] 1 4 9 16 25
```

但如果你将表达式放入 `invisible` 函数调用中，R 将不会打印结果：

```
invisible(x**2)
```

我们通常利用赋值操作的副作用（为值赋予名称），因此你可能会忘记它们也是表达式；但事实上，你在 R 中执行的一切都是表达式。这包括像 `if` 语句和 `for` 循环这样的控制结构。它们都会返回值。它们实际上是函数本身，并且会返回值。如果你求值一个 `if` 语句，你会得到它所执行分支中最后一个表达式的值：

```
if (2 + 2 == 4) "美丽新世界" else "一九八四"
## [1] "美丽新世界"
```

如果你求值一个循环，你会得到值 `NULL`（而不是循环体中的最后一个表达式）：

```
x <- for (i in 1:10) i
x
## NULL
```

甚至括号和下标操作也是函数。括号求值为你放入其中的值（但会剥离不可见性），而下标操作 `[...]` 或 `[[...]]` 则会求值为你所访问的数据结构上的某个适当值（如果你愿意，也可以为你自己的数据结构定义这种工作方式）。

如果你希望在函数最后一个表达式之前返回一个值，可以使用 `return` 函数。它看起来可能像关键字，但*它*是一个函数，使用时需要包含括号。许多语言允许你这样写来返回值：

```
return expression
```

但 R 不行。在 R 中，你需要这样写：

```
return(expression)
```

如果你试图返回一个值，这不会造成太大麻烦。如果你使用前一种语法而非后一种，R 会提示语法错误。真正可能出问题的情况是，当你希望从函数中返回但不提供值（此时函数会自动返回 `NULL`）时。

如果你写成这样：

```
f <- function(x) {
  if (x < 0) return;
  # 这里执行其他操作...
}
```

当 `x` 为负数时，并不会返回。`if` 表达式求值得到的是 `return` 函数本身，而非你期望的行为。相反，你必须写成：

```
f <- function(x) {
  if (x < 0) return();
  # 这里执行其他操作...
}
```

如果 `x` 为负数，我们会调用 `return()`，这将返回 `NULL`。（要返回某个值 `val`，请使用 `return(val)`。）

`return` 通常用于提前退出函数，在大多数 R 代码中并不常用。相比显式使用 `return`，让函数最后一个表达式成为返回值更为简单。但你可以像这样用它提前返回：

```
rescale <- function(x, only_translate) {
  m <- mean(x)
  translated <- x - m
  if (only_translate) return(translated)
  s <- sd(x)
  translated / s
}

rescale(1:4, TRUE)
## [1] -1.5 -0.5 0.5 1.5

rescale(1:4, FALSE)
```

## [1] -1.1618950 -0.3872983 0.3872983 1.1618950

该函数有两个参数：`x` 和 `only_translate`。你的函数可以包含任意数量的参数。然而，当函数需要很多参数时，记住它们的传入顺序就会变得困难。为解决这个问题，R 语言允许你使用参数名称来向函数提供参数。因此，前面的两次函数调用也可以写成：

`rescale(x = 1:4, only_translate = TRUE)`

`rescale(x = 1:4, only_translate = FALSE)`

## 命名参数与默认参数

如果使用命名参数，顺序就不重要了，因此以下函数调用也是等价的：

`rescale(only_translate = TRUE, x = 1:4)`

`rescale(only_translate = FALSE, x = 1:4)`

你可以混合使用位置参数和命名参数。位置参数必须按照函数定义中的顺序出现，而命名参数则可以按任意顺序排列。以下四个函数调用都是等价的：

`rescale(1:4, only_translate = TRUE)`

`rescale(only_translate = TRUE, 1:4)`

`rescale(x = 1:4, TRUE)`

`rescale(TRUE, x = 1:4)`

当你为函数提供命名参数时，不必使用完整的参数名。任何唯一的前缀都可以。因此，我们也可以使用以下两种函数调用：

`rescale(1:4, o = TRUE)`

`rescale(o = TRUE, 1:4)`

这在进行 R 的交互式工作时很方便，因为它可以节省一些打字量，但在编写程序时我不建议这样做。这样做很容易造成混淆，而且如果函数的作者在函数中添加了一个与你所用前缀相同的新参数，你的代码就会出错。如果函数作者为该参数提供了默认值，那么只要你使用完整的参数名，你的代码就*不会*出错。在这种情况下，不出错比出错更糟糕，因为代码不会执行正确的操作，而你却无法立即察觉到。

# 第 2 章 R 语言中的函数

现在来看默认参数，它们是在函数定义时提供的。

我们本可以像这样为 `rescale` 函数中的 `only_translate` 参数提供一个默认值：

```
rescale <- function(x, only_translate = FALSE) {
  m <- mean(x)
  translated <- x - m
  if (only_translate) return(translated)
  s <- sd(x)
  translated / s
}
```

这样，如果我们调用该函数，并且对 `only_translate` 的默认值感到满意，就只需要提供 `x` 参数。

```
rescale(1:4)
## [1] -1.1618950 -0.3872983 0.3872983 1.1618950
```

R 语言大量使用了默认参数。许多常用的函数，例如绘图函数和模型拟合函数，都有很多参数。这些参数让你能够非常精细地控制函数的行为，使它们非常灵活，并且由于它们有默认值，通常你只需要关注其中少数几个参数。

### “吞噬一切其他参数”的参数：“...”

所有函数都可以接受一个特殊的参数，称为 `...`。该参数通常用于将参数传递给*在*函数*内部调用*的其他函数。举例来说，我们可以利用它来处理 `rescale` 函数中的缺失值 `NA`。

我们可以编写如下代码（这里我是在较短的版本基础上构建）：

```
rescale <- function(x, ...) {
  m <- mean(x, ...)
  s <- sd(x, ...)
  (x - m) / s
}
```

如果我们向这个函数传递一个包含缺失值的向量 `x`，它将返回 `NA`：

```
x <- c(NA, 1:3)
rescale(x)
## [1] NA NA NA NA
```

之前这样做也会导致相同的结果，因为 `mean` 和 `sd` 函数就是这样工作的。但这两个函数都接受一个额外的参数 `na.rm`，该参数会让它们在计算之前移除所有 `NA` 值。现在，我们的 `rescale` 函数也能做到这一点：

```
rescale(x, na.rm = TRUE)
## [1] NA -1 0 1
```

输出中的第一个值仍然是 `NA`。对一个 `NA` 值进行缩放不可能得到其他结果。但其余部分都是缩放后的值，在计算均值和标准差时，那个 `NA` 已被忽略。

`...` 参数允许一个函数接受任何命名参数。如果你编写的函数没有它，那么该函数只能接受预先确定的参数；但如果你添加了这个参数，它就能接受任何命名参数：

```
f <- function(x) x
g <- function(x, ...) x
f(1:4, foo = "bar")
```

```
## Error in f(1:4, foo = "bar"): unused argument (foo = "bar")
g(1:4, foo = "bar")
## [1] 1 2 3 4
```

如果你随后用 `...` 作为参数调用了另一个函数，那么第一个函数不识别的所有参数都会被传递给第二个函数：

```
f <- function(...) list(...)
g <- function(x, y, ...) f(...)
g(x = 1, y = 2, z = 3, w = 4)
## $z
## [1] 3
##
## $w
## [1] 4
```

在前面的例子中，函数 `f` 从 `...` 创建了一个命名元素的列表，正如你所见，它获取了函数 `g` 没有显式接受的参数。

使用 `...` 并不特别安全。通常很难弄清楚它在特定代码段中实际上做了什么。传递给其他函数的内容取决于第一个函数显式接受哪些参数，而当你使用 `...` 调用第二个函数时，你会传递其中的所有参数。如果你调用的函数不知道如何处理它们，就会出现错误：

```
f <- function(w) w
g <- function(x, y, ...) f(...)
g(x = 1, y = 2, z = 3, w = 4)
## Error in f(...): unused argument (z = 3)
```

在 `rescale` 函数中，显式添加 `na.rm` 参数会好得多。

尽管如此，`...` 在 R 语言中仍被频繁使用。这尤其是因为许多函数带有非常多的默认参数，如果将这些参数全部添加到调用它们的函数中，将会非常繁琐且容易出错。此外，在特化泛型函数时，这也是添加参数的最佳方式——泛型函数是另一本书《高级 R 面向对象编程》（本人所著）中的主题。

## 惰性求值

函数调用中使用的表达式在传递给函数之前不会被求值。大多数常见语言采用所谓的传值语义，这意味着在函数被调用之前，所有传递给函数参数的表达式都会被求值。而在 R 语言中，其语义是“按承诺调用”，也称为“惰性求值”。

当你调用一个函数并将表达式作为其参数时，这些表达式并不会在此时被求值。函数接收到的不是求值结果，而是实际的表达式，这些表达式被称为“承诺”（它们是对求值的承诺，当你需要时可以得到一个值），因此有了术语“按承诺调用”。这些表达式只有在实际需要时才被求值，因此也有了术语“惰性求值”。

这对函数的运行方式产生了几个影响。首先，函数中未使用的表达式不会被求值：

```
f <- function(a, b) a
f(2, stop("error if evaluated"))
## [1] 2
f(stop("error if evaluated"), 2)
## Error in f(stop("error if evaluated"), 2): error if evaluated
```

如果你有一个参数只有在特定上下文中才有意义，那么只要只在满足这些必要条件时才引用它，将其作为参数就是足够安全的。

这对于参数的默认值也非常有用。这些默认值在函数的作用域内被求值，因此你可以编写依赖于其他参数的默认值：

```
f <- function(a, b = a) a + b
f(a = 2)
```

然而，这*并不*意味着所有表达式都在函数的作用域内求值。我们将在[第 4 章，b](https://doi.org/10.1007/978-1-4842-9487-1_4)中讨论作用域，但现在，你可以将其视为两个作用域：全局变量所在的全局作用域，以及包含参数和局部变量的函数作用域。

如果你像这样调用一个函数：

`f(a = 2, b = a)`

并且期望 `b` 在函数内部与 `a` 相同，那么你会得到一个错误。

如果幸运的话，当没有名为 `a` 的全局变量时，你会得到一个运行时错误。如果不幸，恰好*存在*一个名为 `a` 的全局变量，那么 `b` 就会被赋值为该值；而如果你期望它被设为 `2`，你的代码就会给出错误的结果。

不过，默认参数可以是使用其他函数参数的表达式，这是安全的。默认参数在函数被调用后才求值，此时它们可以访问其他参数。然而，在调用函数时使用的表达式，无法看到函数内部的局部变量，只能看到调用作用域中的变量。

**图 2-2.** 参数与默认参数的求值位置 请参考图 2-2。我们有一个函数 `f`，它接受两个参数 `a` 和 `b`，其中 `b` 的默认值为 `2*a`。如果我们以 `f(2*a, b = 2*a)` 的形式调用它，那么两个参数都是表达式，R 会知道它们必须在全局作用域中求值，此时 `a` 是列表 `1 2 3 4 5`，并且没有 `b`。在我们查看参数之前，这两个参数都不会被求值；但当我们查看时，两者都会被求值，并且由于它们都是 `2*a` 且 `a` 指向全局变量 `a`，因此得到相同的值。然而，如果我们以 `f(2*a)` 的形式调用 `f`，从而使 `b` 使用默认值，情况就不同了。在函数调用内部，`a` 仍然指向需要在全局作用域中求值的表达式 `2*a`，但 `b`（同样指向表达式 `2*a`）将在*局部*作用域中求值。因此，如果我们对 `b` 求值，我们首先会求值参数 `a` 得到 `2*a`（使用全局变量 `a` 求值）`2 4 6 8 10`，然后使用这个局部变量 `a` 求值 `2*a`，得到 `4 8 12 16 20`。

所以，尽管调用函数时参数尚未求值，但当你访问它们时就会被求值。如果是默认参数，则在函数内部求值；如果是在函数调用中提供的参数，则在调用处（函数被调用的地方）外部求值。

这也意味着，你不能仅仅通过更改局部变量来改变表达式的求值结果：

```
a <- 4
f <- function(x) {
  a <- 2
  x
}
f(1 + a)
## [1] 5
```

在这个例子中，表达式 `1 + a` 在 `f` 内部求值，但表达式中的 `a` 是 `f` 外部的 `a`，而不是 `f` 内部的局部变量 `a`。

这当然是符合预期的。如果表达式真的在函数的作用域内求值，那么当你用一个表达式调用函数时，你将完全无法预知其求值结果，因为它会取决于函数可能使用的任何局部变量。

由于表达式在调用作用域而非函数作用域中求值，因此你通常不会注意到传值调用（call-by-value）与传承诺调用（call-by-promise）之间的区别。不过，在某些情况下，如果你不小心，这种区别可能会带来麻烦。

举个例子，我们可以考虑这个函数：

`f <- function(a) function(b) a + b`

如果你不习惯，这看起来可能有点奇怪，但它是一个返回另一个函数的函数。在后续章节中，我们会看到很多这类函数的例子。

当我们用参数 `a` 调用 `f` 时，我们会得到一个将 `a` 加到其参数上的函数：

```
f(2)(2)
## [1] 4
```

### 第 2 章 R 语言中的函数

然而，当我们调用 `ff` 中的函数时，奇怪的事情发生了：

```
ff[[1]](1)
## [1] 5
```

当我们获取元素 `ff[[1]]` 时，得到的是我们在循环中创建的第一个函数。如果我们将调用 `f` 时传入的值代入，它应该是 `function(b) i + b`。

`f` 的参数 `a` 已被设为我们传入的参数 `i`，但此时 `i` 尚未被求值！

当我们调用这个函数时，表达式在全局作用域中被求值，而此时的 `i` 值为 `4`，因为这是它在循环中被赋予的最后一个值。我们创建函数时 `i` 的值是 `1`，但表达式实际被求值时它变成了 `5`。

这也意味着，我们可以在求值某个函数之前更改 `i` 的值，这会使其与我们在创建函数时预期的值不同：

```
i <- 1
ff[[2]](1)
## [1] 2
```

这种惰性求值只在第一次调用函数时生效。如果我们再次更改 `i` 并调用该函数，得到的值与第一次求值时相同：

```
i <- 2
ff[[2]](1)
## [1] 2
```

### 第 2 章 R 语言中的函数

我们可以通过循环遍历这些函数并求值来看到这一效果：

```
results <- vector("numeric", 4)
for (i in 1:4) {
  results[i] <- ff[[i]](1)
}
results
## [1] 5 2 4 5
```

我们已经对前两个函数求过值了，因此它们被固定在了第一次求值时的结果。另外两个函数得到了预期的功能，但仅仅是因为我们在求值函数的循环中设置了变量 `i`。如果我们使用了不同的循环变量，就不会这么幸运了。

这个问题源于函数包含一个未求值的表达式，且该表达式依赖于外部作用域中的变量。不过，如果你想利用函数式语言的优势，返回函数的函数并不罕见。这也是允许变量改变值的后果——出于类似原因，大多数函数式编程语言都不允许变量改变值。然而，仅仅通过避免 `for` 循环，你并不能完全避免这个问题。如果你调用的函数为你进行了循环，你未必能控制它们如何执行，最终可能陷入同样的境地。

避免问题的方法是强制对参数进行求值。一旦你对其求值，它就会记住该值，问题就不复存在了。

你可以通过将参数写成一个单独的语句来实现这一点。

这样会对它求值。不过，最好使用 `force` 函数，以明确表明你正在这样做。它实际上只是将表达式返回给你，因此其效果与直接写参数完全相同，但代码能更清楚地表明你为何这样做。

### 第 2 章 R 语言中的函数

如果你这样做，问题就消失了：

```
f <- function(a) {
  force(a)
  function(b) a + b
}
ff <- vector("list", 4)
for (i in 1:4) {
  ff[[i]] <- f(i)
}
ff[[1]](1)
## [1] 2
i <- 1
ff[[2]](1)
```

## 第 2 章：R 语言中的函数

本章将介绍如何在 R 中编写函数。如果你对大部分内容已有所了解，可以放心跳过。我们将讨论参数如何作为"承诺"传递给函数——这种参数传递方式被称为惰性求值。如果你不熟悉这个概念但会编写函数，可以直接跳到该部分。我们还会介绍如何编写中缀运算符和替换函数，如果你不清楚这些是什么以及如何编写，也可以直接跳转到相关章节。如果你是 R 函数的新手，请从这里开始阅读。

## 在 R 中编写函数

你可以使用 `function` 关键字来创建 R 函数，或者从 R 4.1 开始，也可以使用 `\()` 语法。例如，我们可以这样编写一个计算平方的函数：

```
square <- function(x) x**2
```

或者这样写：

```
square <- \(x) x**2
```

然后这样使用：

```
square(1:5)
## [1] 1 4 9 16 25
```

T. Mailund, *R 4 中的函数式编程*, https://doi.org/10.1007/978-1-4842-9487-1_2

较短的语法 `\(x) x**2` 专为所谓的"lambda 表达式"设计，反斜杠符号旨在模仿希腊字母 lambda（λ）。当我们需要将简短函数作为参数传递给其他函数时，lambda 表达式非常有用——我们将在后续章节中讨论这一点。通常，在定义可复用的函数时，我们使用 `function()` 语法，在定义并命名函数时（如之前的 `square`），我将坚持使用这种写法。

我们编写的函数接受一个参数 `x`，并返回结果 `x**2`。函数的返回值始终是函数体内最后一个表达式的值。如果函数只有一个表达式，你可以像之前那样编写；但对于更复杂的函数，通常需要多条语句。这时，你可以将函数体放入花括号中，如下所示：

```
square <- function(x) {
  x**2
}
```

下面的函数需要花括号，因为它需要三条独立的语句来计算返回值：第一条计算输入的均值，第二条获取标准差，最后一条返回以均值为中心、标准差为单位的缩放后输入值。

```
rescale <- function(x) {
  m <- mean(x)
  s <- sd(x)
  (x - m) / s
}
```

前两条语句仅用于定义一些可在最后一条表达式中使用的变量。这是编写短函数的典型做法。

在函数内部赋值的变量仅在函数内部可见。当函数执行完毕后，这些变量将不复存在。从函数内部，你可以看到所谓的*局部*变量（函数参数和在函数体内赋值的变量），以及所谓的*全局*变量（在函数外部赋值的变量）。然而，在函数外部，你只能看到全局变量。至少在我们深入探讨[第 4 章](https://doi.org/10.1007/978-1-4842-9487-1_4)的细节之前，这是一种理解程序中任意时刻可见变量的好方法。目前，我们暂且从全局变量和局部变量的角度思考：在函数外部编写的任何内容都属于第一类，所有人都能看到；而函数参数和在函数内部赋值的变量则属于第二类；参见图 2-1。如果全局变量和局部变量同名（如图中全局变量 `x` 和函数参数 `x`），那么该名称始终指向局部变量。

赋值操作实际上也是表达式。它们会返回一个对象（即被赋的值），只是以静默方式返回。R 认为某些表达式是"不可见的"——虽然它们会像所有表达式一样求值得到某个值，但 R 不会打印结果。赋值操作正是以这种方式不可见；它们确实会返回赋值运算符右侧的值，但 R 使结果不可见。你可以将赋值语句放在括号中，从而移除这种不可见性。括号会让 R 移除表达式结果的不可见性，因此你能看到实际的值：

```
(x <- 1:5)
## [1] 1 2 3 4 5
```

你也可以反其道而行之，使值变为不可见。通常，当你求值一个表达式时，R 会打印它：

```
x**2
## [1] 1 4 9 16 25
```

但如果你将表达式放入 `invisible` 函数调用中，R 将不会打印结果：

```
invisible(x**2)
```

我们通常利用赋值操作的副作用（为值赋予名称），因此你可能会忘记它们也是表达式；但事实上，你在 R 中执行的一切都是表达式。这包括像 `if` 语句和 `for` 循环这样的控制结构。它们都会返回值。它们实际上是函数本身，并且会返回值。如果你求值一个 `if` 语句，你会得到它所执行分支中最后一个表达式的值：

```
if (2 + 2 == 4) "美丽新世界" else "一九八四"
## [1] "美丽新世界"
```

如果你求值一个循环，你会得到值 `NULL`（而不是循环体中的最后一个表达式）：

```
x <- for (i in 1:10) i
x
## NULL
```

甚至括号和下标操作也是函数。括号求值为你放入其中的值（但会剥离不可见性），而下标操作 `[...]` 或 `[[...]]` 则会求值为你所访问的数据结构上的某个适当值（如果你愿意，也可以为你自己的数据结构定义这种工作方式）。

如果你希望在函数最后一个表达式之前返回一个值，可以使用 `return` 函数。它看起来可能像关键字，但*它*是一个函数，使用时需要包含括号。许多语言允许你这样写来返回值：

```
return expression
```

但 R 不行。在 R 中，你需要这样写：

```
return(expression)
```

如果你试图返回一个值，这不会造成太大麻烦。如果你使用前一种语法而非后一种，R 会提示语法错误。真正可能出问题的情况是，当你希望从函数中返回但不提供值（此时函数会自动返回 `NULL`）时。

如果你写成这样：

```
f <- function(x) {
  if (x < 0) return;
  # 这里执行其他操作...
}
```

当 `x` 为负数时，并不会返回。`if` 表达式求值得到的是 `return` 函数本身，而非你期望的行为。相反，你必须写成：

```
f <- function(x) {
  if (x < 0) return();
  # 这里执行其他操作...
}
```

如果 `x` 为负数，我们会调用 `return()`，这将返回 `NULL`。（要返回某个值 `val`，请使用 `return(val)`。）

`return` 通常用于提前退出函数，在大多数 R 代码中并不常用。相比显式使用 `return`，让函数最后一个表达式成为返回值更为简单。但你可以像这样用它提前返回：

```
rescale <- function(x, only_translate) {
  m <- mean(x)
  translated <- x - m
  if (only_translate) return(translated)
  s <- sd(x)
  translated / s
}

rescale(1:4, TRUE)
## [1] -1.5 -0.5 0.5 1.5

rescale(1:4, FALSE)
```

## [1] -1.1618950 -0.3872983 0.3872983 1.1618950

该函数有两个参数：`x` 和 `only_translate`。你的函数可以包含任意数量的参数。然而，当函数需要很多参数时，记住它们的传入顺序就会变得困难。为解决这个问题，R 语言允许你使用参数名称来向函数提供参数。因此，前面的两次函数调用也可以写成：

`rescale(x = 1:4, only_translate = TRUE)`

`rescale(x = 1:4, only_translate = FALSE)`

## 命名参数与默认参数

如果使用命名参数，顺序就不重要了，因此以下函数调用也是等价的：

`rescale(only_translate = TRUE, x = 1:4)`

`rescale(only_translate = FALSE, x = 1:4)`

你可以混合使用位置参数和命名参数。位置参数必须按照函数定义中的顺序出现，而命名参数则可以按任意顺序排列。以下四个函数调用都是等价的：

`rescale(1:4, only_translate = TRUE)`

`rescale(only_translate = TRUE, 1:4)`

`rescale(x = 1:4, TRUE)`

`rescale(TRUE, x = 1:4)`

当你为函数提供命名参数时，不必使用完整的参数名。任何唯一的前缀都可以。因此，我们也可以使用以下两种函数调用：

`rescale(1:4, o = TRUE)`

`rescale(o = TRUE, 1:4)`

这在进行 R 的交互式工作时很方便，因为它可以节省一些打字量，但在编写程序时我不建议这样做。这样做很容易造成混淆，而且如果函数的作者在函数中添加了一个与你所用前缀相同的新参数，你的代码就会出错。如果函数作者为该参数提供了默认值，那么只要你使用完整的参数名，你的代码就*不会*出错。在这种情况下，不出错比出错更糟糕，因为代码不会执行正确的操作，而你却无法立即察觉到。




现在来看默认参数，它们是在函数定义时提供的。

我们本可以像这样为 `rescale` 函数中的 `only_translate` 参数提供一个默认值：

```
rescale <- function(x, only_translate = FALSE) {
  m <- mean(x)
  translated <- x - m
  if (only_translate) return(translated)
  s <- sd(x)
  translated / s
}
```

这样，如果我们调用该函数，并且对 `only_translate` 的默认值感到满意，就只需要提供 `x` 参数。

```
rescale(1:4)
## [1] -1.1618950 -0.3872983 0.3872983 1.1618950
```

R 语言大量使用了默认参数。许多常用的函数，例如绘图函数和模型拟合函数，都有很多参数。这些参数让你能够非常精细地控制函数的行为，使它们非常灵活，并且由于它们有默认值，通常你只需要关注其中少数几个参数。

### “吞噬一切其他参数”的参数：“...”

所有函数都可以接受一个特殊的参数，称为 `...`。该参数通常用于将参数传递给*在*函数*内部调用*的其他函数。举例来说，我们可以利用它来处理 `rescale` 函数中的缺失值 `NA`。

我们可以编写如下代码（这里我是在较短的版本基础上构建）：

```
rescale <- function(x, ...) {
  m <- mean(x, ...)
  s <- sd(x, ...)
  (x - m) / s
}
```

如果我们向这个函数传递一个包含缺失值的向量 `x`，它将返回 `NA`：

```
x <- c(NA, 1:3)
rescale(x)
## [1] NA NA NA NA
```

之前这样做也会导致相同的结果，因为 `mean` 和 `sd` 函数就是这样工作的。但这两个函数都接受一个额外的参数 `na.rm`，该参数会让它们在计算之前移除所有 `NA` 值。现在，我们的 `rescale` 函数也能做到这一点：

```
rescale(x, na.rm = TRUE)
## [1] NA -1 0 1
```

输出中的第一个值仍然是 `NA`。对一个 `NA` 值进行缩放不可能得到其他结果。但其余部分都是缩放后的值，在计算均值和标准差时，那个 `NA` 已被忽略。

`...` 参数允许一个函数接受任何命名参数。如果你编写的函数没有它，那么该函数只能接受预先确定的参数；但如果你添加了这个参数，它就能接受任何命名参数：

```
f <- function(x) x
g <- function(x, ...) x
f(1:4, foo = "bar")
```

```
## Error in f(1:4, foo = "bar"): unused argument (foo = "bar")
g(1:4, foo = "bar")
## [1] 1 2 3 4
```

如果你随后用 `...` 作为参数调用了另一个函数，那么第一个函数不识别的所有参数都会被传递给第二个函数：

```
f <- function(...) list(...)
g <- function(x, y, ...) f(...)
g(x = 1, y = 2, z = 3, w = 4)
## $z
## [1] 3
##
## $w
## [1] 4
```

在前面的例子中，函数 `f` 从 `...` 创建了一个命名元素的列表，正如你所见，它获取了函数 `g` 没有显式接受的参数。

使用 `...` 并不特别安全。通常很难弄清楚它在特定代码段中实际上做了什么。传递给其他函数的内容取决于第一个函数显式接受哪些参数，而当你使用 `...` 调用第二个函数时，你会传递其中的所有参数。如果你调用的函数不知道如何处理它们，就会出现错误：

```
f <- function(w) w
g <- function(x, y, ...) f(...)
g(x = 1, y = 2, z = 3, w = 4)
## Error in f(...): unused argument (z = 3)
```

在 `rescale` 函数中，显式添加 `na.rm` 参数会好得多。

尽管如此，`...` 在 R 语言中仍被频繁使用。这尤其是因为许多函数带有非常多的默认参数，如果将这些参数全部添加到调用它们的函数中，将会非常繁琐且容易出错。此外，在特化泛型函数时，这也是添加参数的最佳方式——泛型函数是另一本书《高级 R 面向对象编程》（本人所著）中的主题。

## 惰性求值

函数调用中使用的表达式在传递给函数之前不会被求值。大多数常见语言采用所谓的传值语义，这意味着在函数被调用之前，所有传递给函数参数的表达式都会被求值。而在 R 语言中，其语义是“按承诺调用”，也称为“惰性求值”。

当你调用一个函数并将表达式作为其参数时，这些表达式并不会在此时被求值。函数接收到的不是求值结果，而是实际的表达式，这些表达式被称为“承诺”（它们是对求值的承诺，当你需要时可以得到一个值），因此有了术语“按承诺调用”。这些表达式只有在实际需要时才被求值，因此也有了术语“惰性求值”。

这对函数的运行方式产生了几个影响。首先，函数中未使用的表达式不会被求值：

```
f <- function(a, b) a
f(2, stop("error if evaluated"))
## [1] 2
f(stop("error if evaluated"), 2)
## Error in f(stop("error if evaluated"), 2): error if evaluated
```

如果你有一个参数只有在特定上下文中才有意义，那么只要只在满足这些必要条件时才引用它，将其作为参数就是足够安全的。

这对于参数的默认值也非常有用。这些默认值在函数的作用域内被求值，因此你可以编写依赖于其他参数的默认值：

```
f <- function(a, b = a) a + b
f(a = 2)
```

然而，这*并不*意味着所有表达式都在函数的作用域内求值。我们将在[第 4 章，b](https://doi.org/10.1007/978-1-4842-9487-1_4)中讨论作用域，但现在，你可以将其视为两个作用域：全局变量所在的全局作用域，以及包含参数和局部变量的函数作用域。

如果你像这样调用一个函数：

`f(a = 2, b = a)`

并且期望 `b` 在函数内部与 `a` 相同，那么你会得到一个错误。

如果幸运的话，当没有名为 `a` 的全局变量时，你会得到一个运行时错误。如果不幸，恰好*存在*一个名为 `a` 的全局变量，那么 `b` 就会被赋值为该值；而如果你期望它被设为 `2`，你的代码就会给出错误的结果。

不过，默认参数可以是使用其他函数参数的表达式，这是安全的。默认参数在函数被调用后才求值，此时它们可以访问其他参数。然而，在调用函数时使用的表达式，无法看到函数内部的局部变量，只能看到调用作用域中的变量。

**图 2-2.** 参数与默认参数的求值位置 请参考图 2-2。我们有一个函数 `f`，它接受两个参数 `a` 和 `b`，其中 `b` 的默认值为 `2*a`。如果我们以 `f(2*a, b = 2*a)` 的形式调用它，那么两个参数都是表达式，R 会知道它们必须在全局作用域中求值，此时 `a` 是列表 `1 2 3 4 5`，并且没有 `b`。在我们查看参数之前，这两个参数都不会被求值；但当我们查看时，两者都会被求值，并且由于它们都是 `2*a` 且 `a` 指向全局变量 `a`，因此得到相同的值。然而，如果我们以 `f(2*a)` 的形式调用 `f`，从而使 `b` 使用默认值，情况就不同了。在函数调用内部，`a` 仍然指向需要在全局作用域中求值的表达式 `2*a`，但 `b`（同样指向表达式 `2*a`）将在*局部*作用域中求值。因此，如果我们对 `b` 求值，我们首先会求值参数 `a` 得到 `2*a`（使用全局变量 `a` 求值）`2 4 6 8 10`，然后使用这个局部变量 `a` 求值 `2*a`，得到 `4 8 12 16 20`。

所以，尽管调用函数时参数尚未求值，但当你访问它们时就会被求值。如果是默认参数，则在函数内部求值；如果是在函数调用中提供的参数，则在调用处（函数被调用的地方）外部求值。

这也意味着，你不能仅仅通过更改局部变量来改变表达式的求值结果：

```
a <- 4
f <- function(x) {
  a <- 2
  x
}
f(1 + a)
## [1] 5
```

在这个例子中，表达式 `1 + a` 在 `f` 内部求值，但表达式中的 `a` 是 `f` 外部的 `a`，而不是 `f` 内部的局部变量 `a`。

这当然是符合预期的。如果表达式真的在函数的作用域内求值，那么当你用一个表达式调用函数时，你将完全无法预知其求值结果，因为它会取决于函数可能使用的任何局部变量。

由于表达式在调用作用域而非函数作用域中求值，因此你通常不会注意到传值调用（call-by-value）与传承诺调用（call-by-promise）之间的区别。不过，在某些情况下，如果你不小心，这种区别可能会带来麻烦。

举个例子，我们可以考虑这个函数：

`f <- function(a) function(b) a + b`

如果你不习惯，这看起来可能有点奇怪，但它是一个返回另一个函数的函数。在后续章节中，我们会看到很多这类函数的例子。

当我们用参数 `a` 调用 `f` 时，我们会得到一个将 `a` 加到其参数上的函数：

```
f(2)(2)
## [1] 4
```




我们可以基于这个 `f` 创建一个函数列表：

```
ff <- vector("list", 4)
for (i in 1:4) {
  ff[[i]] <- f(i)
}
ff
## [[1]]
## function(b) a + b
## <bytecode: 0x7fe446ad68a8>
## <environment: 0x7fe446a07ca0>
##
## [[2]]
## function(b) a + b
## <bytecode: 0x7fe446ad68a8>
## <environment: 0x7fe446ad71e8>
##
## [[3]]
## function(b) a + b
## <bytecode: 0x7fe446ad68a8>
## <environment: 0x7fe446ad7098>
##
## [[4]]
## function(b) a + b
## <bytecode: 0x7fe446ad68a8>
## <environment: 0x7fe446ad6f48>
```

这里，`ff` 包含了四个函数，它们的意图是：第一个函数对其参数加 `1`，第二个加 `2`，以此类推。




然而，当我们调用 `ff` 中的函数时，奇怪的事情发生了：

```
ff[[1]](1)
## [1] 5
```

当我们获取元素 `ff[[1]]` 时，得到的是我们在循环中创建的第一个函数。如果我们将调用 `f` 时传入的值代入，它应该是 `function(b) i + b`。

`f` 的参数 `a` 已被设为我们传入的参数 `i`，但此时 `i` 尚未被求值！

当我们调用这个函数时，表达式在全局作用域中被求值，而此时的 `i` 值为 `4`，因为这是它在循环中被赋予的最后一个值。我们创建函数时 `i` 的值是 `1`，但表达式实际被求值时它变成了 `5`。

这也意味着，我们可以在求值某个函数之前更改 `i` 的值，这会使其与我们在创建函数时预期的值不同：

```
i <- 1
ff[[2]](1)
## [1] 2
```

这种惰性求值只在第一次调用函数时生效。如果我们再次更改 `i` 并调用该函数，得到的值与第一次求值时相同：

```
i <- 2
ff[[2]](1)
## [1] 2
```




我们可以通过循环遍历这些函数并求值来看到这一效果：

```
results <- vector("numeric", 4)
for (i in 1:4) {
  results[i] <- ff[[i]](1)
}
results
## [1] 5 2 4 5
```

我们已经对前两个函数求过值了，因此它们被固定在了第一次求值时的结果。另外两个函数得到了预期的功能，但仅仅是因为我们在求值函数的循环中设置了变量 `i`。如果我们使用了不同的循环变量，就不会这么幸运了。

这个问题源于函数包含一个未求值的表达式，且该表达式依赖于外部作用域中的变量。不过，如果你想利用函数式语言的优势，返回函数的函数并不罕见。这也是允许变量改变值的后果——出于类似原因，大多数函数式编程语言都不允许变量改变值。然而，仅仅通过避免 `for` 循环，你并不能完全避免这个问题。如果你调用的函数为你进行了循环，你未必能控制它们如何执行，最终可能陷入同样的境地。

避免问题的方法是强制对参数进行求值。一旦你对其求值，它就会记住该值，问题就不复存在了。

你可以通过将参数写成一个单独的语句来实现这一点。

这样会对它求值。不过，最好使用 `force` 函数，以明确表明你正在这样做。它实际上只是将表达式返回给你，因此其效果与直接写参数完全相同，但代码能更清楚地表明你为何这样做。

## 函数没有名称

在讨论函数定义时，我想强调的最后一点是：函数本身并没有名称。变量才有名称，变量可以指向函数，但这是两个不同的概念。

在许多语言，比如 Java、Python 或 C++ 中，当你定义一个函数时，同时也会给它一个名称。即便在允许的情况下，你也需要借助特殊的语法才能定义一个没有名称的函数。

但在 R 语言中并非如此。在 R 里，函数没有名称，当你定义它们时，并没有赋予它们名字。之前我们使用过的所有函数，都是通过在定义处将它们赋值给变量来命名的。但我们并非必须这样做。实际上，是`function(...)`这个语法定义了函数。无论我们是否将其赋值给变量，都是在定义一个函数。




我们可以像这样定义一个函数并立即调用它：`(function(x) x²)(2)`

## [1] 4

当然，我们通常不会这样做。在任何需要定义匿名函数并立即调用的场景下，我们大可直接使用函数体。对于想要复用的函数，我们必须给它一个名称，以便能够再次调用它。

然而，定义函数的语法并不强制我们给函数命名。当你开始编写高阶函数（即接受其他函数作为输入或返回函数的函数）时，这种特性会非常便利。

这类高阶函数是函数式编程的重要组成部分，我们在本书后面会经常遇到它们。

## 向量化函数

R 语言中的表达式是向量化的。当你编写一个表达式时，它会隐式地作用于值的向量，而不是单个值。即使是只涉及数字的简单表达式，本质上也是向量运算，只不过这些向量的长度为 1。

对于更长的向量，表达式会按元素逐个进行计算。因此，如果你有向量`x`和`y`，只需写成`x - y`就可以实现第二个向量元素减去第一个向量元素的操作：

```
x <- 1:5
y <- 6:10
x - y
```

输出：
```
## [1] -5 -5 -5 -5 -5
```

如果向量的长度不同，较短的向量会根据需要被重复多次。这就是为什么你可以将一个数与一个向量相乘，例如：

```
2 * x
```

输出：
```
## [1] 2 4 6 8 10
```

这里，`2`是长度为 1 的向量，`x`是长度为 5 的向量，`2`被重复了五次。如果较长向量的长度不是较短向量长度的整数倍，你会收到一个警告，通常应尽量避免这种情况。不过语义是一样的：R 会尽可能多次地重复较短的向量，直到与较长向量长度匹配。

```
x <- 1:6
y <- 1:3
x - y
```

输出：
```
## [1] 0 0 0 3 3 3
```

根据函数的编写方式，它也可以用在向量化表达式中。只要函数调用的结果是一个向量，R 就乐意将其用于向量表达式。但这与函数对向量按元素进行操作并非完全相同。这样的函数我们可以称之为向量化函数。

大多数数学函数，如`sqrt`、`log`、`cos`和`sin`，都是向量化的，你可以在表达式中使用它们：

```
log(1:3) - sqrt(1:3)
```

输出：
```
## [1] -1.0000000 -0.7210664 -0.6334385
```

如果你自己编写的函数的主体仅包含向量化表达式，那么该函数也会是向量化的：

```
f <- function(a, b) log(a) - sqrt(b)
f(1:3, 1:3)
```

输出：
```
## [1] -1.0000000 -0.7210664 -0.6334385
```

我们在本书中编写的第一个函数`square`也是一个向量化函数。函数`scale`同样如此，尽管它内部使用的`mean`和`sd`函数并非向量化函数；它们接收向量输入，但返回的是整个向量的汇总统计量，而不是对向量分量进行操作。

使用了控制结构的函数通常不会是向量化的。

我们可以编写一个比较函数，如果第一个参数小于第二个参数则返回 -1，如果第二个参数大于第一个参数则返回 1，否则返回 0，如下所示：

```
compare <- function(x, y) {
  if (x < y) {
    -1
  } else if (y < x) {
    1
  } else {
    0
  }
}
```

这个函数对于单个值工作良好，但不适用于向量。问题在于`if`表达式只会查看逻辑向量`x < y`的第一个元素。（没错，`x < y`是一个向量，因为`<`是一个向量化函数。）

为了处理`if`表达式，我们可以使用`ifelse`函数来绕过这个问题。这是一个向量化函数，其行为类似于 if-else 表达式：

```
compare <- function(x, y) {
  ifelse(x < y, -1, ifelse(y < x, 1, 0))
}
compare(1:6, 1:3)
```

输出：
```
## [1] 0 0 0 1 1 1
```

情况并非总是简单到可以用`ifelse`替换 if 语句。大多数情况下可以，但当不能时，我们可以改用`Vectorize`函数。这个函数接受一个可操作单个值的函数，并将其转换为能按元素处理向量的函数。

举个例子，我们可以使用之前的`compare`函数并对其进行向量化：

```
compare <- function(x, y) {
  if (x < y) {
    -1
  } else if (y < x) {
    1
  } else {
    0
  }
}
compare <- Vectorize(compare)
compare(1:6, 1:3)
```

输出：
```
## [1] 0 0 0 1 1 1
```

默认情况下，`Vectorize`会对函数的所有参数进行向量化。例如，假设我们想要一个缩放函数，它不按同一个向量的均值和标准差来缩放该向量中的所有变量，而是使用另一个向量的均值和标准差：

```
scale_with <- function(x, y) {
  (x - mean(y)) / sd(y)
}
```

这个函数在其第一个参数上已经是向量化的了，因为它仅由一个向量化表达式组成，但如果对其使用`Vectorize`，反而会破坏它：

```
scale_with(1:6, 1:3)
```

输出：
```
## [1] -1 0 1 2 3 4
```

```
scale_with <- Vectorize(scale_with)
scale_with(1:6, 1:3)
```

输出：
```
## [1] NA NA NA NA NA NA
```

用`Vectorize`创建的函数对`x`和`y`都是向量化的，这意味着它会按分量对它们进行操作。在缩放时，该函数只看到`y`的一个分量，而不是整个向量。结果会得到一个缺失值向量`NA`，因为单个值的标准差是未定义的。

我们可以通过显式告诉`Vectorize`哪些参数需要向量化来解决这个问题——在本例中，只有参数`x`：

```
scale_with <- function(x, y) {
  (x - mean(y)) / sd(y)
}
scale_with <- Vectorize(scale_with, vectorize.args = "x")
scale_with(1:6, 1:3)
```

输出：
```
## [1] -1 0 1 2 3 4
```

简单的函数通常已经是向量化的，或者可以通过`ifelse`轻松实现向量化，但对于更复杂的函数，则需要用到`Vectorize`函数。

举个例子，我们可以考虑一个树形数据结构，以及一个用于计算命名节点深度的函数——节点深度定义为到根节点的距离。为简单起见，我们只考虑二叉树。

我们可以使用列表来实现树：

```
make_node <- function(name, left = NULL, right = NULL) list(name = name, left = left, right = right)

tree <- make_node("root",
                  make_node("C", make_node("A"),
                            make_node("B")),
                  make_node("D"))
```

要计算节点深度，我们可以递归地遍历树：

```
node_depth <- function(tree, name, depth = 0) {
  if (is.null(tree)) return(NA)
  if (tree$name == name) return(depth)
  left <- node_depth(tree$left, name, depth + 1)
  if (!is.na(left)) return(left)
  right <- node_depth(tree$right, name, depth + 1)
  return(right)
}
```

这并非一个特别复杂的函数，但它比`scale_with`函数更难向量化。就其本身而言，它对单个名称运行良好：

```
node_depth(tree, "D")
```

输出：
```
## [1] 1
```

```
node_depth(tree, "A")
```

输出：
```
## [1] 2
```

但如果你在一个名称序列上调用它，你会得到一个错误：
```r
node_depth(tree, c("A", "B", "C", "D"))
```
## [1] 2 2 1 1

不难想象，向量化版本会很有用。例如，要获取一个名称序列的深度：
```r
node_depth <- Vectorize(node_depth, vectorize.args = "name", USE.NAMES = FALSE)
node_depth(tree, c("A", "B", "C", "D"))
```
## [1] 2 2 1 1

这里，需要设置`USE.NAMES = FALSE`才能得到一个简单的向量。如果不设置，向量将基于输入变量包含名称。详情请参阅`Vectorize`的文档。

## 中缀运算符

R 中的中缀运算符也是函数。你可以用其他函数覆盖它们（但你真的不应该这样做，因为可能会搞乱大量代码），你也可以创建自己的中缀运算符。

用户定义的中缀运算符是具有特殊名称的函数。名称以`%`开头和结尾的函数会被 R 视为中缀运算符。创建用作中缀运算符的函数没有特殊语法，只是它应该接受两个参数。不过，变量赋值有特殊语法，包括名称以`%`开头和结尾的变量。

### 第 2 章 R 中的函数

要处理特殊变量，你需要用反引号引用它们。你不能写`+(2, 2)`，尽管`+`是一个函数。R 不会将其理解为一个函数调用。但你可以引用`+`，写成`` `+` ``，然后它就像所有其他变量名一样是一个变量名：

```r
`+`(2, 2)
```
## [1] 4

这同样适用于 R 中所有其他中缀运算符，甚至控制结构：

```r
`if`(2 > 3, "true", "false")
```
## [1] "false"

R 解析器识别控制结构关键字和各种运算符，例如算术运算符，因此它们拥有特殊语法。但它们实际上都只是函数。甚至括号也是函数`(`的特殊语法，下标运算符也是如此，分别是`` `[` ``和`` `[[` ``。如果你引用它们，你就得到了一个变量名，可以像使用其他任何函数名一样使用它。

就像所有这些运算符都有特殊语法一样，以`%`开头和结尾的变量也有特殊语法。R 期望它们是中缀运算符，并将像`exp1 %op% exp2`这样的表达式视为函数调用`` `%op%`(exp1, exp2) ``。

知道你可以通过引用运算符名将其转换为函数名，也告诉了你如何定义新的中缀运算符。如果你将一个函数赋值给一个变量名，你就可以通过该名称引用它。

### 第 2 章 R 中的函数

如果该名称是一个被引用的特殊名称，它就可以使用该名称的特殊语法。

因此，要定义一个执行乘法的运算符`%x%`，我们可以写：
```r
`%x%` <- `*`
3 %x% 2
```
## [1] 6

这里，我们使用了两次引号，第一次是为`%x%`获取一个可以赋值给它的变量名，第二次是获取乘法运算符`*`所指的函数。

仅仅因为 R 中所有的控制结构和运算符都是你可以覆盖的函数，并不意味着你可以不加极端谨慎地这样做。

你*永远*不应该更改控制结构指向的函数，也不应该更改其他运算符，除非你在新类型上定义运算符，这样相对安全。然而，定义全新的中缀运算符可能非常有用，如果它们能简化你经常编写的表达式的话。

举个例子，让我们对`%x%`运算符做些别的事情——毕竟，乘法没有必要有两个不同的运算符。

我们可以让它将左侧表达式复制右侧数字指定的次数：


### 第 2 章 R 中的函数

出于诚实的考虑，我必须提一下，除了参数顺序交换之外，我们不仅仅是给`replicate`取了个新名字。`%x%`运算符的工作方式略有不同。在`%x%`中，`expr`参数在调用`replicate`时会被求值。所以，如果我们用一个采样随机数的函数调用`%x%`，我们会得到相同的重复结果`num`次；不会采样`num`次。

## 替换函数概念

在 R 语言中，当你给一个变量赋值时，你实际上是在调用赋值函数 `<-`。当你给向量或列表中的某个元素赋值时，你使用的是 `[<-` 函数。但其实还有一整类这样的函数，它们可以让你在不实际修改对象的情况下，做出修改对象的样子。这些函数被称为替换函数，其名称以 `<-` 结尾。一个例子是 `names<-` 函数。如果你有一个向量 `x`，你可以使用如下语法为其元素命名：

```r
x <- 1:4
x
## [1] 1 2 3 4

names(x) <- letters[1:4]
x
## a b c d
## 1 2 3 4

names(x)
## [1] "a" "b" "c" "d"
```

这里涉及两个不同的函数。最后一个表达式，它返回了 `x` 的名称，这是 `names` 函数。而我们用来将名称*赋值*给 `x` 的函数是 `names<-` 函数。

任何你定义的、名称以 `<-` 结尾的函数都会成为一个替换函数。其语法是，它会求值赋值运算符右侧的内容，并将结果赋值给它作为参数接收的那个变量。

因此，这个语法

```r
names(x) <- letters[1:4]
```

会被翻译成

```r
x <- `names<-`(x, letters[1:4])
```

在这个求值过程中，没有任何值被破坏，只是变量被设置为了新的值。

## 自定义替换函数

我们可以使用这种语法编写自定义的替换函数。只有两个要求。函数名必须以 `<-` 结尾——因此我们在赋值时需要给名称加上引号——并且，用于赋值运算符右侧的那个值的参数，必须命名为 `value`。最后一个要求的存在，是为了使替换函数可以接受两个以上的参数。

```r
## [1] "bar"
```

## 纯函数式编程

“纯”函数是一种行为与数学函数类似的函数：它将一个空间的值映射到另一个空间，相同的值总是映射到相同的结果，并且数学函数中没有“副作用”这种东西。

编程语言为确保函数纯正所采取的程度各不相同，而 R 语言在这方面做得非常有限。由于值是不可变的，你对函数可能产生的副作用有一定保证，但并不多。函数可以修改其作用域之外的变量，例如修改全局变量。它们可以打印或绘图，并以这种方式改变 R 进程的状态。它们还可以抽取随机数并用其进行计算，从而在某种意义上使函数的结果变得不确定，因此相同的值并不总是映射到相同的结果。

纯函数之所以可取，是因为它们更容易推理。如果一个函数没有任何副作用，你就可以将其视为一个仅在值之间进行映射的黑箱。如果它有副作用，你还需要了解它如何修改程序的其他部分，这意味着你至少要在某种程度上理解函数体在做什么。如果你只需要知道一个函数如何将输入参数映射到结果，你可以在任何时候更改其实现，而不会破坏任何依赖该函数的代码。

T. Mailund，《R 4 函数式编程》，<https://doi.org/10.1007/978-1-4842-9487-1_3>

### 非确定性函数

对于相同输入，结果并非总是相同的函数未必难以推理。但如果它们的结果依赖于随机数，那么测试和调试起来就会更困难。

由于纯函数更容易推理和测试，你应尽可能多地使用纯函数来编写程序。你未必能用纯函数编写*所有*程序。有时你需要随机性来实现蒙特卡洛方法，或者需要函数产生输出。但如果你用纯函数编写了大部分程序，并且知道不纯函数所在的位置，那么你就编写出了更好、更健壮的程序。



## 编写纯函数

要保证你编写的函数是纯的，相关工作并不多。你应该避免抽样随机数，并且避免修改函数作用域之外的变量。

避免抽样随机数是轻而易举的。不要直接或通过其他函数调用任何执行此操作的函数。如果一个函数只调用确定性函数，并且自身不引入任何随机性，那么该函数就是确定性的。

保证你不修改函数作用域之外的任何内容，这一点稍微不那么简单。你需要一个特殊的函数`<<-`来修改函数局部作用域之外的变量（我们将在下一章讨论这个运算符），所以请避免使用它。这样所有赋值都将针对局部变量，你也就无法修改其他作用域中的变量。如果你避免使用这个运算符，那么修改作用域之外函数的唯一风险就是通过惰性求值。还记得上一章中我们创建了一个函数列表的例子吗？这些函数包含未求值的表达式，这些表达式的值依赖于我们在求值表达式之前正在更改的变量。

严格来说，如果我们返回的函数包含依赖于局部变量的这种未求值表达式，我们仍然拥有一个纯函数。甚至我们要返回的函数本身也是纯的。它们会引用第一个函数中的局部变量，一旦第一个函数返回，如果没有`<<-`运算符，这些变量就无法更改。只是它们未必是你想要返回的函数。

虽然根据严格定义，这样的函数是纯的，但它们确实存在一个问题：我们返回的函数依赖于第一个函数内部局部变量的状态。从编程的角度来看，如果这些函数难以推理，那么它们是纯的这个事实对我们帮助不大；在这种情况下，我们需要知道改变第一个函数的状态如何影响其他函数的功能。

避免函数依赖于其自身作用域之外的变量（即既不是参数也不是局部变量的变量）的一个解决方案是，永远不改变变量所引用的内容。那些保证函数纯正的编程语言强制执行这一点。那里根本没有修改变量值的方法。你可以定义常量，但不存在变量这种东西。由于 R 语言确实有变量，如果你想以这种方式保证函数的纯正，就必须避免多次给同一个变量赋值。

在一个长函数中，即使你从未打算改变变量的值，也非常容易意外地重复使用变量名。保持函数简短精炼可以在一定程度上缓解这个问题，但无法保证这种情况不会发生。唯一迫使我们改变变量的控制结构是`for`循环。编写`for`循环时，你不可能不设置一个循环变量。

现在，`for`循环在 R 语言中名声不佳，许多人会告诉你避免使用它们，因为它们很慢。事实并非如此。与更底层语言中的循环相比，它们确实较慢，但这与它们是循环无关。因为 R 是一种非常动态的语言，你所做的每件事都涉及调用函数，而这些函数随时可能因为某人重定义变量而发生变化，所以 R 代码通常都很慢。当你调用像`sum`或`mean`这样的内置函数时，它们很快，因为是用 C 语言实现的。通过使用向量化表达式和内置函数，你可以避免动态性带来的性能惩罚。但如果你在 R 中自己编写循环，就会受到这种惩罚。然而，如果你使用人们推荐替代循环的其他构造（我们将在第[6](https://doi.org/10.1007/978-1-4842-9487-1_6)章讨论这些构造），你会付出相同的代价。

你应该使用这些其他构造的真正原因在于，它们能使代码背后的意图比循环更清晰（至少在你熟悉函数式编程之后是这样的），并且避免了可能引发问题的循环变量。人们通常发现自己的循环效率低下的原因在于，很容易写出“修改”数据的循环，从而迫使 R 制作副本。仅仅避免循环并不能解决这个问题，我们将在本章稍后部分再次讨论这一点。

## 递归作为循环

函数式编程语言避免循环的方式是改用递归。任何可以用循环编写的内容，你也可以用递归函数调用来编写，本章的大部分内容将侧重于让你习惯以递归函数的方式进行思考。

将问题视为递归不仅仅是一种避免循环的编程技巧。它通常是一种将问题分解为更易于解决的简单子问题的方法。当你需要处理一个问题时，你可以首先考虑是否存在容易解决的基准情形。

如果我们要在一个序列中搜索某个元素，当序列为空时，判断该元素是否存在是微不足道的：显然它不存在。现在，如果序列不为空，我们面临一个更难的问题，但我们可以将其分解为两个更小的问题。我们要搜索的元素是否是序列的第一个元素？如果是，则该元素存在。如果第一个元素不等于我们要搜索的元素，那么它只有在序列的剩余部分中才可能存在。

我们可以基于这种问题分解来编写一个线性搜索函数。首先检查基准情形，如果我们在空序列中搜索，就返回`FALSE`。否则，检查第一个元素；如果找到，返回`TRUE`；如果第一个元素不是我们要找的，则对序列的剩余部分递归调用该函数：

```r
lin_search <- function(element, sequence) {
  if (is_empty(sequence)) FALSE
  else if (first(sequence) == element) TRUE
  else lin_search(element, rest(sequence))
}

x <- 1:5
lin_search(0, x)
```

```
## [1] 假
lin_search(1, x)
```

```
## [1] 真
lin_search(5, x)
```

```
## [1] 真
lin_search(6, x)
```

## [1] 假

我将判空、提取第一个元素以及获取序列剩余部分的操作，分别隐藏在三个函数中：`is_empty`、`first`和`rest`。对于向量，可以这样实现：

```
is_empty <- function(x) length(x) == 0
first <- function(x) x[1]
rest <- function(x) x[-1]
```

如果向量的长度为 0，则视为空。第一个元素自然就是第一个元素。`rest`函数返回除第一个元素之外的所有内容（通过`-1`索引实现）。

现在这个搜索算法可以运行，但你绝不应照搬我刚才写的`rest`函数那样的代码。我们通过切片方式提取向量剩余部分时，R 会复制那个子向量。第一次调用`rest`，得到的是去掉第一个元素的整个向量；第二次调用，得到的是去掉前两个元素的整个向量，依此类推。这会导致运算量大约达到向量长度平方的一半。因此，虽然搜索算法本应是线性时间复杂度的，但我们提取向量剩余部分的方式却使其变成了平方时间复杂度。

在实践中，这其实无关紧要。R 对递归调用的深度有限制，而在性能成为问题之前，我们早就触达这个上限了。我们会在本章末尾再讨论这些问题，但目前，出于简洁性的考虑，既然我们可以实现线性时间算法，就尽量避开平方时间算法。

那些为递归而非循环而设计的语言，通常以另一种方式来表示序列——这种方式下，你可以在常数时间内获取序列的剩余部分。我们可以实现这样一个版本的序列：将序列中的元素表示为一个结构，该结构包含一个指向剩余部分的`next`变量。

我们将这种结构称为*next 列表*。这是*链表*的一个例子，但链表有不同的变体，而这种只需引用序列的剩余部分，所以我将其称为*next 列表*。我们可以使用下面的函数将单个元素转换为这种序列：

```
next_list <- function(element, rest = NULL) list(element = element, rest = rest)
```

然后通过嵌套调用该函数来构造序列，这与上一章中构造树的方式类似：

```
x <- next_list(1, next_list(2, next_list(3, next_list(4))))
```

## 递归函数的结构

递归函数都遵循相同的模式：找出易于解决的基准情形，并理解如何将问题分解成可通过递归解决的更小子问题。这种思路在算法设计理论中被称为“分治”。将问题归约成更小的子问题是难点所在。需要注意两点：这些子问题是否真的更小了？如何组合子问题的解来解决更大的问题？

### 示例：线性搜索

我们可以先看几个例子。首先，使用 `next_list`（一种链表结构）来定义搜索：

```r
nl_is_empty <- function(nl) is.null(nl)
nl_first <- function(nl) nl$element
nl_rest <- function(nl) nl$rest
```

实际的搜索算法是这样的：

```r
nl_lin_search <- function(element, sequence) {
  if (nl_is_empty(sequence)) FALSE
  else if (nl_first(sequence) == element) TRUE
  else nl_lin_search(element, nl_rest(sequence))
}
```

这运行良好，并且是线性时间，但构造列表有点繁琐。我们应该写一个函数，用于将向量转换为 `next_list`。要构造这样的函数，我们可以再次采用递归思路。如果向量的长度为零（即基准情形），那么 `next_list` 应为 `NULL`。否则，我们希望构造一个 `next_list`：第一个元素是向量的第一个元素，列表的剩余部分则是向量剩余部分对应的 `next_list`：

```r
vector_to_next_list <- function(x) {
  if (is_empty(x)) NULL
  else next_list(first(x), vector_to_next_list(rest(x)))
}
```

这也能运行，但显然，我们只是把性能问题从搜索算法转移到了 `vector_to_next_list` 函数上。该函数仍然需要获取向量的剩余部分，而这需要复制。从向量到 `next_list` 的转换是平方时间复杂度的。我们需要一种方法来获取向量的剩余部分，且无需复制。

一种解决方案是跟踪向量中的索引。如果将该索引视为向量真正起始位置的索引，那么只需增加索引即可获取向量的剩余部分。我们可以使用这些辅助函数：

```r
i_is_empty <- function(x, i) i > length(x)
i_first <- function(x, i) x[i]
```

并这样编写转换函数：

```r
i_vector_to_next_list <- function(x, i = 1) {
  if (i_is_empty(x, i)) NULL
  else next_list(i_first(x, i), i_vector_to_next_list(x, i + 1))
}
```

当然，使用同样的技巧，我们本可以直接用索引来实现搜索算法：

```r
i_lin_search <- function(element, sequence, i = 1) {
  if (i_is_empty(sequence, i)) FALSE
  else if (i_first(sequence, i) == element) TRUE
  else i_lin_search(element, sequence, i + 1)
}
```

使用索引实现时，我们实际上无法写出一个 `rest` 函数。编写一个返回向量和索引对的函数，操作起来不如直接递增索引本身方便。

当你对序列编写递归函数时，所需的关键抽象包括：检查序列是否为空、获取第一个元素以及获取序列的剩余部分。使用针对这三种操作的函数，并不能真正帮助我们，除非这些函数能让我们处理不同类型的数据序列。实现这样的抽象是可能的，但在本书中我们不再深入探讨。从现在起，我们将直接在递归函数中实现这些抽象。如果这样做，线性搜索算法就简化为：

```r
lin_search <- function(element, sequence, i = 1) {
  if (i > length(sequence)) FALSE
  else if (sequence[i] == element) TRUE
  else lin_search(element, sequence, i + 1)
}
```

在我们至今研究的线性搜索中，我们知道递归调用处理的是更小的子问题，因为每次调用面对的都是更短的序列。无论我们是用列表实现函数，还是使用向量索引，当我们递归调用时，我们处理的都是更短的序列。对于处理序列的函数来说，通常都是如此。如果你知道每次递归调用都离基准情形更近一步，你就知道函数最终会完成计算。

### 二分搜索与正确性

递归并不总是只针对序列中除了第一个元素以外的所有部分。例如，对于二分搜索，我们可以通过每次递归调用将问题规模减半，从而在已排序的序列中以对数时间完成搜索。算法是这样的：如果序列为空，则找不到要搜索的元素，返回 `FALSE`。如果序列非空，检查中间元素是否是目标元素，如果是则返回 `TRUE`。如果不是，检查它是否小于目标元素：如果是，则对序列的后半部分递归调用；如果不是，则对序列的前半部分递归调用。

这听起来很简单，但初次尝试实现时，往往会导致在同一序列上反复递归，永远无法接近完成。这种情况出现在我们选择前半部分或后半部分时不够仔细时。以下实现就是错误的。如果你搜索 `0` 或 `5`，将会陷入无限递归：

```r
binary_search <- function(element, x, first = 1, last = length(x)) {
  if (last < first) return(FALSE) # empty sequence
  middle <- (last - first) %/% 2 + first
  if (element == x[middle]) {
    TRUE
  } else if (element < x[middle]) {
    binary_search(element, x, first, middle)
  } else {
    binary_search(element, x, middle, last)
  }
}
```

原因是中间索引等于 `first`，导致你递归调用时面对的是与之前相同的问题，而非更简单的问题。解决方法是，在递归调用的范围中绝不要包含 `middle`——毕竟，只有在确定 `middle` 不是目标元素时，你才会调用递归：

```r
binary_search <- function(element, x, first = 1, last = length(x)) {
  if (last < first) return(FALSE) # empty sequence
  middle <- (last - first) %/% 2 + first
  if (element == x[middle]) {
    TRUE
  } else if (element < x[middle]) {
    binary_search(element, x, first, middle - 1)
  } else {
    binary_search(element, x, middle + 1, last)
  }
}
```

关键在于必须确保所有递归调用确实是在处理更小的子问题。对于序列，这通常意味着要确保递归调用处理的是更短的序列。

对于树这种本质上是递归的数据结构——树要么是叶子节点，要么是包含若干子节点的内部节点，而这些子节点本身也是树——我们会在子树上递归调用，从而保证每次递归调用处理的都是更小的子问题。我们在第一章中编写的 `node_depth` 函数就是一个例子：

```r
node_depth <- function(tree, name, depth = 0) {
  if (is.null(tree)) return(NA)
  if (tree$name == name) return(depth)
  left <- node_depth(tree$left, name, depth + 1)
  if (!is.na(left)) return(left)
  right <- node_depth(tree$right, name, depth + 1)
  return(right)
}
```

基准情形处理空树——空树不包含我们要找的节点，因此直接返回 `NA`。如果树非空，要么我们找到了目标节点，可以返回结果；要么则对左子树递归调用。如果找到了目标节点，就返回结果；否则，返回对右子树递归调用的结果（无论是否找到，如果节点根本不在树中，最终结果就是 `NA`）。

### 组合子问题的解

我们到目前为止编写的函数，都没有组合子问题的解。这些函数都是搜索函数，返回的结果要么是直接找到的，要么是某个递归函数返回的结果。并非总是这么简单，通常你需要对递归调用的结果进行处理，才能解决更大的问题。

一个简单的例子是计算阶乘。数字 *n* 的阶乘（*n*!）等于 *n* × (*n* − 1)!，基准情形为 `1! = 1`。编写递归函数计算阶乘非常简单，但我们不能直接返回递归调用的结果，而需要将递归调用的结果乘以 *n*。

# R 语言中的递归

以下是用于计算阶乘的 R 代码：

```r
factorial <- function(n) {
  if (n == 1) 1
  else n * factorial(n - 1)
}
```

这里，我假设 `n` 是整数且 `n > 0`。如果不是这样，递归就不会向基准情形靠近，原则上会无限进行下去。因此，这又是一个需要小心确保递归调用确实在推进问题求解的例子。在这个函数中，我只对正整数保证了这一点。

在大多数算法中，我们需要对递归调用的结果进行某些操作，才能完成计算。除了阶乘，另一个例子是去除序列中重复元素的函数。重复元素是指序列中与下一个元素相等的元素。这个函数类似于 R 内建的 `unique` 函数，但不同之处在于它只移除相邻的重复元素。

编写这个函数时，我们遵循递归函数的编写步骤。基准情形是什么？空序列没有重复元素，所以结果就是空序列。只有一个元素的序列也是如此：这样的序列没有重复元素，因此结果就是输入序列本身。如果我们始终知道函数的输入至少包含一个元素，就不必担心第一种基准情形；但如果函数可能被调用处理空序列，我们就需要同时处理这两种情况。对于包含多个元素的序列，我们需要检查第一个元素是否与下一个元素相等。如果是，则对去掉第一个元素后的序列递归调用，从而移除一个重复元素。如果不是，则返回第一个元素，以及已经去除重复后的剩余序列。

使用“`next` 列表”的解法如下：

```r
rm_duplicates <- function(x) {
  # Base cases
  if (is.null(x)) return(NULL)
  if (is.null(x$rest)) return(x)
  # Recursive case
  if (x$element == x$rest$element) rm_duplicates(x$rest)
  else next_list(x$element, rm_duplicates(x$rest))
}

x <- next_list(1, next_list(1, next_list(2, next_list(2))))
rm_duplicates(x)
```

输出结果为：

```
$element
[1] 1

$rest
$rest$element
[1] 2

$rest$rest
[1] NULL
```

为了得到一般问题的解，我们需要将递归调用所得到的较小解决方案与较大问题中的信息结合起来。如果第一个元素等于从递归调用返回的第一个元素，则存在重复，应直接返回递归调用的结果；如果不等，则需要将第一个元素与递归调用返回的下一个列表进行合并。

我们也可以为向量实现此函数。为了避免每次删除重复元素时都复制向量，可以将该函数拆分为两部分。首先，找出所有重复元素的索引，然后通过单次操作将这些索引从向量中删除：

```r
vector_rm_duplicates <- function(x) {
  dup <- find_duplicates(x)
  x[-dup]
}

vector_rm_duplicates(c(1, 1, 2, 2))
```

输出结果为：

```
[1] 1 2
```

R 语言中已有一个用于查找重复元素的内置函数 `duplicated`，我们可以用它来实现 `find_duplicates`（该函数返回布尔向量，但我们可以使用 `which` 函数获取 `TRUE` 值对应的索引）。不过，自己动手实现也是一个不错的练习。

```r
find_duplicates <- function(x, i = 1) {
  if (i >= length(x)) return(c())
  if (x[i] == x[i + 1]) c(i, find_duplicates(x, i + 1)) else find_duplicates(x, i + 1)
}
```

该结构与列表版本非常相似，但如果当前索引对应重复元素，则返回递归调用结果和当前索引；否则仅返回递归调用结果。

这个解决方案并不完美。每次我们将当前索引与递归结果合并创建索引向量时，都会进行一次复制，因此运行时间与结果长度呈二次关系。我们可以通过构建一个 `next` 链表（而非索引向量），然后在删除重复元素的函数中将其转换为向量，再对向量 `x` 进行索引删除重复元素，从而将其转变为线性时间算法。这项工作留作练习。

作为另一个需要合并递归调用结果的递归函数示例，我们考虑计算树的大小。

基本情况是树为空（值为 `NULL`），此时大小为 0。递归情况为左子树大小加上右子树大小再加 1（表示当前节点）：

```r
size_of_tree <- function(node) {
  if (is.null(node)) 0
  else size_of_tree(node$left) + size_of_tree(node$right) + 1
}
```

我们可以使用以下函数来创建节点：

```r
make_node <- function(name, left = NULL, right = NULL) list(name = name, left = left, right = right)
```

并构建一棵树：

```r
tree <- make_node("root",
                  make_node("C", make_node("A"),
                            make_node("B")),
                  make_node("D"))
```

然后计算它的大小：

```r
size_of_tree(tree)
```

输出结果为：

```
[1] 5
```

如果我希望记住子树的大小以避免重复计算，可以尝试如下方案：

```r
set_size_of_subtrees <- function(node) {
  if (is.null(node)) return(0)  # 无法在 NULL 中保存任何数据
  # 若没有存储大小，则进行计算
  if (is.null(node$size)) {
    left_size <- set_size_of_subtrees(node$left)
    right_size <- set_size_of_subtrees(node$right)
    node$size <- left_size + right_size + 1
  }
  return(node$size)
}
```

但请注意，R 语言中的数据无法被修改。如果我在树上运行此函数，它会创建知道子树大小的新节点，但这些节点是副本，而非调用函数时所用的原树节点：

```r
set_size_of_subtrees(tree)
```

输出结果为：

```
[1] 5
```

然而：

```r
tree$size
```

输出结果为：

```
NULL
```

为了真正记住大小，我需要构建一棵全新的树，其节点都已知自身大小。因此需要以下函数：

```r
# 同时处理 NULL 和已知自身大小的节点
get_size <- function(node) if (is.null(node)) 0 else node$size

set_size_of_subtrees <- function(node) {
  if (is.null(node)) return(NULL)
  # 更新子节点
  node$left <- set_size_of_subtrees(node$left)
  node$right <- set_size_of_subtrees(node$right)
  # 设置当前节点大小
  node$size <- get_size(node$left) + get_size(node$right) + 1
  return(node)
}
```

然后：

```r
tree <- set_size_of_subtrees(tree)
tree$size
```

输出结果为：

```
[1] 5
```

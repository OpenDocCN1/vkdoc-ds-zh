## 纯函数式编程

“纯”函数是一种行为与数学函数类似的函数：它将一个空间的值映射到另一个空间，相同的值总是映射到相同的结果，并且数学函数中没有“副作用”这种东西。

编程语言为确保函数纯正所采取的程度各不相同，而 R 语言在这方面做得非常有限。由于值是不可变的，你对函数可能产生的副作用有一定保证，但并不多。函数可以修改其作用域之外的变量，例如修改全局变量。它们可以打印或绘图，并以这种方式改变 R 进程的状态。它们还可以抽取随机数并用其进行计算，从而在某种意义上使函数的结果变得不确定，因此相同的值并不总是映射到相同的结果。

纯函数之所以可取，是因为它们更容易推理。如果一个函数没有任何副作用，你就可以将其视为一个仅在值之间进行映射的黑箱。如果它有副作用，你还需要了解它如何修改程序的其他部分，这意味着你至少要在某种程度上理解函数体在做什么。如果你只需要知道一个函数如何将输入参数映射到结果，你可以在任何时候更改其实现，而不会破坏任何依赖该函数的代码。

### 非确定性函数

对于相同输入，结果并非总是相同的函数未必难以推理。但如果它们的结果依赖于随机数，那么测试和调试起来就会更困难。

由于纯函数更容易推理和测试，你应尽可能多地使用纯函数来编写程序。你未必能用纯函数编写*所有*程序。有时你需要随机性来实现蒙特卡洛方法，或者需要函数产生输出。但如果你用纯函数编写了大部分程序，并且知道不纯函数所在的位置，那么你就编写出了更好、更健壮的程序。

## 编写纯函数

要保证你编写的函数是纯的，相关工作并不多。你应该避免抽样随机数，并且避免修改函数作用域之外的变量。

避免抽样随机数是轻而易举的。不要直接或通过其他函数调用任何执行此操作的函数。如果一个函数只调用确定性函数，并且自身不引入任何随机性，那么该函数就是确定性的。

保证你不修改函数作用域之外的任何内容，这一点稍微不那么简单。你需要一个特殊的函数 `<<-` 来修改函数局部作用域之外的变量（我们将在下一章讨论这个运算符），所以请避免使用它。这样所有赋值都将针对局部变量，你也就无法修改其他作用域中的变量。如果你避免使用这个运算符，那么修改作用域之外函数的唯一风险就是通过惰性求值。还记得上一章中我们创建了一个函数列表的例子吗？这些函数包含未求值的表达式，这些表达式的值依赖于我们在求值表达式之前正在更改的变量。

严格来说，如果我们返回的函数包含依赖于局部变量的这种未求值表达式，我们仍然拥有一个纯函数。甚至我们要返回的函数本身也是纯的。它们会引用第一个函数中的局部变量，一旦第一个函数返回，如果没有 `<<-` 运算符，这些变量就无法更改。只是它们未必是你想要返回的函数。

虽然根据严格定义，这样的函数是纯的，但它们确实存在一个问题：我们返回的函数依赖于第一个函数内部局部变量的状态。从编程的角度来看，如果这些函数难以推理，那么它们是纯的这个事实对我们帮助不大；在这种情况下，我们需要知道改变第一个函数的状态如何影响其他函数的功能。

避免函数依赖于其自身作用域之外的变量（即既不是参数也不是局部变量的变量）的一个解决方案是，永远不改变变量所引用的内容。那些保证函数纯正的编程语言强制执行这一点。那里根本没有修改变量值的方法。你可以定义常量，但不存在变量这种东西。由于 R 语言确实有变量，如果你想以这种方式保证函数的纯正，就必须避免多次给同一个变量赋值。

在一个长函数中，即使你从未打算改变变量的值，也非常容易意外地重复使用变量名。保持函数简短精炼可以在一定程度上缓解这个问题，但无法保证这种情况不会发生。唯一迫使我们改变变量的控制结构是 `for` 循环。编写 `for` 循环时，你不可能不设置一个循环变量。

现在，`for` 循环在 R 语言中名声不佳，许多人会告诉你避免使用它们，因为它们很慢。事实并非如此。与更底层语言中的循环相比，它们确实较慢，但这与它们是循环无关。因为 R 是一种非常动态的语言，你所做的每件事都涉及调用函数，而这些函数随时可能因为某人重定义变量而发生变化，所以 R 代码通常都很慢。当你调用像 `sum` 或 `mean` 这样的内置函数时，它们很快，因为是用 C 语言实现的。通过使用向量化表达式和内置函数，你可以避免动态性带来的性能惩罚。但如果你在 R 中自己编写循环，就会受到这种惩罚。然而，如果你使用人们推荐替代循环的其他构造（我们将在第 [6](https://doi.org/10.1007/978-1-4842-9487-1_6) 章讨论这些构造），你会付出相同的代价。

你应该使用这些其他构造的真正原因在于，它们能使代码背后的意图比循环更清晰（至少在你熟悉函数式编程之后是这样的），并且避免了可能引发问题的循环变量。人们通常发现自己的循环效率低下的原因在于，很容易写出“修改”数据的循环，从而迫使 R 制作副本。仅仅避免循环并不能解决这个问题，我们将在本章稍后部分再次讨论这一点。

## 递归作为循环

函数式编程语言避免循环的方式是改用递归。任何可以用循环编写的内容，你也可以用递归函数调用来编写，本章的大部分内容将侧重于让你习惯以递归函数的方式进行思考。

将问题视为递归不仅仅是一种避免循环的编程技巧。它通常是一种将问题分解为更易于解决的简单子问题的方法。当你需要处理一个问题时，你可以首先考虑是否存在容易解决的基准情形。

如果我们要在一个序列中搜索某个元素，当序列为空时，判断该元素是否存在是微不足道的：显然它不存在。现在，如果序列不为空，我们面临一个更难的问题，但我们可以将其分解为两个更小的问题。我们要搜索的元素是否是序列的第一个元素？如果是，则该元素存在。如果第一个元素不等于我们要搜索的元素，那么它只有在序列的剩余部分中才可能存在。

我们可以基于这种问题分解来编写一个线性搜索函数。首先检查基准情形，如果我们在空序列中搜索，就返回 `FALSE`。否则，检查第一个元素；如果找到，返回 `TRUE`；如果第一个元素不是我们要找的，则对序列的剩余部分递归调用该函数：

```r
lin_search <- function(element, sequence) {
  if (is_empty(sequence)) FALSE
  else if (first(sequence) == element) TRUE
  else lin_search(element, rest(sequence))
}

x <- 1:5
lin_search(0, x)
```

我将判空、提取第一个元素以及获取序列剩余部分的操作，分别隐藏在三个函数中：`is_empty`、`first`和`rest`。对于向量，可以这样实现：

```
is_empty <- function(x) length(x) == 0
first <- function(x) x[1]
rest <- function(x) x[-1]
```

如果向量的长度为 0，则视为空。第一个元素自然就是第一个元素。`rest`函数返回除第一个元素之外的所有内容（通过 `-1` 索引实现）。

现在这个搜索算法可以运行，但你绝不应照搬我刚才写的 `rest` 函数那样的代码。我们通过切片方式提取向量剩余部分时，R 会复制那个子向量。第一次调用 `rest`，得到的是去掉第一个元素的整个向量；第二次调用，得到的是去掉前两个元素的整个向量，依此类推。这会导致运算量大约达到向量长度平方的一半。因此，虽然搜索算法本应是线性时间复杂度的，但我们提取向量剩余部分的方式却使其变成了平方时间复杂度。

在实践中，这其实无关紧要。R 对递归调用的深度有限制，而在性能成为问题之前，我们早就触达这个上限了。我们会在本章末尾再讨论这些问题，但目前，出于简洁性的考虑，既然我们可以实现线性时间算法，就尽量避开平方时间算法。

那些为递归而非循环而设计的语言，通常以另一种方式来表示序列——这种方式下，你可以在常数时间内获取序列的剩余部分。我们可以实现这样一个版本的序列：将序列中的元素表示为一个结构，该结构包含一个指向剩余部分的 `next` 变量。

我们将这种结构称为*next 列表*。这是*链表*的一个例子，但链表有不同的变体，而这种只需引用序列的剩余部分，所以我将其称为*next 列表*。我们可以使用下面的函数将单个元素转换为这种序列：

```
next_list <- function(element, rest = NULL) list(element = element, rest = rest)
```

然后通过嵌套调用该函数来构造序列，这与上一章中构造树的方式类似：

```
x <- next_list(1, next_list(2, next_list(3, next_list(4))))
```

对于这种结构，我们可以如下定义搜索算法所需的函数：

```
nl_is_empty <- function(nl) is.null(nl)
nl_first <- function(nl) nl$element
nl_rest <- function(nl) nl$rest
```

实际的搜索算法是这样的：

```
nl_lin_search <- function(element, sequence) {
  if (nl_is_empty(sequence)) FALSE
  else if (nl_first(sequence) == element) TRUE
  else nl_lin_search(element, nl_rest(sequence))
}
```

这运行良好，并且是线性时间，但构造列表有点繁琐。我们应该写一个函数，用于将向量转换为 next 列表。要构造这样的函数，我们可以再次采用递归思路。如果向量的长度为零（即基准情形），那么 next 列表应为 `NULL`。否则，我们希望构造一个 next 列表：第一个元素是向量的第一个元素，列表的剩余部分则是向量剩余部分对应的 next 列表：

```
vector_to_next_list <- function(x) {
  if (is_empty(x)) NULL
  else next_list(first(x), vector_to_next_list(rest(x)))
}
```

这也能运行，但显然，我们只是把性能问题从搜索算法转移到了 `vector_to_next_list` 函数上。该函数仍然需要获取向量的剩余部分，而这需要复制。从向量到 next 列表的转换是平方时间复杂度的。我们需要一种方法来获取向量的剩余部分，且无需复制。

一种解决方案是跟踪向量中的索引。如果将该索引视为向量真正起始位置的索引，那么只需增加索引即可获取向量的剩余部分。我们可以使用这些辅助函数：

```
i_is_empty <- function(x, i) i > length(x)
i_first <- function(x, i) x[i]
```

并这样编写转换函数：

```
i_vector_to_next_list <- function(x, i = 1) {
  if (i_is_empty(x, i)) NULL
  else next_list(i_first(x, i), i_vector_to_next_list(x, i + 1))
}
```

当然，使用同样的技巧，我们本可以直接用索引来实现搜索算法：

```
i_lin_search <- function(element, sequence, i = 1) {
  if (i_is_empty(sequence, i)) FALSE
  else if (i_first(sequence, i) == element) TRUE
  else i_lin_search(element, sequence, i + 1)
}
```

使用索引实现时，我们实际上无法写出一个 `rest` 函数。编写一个返回向量和索引对的函数，操作起来不如直接递增索引本身方便。

当你对序列编写递归函数时，所需的关键抽象包括：检查序列是否为空、获取第一个元素以及获取序列的剩余部分。使用针对这三种操作的函数，并不能真正帮助我们，除非这些函数能让我们处理不同类型的数据序列。实现这样的抽象是可能的，但在本书中我们不再深入探讨。从现在起，我们将直接在递归函数中实现这些抽象。如果这样做，线性搜索算法就简化为：

```
lin_search <- function(element, sequence, i = 1) {
  if (i > length(sequence)) FALSE
  else if (sequence[i] == element) TRUE
  else lin_search(element, sequence, i + 1)
}
```

## 递归函数的结构

递归函数都遵循相同的模式：找出易于解决的基准情形，并理解如何将问题分解成可通过递归解决的更小子问题。这种思路在算法设计理论中被称为“分治”。将问题归约成更小的子问题是难点所在。需要注意两点：这些子问题是否*真的*更小了？如何组合子问题的解来解决更大的问题？

在我们至今研究的线性搜索中，我们知道递归调用处理的是更小的子问题，因为每次调用面对的都是更短的序列。无论我们是用列表实现函数，还是使用向量索引，当我们递归调用时，我们处理的都是更短的序列。对于处理序列的函数来说，通常都是如此。如果你知道每次递归调用都离基准情形更近一步，你就知道函数最终会完成计算。

递归并不总是只针对序列中除了第一个元素以外的所有部分。例如，对于二分搜索，我们可以通过每次递归调用将问题规模减半，从而在已排序的序列中以对数时间完成搜索。算法是这样的：如果序列为空，则找不到要搜索的元素，返回 `FALSE`。如果序列非空，检查中间元素是否是目标元素，如果是则返回 `TRUE`。如果不是，检查它是否小于目标元素：如果是，则对序列的后半部分递归调用；如果不是，则对序列的前半部分递归调用。

这听起来很简单，但初次尝试实现时，往往会导致在同一序列上反复递归，永远无法接近完成。这种情况出现在我们选择前半部分或后半部分时不够仔细时。以下实现就是错误的。如果你搜索 `0` 或 `5`，将会陷入无限递归：

```
binary_search <- function(element, x, first = 1, last = length(x)) {
  if (last < first) return(FALSE) # empty sequence
  middle <- (last - first) %/% 2 + first
  if (element == x[middle]) {
    TRUE
  } else if (element < x[middle]) {
    binary_search(element, x, first, middle)
  } else {
    binary_search(element, x, middle, last)
  }
}
```

原因是中间索引等于 `first`，导致你递归调用时面对的是与之前相同的问题，而非更简单的问题。解决方法是，在递归调用的范围中绝不要包含 `middle`——毕竟，只有在确定 `middle` 不是目标元素时，你才会调用递归：

```
binary_search <- function(element, x, first = 1, last = length(x)) {
  if (last < first) return(FALSE) # empty sequence
  middle <- (last - first) %/% 2 + first
  if (element == x[middle]) {
    TRUE
  } else if (element < x[middle]) {
    binary_search(element, x, first, middle - 1)
  } else {
    binary_search(element, x, middle + 1, last)
  }
}
```

关键在于必须确保所有递归调用确实是在处理更小的子问题。对于序列，这通常意味着要确保递归调用处理的是更短的序列。

对于树这种本质上是递归的数据结构——树要么是叶子节点，要么是包含若干子节点的内部节点，而这些子节点本身也是树——我们会在子树上递归调用，从而保证每次递归调用处理的都是更小的子问题。我们在第一章中编写的 `node_depth` 函数就是一个例子：

```
node_depth <- function(tree, name, depth = 0) {
  if (is.null(tree)) return(NA)
  if (tree$name == name) return(depth)
  left <- node_depth(tree$left, name, depth + 1)
  if (!is.na(left)) return(left)
  right <- node_depth(tree$right, name, depth + 1)
  return(right)
}
```

基准情形处理空树——空树不包含我们要找的节点，因此直接返回 `NA`。如果树非空，要么我们找到了目标节点，可以返回结果；要么则对左子树递归调用。如果找到了目标节点，就返回结果；否则，返回对右子树递归调用的结果（无论是否找到，如果节点根本不在树中，最终结果就是 `NA`）。

我们到目前为止编写的函数，都没有组合子问题的解。这些函数都是搜索函数，返回的结果要么是直接找到的，要么是某个递归函数返回的结果。并非总是这么简单，通常你需要对递归调用的结果进行处理，才能解决更大的问题。

一个简单的例子是计算阶乘。数字 *n* 的阶乘（*n*!）等于 *n* × (*n* − 1)!，基准情形为 `1! = 1`。编写递归函数计算阶乘非常简单，但我们不能直接返回递归调用的结果，而需要将递归调用的结果乘以 *n*：

```
factorial <- function(n) {
  if (n == 1) 1
  else n * factorial(n - 1)
}
```

这里，我假设 *n* 是整数且 *n* > 0。如果不是这样，递归就不会向基准情形靠近，原则上会无限进行下去。因此，这又是一个需要小心确保递归调用确实在推进问题求解的例子。在这个函数中，我只对正整数保证了这一点。

在大多数算法中，我们需要对递归调用的结果进行某些操作，才能完成计算。除了阶乘，另一个例子是去除序列中重复元素的函数。重复元素是指序列中与下一个元素相等的元素。这个函数类似于 R 内建的 `unique` 函数，但不同之处在于它只移除相邻的重复元素。

编写这个函数时，我们遵循递归函数的编写步骤。基准情形是什么？空序列没有重复元素，所以结果就是空序列。只有一个元素的序列也是如此：这样的序列没有重复元素，因此结果就是输入序列本身。如果我们始终知道函数的输入至少包含一个元素，就不必担心第一种基准情形；但如果函数可能被调用处理空序列，我们就需要同时处理这两种情况。对于包含多个元素的序列，我们需要检查第一个元素是否与下一个元素相等。如果是，则对去掉第一个元素后的序列递归调用，从而移除一个重复元素。如果不是，则返回第一个元素，以及已经去除重复后的剩余序列。

使用“next 列表”的解法如下：

```
rm_duplicates <- function(x) {
  # Base cases
  if (is.null(x)) return(NULL)
  if (is.null(x$rest)) return(x)
  # Recursive case
  if (x$element == x$rest$element) rm_duplicates(x$rest)
  else next_list(x$element, rm_duplicates(x$rest))
}

x <- next_list(1, next_list(1, next_list(2, next_list(2))))
rm_duplicates(x)
```

为了得到一般问题的解，我们需要将递归调用所得到的较小解决方案与较大问题中的信息结合起来。如果第一个元素等于从递归调用返回的第一个元素，则存在重复，应直接返回递归调用的结果；如果不等，则需要将第一个元素与递归调用返回的下一个列表进行合并。

vector_rm_duplicates <- function(x) {
  dup <- find_duplicates(x)
  x[-dup]
}

R 语言中已有一个用于查找重复元素的内置函数 `duplicated`，我们可以用它来实现 `find_duplicates`（该函数返回布尔向量，但我们可以使用 `which` 函数获取 `TRUE` 值对应的索引）。不过，自己动手实现也是一个不错的练习。

```
find_duplicates <- function(x, i = 1) {
  if (i >= length(x)) return(c())
  if (x[i] == x[i + 1]) c(i, find_duplicates(x, i + 1)) else find_duplicates(x, i + 1)
}
```

该结构与列表版本非常相似，但如果当前索引对应重复元素，则返回递归调用结果和当前索引；否则仅返回递归调用结果。

这个解决方案并不完美。每次我们将当前索引与递归结果合并创建索引向量时，都会进行一次复制，因此运行时间与结果长度呈二次关系。我们可以通过构建一个 `next` 链表（而非索引向量），然后在删除重复元素的函数中将其转换为向量，再对向量 `x` 进行索引删除重复元素，从而将其转变为线性时间算法。这项工作留作练习。

size_of_tree <- function(node) {
  if (is.null(node)) 0
  else size_of_tree(node$left) + size_of_tree(node$right) + 1
}

```
# 同时处理 NULL 和已知自身大小的节点
get_size <- function(node) if (is.null(node)) 0 else node$size

set_size_of_subtrees <- function(node) {
  if (is.null(node)) return(NULL)
  # 更新子节点
  node$left <- set_size_of_subtrees(node$left)
  node$right <- set_size_of_subtrees(node$right)
  # 设置当前节点大小
  node$size <- get_size(node$left) + get_size(node$right) + 1
  return(node)
}
```

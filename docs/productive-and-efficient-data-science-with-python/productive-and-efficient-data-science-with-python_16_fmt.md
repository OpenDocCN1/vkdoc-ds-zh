# 可扩展数据科学

数据科学任务可能会处理规模千差万别的数据集，小至千字节，大至拍字节。有些企业电子表格可能只有几百行，而整个工厂可能将海量传感器数据源源不断地发送到单个数据集中，导致每天甚至每小时产生数十亿行数据。有些数据集可能行数众多但列数较少，而另一些则可能只有少量行，但特征维度却可达数百万列。即使在同一个组织或数据科学团队内部，也可能存在多条处理不同类型输入的数据管道，它们面临的数据集规模和复杂度可能存在巨大差异。

数据科学家通常会自然地构建数据科学任务（例如结合数据整理、机器学习算法和一些预测功能）的可扩展原型。他们构建这样一个原型，用预期会进入管道的典型数据集进行测试，利用几种机器学习算法评估结果或衡量某些性能指标，进行调优，最终做出选择。这是一种实验性思维，非常符合“*用数据做科学*”的精神。然而，为了支持这种快速分析和原型设计，数据科学家必须能够根据需求，快速地在各种数据集规模和复杂度之间进行扩展。他们不应该在笔记本电脑上构建原型时遇到内存不足等问题。

本章将讨论在扩展到更大数据集时出现的常见问题和限制，以及目前有哪些工具可以解决这些问题。具体来说，你将了解在使用最常用的数据分析库 `Python` `pandas` 处理大型数据集时出现的一些限制，并探索两种可以克服这些限制的替代库或扩展插件。

事实上，可扩展性与大型数据的并行处理能力密切相关。因此，这一主题将在下一章继续展开，届时你将探索在数据科学任务中原生支持并行处理的 `Python` 库。

## 可扩展性的常见问题

`Python` 是一种优秀的数据科学语言。像 `pandas` 这样的库为数据科学家提供了无限可能，让他们能够以任意方式对数据进行切片和切块，并用相对较少的编程工作生成有意义的见解和影响深远的分析报告。然而，在处理大型数据集（即使是像包含十亿行数据的 `CSV` 文件这样简单的结构）时，它们存在一些严重的局限性。

随着数据规模的增长，数据科学家可能遇到的两个最常见问题是核心外故障以及与 `Python` 单线程特性相关的低效问题。

*核心外*实际上是指无法将完整数据正确加载到机器的工作内存（`RAM`）中。单线程问题与 `Python` 的基本设计特性——全局解释器锁（`GIL`）（`https://realpython.com/python-gil/`）有关，该特性允许单个线程锁定解释器，从而阻止其他线程获取控制权。两者共同作用，使得在硬件有限的情况下，对大型数据集（任何大于几 `GB` 的数据集）进行高效数据分析变得相当棘手。

### `Python` 单线程

`GIL` 是 `Python` 语言的早期设计选择之一，它解决了与内存泄漏和竞争条件相关的几个重要问题。简而言之，它是一种锁定机制，只允许一个线程持有对 `Python` 解释器的控制权。这意味着在任何给定时间点，只有一个线程可以处于执行状态。

通常，对于执行单线程程序的程序员来说，其影响并不明显。事实上，许多数据科学任务可以正常运行，无需担心 `GIL`，因为它们按顺序执行一系列任务，并且不使用许多并行处理技巧。然而，在 `CPU` 密集型和多线程代码中，它可能会成为性能瓶颈。

对于更大的数据集，有时将数据分成多个块并利用并行处理执行流程是合理的。其理念是将分块后的数据发送到 `CPU` 的每个核心，并尽可能并行地执行分析。当执行完成后，可以合并结果以得到转换后的数据集。虽然这不一定有助于将更大的数据集放入内存，但可以通过并行执行来加快对同一数据集的分析速度。

美妙之处在于，即使不租用云上的大型 `CPU` 集群，这种方法也能加速数据科学探索和原型设计任务。这实际上是利用数据科学家笔记本电脑中单个现代 `CPU` 通常配备的 8 核或 16 核的问题。然而，你必须确保数据科学代码和库不会成为障碍，并且你正在使用能够充分利用多核硬件平台的库。

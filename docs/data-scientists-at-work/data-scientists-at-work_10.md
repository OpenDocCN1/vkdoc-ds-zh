## 第 6 章 | 约翰·福尔曼，MailChimp

### 约翰·福尔曼

约翰·福尔曼是火箭科学集团（Rocket Science Group）的首席数据科学家，该公司旗下拥有 `MailChimp.com`、`Mandrill.com`、`TinyLetter.com` 以及其他十二个与电子邮件相关的网页和移动应用。火箭科学集团是一家电子邮件发送公司，专注于为从个人到跨国公司的各种团体和企业提供交易邮件、营销邮件和新闻邮件。

其三大主要服务每月为其七百万客户发送超过一百亿封邮件。每天有一万名新成员注册。随着这种增长，挑战也随之而来，因为日益增长的成员、收件人、电子邮件地址和发送的邮件数量使得智能地对抗垃圾邮件、为邮件发送者和接收者行为建模以及理解整个电子邮件生态系统变得愈发困难。

在成为数据科学家之前，福尔曼的职业生涯横跨多个职位：美国国家安全局、麻省理工学院从事动态库存管理、博思艾伦咨询公司担任分析与管理顾问，以及在 Revenue Analytics 公司帮助《财富》世界 500 强公司进行收入管理、定价优化和销售预测。在这些不同的角色中，福尔曼与广泛的利益相关者打交道——从美国国防部和国税局，到可口可乐、皇家加勒比国际游轮和洲际酒店集团等公司。他拥有麻省理工学院运筹学硕士学位和佐治亚大学数学学士学位。

如今，作为一名“正在康复的顾问”，他保留了以客户为中心的视角，并拥抱了数据科学的世界。他是《数据智能：利用数据科学将信息转化为洞察》一书的作者，该书通过在简单的电子表格中使用强有力的例子来解释关键的数据科学技术，使这个领域变得不再神秘。

福尔曼是那种为了最好地满足最终用户需求而精选最新数据科学技术的数据科学家的典型代表。他将最终用户放在首位，这影响了他对自己作为客户与数据科学团队之间翻译者角色的理解，以及他那个反直觉的观察——过度依赖关键绩效指标（KPI）可能会损害最终用户体验。福尔曼在选择工具时的深思熟虑、他帮助其他数据科学家成功的意愿，以及他始终以最终用户为导向的态度，都构成了他本次访谈的特色。

福尔曼： 如果你把 Facebook 的“点赞”理解为关注一个页面，你并不完全清楚为什么“喜欢”那个页面或公司，因为那是一个非常公开的行为。你在 Facebook 上互动的东西非常公开。它们一部分是为了你自己，但另一部分也是为了展现自我。它们是为那些看着你的人而做的行为。Twitter 也是如此。你在 Twitter 上的行为也具有展现自我的性质。它们是为那些看着你的人而做的。

**古铁雷斯：** 为什么`发现相似订阅者`对 MailChimp 很重要？

**福尔曼：** 作为一家邮件公司，MailChimp 存在的意义是帮助人们与他们的受众互动。无论是希望与捐助者互动的非营利组织，运营新闻通讯的小型企业，还是联系老客户的大型企业，都是如此。我们在与各种规模的团体合作时发现，几乎所有人都想有效了解他们名单上的人之间有何不同，以便与他们进行恰当的沟通。他们明白，不同类型的人对不同的沟通方式反应良好。MailChimp 自认是一家科技公司，因此我们的工具带有一定自助服务的元素。所以，为我们自己构建一个能帮助客户轻松、有效地自行细分名单的工具就显得非常重要。`发现相似订阅者`正是促进了应用中的这种自助式受众研究。

在 MailChimp，由于我们拥有庞大的用户群和收件人地址库，我们确实在全球层面了解读者。因此，我们可以向用户提供关于他们自己名单的情报，这是竞争对手无法做到的。我们之所以能做到这一点，是因为我们从全球的电子邮件数据集中提取信息，这些数据包括梦幻足球联赛名单、拼布爱好者通讯，以及规模更大的公司通讯名单。我们拥有这些数据，因此可以想办法让用户也能获取。所以，`发现相似订阅者`产品是我们将自身对电子邮件的理解带给客户的一种方式——通过这种方式告诉他们：“根据您提供的标准，我们认为您名单上的这些人属于这个细分群体，而这些人属于另一个细分群体。”

**古铁雷斯：** 这个工具你们内部也使用吗？

**福尔曼：** 是的。我们自己在大约两年前发布一个名为`Mandrill`的新产品时就使用过它。`Mandrill`是一个通过 API 操作的交易邮件产品。应用程序可以用它来发送邮件。这与 MailChimp 非常不同。使用 MailChimp，你需要登录、上传邮件列表，然后在拖放编辑器中组合内容。而`Mandrill`的不同之处在于，你需要将它集成到你的应用程序中。这样你就可以用它来发送收据、密码重置邮件以及类似的交易邮件。这是一个非常棒的产品。

当我们准备宣布推出`Mandrill`时，我们正是使用`发现相似订阅者`来挖掘哪些客户可能想了解我们的新产品。

当时，我们拥有一个包含大约三百万个电子邮件地址的客户名单。那么问题来了，我们是否要让所有三百万人知道，如果他们正在开发应用程序，他们也可以使用我们开发的这个其他产品？答案并不意外：不。毕竟，我所在的本地教堂，他们只是定期发送新闻通讯，并不需要知道`Mandrill`。他们没有理由知道，我们也不想打扰他们。所以我们所做的就是使用`发现相似订阅者`工具来确定我们应该向谁发送关于新产品的邮件。

**古铁雷斯：** `发现相似订阅者`工具是如何工作的？

**福尔曼：** 当你思考我们拥有的数十亿个电子邮件地址时，你可以把它们想象成一个全球连接的图，所有这些地址基于共同的订阅或兴趣相互连接。有了所有这些连接，我就可以根据邻近度计算，找出谁（在兴趣意义上）“居住”在谁旁边或附近。基本上，你可以用邻里的概念来理解——也就是说，哪些邮件地址互为邻居。因此，一个拥有订阅者名单的用户，可以根据这个全球连接的图，提取出不同的细分群体。然后他们可以为自己名单中的这些特定细分群体创建并命名。

回到`Mandrill`的例子，我们就是这么做的——我们根据兴趣（软件开发）创建了一个细分群体。然后，我们专门向这个群体发送了我们的产品发布通知邮件，说：“嘿，请注意，`Mandrill`现在推出了。如果你想使用它，真的非常酷。” 那封邮件获得了惊人的参与度。我们不仅从中获得了极佳的参与度，也没有打扰到其他那些不想知道这个新产品的用户。这就是我所看到的，拥有这种数据并向用户提供这种细分能力的力量所在。

**古铁雷斯：** 你如何向不熟悉背后数学原理的人描述你的工作？

**福尔曼：** 对于那些不熟悉数学的人，我会说我扮演着三个角色。第一，我构建数据产品；第二，我是客户与我们的数据科学团队之间的翻译者；第三，我是 MailChimp 的大使。关于构建数据产品，我为两类客户做这件事。第一类客户是 MailChimp 的用户。为他们构建的数据产品通常是面向外部的产品，或像报告、博客文章这样的制品。我们对全球数据集进行研究，并向外部客户提供制品或产品，例如`发现相似订阅者`或`发送时间优化`。

另一类客户实际上是内部客户。在 MailChimp，各个团队都非常需要了解我们所拥有的数据，特别是了解我们的客户及其独特特征。这些正是数据科学团队可以提供支持的领域，因此我们也为这些内部客户构建工具。这些工具涵盖从反滥用模型、支持排班工具到支付意愿模型等各种类型。

第二个角色是成为内外部客户与数据科学团队之间的翻译者。作为一名翻译者，这有助于我弄清楚应该构建什么。我需要他人的意见；我不会自己凭空创造工作量。实际上，当一些分析团队那样做时是很可怕的。他们只是出现并说：“嗯，我们应该构建这个”，而他们并没有与任何人沟通。他们只是觉得使用某些工具会很酷。因此，我所做的工作很大一部分是与人交谈，理解他们的需求和问题，然后将这些需求翻译给 MailChimp 内部的技术同事。

**古铁雷斯：** MailChimp 如何看待垃圾邮件？

**福尔曼：** 首先，我们来谈谈电子邮件。电子邮件是一种无人真正控制的通讯标准。其他通讯系统，例如由 Facebook 运营的 Facebook Messenger，则受控于某个实体，由它决定其系统上发生什么。而电子邮件则不同，它的强大之处在于，任何地方的任何人都可以随时向你发送关于任何事情的电子邮件——无需某个更大的实体来规定交换的条款。

任何人都可以建立一个邮件服务器，并突然拥有发送和接收电子邮件的能力。当有人收到他们不想要的电子邮件时，我们称之为垃圾邮件。这一直是电子邮件的一个问题，因此人们与垃圾邮件斗争了很长时间。

打击垃圾邮件对 MailChimp 尤其重要，主要有两个原因。一是我们不想让用户发送垃圾邮件；二是如果大邮件公司（如 Gmail、AOL、Hotmail 等）的用户举报来自我们 IP 地址的垃圾邮件，这些公司会屏蔽我们的 IP 地址。我们的 IP 地址有可能被屏蔽是一个大问题。我们为七百万用户发送邮件，但我们没有七百万个 IP 地址。除了少数拥有专用 IP 地址的用户外，大多数用户是与其他用户共享一个 IP 地址来发送邮件的。如果我们允许一个不良用户发送恶意内容，邮件接收方就会屏蔽那个 IP 地址，这对使用该 IP 地址的所有用户都是不利的。因此，我们在打击垃圾邮件方面做了大量工作。

**古铁雷斯：** 通常如何打击垃圾邮件？

**福尔曼：** 十多年前，保罗·格雷厄姆写了一篇题为《垃圾邮件应对计划》的文章。从那时起，人们在垃圾邮件检测方面做了大量工作。如果你回顾一下那些早期的文章，处理方式是查看电子邮件的实际内容。人们分析页面上的词语，将其输入模型，以判断邮件中的词语是否涉及不良或垃圾内容。当然，这开启了垃圾邮件发送者与试图阻止他们的人之间的较量。

突然之间，Viagra（伟哥）这个词里出现了 @ 符号、用数字 `1` 代替字母“I”，或者类似的手段。垃圾邮件发送者试图绕过匹配标记、朴素贝叶斯过滤器以及类似的垃圾邮件检测技术。这种较量不断升级。然后，垃圾邮件发送者不再使用文字，而是开始使用包含文字的图片，这意味着试图阻止他们的人必须开始对图片进行 OCR（光学字符识别）以提取标记，再放入模型中来识别垃圾邮件。

# MailChimp 打击垃圾邮件的方式

这种状况一直持续到需要新方法的时刻。我们非常清楚，仅仅查看垃圾邮件发送者发送的内容是不够的。我们是一家国际公司，因此我们分析的内容可能涉及多种语言。也可能全是图片。或者，最令人担忧的——或许是最大的问题——是内容可能看起来完全正常。我认为这一点很多人并不了解垃圾邮件的本质。现代经典垃圾邮件过滤器运作的前提假设是，垃圾邮件体现了一种理想形式，即垃圾邮件总是与尼日利亚王子、`Viagra` 或类似的东西相关。

**古铁雷斯:** `MailChimp` 是如何打击垃圾邮件的？

**福尔曼:** 我们采用后现代的定义来思考垃圾邮件，即“垃圾邮件存在于读者的眼中”。我们知道这是真的，因为电子邮件客户端都有举报垃圾邮件的按钮。是收到邮件的你——将一封邮件判定为垃圾邮件。不是页面上的文字，而是`你如何解读`这些文字，以及你与发送者的关系。从数据科学的角度来看，这非常引人入胜。

我们打击垃圾邮件的方式是追踪发送者和接收者之间的关系。发送出去的邮件内容可能非常无害。比如说，可能是当地房地产广告。在这个例子中，可能是一个房地产经纪人发送某个市场待售房屋的广告。我们要弄清楚并试图判断的是，这个房地产经纪人如何获取他通过邮件联系的那些人的名单。这些人是他们过去服务过的客户，并且告诉经纪人：“是的，我希望以后还能看到你的内容！”吗？还是经纪人在当地商会会议上拿走了邮件列表？或者经纪人向州政府提交了公共信息请求，获取了公立大学雇员的电子邮件地址——我们见过有人这么做。经纪人是否从互联网上抓取了电子邮件地址？经纪人是否访问了公开的 `Facebook` 个人资料并获取了这些地址？所有这些获取电子邮件的方式，都会表现为发送者和接收者之间不同的关系。

## 数据科学家在工作

因此，我们需要做的是确定发送者和接收者之间的关系，以判断它看起来像是垃圾邮件发送者还是非垃圾邮件发送者的关系。再次强调，因为 `MailChimp` 与其他竞争对手不同，拥有关于邮件如何关联、人们在阅读什么、用户过去如何与邮件地址交互等海量全球信息，我们可以利用所有这些信息来解决这个问题。因此，我们可以计算出用户与他们构建的邮件列表之间的关系是否正常。我们通过围绕交易数据、元数据和邮件列表数据构建大量 `AI` 模型来实现这一点。所以，当新用户注册时，我们可以将他们及其列表运行通过 `AI` 模型，要么允许他们通过，要么立即阻止他们。这种方法的好处在于，我们甚至可以在用户为邮件创建内容之前，就判断出我们是否应该阻止他，因为这种关系看起来非常可疑。当然，我们会与他们沟通，我们认为这种关系完全是虚假的，他们必须另寻出路，因为我们能立即判断出这看起来像是一个垃圾邮件发送者账户。

## 《数据科学家在工作》

**古铁雷斯：** 你是怎么进入 `MailChimp` 的？

**福尔曼：** 我见到了当时 `MailChimp` 的首席运营官尼尔·班顿，并与他讨论了 `MailChimp` 面临的问题，以及数据如何能潜在解决其中一些问题。因为它是一家成功的在线公司，在 `Alexa` 500 强中拥有两个域名，其产生的数据集非常庞大。所以这正是一个利用数据解决问题的绝佳机会。起初我和他见面时，我以为是因为他在寻找人才，于是我开始推荐其他他应该谈谈的人。经过一些交谈后，他问道：“那么，你呢？” 随着我们谈得更多，这个机会的广度对我来说变得清晰起来，于是我最终来到了这里。

这绝对是一段极其精彩的经历，因为 `MailChimp` 的运作方式与政府或大型企业公司截然不同。在政府中，管理层级层层叠叠，有着非常明确的沟通链条。在企业界也是如此。而 `MailChimp` 是一个小型组织，所以结构非常扁平化。这不是一个你去告诉别人该做什么，或者去找他们的经理、让经理吩咐他们该做什么的地方。不，一切都要通过紧密的沟通与协作来完成，因此在这种环境下做分析工作是一个新的挑战。我发现我真的很喜欢随之而来的独立性和混乱状态。

**古铁雷斯：** 你是什么时候意识到数据的力量的？

**福尔曼：** 当你研究运筹学问题或优化问题时，数据很重要，但真正关键的是问题的建模。你只有很少量的输入数据——却需要基于这些数据做出非常复杂的决策。当我开始做价格优化模型时，数据的力量真正击中了我，让我大开眼界。这是因为你要利用历史数据来预测某种产品的需求，不管是酒店房间、游轮舱房、飞机座位还是其他什么，然后随着更多数据的涌入来更新该产品的定价。

这些定价模型的惊人之处——我认为它们是目前最酷的数据科学模型之一——在于其决策直接影响收入。如果我选择降低酒店的价格，因为我认为这能最大化收入，这对一个模型来说，是一个相当大胆的决策。它居然能说“你需要把价格降低 15 美元”，并且这能对你的最终利润产生积极的影响，这太神奇了。这个模型确实能这么说，之后我们还可以回过头来证明它是正确的。我们看到一些《财富》500 强公司每年因之获得 2% 的收入增长，在那种规模下，这是非常惊人的。

这真正让我认识到，如果你能够恰当地收集并跟踪大量的交易数据，那么你就拥有了一项竞争优势。

**古铁雷斯：** 你是如何学习并保持对数据科学行业的最新了解的？

很多数据科学书籍有趣的一点是，它们都预先选定了一种特定的工具，不管是 `R` 语言、`Python` 还是其他东西。

如果你想真正学会如何完成这些工作，就必须使用现有的工具来实践，因此书籍会做出工具相关的决策。通过学习这些书中的代码示例，可以帮助你初步入门。但当你试图真正理解一项技术时，这同样可能成为一种干扰。

这也是我写《Data Smart》这本书的部分原因。我觉得书中的许多示例都只是：“让我们加载支持向量机包，训练模型，然后查看结果。”这就像是等等等等等等。你需要详细解释那个支持向量机是如何构建起来的。你不能只是构建它。那是作弊，而这正是你在实际工作中会做的事——你相信那些包能正常工作——但为了学习目的，你不能这样。所以我写这本书就是为了详细拆解所有这些内容，并且不使用非常复杂的公式，也许不像哈斯蒂那本书那样。

一天中的另一部分时间用于非常仔细地规划和思考我们要构建的基础设施类型。既然我们在 MailChimp 有了一个数据科学团队，就不能仅仅着眼于构建维持应用程序运行的基础设施了。那显然是第一要务。但现在我们有了所有这些想要访问数据进行分析的人。这种访问模式与用户访问他们自己的数据非常不同，所以我们需要仔细考虑这一点。每当我执行一个`SQL`查询时，大家都会跑开，因为从应用程序运行的查询只命中索引，而我运行的查询则涉及大量的连接或子查询。所以，当我带着一个包含百万次连接的奇怪嵌套查询出现时，天哪，里面还有一个交叉连接，我正把某个数据集搞得一团糟，并在`SQL`中对它做窗口函数之类的事情，我会让我们 NOC [网络运营中心] 墙上的所有信号灯变红。这对他们和我来说都不好玩。因此，白天肯定需要讨论我们要构建哪些系统，以及它们将如何被使用。

我们必须为分析师留出空间，让他们可以随心所欲地访问这些服务器，或者随心所欲地处理不同的数据集。这需要反复沟通：你需要什么数据？我们能提供什么数据？你的需求是什么？你是在为生产环境构建东西，还是在为分析构建东西？你能否接受查询运行很长时间？它需要运行得非常快吗？所以，我一天中的一部分时间涉及技术需求。

一天中的另一部分时间则用于与高管和其他面向客户的团队交谈，询问他们从用户那里听说了哪些他们想要的功能。然后思考是否可以利用数据来实现这些被要求的功能。我们最近完成的一个被要求的功能是发送时间优化。我们花了大量时间讨论如何利用我们的数据来适当地预测和优化客户应该何时发送他们的新闻通讯，以便最好地吸引他们的受众。推动参与度的因素之一可能是电子邮件接收者的时区。每个人都不同，每个人的日程安排也不同，但他们可能会集中在一天中的几个特定时间点，尤其是根据他们在地球的哪一侧，因为大多数人上白班，大多数人晚上睡觉。这些都是显而易见的事情。但从那以后，问题就变得更加复杂了。所以，我们与高管和我们的定性研究团队交谈，以真正了解人们是否想要这个功能，然后弄清楚需要什么数据。如果我们真的构建了它，我们认为应该如何向用户展示它。我们花了相当多的时间来确保，如果我们在这个项目上投入时间和精力，这将是一项很好的投资。

# 在我一天的工作中

一旦我们花时间弄清了客户的需求，接下来的部分就是规划我们下一步要构建哪些产品，然后将这些规划带回我们合作的团队，向他们解释我们将如何构建特定产品。例如，我们内部很多事情都是通过内部 API 调用来完成的，因此我们需要确保这些 API 的构建方式能够满足我们内部客户的需求。

**古铁雷斯：** 你如何看待和衡量成功？

**福尔曼：** 对于使用所谓的 `KPIs` 来衡量成功，我们非常谨慎，甚至可以说是抱有敌意。我们看到许多竞争对手用非常死板的方式衡量成功。互联网公司关注诸如 `ARPU`（每用户平均收入）、留存率或向付费计划的转化率等指标。我们本也可以这样做，但我们没有。整个组织完全不衡量这些指标。具体原因是我们作为一个组织——不仅仅是数据科学团队，而是整个组织——都认为，当你开始关注这些定量的成功指标时，事情会变得扭曲。

我来举个例子说明 `KPIs` 导致的这种扭曲。我是大力水手炸鸡的忠实粉丝。我喜欢他们的鸡肉和红豆米饭。然而，最近我去他们的一家汽车穿梭餐厅点餐。我把车开到窗口，他们有一个计时器在运行。这个计时器本质上是为了评估他们服务每位顾客的速度绩效。如果这个指标是被激励的，是每个人都关注的指标，那么在理想情况下，人们会以适当的方式努力改进这个指标。

但他们实际的做法是以一种扭曲的方式来改进指标。每一位开车过来的顾客，都会立刻被告知：“嘿，你能把车停到那边的车位吗？我稍后会把食物给你送过去。”于是，他们立刻就降低了实际绩效，并没有真正加快任何速度。他们之所以改善了被衡量的“服务每位顾客的时间”指标，是因为他们重置了时钟——因为你只是把车开进了停车位。毕竟，你很难拒绝他们，因为他们正在为你准备食物，你也不想惹麻烦。但现在他们的绩效反而下降了，因为他们不得不把食物送过来。所以他们花时间绕过柜台、走出店门、试图找到哪辆车对应这份订单、把食物送到我的车窗、和我确认确保找对了车、然后走回店内、再绕过柜台去服务下一位顾客。你可以想象，这会花很长时间。因此，由于这个组织专注于这个时间指标 `KPI`，他们实际上从全局上降低了绩效。

回到我们的业务，我们在竞争对手那里也看到了类似的行为。他们专注于某些指标，结果却导致了无法恰当地服务用户——也许他们在短期内创造了更多收入，推高了股价，但实际上也与用户之间积累了大量敌意。我们不必担心这个，因为我们是一家私营公司，不为他人所有。我们关注的是——这听起来可能有点傻，尤其对于数据科学家来说——我们用户的幸福感。因此，我们与用户保持着非常密切的沟通，不仅是通过社交媒体在线积极互动，还飞往全球各地与用户交谈。我们利用这些对话来了解客户在说什么，他们喜欢什么，不喜欢什么。我们只专注于他们的幸福感，以便提供尽可能最好的产品。

抛开指标不谈，如果你正在尽己所能解决所有你通过对话了解到的问题，并专注于你做得好的方面，那么这实际上就是你能做到的最好状态。这也不会产生任何奇怪的、扭曲的衡量标准，让你不去看用户和你的产品，而是避开用户和产品，只盯着一个 `KPI` 数字。在某些情况下，你甚至会在内部与其他团队就这个数字展开竞争，并提出诸如“这个数字中有多少可以归功于数据科学团队？”这样的问题。这是一种看待问题的可怕方式。

有多少收入可以归功于数据科学，而不是市场营销或用户体验？一旦你开始这样区分，突然间，你就让团队之间产生了对立，让领导之间产生了对立，合作的意愿就降低了。

所以，我认为，通过不专注于这些衡量标准，我们实际上为组织做出了巨大贡献，我们只是鼓励每个人都专注于让我们的用户满意。当需要解决的问题出现时，我们更容易直接说“这里有个问题需要解决”，然后问“谁能为此做些什么？”也许问题背后并没有一个数字，所以我衡量成功的方式就是我从客户那里得到的反馈——无论是内部客户还是外部客户。专注于获得非常积极的反馈，确保我的目标是看到人们以正确的方式使用我的功能，并从中获得良好的体验。

当然，我们也会衡量一些非常实在的指标，以确保我们的客户保持满意度。这些低层次的指标更多是关于服务器正常运行时间、发送时间优化是否有效、人们是否在使用它、细分效果如何、它是否有帮助、不良用户是否被拦截、垃圾邮件报告情况如何、邮件是否被退回，以及其他类似的局部指标。因此，我们关注的是类似这样的运营指标——只是没有那些疯狂的、全局性的愚蠢指标。

**古铁雷斯：** 你如何知道你正在解决正确的问题？

**福尔曼：** 这是个难题，因为弄清楚你应该解决什么问题的有趣之处在于，它需要结合用户认为他们想要什么、用户实际想要什么，以及这个领域的发展方向。与用户交谈至关重要，因为他们会为你指明正确的方向。然而，内部或外部用户描述问题的方式，通常是某人已经以特定方式思考和处理过问题的结果，这意味着我们必须弄清楚他们提出的问题方式是否就是实际的问题。

回到前面提到的电梯群例子，也许问题是“我需要你构建一个优化方案来加快我的电梯速度”，而实际上，问题是“我想用任何可能的方式让更多人进入电梯”。根据你解决的是哪个问题，解决方案会截然不同。一旦明白了人们只需要通过（挤进电梯），正确的解决方案就是在那里放上镜子，这样人们就会挤得更紧密。所以你必须非常小心，当人们要求功能或工具时，你实际上解决的是他们根本的问题。

# 在竞争激烈的行业中成为一家公司的意义

此外，在竞争激烈的行业中成为一家公司，意味着要创造出人们可能还没想到、但一看到就会觉得“哦，对，这样好多了”的东西。所以这其中也包含了创意的概念。我们必须确保不仅理解我们所在行业的走向，还要关注其他领域正在发生什么。通过这种方式，我们可以借鉴那些隐喻，并思考如何将它们应用到我们的世界中。这就是数据科学中那一点“黑魔法”的用武之地——也就是这个创意部分。这不仅仅关乎理解我可用的技术、数据和技术本身——那些只是基础。它更关乎花时间去构想和发挥创意，而不是等着别人告诉我该做什么。

因此，这里既有真正主动倾听、弄清人们实际在说什么的概念，也有倾听世界上正在发生的事情、并理解它如何影响我的世界的概念。法语中有一个词叫 `bricolage`，意思是将这些毫不相干的东西组合成新的事物。就我而言，就是思考其他行业的人们如何解决问题，以及这如何应用于我们正在做的事情。有时你会走进死胡同，意识到对于我们的客户和我们的目标而言，这毫无用处。而其他时候，你则会发现宝藏，意识到：“天哪，如果我们像他们那样做，如果我们真的能创造出这个东西，那对我们的客户来说太棒了。”

## 关于工具集和技术

**古铁雷斯：** 你如何看待工具集以及你目前正在使用的技术？

**福尔曼：** 我在思考工具方面非常保守。在数据科学领域，让我印象深刻的是，工具在牵着分析走，也就是说，很多组织会被崭新、闪亮的新工具所吸引，而不是思考他们试图解决什么问题。他们会说：“哦，我们真的很想用这个工具。”然后他们才想出一个使用它的理由。供应商可能在一定程度上助长了这种情况。供应商的存在是为了向你推销一个解决你可能还没有遇到的问题的工具，而且他们非常善于说服你需要它，无论你是否真的需要。我经常遇到运行着 `Hadoop` 的人，他们兴奋地告诉我，现在他们所有的数据都在 `HDFS` 里了。我问他们有多少数据，是否是结构化的。当他们告诉我只有几个 GB 的结构化数据时，我总是感到很惊讶。这种大小和类型的数据，一个很小的免费 `SQLite` 数据库就能装下。这告诉我，他们遇到了一个非常优秀的销售员，而并没有真正思考过他们要解决的问题是什么。

如果你用这种本末倒置的方法，那就像大多数人想要健康减肥的新年决心一样。1 月 1 日，我去办了一张健身卡，买了一大堆健身装备和新衣服。我做了什么？什么都没做。我还是和以前一样胖，但我觉得自己正在取得进展，因为我花了钱，买了东西。在我看来，那些出去采购工具的公司也是如此。他们对自己说：“我们必须搞大数据，我们必须搞数据科学，那我们去买工具、请顾问吧，然后我们就准备好了。” 他们还没回过神来，所得到的成果就只是花了一大笔钱、一堆工具，也许还有一张信息图，因为他们从未花时间去做那件很难展示进展的事情——思考。他们从未坐下来好好思考：我们应该解决什么问题？我们有什么数据？基于我们现有的数据，应该如何处理这些问题？

相反，他们出去花掉了预算，因为这是表明你在做事的一个好办法。你在花钱。肯定有事情在发生。每个人都在等着别人在花钱的同时把事情做成。

我们与众不同，而且非常保守，因为我思考工具的方式是以问题为中心的。我们从想要解决的问题入手，或者对几个想要解决的问题有一个大致了解。然后，我们评估可用的数据。我们思考可用的技术。我们思考可用的技术方案。然后，也只有到那时，我们才会选择能够解决这些问题的技术。

例如，在我们为合规性构建的一些 AI 模型中，我们本可以使用一些非常酷炫的工具。然而，我们意识到，所有这些模型关心的数据都已经是结构化的。正因为是结构化的，它们在 `SQL` 上下文中已经运行得很好。此外，我们为训练集需要运行的许多查询，都是通过 `SQL` 窗口函数最能高效完成的，因为我们处理的是大量滞后的时间序列数据。所以，一旦我们意识到这一点，我们就发现这些数据放在一个分片的 `PostgreSQL` 数据库中就很合适，因为数据量可能小于 30TB。意识到这一点后，我们反问自己，为什么还需要别的呢？这个工具非常健壮和稳定。它是一个开发人员非常擅长的工具。他们可以快速部署。我们的合规团队昨天就想要模型了。我为什么要选择那些不那么稳定、看起来更酷，但我们的开发和运维人员还不太了解的工具呢？当我可以使用我们已经熟悉的其他东西时，我为什么要冒险呢？所以，我在选择工具时非常保守。

## 关于招聘

**古铁雷斯：** 你在招聘时看重什么？

**福尔曼：** 显然，如果我们知道我们现在和将来要使用的技术，我们确实希望招聘熟悉这些技术的人。我们希望招揽那些真正掌握我们目前正在使用、将来会使用，或者在我们未来可能使用的工具范畴内（即使我们现在还不知道）的人才。

然而，我认为这不是你唯一应该看重的。我寻找我认为非常重要的几点：学习能力和沟通能力。我们希望了解的是，即使你过去没有完全使用过我们将来要用的东西，也许你用过别的，但你仍然能够学习这些东西。这对于了解和判断一个人来说是一件很棘手的事，所以你必须要求他们举例子。你得听他们清晰地讲述过去遇到的问题。如果他们不能清晰地阐述遇到问题的情况，以及他们如何使用各种方法、表现出足智多谋（比如这样说：“我当时不知道怎么用，但我拿起它，我们就这样用了”），如果他们连类似这样的故事都讲不清楚，那可能就是一个危险信号。所以我们一定会寻找这种学习能力。

能够清晰地讲述这样的故事，本身就要求必须具备沟通能力。我认为，对于一个数据科学团队来说，招到那些能够用非技术人员能理解的方式，真正讲述他们所做技术工作的人至关重要。这是因为，作为一个数据科学团队，你最终要和很多非常非技术性的团队合作。我和营销团队合作的次数和与开发团队合作的次数一样多。所以，如果我团队里有一群人沟通能力很差，只是像等待人扔过栅栏的鲜肉一样等着工作被安排过来，那这种状态是不可持续且毫无效率可言的。

**福尔曼：** 这又回到了我热衷的一个话题，也许很多人并不在意，那就是：人们很容易痴迷于工具——你必须时刻警惕。让工具替你完成所有工作是非常容易的。但我认为，数据科学从业者了解这些工具在做什么是很重要的。你不必知道所有细节，但应该有一个总体概念。

这一点在研究生阶段就深深地烙在了我的脑海里。有一次课上，教授让我们手工构建一个优化模型。我们必须手写在纸上完成单纯形法的所有迭代运算。那真是糟糕透顶。任何时候你要手工对矩阵进行大量运算，都是一场噩梦。他让我们只做了一次，之后我们再也不需要手工做了。虽然过程很痛苦，但现在当我运行单纯形法时，我清楚地知道背后发生了什么，因为我曾用手工做过。

这对于直观地理解你所做的事情非常有帮助。

当你构建一个模型时，你会本能地知道自己在做什么，以及当你调用某个方法时，它会做什么。如果你没有做过一次，没有真正学习并内化它，那么我觉得你内心总会潜藏着某种隐秘的疑虑。而且你将无法完全证明或相信你所做的事情，因为你在某个时刻就像念了一句神奇的咒语：“调用这个人工智能模型。”你实际上并不了解它在做什么。你可能会对它期望过低，也可能期望过高，但就是无法完全理解它。

我认为很多人工智能模型其实非常“笨”。朴素贝叶斯是你见过的最笨的东西。所以，既然我知道它是如何构建的，并且实际上手工做过一次，我就大概知道它能达到什么效果，因为我了解它内部的工作原理。

因此，我写那本《数据智慧》的目的是，带领读者体验各种不同类型的建模。它引导人们从无监督人工智能一直到数据挖掘。它多次引导人们进行有监督人工智能建模。它还引导人们进行预测、异常值检测、优化和模拟。而他们进行建模的方式是在电子表格中手工完成每一个模型。

他们在电子表格中完成，因为这样无处可逃，也无法隐藏。你亲手完成每一步，就能看到它是如何工作的。我这样做有几个原因。一是向人们展示这不是什么黑魔法。数据科学和机器学习周围有很多非常酷的词汇，让它们听起来像《终结者 2》里那样，机器人要来毁灭地球。然而，当你看到像提升树模型这样的东西时，它虽然相对前沿，但并没有那么难。我认为一个有大学一年级数学基础的人就能构建那个模型，并理解关于它的一切。

# 写书的目的与读者对象

所以我写了这本书，因为我想带领读者深入了解这些内容，帮助他们建立信心，让他们明白自己可以在这些模型中进行原型设计，而不必害怕。我希望他们看到，尽管这些模型看起来简单甚至有些愚蠢，但它们依然能出色地完成任务。我想拓宽讨论的范围。我觉得很多人谈论这些东西的方式太过神秘了。他们并不真的想告诉你他们在做什么，因为他们的工作保障建立在某种像萨满一样的角色之上。但这不应该是你工作保障的真正基础——它应该基于解决问题。如果你能恰当地解决问题，并且你能很好地解释自己，你就不会失去工作。你不必躲在没人了解这个模型背后的事实后面。

这就是这本书的目的。它适合那些乐于接受挑战、真正想了解这些模型如何工作的人。你可以和我一起操作电子表格。到最后，如果你坚持下来了，你就能真正掌握这些东西。你会知道如何有根据地讨论它们。所以我认为这对特定类型的读者来说非常有趣。这不是睡前读物。你不会在床上读它。它更像是让你坐在书桌前，身体前倾，跟着我一步步操作。所以我认为这是对市面上许多其他书籍的一个很酷的补充。

## 使用 Excel 作为工具的原因

这意味着那些使用前面提到的编程语言的书籍把这些人都抛在了后面。

**埃伦伯格：** 有趣的是，最有价值的公司看起来很像平台，但它们并非一开始就是这样。它们起初往往看起来像是拥有非常具体垂直应用的初创公司。随着时间的推移，当在一个特定用例或垂直领域取得成功后，这些公司才会扩展到其他垂直领域。我认为，拥有一个非常清晰的早期用例至关重要，因为《工作中的数据科学家》第 135 页提到，当你支持这些拥有平台愿景的杰出技术专家时，很容易分心太多，“试图煮沸整个海洋”。

对我们而言，我们主要支持的是初次创业者，所以他们不仅没有所有答案，而且通常缺乏商业建设的经验。

**古铁雷斯：** 与公司早期合作是什么样的？

**埃伦伯格：** 我们很早就与所投公司合作，确定在执行他们的计划时，关键绩效指标是什么以及应该是什么。关键绩效指标并非在第一天就能确定。当然，有一些通用指标是每个人都需要追踪的，但根据业务不同，你可能还需要收集其他数据元素，而这些元素的重要性只有在客户开始与产品互动时才会显现。因此，我们与公司合作，努力建立一种衡量文化。我们倾向于那些直觉上就接受数据收集和分析的创始人。我们与这些团队合作，根据他们的特定业务识别出需要追踪的正确数据，以及如何利用这些数据来改进产品和/或营销策略。

**古铁雷斯：** 在访谈中，你谈到投资那些将*被动数据*转化为*主动数据资产*的公司。你是如何找到这些公司的？

**埃伦伯格：** 识别机会有两种主要方法。一种是筛选我们大量的*进入式*交易流，这些交易流要么通过可信赖的关系以“*热*”的方式来到我们面前，要么通过不在我们网络中的人直接接触以“*冷*”的方式出现。另一种方法源于我们对某个特定市场机会或新兴领域的假设。在这种情况下，我们会主动寻找那些试图解决我们眼中市场空白问题的人，并且我们对寻找解决方案充满热情。

而帮助将被动数据转化为主动数据的问题则是在后期才出现的。

我们投资的是一个正在建立业务的团队。我们投资的是一个不是正在建立数据集的团队。数据集在许多情况下是与客户互动产生的副产品。一旦公司与客户互动，我们就可以考虑这些副产品，以及公司如何通过从数据中获取洞察来改进产品或客户体验。

**埃伦伯格：** 除了阅读当前文献，我认为就是观察社会如何应对快速变化的条件和新技术的浪潮。随着我们投资组合的增长以及我们对所投公司有了更长的纵向经验，我们能够越来越多地了解到哪些是有效的，哪些是无效的，以及哪些是尚未解决的大问题。我们一直在收集数据，无论是来自我们自己公司的内部数据，还是我们在外部世界中观察到的东西。

**古铁雷斯：** 你最初关于以数据为中心的公司的看法是如何形成的？

**埃伦伯格：** 很大一部分是通过我在华尔街的经历潜移默化而来的。我职业生涯的最后五年都沉浸在高速数据和数据流的世界里。这让我明白，尽管 90 年代末和 21 世纪初存在的基础设施还不错，但相对于我所认为的数据速度和体量不可阻挡的增长而言，存在着巨大的差距。我明白需要出现新的技术来处理这个不断变化的世界。

另一个帮助我形成观点的经历是预测分析和语义智能如何被实际应用。同样，这些也是我们在 DB Advisors 的一些策略中涉足过的事情。所以，即使我离开了华尔街，我仍然觉得这两个领域非常吸引人。有趣的是，大多数传统的量化方法已经是众所周知的。文献资料就摆在那里，人人都可以看到，因此，要么需要在被解析以产生洞察的数据类型上进行创新，要么需要在解析现有数据以产生更好、更快洞察的技术上进行创新。

所以，这些是早期帮助塑造我思维的一些影响。

然后，当我看到广告技术领域正在发生的事情时，我凭直觉就明白，广告市场和金融市场的结构会随着时间的推移而趋于一致。至于何时会发生，我当时并不确定，但这正是指导我在早期进行广告技术投资（例如投资 Invite Media 和 TubeMogul 这样的公司）的理念。这些早期的洞察，以及它们后来被验证的方式，一直延续到了 IA Ventures。

**古铁雷斯：** 既然有了这些看法和洞察，你是否创办了一家公司来利用它们？

**埃伦伯格：** 我确实自己创办了一家公司。不幸的是，我们起步太早，犯了很多错误，最终失败了。在帮助建立这家公司的过程中，我继续做天使投资，所以收集了大量关于成功的创始人如何建立公司，以及这与我的第一手经验有何不同的数据。在我作为公司创始人失败后，我决定有一种方法可以让我继续成为建设者——那就是成为一名全职投资者。这就是促使我创办一家风险投资公司，并更好地利用我的核心能力的原因。到目前为止，一切进展得相当顺利，但风险投资和公司建设是一个非常长周期的事业。

**古铁雷斯：** 你如何引导初次创业者思考并找到他们的核心能力？

**埃伦伯格：** 当我们进行投资时，我们对创始人的核心能力已经有了一个概念。仅仅因为创始人的技能组合不完整，并不意味着他们不能成长和发展，特别是考虑到我们支持的大多数创始人都在 20 多岁和 30 多岁——这些是年轻人，有大量的时间成长和发展。然而，有些人就是不想改变。比如说，一个创始人非常专注于技术，他们只想写代码。所以他们既不想做 CTO，也不想做工程副总裁。他们真正想做的是首席架构师。我们尝试做的是支持那些人才济济的优秀小团队。然后，随着时间的推移，当公司执行他们的计划并相应配置人员时，他们和我们都会重新评估角色和职责。


有些技术型创始人绝对、肯定地想要成为 CEO，然而他们知道，与那些成功将公司做大的前辈相比，自己在知识和经验上存在差距。这些技术创始人中的许多人会积极寻求指导。他们思想开放，渴望拓展自己的技能组合。然而，有时候，一个创始人认为自己想当 CEO，但当他被要求负责招聘、财务和整体监督时，他们会意识到(a) 他们不擅长这些，并且 (b) 他们讨厌这些。

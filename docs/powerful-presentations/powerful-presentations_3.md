# 3. 撰写吸引观众的演讲简介

一旦你设计好了演讲内容和所有幻灯片，你就需要鼓励聚会小组或会议安排你的演讲。当演讲被选中后——尤其是如果你在一个听众同时有多个演讲可供选择的会议上发言——你需要说服与会者报名参加你的演讲。实现这一目标的工具就是演讲简介。简介包含演讲的名称以及演讲的内容。你的演讲简介是留下良好第一印象的最佳机会。

在本章中，我们将回顾简介的标准结构，然后看看我过去做过的四个演讲的简介。

## 简介的重要性

一份简介可以成就或毁掉你演讲的成功。你可能认为你的演讲是有史以来最好的，但如果你的简介很薄弱，无法激发潜在听众的兴趣，他们就会选择另一场演讲。

撰写简介没有固定的规则，但有一个你可以遵循的结构。你可能决定不总是使用这个结构，这也没问题，但它为你提供了一个坚实的起点。典型的简介结构可以概述如下：
*   引人入胜的演讲标题
*   开场钩子
*   更多细节
*   结束语

### 引人入胜的演讲标题

任何人首先看到的就是你的演讲标题，这将决定他们是否想继续阅读。如果标题没有吸引住他们，他们就会直接点击到下一个演讲。我一直成功地采用主标题加副标题的方式来命名演讲。这种格式似乎效果很好。在本章后面，我将带你了解我自己演讲中的四个简介示例，但现在，我们先来看看标题。

第一个标题是“对抗分心的世界：提升你的专注力与自驱力”。主标题相当引人入胜，以一个关于分心世界的演讲吸引了你——这是大多数人都能感同身受的话题。然后副标题谈到提升专注力和自驱力。我们立刻就能看出这个演讲是关于战胜分心、提升专注力和动力的。这个标题本身就很好地展示了演讲的内容。

下一个标题是“`.NET Core` 数据安全：希望不是一种策略”。这是一个非常技术性的软件开发演讲的标题，专注于微软 `\.NET` 编程框架。这个听众群体将立即知道这个演讲是关于 `\.NET` 自带的那个安全框架。副标题说希望不是一种策略，暗示忽视数据安全是徒劳的，而本演讲将为你提供一个真正的策略。同样，合适的听众仅从标题就能立即知道演讲内容。这目前是我最受欢迎的演讲，我在世界各地都做过不同版本；它的评分一直非常高。

下一个标题是“使用 Azure Key Vault 保护加密密钥”。这个标题没有副标题，但主标题直切要点。任何在微软 Azure 云计算领域工作的软件开发者都会立刻明白这个演讲的内容。没有花哨的标题党风格用语；标题直接就切入主题。

本章要讨论的最后一个演讲标题是“入侵人类：社会工程学技术及如何防范”。“入侵人类”这个说法是特意选择的，相当大胆。这是一个关于社会工程学的安全演讲，但乍一看，“入侵人类”可能会被理解为别的东西。不过副标题确认了，这个演讲并非关于斧头谋杀。演讲涵盖了社会工程学技术以及如何防范。听过这个演讲的人说，完整的主标题和副标题非常引人注目，因为它们直接暗示你将了解到社会工程师如何运作以及如何防范他们。

最近有一股使用像 BuzzFeed 这类网站上的标题党风格标题的潮流。不过我要说，除非你的演讲设计成幽默风格，否则我建议避免使用标题党。如果内容严肃，标题党看起来会很糟糕，并且会削弱演讲的影响力。如果你觉得这个有趣，你绝对猜不到我接下来要说什么！光是写这句话我就觉得很尴尬。

### 开场钩子

一旦演讲标题抓住了读者的注意力，他们就会想了解更多。你简介的开头几句需要提供一个出色的钩子。你可以陈述一个有趣的事实，或者提出一个你将解决的问题。如今人们的注意力持续时间很短，所以这几句开场白必须吸引人。一旦他们被钩住，就会继续读下去。如果他们读完你的钩子后认为这个演讲不适合自己，他们很可能会停止阅读，不会来参加你的演讲。我将在本章后面部分探讨我一些演讲中的钩子。

### 更多细节

既然你已经通过标题和开场钩子抓住了他们的注意力，他们会想要更多关于你演讲的细节。在这一部分，你可以提供关于你将涵盖内容的详细细节。如果这个演讲针对的是中级或高级水平的人，你需要包含相当多的细节，以便他们能判断你的演讲是否适合他们。你不希望参会者来到你的演讲，期待某些主题，却感觉你没有满足他们的期望。

### 结束语

结束语是最后的一两句总结，旨在为读者留下最后的钩子。在提供演讲的主要细节后，你可以陈述一个有趣的事实，或重申你试图解决的问题。本质上，你是在提醒读者，如果参加你的演讲，他们能获得什么。

撰写演讲摘要的这四个步骤是一个指南，而非一套明确的规则。当然，你可以在摘要中自由发挥，但这些步骤提供了一种可靠的方法来写出引人入胜的演讲介绍。我并非一直遵循这种风格，但如果你需要从某个起点开始，它们会有所帮助。

现在，让我们看看我发表过的四场演讲的摘要。这些是我最受欢迎的四场演讲，已被全球各地的会议接受，并且在要求参会者评分的活动中获得了极高的评价。我的演讲主题通常涉及软件开发、安全和个人生产力。即使你感兴趣的领域不同也没关系，关键在于原则，如下面的示例所示。

**注意：** 演讲摘要除了演示文稿本身之外，是演讲设计中最重要的方面之一。如果你向会议投稿，演讲是否被接受将完全取决于摘要。一旦你被获准在活动中演讲，摘要就会成为主要的广告，用来鼓励人们优先选择你的演讲而非其他人的。

## 演讲 1：对抗分心的世界：提升专注力与自我驱动力

《对抗分心的世界》是我从 2019 年开始在会议上发表的一篇关于生产力的演讲。它非常受欢迎，经常能坐满整个大厅，与会者反馈也很好。我在本书前面部分已经讨论过这个演讲的标题，以及我如何使用主标题和副标题来让读者对演讲内容有个好印象。

在进一步分解摘要之前，我希望你先完整地阅读它。

> *我们生活在一个科技奇迹的时代，互联网、高端游戏和流媒体服务都在争抢我们的注意力。我们从未有过如此多的重要创新可以随时随地在指尖获取。然而，伴随着所有这些系统，我们变得越来越分心，难以长时间集中注意力。如果任其发展，这些干扰会影响我们的工作、职业和自信心。我们需要能够打破这种分心的循环，同时仍能享受所有这些创新。*

> *当我刚开始成为自由职业者时，我以为我将拥有终极的自由，可以随时做自己想做的事。某种程度上确实如此，但没有人监督我，让我保持责任感。我开始变得分心。过了一段时间，我决定必须做出改变。我开启了一段旨在变得更高效、更专注、更有动力的旅程——同时仍然偶尔会沉迷于狂刷 Netflix。*

> *在这个演讲中，我将分享我个人关于分心、动力不足和项目焦虑增加的故事。我也会分享我如何打破这个循环，找回创造力和高效的工作状态。*

> *这个演讲面向任何渴望提高生产力但却每日与分心作斗争的人。我将涵盖以下主题：*

* > *分心与拖延*

* > *在工作中寻找意义*

* > *自我激励*

* > *控制点*

* > *生产力与时间管理*

* > *社交媒体成瘾*

> *我现在认为自己非常高效，但达到这个状态是一场战斗。让我分享我的故事，这样我也可以帮助你变得高效和自信。*

总的来说，这是一个我引以为豪的摘要，也是我较新的演讲之一。我们已经看过了标题，现在让我们进一步分析开头的钩子。

> *我们生活在一个科技奇迹的时代，互联网、高端游戏和流媒体服务都在争抢我们的注意力。我们从未有过如此多的重要创新可以随时随地在指尖获取。然而，伴随着所有这些系统，我们变得越来越分心，难以长时间集中注意力。如果任其发展，这些干扰会影响我们的工作、职业和自信心。我们需要能够打破这种分心的循环，同时仍能享受所有这些创新。*

我一开始就提醒读者，我们生活在一个美妙的时代，所有科技都触手可及。就拿不起眼的 iPad 为例，一块你可以随身携带的玻璃屏幕，可以访问任何你想要的信息、看电影、与家人朋友通话或玩游戏。不久之前，像 iPad 这样的设备还是科幻小说的主打。我总记得《星际迷航》中的让-卢克·皮卡德在进取号星舰的休息室里，在一个看起来像平板设备的装置上查阅信息。我一直想要一个，现在我家里有好几个类似的设备了。

接着，我指出，尽管这些设备功能强大，但它们也极擅长分散我们的注意力——邮件、通知、电话、视频通话、推特消息。大量的干扰会阻碍你的工作效率。我提出，如果对这些干扰置之不理，我们的职业生涯和自信都会受到影响。我以此收尾，重申我们需要打破这种分心的循环，同时依然要享受科技带来的便利。在这里，我试图暗示我们将在演讲中尝试解决这个问题，但演讲的目的并非让你放弃科技。

这是一个强有力的开场钩子。只需阅读这几句话，你就能对演讲的基调和内容有所了解。一些已接纳此演讲的会议会在日程页面上显示演讲标题和我的开场钩子。读者随后必须点击演讲才能了解更多信息。

接着，在摘要中，我们会为那些在阅读开场钩子后感兴趣的读者提供更多关于演讲的信息。

> *刚成为自由职业者时，我以为自己会拥有终极自由，想做什么就做什么。某种程度上确实如此，但没有人监督我，没人让我负起责任。我开始变得分心。过了一段时间，我决定必须做出改变。我开启了一段探索之旅，力求提高效率、专注力和动力——同时仍会偶尔放纵自己刷一刷网飞。*

在摘要的下一部分，我介绍了自己的个人故事。我的意图是向读者暗示，我不只是要罗列一系列技巧——我是在分享亲身经验。在我看来，我最喜欢的一些演讲都基于演讲者的亲身经历，这能让你在演讲中编织一个故事，而大家都喜欢好故事。

现在，我们希望读者已经完全被吸引住了。他们知道了演讲的主题以及我个人故事的引子。现在让我们提供更多细节。

> *在本次演讲中，我将分享我关于个人分心、动力不足以及项目焦虑加剧的故事。我还会分享我是如何打破这个循环，重新找回创造力和工作热情的。*

# 演讲文稿设计与结构分析

> *本次演讲面向所有渴望提高效率但每天却与分心作斗争的人。我将涵盖以下主题：*
> *   *分心与拖延*
> *   *在工作中寻找意义*
> *   *自我激励*
> *   *控制点*
> *   *效率与时间管理*
> *   *社交媒体成瘾*

如果读者还没意识到我将要谈论个人经历，我会明确地告诉他们，这个演讲是关于我分心、动力不足和项目焦虑的故事。我声明将谈论我是如何打破这个循环的。我讲故事不是为了讲故事本身；谈论如何克服问题是有其目的的。

然后我提到演讲的目标受众；在这个案例中，是那些想要提高效率、减少分心的人，这大概涵盖了所有人。接着，我将演讲的主要议题以项目符号列表的形式呈现。这意味着关于我将要涵盖的内容不会有任何歧义，因为我已直接说明。事实上，这个列表后来成为了演讲的主要章节标题。没人能说他们不知道演讲内容，因为我说得非常直接。

有些人可能会说，详细到这种程度就相当于剧透了演讲内容，但我不同意。他们知道主要议题，但不知道所有细微的内容。这场演讲时长一小时，我平均会讲 55 分钟。里面内容很丰富。

最后，我们进入结束语。

> *我现在认为自己非常高效，但达到这个状态是一场战斗。让我分享我的故事，从而帮助你变得高效和自信。*

我的结束语只有两句话，但很具体。我首先说明我认为自己现在很高效。换句话说，我解决了问题，但这过程很艰难。这向读者传递了一个信号：这是一场可以打赢的战斗。最后，我说我将分享我的故事——以防这一点还不够明确——并且我会帮助你变得高效和自信。换句话说，我不仅要给你讲故事，还要给你提供解决方案。

在我写过的所有演讲中，这是个人最喜欢的一个。这也是我首先谈到它的原因。当我做这个演讲时，与会者会在活动结束后过来与我交谈，或私下联系我，告诉我他们有多喜欢这个演讲，以及它如何帮助他们，这让我感到无比谦卑。为了撰写这次演讲，我付出了很多心血，为了精心打磨一个——在我看来——完美的摘要也费了不少功夫。这个摘要并非一蹴而就，而是经历了多次修改。

接下来我想介绍的演讲则完全不同，因为它面向的是极其特定的技术受众。

## 演讲 2：.NET Core 数据安全：希望不是策略

这场演讲是我设计并交付的第一场演讲。它面向特定的受众群体——微软`.NET`开发者，因此相当垂直。

在查看开篇引子之前，你可以先阅读完整摘要。

> 不对数据进行加密是一种冒险行为，单纯希望自己不会被黑客攻击或数据泄露并非策略。作为一名软件开发人员，你有责任为雇主保护和捍卫他们的数据安全。

> 通过这场演讲，你将学会如何使用`.NET`框架来保护数据，以确保数据的机密性、完整性、不可否认性和身份验证。

> 本次演讲涵盖随机数生成、哈希运算、认证哈希、基于密码的密钥派生函数，以及使用`DES`、`Triple DES`、`AES`（`CBC`和`GCM`）和`RSA`进行的对称与非对称加密。你还将学习如何将它们组合起来，构建一个包含`AES`、`RSA`、哈希消息认证码和数字签名的混合加密方案。

主标题“.NET Core 数据安全”对微软`.NET`开发者而言不言自明——正如我所说，这是一场垂直演讲。副标题“希望不是策略”暗示着，仅仅希望你的数据不会受损并非良策；你需要采取行动。

接着，我用一个极其简洁的引子进一步深化了这个观点。

> 不对数据进行加密是一种冒险行为，单纯希望自己不会被黑客攻击或数据泄露并非策略。作为一名软件开发人员，你有责任为雇主保护和捍卫他们的数据安全。

在这里，我再次强调了演讲的副标题，以防读者没有领会其意。同样，当会议网站展示一场演讲时，通常只会包含演讲标题和开头一两句话，读者必须点击才能查看更多内容。当读者想了解更多时，他们才会看到后续的详细信息。

接着，我指出作为一名软件开发人员，你有责任保护雇主的数据。在这一点上，我是在告诉读者：如果你是一名开发者，你就肩负着一份责任。我希望这能让读者突然坐直身体，意识到自己需要重视起来。

接下来，我们进入演讲的主要细节部分。

> 通过这场演讲，你将学会如何使用`.NET`框架来保护数据，以确保数据的机密性、完整性、不可否认性和身份验证。

> 本次演讲涵盖随机数生成、哈希运算、认证哈希、基于密码的密钥派生函数，以及使用`DES`、`Triple DES`、`AES`（`CBC`和`GCM`）和`RSA`进行的对称与非对称加密。你还将学习如何将它们组合起来，构建一个包含`AES`、`RSA`、哈希消息认证码和数字签名的混合加密方案。

主要细节部分技术性很强，但我瞄准的是特定的垂直受众。如果读者对这些术语感到熟悉，那么这场演讲很可能就是为他们准备的。在这些细节中，我列出了将要讨论的密码学原语，以及如何在他们的软件解决方案中协同使用这些原语。实际的演讲内容与我在本节中提到的内容高度吻合。

这场演讲没有结束语。自从我最初设计它以来，摘要内容变化不大。由于该演讲对目标受众来说非常垂直，我要讲的内容和演讲的深度都是显而易见的。

这场演讲非常受欢迎，我有幸在全球各地进行过分享，但这是我设计的第一场演讲，在设计上可能并非最佳。不过，多年来我一直在调整它，它在目标受众中始终反响很好。

接下来我想介绍的演讲，同样是一场面向垂直受众的特定技术演讲。

## 演讲 3：使用 `Azure Key Vault` 保护加密密钥

“使用 `Azure Key Vault` 保护加密密钥”是另一场面向使用微软 Azure 云计算平台的微软开发者的垂直软件开发演讲。这场演讲聚焦于 Azure 提供的一项名为 `Key Vault` 的服务，该服务允许你创建和管理加密密钥，同时还能存储诸如第三方服务密码之类的机密信息。对这场演讲感兴趣的人群是在大型企业环境中工作的软件开发者，这就是我的目标受众。

这场演讲的标题没有副标题。主标题陈述了演讲内容和目标平台——`Azure Key Vault`。当我将它提交给专注于微软软件开发的活动时，任何读到这个标题的人都会立刻明白演讲内容。

## 总结

我花了相当长的时间来讨论如何撰写演讲摘要，因为它与演讲本身同等重要，甚至可能更重要。演讲本身必须精彩。如果你没有想好摘要，会议可能不会选中你的演讲。

摘要有多个用途。如果你是在工作场所向同事做演示，摘要将提供信息，让他们设定预期。例如，如果你是在会议上公开演讲，那么摘要就是一个工具，它能帮助你在竞争中胜出，让你的演讲被选中。会议演讲竞争激烈，因此撰写这份至关重要的文档非常重要。

如果他们选择你在会议上发言，那么你的摘要还有第二个目的，那就是鼓励与会者来听你的演讲。它就像一封给观众的推销信。要谨慎地用准确的信息来定位摘要，以便吸引合适的人来听。不要虚张声势。如果人们带着错误的预期来参加，他们可能会给你的演讲打低分，这会影响你在该会议上再次被选中的可能性。

## 研讨问题

1.  开始思考你演示文稿的摘要。在最终设计演示文稿之前先写好摘要是一个好主意。请包含以下每一项：

    *   **引人注目的演讲标题和副标题**：选择一个能吸引潜在听众的标题。尽量不要让它听起来像点击诱饵链接，但可以尝试一个巧妙的标题，前提是它不会产生误导。对于我之前描述的《黑掉人类》演讲，这是一个引人注目的标题，而副标题则提供了背景信息，*社会工程学技术及如何防范*。
    *   **初始钩子**：初始钩子会在标题之后吸引读者。会议日程表通常只显示标题和初始钩子，观众需要点击才能阅读更多内容，因此这个初始钩子的影响力可能决定是否有人会来听你的演讲。
    *   **更多细节**：在这一部分，你可以更详细地介绍你正在解决的问题以及你将如何解决它。此部分旨在传达更详细的信息，以帮助人们决定是否来听你的演讲。但是，不要写太多；它仍然应该保持简洁。
    *   **结束语**：结束语是一个总结为什么某人应该来听你演讲的机会。

2.  写好摘要后，你应该把它给不同的人看，以获取反馈。一个有用的技巧是写两三份风格不同的摘要文档。然后让人们选出他们最喜欢的，并告诉你为什么选择它而不是其他。摘要与实际演示本身同等重要，因为你将用它来向与会者和会议方推销你的演示想法。

# 排版后的 Markdown 文档

要解决这个问题并没有好办法。如果你调用一个需要引用表达式的函数，你应该给它一个字面表达式来引用。这类函数本质上对编程没有帮助——它们为特定领域语言的用户提供了一个接口，但你无法通过从其他函数调用它们来实现该语言。

解决方案是编写那些期望表达式被引用的函数，比如我们之前编写的函数 `f` 和 `fq`，并在从一个函数调用另一个函数时使用它们。

```r
g <- function(expr) {
  f(substitute(expr), data.frame(u = 1:4, v = 1:4))
}
g(u + v)
## [1] 2 4 6 8
```

如果你希望某些功能既可用于编程（即从一个函数调用另一个函数），也可作为语言中的操作，那么就编写一个期望表达式被引用的函数，再编写一个包装它的函数。

```r
f <- function(expr, data) eval(expr, data, rlang::caller_env())
fq <- function(expr, data) f(substitute(expr), data)
fq(u + v, data.frame(u = 1:4, v = 1:4))
## [1] 2 4 6 8
```

然而，这引出了第二个陷阱——如何正确连接环境。考虑以下两个函数：

```r
g <- function(x, y, z) {
  w <- x + y + z
  f(quote(w + u + v), data.frame(u = 1:4, v = 1:4))
}
h <- function(x, y, z) {
  w <- x + y + z
  fq(w + u + v, data.frame(u = 1:4, v = 1:4))
}
```

函数 `g` 显式引用了表达式 `w + u + v` 并调用 `f`；`h` 则调用 `fq`，由 `fq` 负责引用工作。第一个函数能工作，第二个则不能。

```r
g(1:4, 1:4, 1:4) == (1:4 + 1:4 + 1:4) + 1:4 + 1:4
## [1] TRUE TRUE TRUE TRUE
h(1:4, 1:4, 1:4) == (1:4 + 1:4 + 1:4) + 1:4 + 1:4
## Error in eval(expr, data, rlang::caller_env()): object 'w' not found
```

这次，问题不在于引用。两个函数都试图在函数 `f` 内部求值同一个表达式 `w + u + v`。问题在于，只有当我们从 `g` 调用 `f` 时，变量 `w` 才对 `f` 可用。要理解原因，请考虑所涉及的环境。我们没有定义任何嵌套函数，因此所有四个函数（`f`、`fq`、`g` 和 `h`）只能访问它们自身的局部环境和全局环境。然而，`f` 作为参数收到的表达式，并非在 `f` 的局部环境中求值，而是在其调用者的环境中求值。当 `f` 直接从 `g` 调用时，调用者的环境是 `g` 调用的局部环境，其中定义了 `w`。但当 `f` 从 `h` 调用时，它并不是直接调用的。由于 `h` 调用了 `fq`，然后 `fq` 再调用 `f`，那么在这种情况下 `f` 的调用者是 `fq`。变量 `w` 定义在 `h` 的局部作用域中，但这并不是 `f` 试图求值表达式的地方；`f` 试图在 `fq` 的作用域中求值表达式，而 `fq` 中并未定义 `w`。

如何解决这个问题并不那么显而易见。可以将环境连同表达式作为单独的函数参数传递，但如果需要处理多个表达式，这会变得很繁琐。我们想要的是将表达式与我们所希望在其中查找未显式覆盖的变量的环境关联起来，比如从数据框中获取这些变量。

表达式本身并不携带任何环境，因此我们无法直接实现这一点。然而，公式（formula）可以。我们可以改用单边公式，而不是表达式。此时的引用工作将涉及从表达式创建一个公式。如果公式是单边的，我们可以获取其第二个元素作为表达式，并且可以通过 `environment` 函数获取公式定义时的环境。我们可以重写 `f` 和 `fq` 函数，使其基于公式工作。

```r
ff <- function(expr, data) {
  eval(expr[[2]], data, environment(expr))
}
ffq <- function(expr, data) {
  expr <- eval(substitute(~ expr))
  environment(expr) <- rlang::caller_env()
  ff(expr, data)
}
```

使用 `ff` 时，你需要显式创建公式——类似于之前在 `f` 中显式引用表达式——这会自动为你提供与公式关联的环境。使用 `ffq` 时，我们通过 `substitute` 将表达式转换为公式，并显式将其环境设置为调用者的环境。现在我们可以像之前一样定义 `g` 和 `h`，只是 `g` 使用公式而非 `quote`。

```r
g <- function(x, y, z) {
  w <- x + y + z
  ff(~ w + u + v, data.frame(u = 1:4, v = 1:4))
}
h <- function(x, y, z) {
  w <- x + y + z
  ffq(w + u + v, data.frame(u = 1:4, v = 1:4))
}
```

这次，两个函数都会在正确的作用域中求值表达式。

```r
g(1:4, 1:4, 1:4) == (1:4 + 1:4 + 1:4) + 1:4 + 1:4
## [1] TRUE TRUE TRUE TRUE
h(1:4, 1:4, 1:4) == (1:4 + 1:4 + 1:4) + 1:4 + 1:4
## [1] TRUE TRUE TRUE TRUE
```

将环境与表达式关联起来，正是 `rlang` 包中 quosure 背后的思想。这个词是 quotes 和 closures 的混成词——类似于闭包是带有环境的函数，quosure 是带有环境的引用表达式。Quosure 基于公式，我们可以像刚才的例子那样使用公式，但 `rlang` 包提供的功能使得使用 quosure 来编程特定领域语言更加简单。`rlang` 包实现了所谓的整洁求值（tidy evaluation），这是下一章的主题。

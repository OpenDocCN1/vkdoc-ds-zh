# 4. 函数、类与运算符

严格来说，我所指的语法就是句法规则。语言学家用"语法"一词同时指形态学和句法学，其中句法学是关于词语如何组合成句的规则。但在计算机科学中，"语法"一词的用法与我此处相同。因此，我将交替使用"句法"和"语法"这两个术语。

纯粹主义者可能会抱怨说，解析器构建的是解析树而非抽象语法树（AST）。两者的区别在于：解析树包含输入中的所有信息（如括号、空格等），但不包含关于其所代表语法结构的元信息；而抽象语法树只包含输入中的相关部分，但在此基础上还包含了语法信息。如果你愿意，可以先将解析过程视为处理输入语言的两个独立步骤：先进行解析，再将结果转换为抽象语法树。而我认为这两个步骤是同一过程的一部分，因此我主张解析器直接构建抽象语法树。

但请注意，赋予语句含义与赋予其正确含义之间存在区别。你的程序计算出了某个结果，并不意味着它计算出了你预期的结果。当我们构建一门语言时，无论是领域特定语言还是通用语言，我们都能赋予语句含义，但我们无法——这在理论上是不可能的——保证这就是预期的含义。这始终是程序员的职责。

运算符优先级是我们用来描述不同运算符"绑定紧密程度"的术语，即哪些运算符优先被调用，换句话说，就是在表达式中隐式设置括号的位置。乘法的绑定比加法更紧密——具有更高优先级——因此表达式 `2*x + 4*y` 被解释为 `(2*x) + (4*y)`，而不是例如 `2*(x + (4*y))`。优先级还告诉我们运算符是从左到右求值还是从右到左求值，因此 `x + y + z` 被求值为 `(x + y) + z` 而不是 `x + (y + z)`，因为 `+` 是从左到右求值的。对于加法，从左到右或从右到左的顺序不影响结果，但对于某些运算符则不然，例如乘方，它是从左到右求值的。所以，`x**y**z` 是 `x**(y**z)`，这（通常）不同于 `(x**y)**z`。如果你在领域特定语言中使用运算符，那么运算符的优先级会影响你的语言。

我们尚未正式定义如何在用于指定语法的句法规则中指定非文字标记，而这样做也不会让示例更清晰，所以我们就非正式地说明一下。

如果你不熟悉连续时间马尔可夫链，可以用非正式的方式这样描述：连续时间马尔可夫链是一个图，其中节点代表状态，边代表状态之间的转移，每条边上标注着变化发生的速率。该模型是随机的，因此速率应被视为随时间变化的期望值。如果状态 `s` 和 `t` 之间速率为 1，那么每个时间单位，我们预期会看到一次从 `s` 到 `t` 的变化。如果我们想知道在时间 =0 时处于状态 `s`，在某个时间 `t` 时处于状态 `t` 的概率，我们不能孤立地考虑状态 `s` 和 `t`。可能还有其他状态可以从 `s` 到达，如果去了那些状态，到达 `t` 所需的时间可能更长或更短；或者可能存在从 `t` 可以继续到达的状态，因此我们可能在时间 `t` 之前经过 `t`，但不再停留在那里。我们必须考虑所有边和所有速率。因此，计算在时间 `t` 时处于状态 `t` 的概率依赖于矩阵运算，特别是矩阵指数运算。

## 函数、类与运算符

在 R 中，你做的所有事情都通过函数完成。因此，如果你想实现一门领域特定语言，就必须通过编写函数来实现。你的新领域特定语言应支持的所有操作都必须用函数实现，如果你希望为领域特定语言提供特殊语法，就必须编写用于解析该语法的函数。正如我们将看到的，在实现嵌入式领域特定语言时，大部分解析工作可以外包给 R 的解析器。为此付出的代价是领域特定语言的语法受到一些限制——领域特定语言必须是语法上有效的 R 代码。我们无法为嵌入式语言构建任意语法，但通过使用运算符重载或元编程，以及定义新的中缀运算符，我们在设计领域特定语言时确实拥有一定的灵活性。

在前两章中，我们看到了如何利用运算符重载和元编程将 R 表达式视为嵌入式语言中的表达式。本章的目的是深入探讨运算符选项的细节，而下一章将涵盖通过元编程显式操控表达式的可能性。

### S3 面向对象编程系统

关于 R 支持的面向对象编程系统，你可以写一整本书——我知道，因为我写过这样一本书——但对于运算符重载和实现领域特定语言解析器，我们只需要少数面向对象特性，本节将快速介绍这些内容。本书中我们将只使用最简单的面向对象系统——S3 系统。如果你已经熟悉 S3 系统，可以直接跳到下一节。

#### 对象与类

S3 系统采用了一种简单直接的方式实现面向对象。它允许我们将类与任何对象关联（`NULL` 除外）。类是没有任何结构的文本字符串，你可以通过调用函数 `class` 获取与对象关联的类。

```r
class(4)
## [1] "numeric"
class("foo")
## [1] "character"
class(TRUE)
## [1] "logical"
class(sin)
## [1] "function"
```

你可以使用相应的赋值函数设置对象的类，如下所示：

```r
class(sin) <- "foo"
class(sin)
## [1] "foo"
```

这不会影响对象的本质或功能。

```r
sin(0)
## [1] 0
```

某些对象的类是可以修改的——例如，你无法更改字面数字和字符串的类，因此如果你尝试这样做：

```r
class(2) <- "character"
class("foo") <- "numeric"
```

你会收到错误信息。尽管如此，你可以随时自由修改对象的类。与对象关联的类只是一个包含一个或多个类名的属性——在前面的例子中，所有对象都只有一个类，但我们在第 2 章创建的矩阵表达式则具有多个类。类名的向量既用于多重继承也用于单继承，并且根本没有正式的类结构。你可以以任何方式设置类。类属性只是一个被解释为类名的字符串向量。

与你可以与对象关联的其他属性相比，类属性之所以有趣，唯一的原因在于它如何用于分发泛型函数。当你调用一个泛型函数时，实际被调用的函数取决于其参数之一的类，通常是第一个参数（如果你没有显式提供参数，则始终是第一个）。


#### 泛型函数

S3 系统中的泛型函数机制是通过 `UseMethod` 和 `NextMethod` 函数实现的。要定义一个名为 `foo` 的泛型函数，你可以编写如下代码：

```
foo <- function(x, y, z) UseMethod("foo")
```

调用 `foo` 时会触发 `UseMethod`，它将搜索 `foo` 的具体实现。这类函数仅通过名称来识别——任何名称以 `foo.` 开头的函数都被视为 `foo` 的实现，具体选用哪个实现取决于参数 `x` 所属的类。我们目前尚未编写任何 `foo` 的实现，因此调用该函数只会返回错误信息。

```
foo(1, 2, 3)
## Error in UseMethod("foo"): no applicable method for 'foo' applied to an object of class "c('double', 'numeric')"
```

不过，我们可以创建一个默认实现。泛型函数的默认实现——即当 `UseMethod` 找不到更合适的匹配实现时调用的那个——其名称以 `.default` 结尾。我们可以这样实现：

```
foo.default <- function(x, y, z) {
cat("default foo\n")
}
```

当我们用一个没有更好实现的类来调用 `foo` 时，就会执行这个函数。

```
foo(1, 2, 3)
## default foo
```

要为特定类定制泛型函数，我们只需定义名称相符的函数即可。任何以 `foo.` 开头的函数名称都可以使用，当用相应类的对象调用 `foo` 时，就会调用该函数。例如，要为 `numeric` 类型定制 `foo`，我们可以编写：

```
foo.numeric <- function(x, y, z) {
cat("numeric\n")
}
```

现在，当 `x` 是数值类型时，将会调用以下函数。

```
foo(1, 2, 3)
## numeric
```

在继续探索如何针对用户自定义类进行泛型函数的分发之前，先快速说明一点：当我们在 `foo` 的定义中使用 `UseMethod` 时，我们传递的名称是 `foo`。这就是它搜索泛型函数实现时所依据的名称。我们也可以让它搜索其他函数。当我们定义 `foo` 时为其指定的泛型函数名称，并非决定调用时搜索内容的关键——真正起到决定作用的是我们传给 `UseMethod` 的名称。此外，我们看到它默认根据 `foo` 的第一个参数进行分发，但这只是默认行为。我们也可以为 `UseMethod` 指定另一个对象来执行分发。

```
bar <- function(x, y, z) UseMethod("foo", y)
```

我不建议这样做——这违反了 `R` 语言中的惯例——但确实可行，使用这个函数时，我们会根据 `y` 参数进行分发（并搜索泛型函数 `foo`，而非 `bar`）。

```
foo("foo",2,3)
## default foo
bar("foo",2,3)
## numeric
bar(1,"bar",3)
## default foo
```

回到分发规则，当 `UseMethod` 被调用时，它会根据函数名称开始搜索。它会按顺序获取对象的类并进行搜索。如果找不到任何匹配的函数，且默认实现存在，则会调用默认实现。

那么，让我们再次审视 `foo`，假设我们已经有了数值类型和默认实现。

```
x <- 1
foo(x, 2, 3)
## numeric
```

这里，我们创建了数值对象 `x`，因此调用 `foo` 时，会匹配到数值函数。但我们可以改变 `x` 的类，看看会发生什么。

```
class(x) <- c("a", "b", "c")
foo(x, 2, 3)
## default foo
```

现在，由于 `x` 的类是 `a`、`b` 和 `c`，而不是 `numeric`，`UseMethod` 未能找到数值版本，因此调用了默认版本。当然，我们可以为其他类定义函数并进行观察。

```
foo.a <- function(x, y, z) cat("a\n")
foo.b <- function(x, y, z) cat("b\n")
foo.c <- function(x, y, z) cat("c\n")
foo(x, 2, 3)
## a
```

因为我们现在为 `x` 的类定义了函数，所以能够找到它们，并且由于 `a` 是第一个类，因此会调用该函数。如果我们改变 `x` 的类的顺序，则会调用其他函数——`UseMethod` 总是调用它找到的第一个函数。

```
class(x) <- c("b", "a", "c")
foo(x, 2, 3)
## b
class(x) <- c("c", "b", "a")
foo(x, 2, 3)
## c
```

当调用 `UseMethod` 时，我们会找到并调用第一个匹配的函数。可以调用相关的 `NextMethod` 函数来查找并调用类链中的下一个函数。为了演示其效果，我们可以重新定义 `a`、`b` 和 `c` 的三个 `foo` 实现，让它们依次调用下一个函数。

```
foo.a <- function(x, y, z) {
cat("a\n")
NextMethod()
}
foo.b <- function(x, y, z) {
cat("b\n")
NextMethod()
}
foo.c <- function(x, y, z) {
cat("c\n")
NextMethod()
}
```

它们都会调用链中的下一个函数，由于我们有 `foo` 的默认实现，链中最后一个函数将调用默认实现。这些函数被调用的顺序完全取决于 `x` 的类的顺序。

```
class(x) <- c("a", "b", "c")
foo(x, 2, 3)
## a
## b
## c
## default foo
class(x) <- c("b", "a", "c")
foo(x, 2, 3)
## b
## a
## c
## default foo
class(x) <- c("c", "b", "a")
foo(x, 2, 3)
## c
## b
## a
## default foo
```

这种泛型分发机制非常灵活，因此需要一定的纪律来确保面向对象设计的稳健性。不过，对于实现领域特定语言而言，我们更关注如何利用它为我们的语言添加运算符。



#### 运算符重载

大多数运算符（箭头赋值运算符 `<-` 和 `->`，以及槽位和组件访问运算符 `@` 和 `$` 除外）都作为泛型函数运行，并且可以被重载。重载运算符的机制与实现新版本泛型函数的机制并无不同——如果你以正确的方式命名函数，当泛型函数被调用时，该函数就会被触发。

例如，要定义对 `a` 对象的加法，我们需要定义 `+.a`，可以按如下方式实现：

```
`+.a` <- function(e1, e2) {
cat("+.a\n")
NextMethod()
}
x + 2
## +.a
## [1] 3
## attr(,"class")
## [1] "c" "b" "a"
```

在这里，我们打印一些输出，然后通过调用 `NextMethod` 来调用底层的数值加法——因为这里的对象 `x` 既是数值，也是类 `a` 的对象。使用 `NextMethod` 非常重要。如果我们直接使用加法，就会再次调用 `+.a`。因此不要尝试这样做：

```
`+.a` <- function(e1, e2) {
cat("+.a\n")
e1 + e2
}
```

这个函数会导致无限递归，这不是你想要的结果。

重载运算符的方式与定义泛型函数的特化版本相同，但两者在分派方式上存在差异。对于标准泛型函数，你会根据第一个参数进行分派。而对于运算符，有一些启发式规则确保无论操作数的顺序如何，都会调用相同的函数。你可以轻易想象出，调试那些交换操作数顺序就会调用完全不同函数的程序是多么痛苦。在 R 中不会发生这种情况，因为运算符与其他泛型函数并不完全相同。

如果我们定义了 `+.a`，并尝试将一个数字加到 `x` 上，那么无论顺序如何，调用的都将是 `+.a` 函数。

```
x + 3
## +.a
## [1] 4
## attr(,"class")
## [1] "c" "b" "a"
3 + x
## +.a
## [1] 4
## attr(,"class")
## [1] "c" "b" "a"
```

如果我们向 `x` 添加另一个不同类的对象，情况也是如此。

```
x <- 1 ; y <- 3
class(x) <- "a"
class(y) <- "b"
x + y
## +.a
## [1] 4
## attr(,"class")
## [1] "a"
y + x
## +.a
## [1] 4
## attr(,"class")
## [1] "b"
```

除非我们也为该类定义了加法运算符。

```
`+.b` <- function(e1, e2) {
cat("+.bn")
NextMethod()
}
x + y
## Warning: Incompatible methods ("+.a", "+.b") for
## "+"
## [1] 4
## attr(,"class")
## [1] "a"
y + x
## Warning: Incompatible methods ("+.b", "+.a") for
## "+"
## [1] 4
## attr(,"class")
## [1] "b"
```

如果类 `a` 和类 `b` 都有各自的加法版本，那么我们需要一种方法来解决 `x+y` 和 `y+x` 应该调用哪个版本的问题。在这里，第一个操作数优先，因此它决定了调用哪个函数——对于这种混乱操作，你会得到一条理所应当的警告。

你或许能想出其他规则来解决此类情况。例如，可以规定应调用最抽象的方法，因此如果 `x` 和 `y` 都属于类 `b`，但只有 `x` 也属于类 `a`，那么我们应该调用 `+.b`。

```
class(x) <- c("a","b")
class(y) <- "b"
```

不幸的是，在 S3 系统中你无法制定这样的规则。但在 S4 系统中是可行的，你可以在其中基于多个参数分派泛型函数，但这超出了本书的范围。我们将通过适当构建语法来确保避免需要添加定义了相同运算符的不同类对象的情况。

不过请注意，多类与 `NextMethod` 的组合仍然像以前一样工作。在 S3 系统中，我们无法定义基于多个参数分派的泛型方法，但可以在评估运算符时使用 `NextMethod` 调用多个方法。如果我们在对象 `x` 上调用 `+.a`，而 `x` 现在具有类 `a` 和 `b`，那么在该函数实现中对 `NextMethod` 的调用将先调用 `+.b`，然后该函数再调用数值加法。

```
class(x) <- c("a", "b")
x + 2
## +.a
## +.bn
## [1] 3
## attr(,"class")
## [1] "a" "b"
x + y
## Warning: Incompatible methods ("+.a", "+.b") for
## "+"
## [1] 4
## attr(,"class")
## [1] "a" "b"
```

R 既有二元运算符，也有一元运算符。否定运算符 `!` 仅作为一元运算符存在，你可以通过定义一个接受单个参数的函数来为给定类特化它。

```
`!.a` <- function(x) {
cat("Not for a\n")
NextMethod()
}
!x
## Not for a
## [1] FALSE
```

但对于 `-` 和 `+` 运算符，我们使用相同的符号来表示一元和二元运算符。在这里，我们必须对两者使用相同的函数，因为我们识别运算符函数的唯一方式是通过其名称，而一元和二元运算符的名称是相同的。我们可以通过测试第二个参数是否缺失来确定该函数是作为一元运算符还是二元运算符的一部分被调用。如果缺失，则是一元运算符；否则是二元运算符。

```
`+.a` <- function(e1, e2) {
if (missing(e2)) {
cat("Unary\n")
} else {
cat("Binary\n")
}
NextMethod()
}
class(x) <- "a"
+x
## Unary
## [1] 1
## attr(,"class")
## [1] "a"
2+x
## Binary
## [1] 3
## attr(,"class")
## [1] "a"
```

### 分组泛型函数

还有另一种基于操作数类来重载运算符的方法：分组泛型函数。顾名思义，分组泛型函数将多个运算符分组。它们提供了一种方法，让我们可以定义单个函数来处理某一特定类型的所有运算符。对于算术和逻辑运算符（`+`、`-`、`*`、`/`、`^`、`%%`、`%/%`、`&`、`|`、`!`、`==`、`!=`、`<`、`<=`、`>=` 和 `>`），相关的分组泛型函数是 `Ops`。

如果我们定义 `Ops.c`，那么当类 `c` 的元素使用所有这些运算符时，都会调用我们定义的函数。

```
Ops.c <- function(e1, e2) {
cat(paste0("Ops.c (", .Generic, ")\n"))
NextMethod()
}
z <- 2
class(z) <- "c"
z + 1
## Ops.c (+)
## [1] 3
## attr(,"class")
## [1] "c"
1 + z
## Ops.c (+)
## [1] 3
## attr(,"class")
## [1] "c"
z ^ 3
## Ops.c (^)
## [1] 8
## attr(,"class")
## [1] "c"
```

“魔法”变量 `.Generic` 包含被调用运算符的名称，而调用 `NextMethod` 将分派到该运算符相关的下一个实现。

如果你同时实现了 `Ops` 分组泛型函数和某些具体运算符泛型函数的具体实现，那么后者会优先。例如，如果我们有一个同时属于类 `a` 和 `c` 的对象，其中我们为类 `a` 定义了加法，并为类 `c` 定义了分组泛型函数，那么加法运算将调用 `+.a` 函数。所有其他运算符将调用 `Ops.c` 函数。

```
class(z) <- c("a", "c")
1 + z
## Binary
## [1] 3
## attr(,"class")
## [1] "a" "c"
2 * z
## Ops.c (*)
## [1] 4
## attr(,"class")
## [1] "a" "c"
```

通过 `Ops`，你拥有一个方法来捕获所有你没有显式编写特化泛型函数的运算符。



### 优先级和求值顺序

一旦我们开始使用运算符，它们的`优先级`就变得重要起来。常规函数调用的语法使得求值顺序相对清晰——在嵌套函数调用中，表达式里有内部函数和外部函数。虽然这并不能保证函数参数的求值顺序，但我们确实知道，函数自身的求值会在其参数求值之后进行。对于运算符，语法并未告知我们函数的调用顺序。要了解这一点，我们需要知道`优先级`规则。

`优先级`规则通过将运算符从高到低排序，并指定运算符是**从左到右**还是**从右到左**求值，来告诉我们运算符函数的调用顺序。在像这样的表达式中：

```
x + y * z
```

我们知道乘法 `y * z` 会在加法之前求值，因此该表达式等价于：

```
x + (y * z)
```

因为乘法优先级高于加法。对于优先级相同的运算符，我们可能不太清楚求值顺序，但在这里，从左到右或从右到左的顺序同样由优先级规则保证。在你可以重载的运算符中，只有指数运算符是从右向左求值的，其他所有运算符都是从左向右求值。因此，下面的表达式：

```
x ^ y ^ z
```

等价于：

```
x ^ (y ^ z)
```

而下面的表达式：

```
x * y / z
```

将按如下方式求值：

```
(x * y) / z
```

你可以使用的运算符，按从高到低的优先级列出如下：

| 运算符         | 通常含义                              |
|----------------|---------------------------------------|
| `[ [[`         | 索引                                  |
| `^`            | 指数运算（从右向左求值）              |
| `- +`          | 一元减号和加号                        |
| `%any%`        | 特殊运算符                            |
| `* /`          | 乘法、除法                            |
| `+ -`          | 二元加法和减法                        |
| `< >`          |                                       |
| `<= >=`        | 排序和比较                            |
| `== !=`        |                                       |
| `!`            | 逻辑非                                |
| `& &&`         | 逻辑与                                |
| `| ||`         | 逻辑或                                |
| `:=`           | 赋值                                  |
| `-> ->>`       | 赋值                                  |
| `<- <<-`       | 赋值（从右向左）                      |
| `?`            | 帮助                                  |

其中，你不能重载“箭头”赋值运算符，只能重载`:=`运算符。

在上一章的图形规范语言中，我们可以同时使用加法和`%=>%`，因为用户定义的中缀运算符——那些使用百分号定义的运算符——优先级高于`+`，所以我们可以在将边添加到图之前先构建边。出于同样的原因，同时使用`>`和`|`也是可行的。此外，由于加法（以及逻辑或）是从左向右求值的，在图形规范开头创建的`dag()`对象会被添加到第一条边上，这会生成另一个图，然后该图再被添加到下一条边上，以此类推。如果加法的求值顺序是从右向左，我们就会把边添加到边上，而不是将图添加到边上，这会使解析器的实现变得复杂。

## 代码块

在设计领域特定语言时，一个可能有用的最终语法组件不是运算符，而是用于构造代码块的花括号。我们不能重载这些花括号的解释方式，但在创建新语言时，我们当然可以为它们找到用途。在完全利用它们之前，我们需要知道如何操作表达式以及如何在不同的上下文中对它们求值——我们将在下一章和第 7 章中介绍这些内容——但作为一个快速的例子，考虑创建一个重复执行某个语句若干次的索引运算符。我们可以这样定义它：

```
`%times%` <- function(n, body) {
  body <- substitute(body)
  for (i in 1:n)
    eval(body, parent.frame())
}
```

下面的代码将`body`参数转换成一个表达式，以便我们可以重复求值：

```
body <- substitute(body)
```

如果我们不这样做，我们只会在第一次访问`body`时对其进行求值——这就是 R 语言惰性求值的工作原理——但使用`substitute`，我们可以从参数中获取逐字的表达式。要对其求值，我们必须使用`eval`函数，并且要在调用`%times%`运算符的上下文中求值，我们需要调用框架，这可以通过`parent.frame`获得（关于求值和环境的更多细节，请参见第 7 章）。

`%times%`的`body`参数可以是单个语句，如下所示：

```
4 %times% cat("foo\n")
## foo
## foo
## foo
## foo
```

然而，由于花括号（`{}`）也被视为表达式，我们也可以使用一系列语句，只要将它们包裹在花括号中即可。

```
2 %times% {
  cat("foo\n")
  cat("bar\n")
}
## foo
## bar
## foo
## bar
```

因为我们可以使用花括号将代码块作为参数传递给函数，所以我们可以利用花括号来创建新的控制结构，比如前面展示的`%times%`运算符。为了充分利用这一点，我们需要了解如何在 R 中求值一般表达式，以及如何控制我们求值的环境。我们还需要解析和操作表达式，以便分析代码块，甚至可能修改它们。我们将把对花括号的进一步讨论留到我们涵盖这些主题之后。

脚注：

1.  我在这里并不完全诚实。R 语言有惰性求值机制，因此不能保证函数参数一定会被求值——但如果它们被求值，它们会在我们返回其所属的函数之前被求值，所以从概念上讲，我们可以认为它们是在调用函数之前被求值的。

2.  表中的最后一个运算符`:=`赋值运算符，在列表中比较特殊。它并不是 R 中真正定义的运算符。你不能将它用作赋值运算符——为此，你应该使用`<-`或`->`——但 R 解析器将其识别为中缀运算符，这意味着你在设计领域特定语言时可以使用它。

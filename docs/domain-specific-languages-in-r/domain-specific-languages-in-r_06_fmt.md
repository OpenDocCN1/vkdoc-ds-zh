# 6. Lambda 表达式

借助目前所学的技术，我们现在已经能够实现一些有用的领域特定语言。在本章中，我们将研究一个玩具示例：lambda 表达式。它可能并非我们在实际代码中会用到的东西，因为它只是为匿名函数提供了一种替代语法，而 R 语言本身已经支持匿名函数。不过，这是一个极好的示例，展示了可能具有实用价值的代码，并让我们有机会对语法进行实验。

我们将使用 `rlang` 包。

```r
library(rlang)
```

## 匿名函数

Lambda 表达式就是匿名函数，换句话说，就是我们没有命名的函数。在 R 语言中，我们已经有了匿名函数。这是函数的默认形式，因为函数在被赋值给变量之前都是匿名的。如果我们不想将函数保存到变量中以便后续访问，可以直接在需要的地方使用 `function` 表达式来创建它。例如，要遍历一个数值向量，我们可以编写如下代码：

```r
sapply(1:4, function(x) x**2)
## [1]  1  4  9 16
```

这是一个玩具示例，因为在类似的情况下，向量化表达式更可取，但它足以说明问题。

```r
(1:4)**2
## [1]  1  4  9 16
```

使用 `function` 表达式比较冗长，因此我们可能想要为匿名函数构建一种替代语法。然后，我们可以将其作为构建领域特定语言的一次练习。我们的目标是将之前的 `sapply` 语法改写成这种形式：

```r
sapply(1:4, x := x**2)
```

我们使用 `:=` 赋值运算符有两个原因。其一，我们可以重载它，这是 `->` 或 `<-` 无法做到的。其二，它的运算符优先级最低，因此我们创建的运算符会在左右两侧被求值之前被调用。

为了实现这种语法，我们需要将赋值运算符的左侧部分变成函数参数列表，即参数对列表。我们还需要将右侧部分变成一个函数体，以便在定义 lambda 表达式的环境中对其进行求值。好消息是，这只需要用到我们已经学过的技术。我们可以编写一个函数，将参数列表转换为可用于定义函数形式参数的参数对列表，如下所示：

```r
make_args_list <- function(args) {
  res <- replicate(length(args), substitute())
  names(res) <- args
  as.pairlist(res)
}
```

对于赋值运算符，我们需要使用 `substitute` 来避免对两个参数进行求值。然后，我们使用 `make_args_list` 将左侧部分转换成形式参数，但保持右侧表达式不变。之后，我们使用 `rlang` 包中的 `new_function` 将组合结果转换成一个函数。由于我们希望在定义 lambda 表达式的作用域内对该新函数进行求值，因此我们使用 `caller_env` 来获取此环境，并将其提供给 `new_function`。整个实现过程就这么简单：

```r
`:=` <- function(header, body) {
  header <- substitute(header)
  body <- substitute(body)
  args <- make_args_list(as.character(header))
  new_function(args, body, caller_env())
}
```

现在，我们可以使用这种新语法作为匿名函数的语法糖。

```r
sapply(1:4, x := x**2)
## [1]  1  4  9 16
```

那么，具有多个参数的 lambda 表达式呢？我们可能想要类似于这样的语法：

```r
mapply(x,y := x*y, x = 1:6, y = 1:2)
```

然而，这是不可能的，因为我们无法覆盖 R 语言对逗号的解释方式。如果要对某些参数进行分组，我们需要将它们放在一个函数调用中。我们可以这样做：

```r
mapply(.(x,y) := x*y, x = 1:6, y = 1:2)
## [1]  1  4  3  8  5 12
```

这里发生的是，`make_args_list` 将左侧表达式的所有组成部分都转换成了函数参数。函数调用对象就像任何其他表达式列表一样，因此在这个特定的例子中，我们创建了一个包含三个参数（`.`、`x` 和 `y`）的函数。由于 `.` 在函数体内并未被使用，所以在调用函数时即使不提供它也没关系。然而，如果我们将其中一个参数名称作为函数名重复用于调用中，就会发生这种情况：

```r
mapply(x(x,y) := x*y, x = 1:6, y = 1:2)
## Error in (function (x, x, y) : argument 1 matches multiple formal arguments
```

我们可以通过移除列表中的第一个元素来去掉调用中的函数名。

```r
`:=` <- function(header, body) {
  header <- substitute(header)
  if (is.call(header)) header <- header[-1]
  body <- substitute(body)
  args <- make_args_list(as.character(header))
  new_function(args, body, caller_env())
}
```

现在，之前的例子就能正常工作了。

```r
mapply(x(x,y) := x*y, x = 1:6, y = 1:2)
## [1]  1  4  3  8  5 12
```

## 对替代语法的实验

用这种方式使用赋值运算符来定义函数可能不是你所能选择的最直观的语法，但我们在尝试替代方案方面有很多选择。

我们可以从已实现为单个函数的功能开始入手。如果我们只需要一个函数，就没有必要使用特殊的语法，因此，我们可以像下面这样实现 lambda 表达式：

```r
lambda <- function(...) {
  spec <- eval(substitute(alist(...)))
  n <- length(spec)
  args <- make_args_list(spec[-n])
  body <- spec[[n]]
  new_function(args, body, caller_env())
}
```

这里的思想是，`lambda` 函数会接收一个参数列表，其中列表的最后一个元素是函数体，前面的元素则是 lambda 表达式的参数。

```r
sapply(1:4, lambda(x, 4 * x**2))
## [1]  4 16 36 64
mapply(lambda(x, y, y*x), x = 1:4, y = 4:7)
## [1]  4 10 18 28
```

`eval(substitute(alist(...)))` 这个表达式如果不太熟悉的话，看起来可能会有点奇怪。我们所做的是，获取由三个点参数捕获的可变数量的参数，并创建一个将它们转换成列表的表达式。与 `list` 不同，`alist` 函数不会对表达式进行求值，而是保持参数的原样，这恰恰是我们在这种情况下想要的。`substitute` 表达式仅创建这个表达式，因此我们需要使用 `eval` 对其进行求值才能获得实际的列表。一旦我们得到了这个列表，就将前面的参数做成函数参数，最后一个做成 lambda 表达式的函数体，然后创建这个函数。

在生产级代码中，我们应该添加一些检查，以确保 lambda 表达式的参数是符号而不是一般的表达式。不过，我们刚刚编写的函数已经具备了 lambda 表达式的完整功能。

当然，`lambda` 函数的行为并不像一个普通函数。我们为了从 `lambda` 的参数中构建出一个函数而应用的非标准求值（NSE），与函数的常规行为截然不同——在常规行为中，我们提供的参数被视为值，而不是符号和表达式。为了从语法上明确表示正在发生不同寻常的操作，你可以更改语法。例如，我们可以使用方括号来代替圆括号。我们可以像下面这样实现一个使用方括号的版本：

```r
lambda <- structure(NA, class = "lambda")
`[.lambda` <- function(x, ...) {
  spec <- eval(substitute(alist(...)))
  n <- length(spec)
  args <- make_args_list(spec[-n])
  body <- spec[[n]]
  new_function(args, body, caller_env())
}
```

我们可以这样使用它：

```r
sapply(1:4, lambda[x, 4 * x**2])
## [1]  4 16 36 64
mapply(lambda[x, y, y*x], x = 1:4, y = 4:7)
## [1]  4 10 18 28
```

这里的方法是，将`lambda`变成一个具有特定类的对象，我们可以利用这个类来定义下标运算符的一种特殊情况。`lambda`的唯一目的是将下标函数分发到正确的特化版本，而下标运算符的这个特化版本就是用来创建新函数的。唯一的区别是，它多接收了一个参数，即`lambda`对象本身。我们并不用它做任何事情，所以直接忽略它即可。

# 请勿在家中尝试
像我们这样为 lambda 表达式实现语法糖，与使用函数表达式相比，只是节省了少量输入。熟悉函数表达式的人应该知道，这样做可能弊大于利，但我们自制的语法可能并非如此。因此，我不建议你为 `R` 语言中已有的语言结构构造新语法。我们在此实现 lambda 表达式，只是为了说明如何用极少的代码构建新语法。

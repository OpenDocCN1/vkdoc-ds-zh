# 1. 引言

本书介绍在 R 语言中嵌入领域特定语言。术语“领域特定语言”（DSL）指的是专用于特定目的的编程语言，与通用编程语言相对。在理想情况下，领域特定语言能让你在特定上下文中，以精确的方式指定想要执行的任务和实现的目标。正则表达式就是领域特定语言的一个例子，它提供了专门的符号来表达文本模式。你可以使用这种领域特定语言来定义要搜索的文本字符串，或指定修改文本的规则。正则表达式通常被认为难以阅读，但它们确实为描述文本模式提供了有用的语言。领域特定语言的另一个例子是 SQL——一种专用于从关系数据库提取和修改数据的语言。通过 SQL，你拥有一种表达力丰富的领域特定语言，可以指定要访问或修改数据库中哪些数据点的规则。

## 本书读者对象

本书面向有经验的 R 语言程序员。本书涵盖的一些概念较为高级，因此你至少应熟悉 R 语言中的函数式编程和面向对象编程（尽管下一章将复习我们将使用的面向对象编程特性）。在需要与周围 R 代码交互的上下文中求值表达式时，具备一些元编程经验会有所帮助。不过，第 7 章将为我们将在本书中使用的技术提供速成课程，因此你稍加努力便能掌握。



## 领域特定语言

在领域特定语言中，我们通常区分“外部”语言和“嵌入”语言。正则表达式和 `SQL` 在程序中使用时通常被指定为字符串，这些字符串需要在程序运行时进行解析和解释。从某种意义上说，它们是与你所使用的编程语言相分离的语言。它们需要被单独编译，然后由主编程语言调用。因此，它们被认为是“外部”语言。相比之下，嵌入式领域特定语言则通过其使用环境的通用语言来表达领域特定语言。在 R 语言中，`ggplot2` 实现的图形语法或 `dplyr` 实现的数据转换操作提供了小型语言——即领域特定语言——你可以在 R 语言内部使用它们，并且你也是用 R 语言为这些语言编写程序。

嵌入式 DSL 扩展了你正在使用的编程语言。它们提供的远不止框架中通常以函数和类形式出现的功能，因为在使用它们时，它们提供了高度的灵活性。毕竟它们是编程语言，你可以在其中表达复杂的想法和任务。它们提供了一种在特定领域表达思想的语言，因此它们不会像你所使用的宿主语言那样提供通用的编程能力，但它们确实用新的表达能力扩展了宿主语言。然而，嵌入在通用语言中意味着它们将遵循你所熟悉的规则——或者至少大部分遵循，因为在 R 这样的语言中，可以通过所谓的非标准求值来稍微修改这些规则。你可以预期嵌入式 DSL 的语法会遵循通用语言的规则。其语义将由 DSL 决定，但当你用 DSL 编写程序时，语法对你来说已经是熟悉的。如果你自己实现一个 DSL，将其嵌入到通用语言中，可以让你重用通用语言的解析和求值能力，从而专注于设计领域特定语言。

实现嵌入式领域特定语言通常涉及元编程；也就是说，它包括将你正在编写的程序视为可以在语言本身内部进行操作的数据。这听起来可能比实际更复杂，但通常实现起来相当直接。通过使用类和运算符重载，我们可以利用 R 的解析器来解析嵌入式语言，只需将语言设计成对表达式进行求值时会自动解析它们即可。这样我们得到的便是我们自己定义的数据结构，而无需自己进行解析，并且在求值以运行嵌入式程序之前，我们可以以各种方式重写这些已解析表达式的结果。表达式的求值可能相对直接，也可能涉及对已解析表达式的更深入分析。

为了感受嵌入式领域特定语言能做什么，让我们考虑一个简单的 DSL：矩阵乘法（我们在第 2 章中更详细地讨论了这个例子）。你可能不认为矩阵表达式是一种编程语言，但算术符号在有限领域内表达思想是非常高效的。想象一下如果没有这种符号，做数学运算会有多困难。当然，R 语言已经支持这种语言——它拥有中缀运算符以及我们在 R 程序中编写算术表达式时所关联的语义。然而，由于矩阵乘法是一个众所周知的任务，它是一个很好的例子，可以说明如果我们用其他更小的编程语言扩展 R 语言，我们能做些什么。

R 语言已经支持矩阵算术，如果你使用运算符 `%*%`，你就可以进行矩阵乘法（如果你使用 `*`，则会进行逐元素乘法）。乘法是一次一次进行的，所以如果你有一系列乘法，像这样：

```
A %*% B %*% C %*% D
```

那么乘积会从左到右计算，如下所示：

```
((A %*% B) %*% C) %*% D
```

每次乘法都会产生一个新矩阵，用于下一次乘法。

现在，矩阵乘法是结合律的，所以你可以任意设置括号，只要尊重矩阵从左到右的顺序（毕竟矩阵乘法不满足交换律），并且你会得到相同的结果。然而，运行时间是不会相同的。我们可以使用 `microbenchmark` 包做一个小的实验来看看这一点。

```
A <- matrix(1, nrow = 400, ncol = 300)
B <- matrix(1, nrow = 300, ncol = 30)
C <- matrix(1, nrow = 30, ncol = 500)
D <- matrix(1, nrow = 500, ncol = 400)
library(microbenchmark)
res <- microbenchmark(A %*% B %*% C %*% D,
((A %*% B) %*% C) %*% D,
(A %*% (B %*% C)) %*% D,
(A %*% B) %*% (C %*% D),
A %*% (B %*% (C %*% D)),
A %*% ((B %*% C) %*% D))
options(microbenchmark.unit="relative")
print(res, signif = 3, order = "mean")
## Unit: relative
##                     expr  min   lq mean median
##  (A %*% B) %*% (C %*% D) 1.00 1.00 1.00   1.00
##  A %*% (B %*% (C %*% D)) 3.92 3.87 3.49   3.84
##      A %*% B %*% C %*% D 6.13 6.06 5.42   6.03
##  ((A %*% B) %*% C) %*% D 6.12 6.05 5.51   6.04
##  A %*% ((B %*% C) %*% D) 7.71 7.62 6.75   7.57
##  (A %*% (B %*% C)) %*% D 9.88 9.76 8.73   9.69
##    uq  max neval
##  1.00 1.00   100
##  3.62 1.41   100
##  5.57 2.06   100
##  5.61 2.35   100
##  7.00 2.30   100
##  8.99 3.71   100
```

这里，我用五种不同的可能方式计算了矩阵乘积。一共有六个表达式，但前两个会以相同的顺序计算矩阵乘法。通过 `microbenchmark`，我们对每个表达式计算了 100 次，并收集了每次求值所需的时间。我们收集了每个表达式的计算时间，这里我展示的是相对于最快表达式的运行时间，并按平均求值时间排序。

平均而言，最快和最慢的求值之间几乎相差一个数量级（对于两种情况下最慢的求值，差异是一个因子 2，这仍然是一个显著的相对差异）。如果我们要将几个大矩阵相乘，通过最优地设置括号是可以有所收获的。然而，矩阵的维度在运行前不一定已知，所以理想情况下，我们希望以最优方式在求值表达式时设置括号。

我们在第 2 章中采用的方法是延迟矩阵乘法的求值，而是为矩阵表达式构建一个数据结构，当我们构建完整个矩阵乘法表达式后，可以稍后再对其进行求值。这是一个简单的 DSL，但它包含了我们通常需要的所有组件：我们需要解析表达式并为其创建表示的代码，需要对表达式进行一些操作，然后需要对它们进行求值。

为了解析表达式，我们需要捕获矩阵和乘法。我们将矩阵包装到一个类中，使它们成为我们语言的对象，而不是普通的 R 数据。

```
m <- function(data) {
structure(data,
nrow = nrow(data),
ncol = ncol(data),
class = c("matrix_expr", class(data)))
}
```

类 `matrix_expr` 是我们用来重载乘法运算符的，我们希望这个类的所有元素都知道它们自己的维度，所以当我们包装数据时，我们保存了行数 `nrow` 和列数 `ncol`。

我们还希望捕获矩阵乘法，不进行乘法的求值，而是简单地保存对要相乘的矩阵的引用。



```r
matrix_mult <- function(A, B) {
  structure(list(left = A, right = B),
    nrow = nrow(A),
    ncol = ncol(B),
    class = c("matrix_mult", "matrix_expr"))
}
```

当然，我们并不希望写出如下表达式：

```r
matrix_mult(matrix_mult(m(A), m(B), matrix_mult(m(C), m(D))))
```

因此，我们对 `*` 操作符进行重载：

```r
`*.matrix_expr` <- function(A, B) {
  matrix_mult(A, B)
}
```

现在，这个表达式：

```r
m(A) * m(B) * m(C) * m(D)
```

成为我们用于矩阵乘法的全新语法，其等价形式如下所示：

```r
A %*% B %*% C %*% D
```

区别在于，前一个表达式仅构建一个代表该表达式的数据结构，而不会对其求值。

当我们需要对矩阵乘法求值时，我们希望分析这个延迟求值，并重新排列乘法顺序以获得最佳性能。在第 2 章中，我们将实现实现此功能的函数 `rearrange_matrix_mult` 和 `eval_matrix_mult`。此处，我们先定义一个用于求值矩阵乘法的函数 `v`：

```r
v <- function(expr)
  eval_matrix_expr(rearrange_matrix_expr(expr))
```

我们可以将此自动括号设置过程与之前看到的默认求值顺序和最优求值顺序进行比较。

```r
res <- microbenchmark(A %*% B %*% C %*% D,
                      (A %*% B) %*% (C %*% D),
                      v(m(A) * m(B) * m(C) * m(D)))
options(microbenchmark.unit="relative")
print(res, signif = 3, order = "mean")
## Unit: relative
##                          expr  min   lq mean
##       (A %*% B) %*% (C %*% D) 1.00 1.00 1.00
##  v(m(A) * m(B) * m(C) * m(D)) 1.13 1.19 1.37
##           A %*% B %*% C %*% D 6.13 6.09 5.65
##  median   uq  max neval
##    1.00 1.00 1.00   100
##    1.23 1.26 1.19   100
##    6.08 5.99 2.19   100
```

自动解决方案仅比最优方案稍慢，而比默认求值方案快了约六倍。

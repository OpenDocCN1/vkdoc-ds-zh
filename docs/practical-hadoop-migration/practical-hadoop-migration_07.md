# 第四章：关系数据库管理系统设计与实现工具

## 数据库管理或管理应用程序

大多数关系数据库都具有相似的结构（原因显而易见），这使得为它们设计通用图形用户界面变得容易。有几家公司已成功设计出能与所有主流关系数据库管理系统配合使用的界面。

大多数数据库管理界面都具有以下功能：

- 修改数据库服务器以及数据库和模式相关的配置
- 添加/修改/删除数据库对象，如表、视图、触发器和存储过程
- 添加/修改/删除登录名/用户/角色，并管理用户/角色的权限
- 管理磁盘空间分配，并收缩数据库以释放已分配但未使用的空间
- 执行数据库维护（重建索引或创建索引），包括备份
- 安排和管理数据库相关的任务/作业，并记录其结果/状态
- 管理数据库服务器的锁定/阻塞/死锁，并记录所有操作（例如，终止或死锁的会话）
- 配置`SMTP`或任何其他协议，供数据库服务器用于向配置的电子邮件地址或电话号码发送警报
- 监控复制和镜像环境以确保数据完整性
- 设置和配置访问、安全和加密功能

所有主流的关系数据库管理系统都有自己的数据库管理界面，但当您需要使用通用界面管理不同的关系数据库管理系统时，问题就出现了。

这时，由第三方或中立供应商开发的界面就派上了用场。

像`Redgate`或`Embarcadero (DBArtisan)`这样的公司已经开发了流行的工具，而像`EMS`这样的公司也开发了免费的多种数据库工具。

## 监控应用程序

监控工具支持广泛的功能，包括监控性能、锁定/阻塞活动、数据库连接和安全漏洞、资源使用情况以及作业输出。当任何（预先设定的）阈值被超过时，它们应生成警报，并在出现任何功能或性能问题时提供故障排除或调试功能。这些工具会建立性能基线、隔离性能问题、识别瓶颈，并提供查询统计信息。以下是详细（但通用）的任务列表：

## 总结

可能会有人质疑包含这一小章节的原因。难道我们不了解 CASE 工具和图表工具吗？我们还没有充分使用它们吗？可能我们用过——但可能不是所有这些工具，或这些工具中的所有功能。再次提醒，真正的重点是关系数据库管理系统数据向 NoSQL 环境的迁移。

您在数据传输过程中需要使用的一些交付物可能正是所讨论工具的产出。了解这些工具的工作原理也将帮助您更好地理解这些交付物。

相反，关系数据库管理系统到 NoSQL 数据传输的某些方面可能需要使用高级工具，本章作为快速参考。它将使您（快速识别符合需求的工具）的任务变得更加容易。我还为每种工具列出了领先的供应商和软件包，它们也可以作为方便的参考。并且我讨论了正向工程和反向工程。

最后，CASE 工具或数据库管理员/监控应用程序很少以供应商中立的方式讨论，因此我以概念层面涵盖了通用特性，以提供更好的理解。令人惊讶的是，您会注意到所有领先的供应商都提供这些特性（或多或少），尽管他们使用的术语可能有所不同。

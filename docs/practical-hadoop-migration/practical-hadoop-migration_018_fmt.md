# 引言

我为大型企业提供咨询服务已超过 20 年。在我刚开始的时候，只有关系型数据库。最终，累积的历史数据量不断增长，以至于无法以良好的性能来管理和分析这些数据。

因此，企业开始思考将（数据中）可用于分析（或生成洞察）的部分与描述性数据分离开来。他们很快意识到关系型设计需要进行根本性的变革，一种称为数据仓库的新范式应运而生。得益于比尔·因蒙和拉尔夫·金博尔所做的工作，世界开始以星型模式、维度和事实为概念进行思考（和设计）。于是设计了`ETL`（抽取、转换、加载）流程来加载数据仓库。

下一步是确保能够以良好的性能检索海量数据。专门软件被开发出来，`RDBMS`解决方案（Oracle、Sybase、SQL Server）也增加了对数据仓库的处理能力。为了达到更高性能，显然需要对数据进行预处理，于是数据立方体被设计出来。由于磁盘驱动器速度较慢，固态设备被开发出来，而缓存（或将数据保存在 RAM 中）数据以提高处理和检索速度的软件也变得流行。那么，有了所有这些先进的性能措施，为什么还需要 Hadoop 或 NoSQL 呢？有两个原因。

首先，值得注意的是，在此期间，被处理的数据要么是关系型数据（对于 `RDBMS`），要么最初就是关系型数据（对于数据仓库）。这些都是结构化数据，并且可能进行的分析（和洞察）类型非常特定于生成该数据的应用程序。仓库的僵化结构严重限制了可能的洞察或数据探索，因为你需要先设计好结构再将数据塞入其中。此外，由于数据量巨大，数据仓库无法按预期性能运行，因此需要一种更新的技术来有效管理这些数据。

其次，近年来引入了一些新型数据：非结构化或半结构化数据。社交媒体变得非常流行，一旦企业意识到其背后的力量，它们便成为企业与公众直接沟通的新途径。企业希望了解人们对其产品、服务、员工，当然还有企业本身的看法。此外，随着电子商务在商业中占据很大比重，企业希望确保自己比竞争对手更受青睐——如果不是这样，他们想知道原因。最后，还需要分析其他类型的非结构化数据，例如来自电气和电子设备的传感器数据，或来自移动设备传感器的数据，这些数据量也非常庞大。所有这些数据通常每天达到数百吉字节。

传统的数据仓库技术无法处理或管理这些数据。因此，必须设计一种新技术来处理它，并且要具备良好的性能（因为总数据量达到太字节级别）。在某些情况下，由于非结构化数据（或从中提取的洞察）需要与结构化数据结合，这种新技术需要支持与数据仓库或 `RDBMS` 的接口。

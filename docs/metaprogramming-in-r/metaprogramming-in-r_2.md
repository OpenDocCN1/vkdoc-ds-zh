# 2. 调用函数

在继续之前，有必要了解一下当函数被调用时这些组成部分是如何协同工作的。我在《R 语言函数式编程》中对此进行过一些详细解释，但理解表达式如何被求值是至关重要的。当你开始接触非标准求值时，这一点就变得更为重要，因此值得重申。

表达式被求值时，是在某个环境中进行的。环境以树状结构链接。每个环境都有一个父环境。当R需要查找一个变量时，它首先在当前环境中查找该环境是否持有该变量。如果没有，R会去父环境中查找。如果在那里也找不到，它会继续去祖父环境中查找，并沿着这个树状结构向上查找，直到找到该变量，或者到达全局环境后发现变量也不存在，这时就会抛出错误。我们称一个表达式通过这种方式能够找到的变量为其作用域。由于查找过程总是选择它找到给定变量的第一个位置，因此局部变量会覆盖全局变量。并且，虽然父环境链上的多个环境可能包含相同的变量名，但只有最内层的环境（即首先找到的那个）会被使用。

当一个函数`f`被创建时，它会与`environment(f)`关联。这个环境就是`f`被定义时所在的环境。当`f`被调用时，R会为`f`创建一个计算环境；我们称其为`evalenv`。`evalenv`的父环境被设置为`environment(f)`。由于`environment(f)`是`f`被定义时所在的环境，将其设置为计算环境的父环境意味着：如果`f`是一个闭包，那么`f`的函数体能够访问其外部作用域。

在计算环境被创建之后，`f`的形式参数会作为promise被添加到该环境中。正如你之前从语言定义中看到的，默认参数和在函数调用处传入的参数，在promise的建立方式上有所不同。默认参数对应的promise应在计算作用域`evalenv`中进行求值。这意味着它们可以引用其他的局部变量或形式参数。由于这些变量会被放入`evalenv`，并且`evalenv`的父环境是`environment(f)`，这些promise也可以引用`f`被定义的作用域中的变量。然而，在函数调用处传给`f`的表达式，会被存储为应在调用环境中求值的promise。我们称该环境为`callenv`。如果它们在`evalenv`中被求值，就无法引用你调用`f`所在作用域中的变量；它们只能引用局部变量或`f`被定义的作用域中的变量。

你可以在下面的示例中看到这一切是如何运作的：

```
enclosing <- function() {
z <- 2
function(x, y = x) {
x + y + z
}
}
f <- enclosing()
calling <- function() {
w <- 5
f(x = 2 * w)
}
calling()
## [1] 22
```

你从全局环境开始，在此处将`enclosing`定义为一个函数。当你调用`enclosing`时，会创建一个计算环境，在其中存储变量`z`，然后返回一个函数，并将其作为`f`存储在全局环境中。由于该函数是在`enclosing`的计算环境中定义的，因此这个环境就是`f`的`environment`。

接着你创建了`calling`，将其存储在全局环境中，并调用它。这再次创建了一个计算环境。在其中，你存储了变量`w`，然后调用`f`。`f`不在当前计算环境中，但由于计算环境的父环境是全局环境，你能够找到它。当你调用`f`时，将表达式`2 * w`作为参数`x`传递给它。

在`f`的内部调用中，有另一个计算环境。它的父环境是你从`enclosing`那里得到的闭包环境。这里你需要对`f`的函数体进行求值：`x + y + z`。然而，在此之前，需要先设置好计算环境。由于`x`和`y`是形式参数，它们会作为promise被存储在计算环境中。你在调用`f`时提供了`x`作为参数，因此这个promise必须在调用环境（即`calling`内部的环境）中求值；而`y`有默认值，因此它必须在计算环境中求值。在这个计算环境中，它可以访问到`x`和`y`，并通过父环境访问到`z`。你对`x`进行求值（即在调用环境中求表达式`2 * w`的值，此处`w`是已知的），然后对`y`在局部环境中进行求值（此处`x`是已知的）。这样，你就得到了这两个变量的值，然后从闭包环境中获取`z`的值。

你可以尝试使用显式环境和`delayedAssign`来存储promise，以模拟这一切。你需要三个环境，因为这个例子不需要模拟全局环境。你需要`f`函数被定义时的环境；我们称其为`defenv`。然后你需要调用`f`时的计算环境，以及`f`被调用的环境。

```
defenv <- new.env()
evalenv <- new.env(parent = defenv)
callenv <- new.env()
```

这里，`defenv`和`calling`的父环境都是全局环境，不过你无需担心这个。计算环境的父环境是`defenv`。

在定义环境中，你保存了`z`的值。

```
defenv$z <- 2
```

在调用环境中，你保存了`w`的值。

```
callenv$w <- 5
```

在计算环境中，你设置好promise。`delayedAssign`函数接收两个环境作为参数。第一个是promise应该被求值的环境，第二个是它应该被存储的环境。对于`x`，你希望表达式在调用环境中求值；对于`y`，你希望它在计算环境中求值。两个变量都应存储在计算环境中。

```
delayedAssign("x", 2 * w, callenv, evalenv)
delayedAssign("y", x, evalenv, evalenv)
```

现在，你可以在`evalenv`中对`f`进行求值。

```
f <- function(x, y = x) x + y + z
eval(body(f), evalenv)
## [1] 22
```

一次函数调用的背后竟然有如此多的操作，这着实令人惊讶，但这一切都遵循着将参数作为promise进行传递的这些规则。

# 修改函数

你不仅能检查函数，还能做更多操作。用于检查的三个函数也各有赋值版本，你可以利用它们修改函数的三个组成部分。回到`f`的简单定义：

```
f <- function(x) x
f
## function(x) x
```

你可以尝试通过为`x`设置默认值来修改其形式参数：

```
formals(f) <- list(x = 3)
f
## function (x = 3)
## x
```

此时，由于`x`有了默认值，你可以在其形式参数的环境中计算函数体：

```
eval(body(f), formals(f))
## [1] 3
```

不过，我要再次强调，调用函数并不是简单地在形式参数上下文中计算函数体。当函数被调用时，你在其定义之外修改形式参数并不影响实际执行。形式参数仍会在函数定义时的环境中被计算。

如果你定义一个闭包，就能看到这一点：

```
nested <- function() {
y <- 5
function(x) x
}
f <- nested()
```

由于`f`是在`nested`的计算环境中定义的，因此`environment(f)`就是那个环境。当你调用它时，它就能看见`nested`中的局部变量`y`。它并没有引用这个变量，但你可以通过修改其形式参数来改变这一点：

```
formals(f) 
```

这里，你必须使用`quote`函数来让`y`成为一个名称。如果不这样做，你会遇到错误，或者得到对全局环境中`y`的引用。在函数定义中，默认参数会被自动引用（quote）以转化为表达式，但当你修改`formals`时，你需要显式地执行这一操作。

如果你现在调用不带参数的`f`，`x`将采用`formals(f)`指定的默认值。也就是说，它会引用`y`。由于这是一个默认参数，它会被转化为一个promise，并在`f`的计算环境中求值。那里没有名为`y`的局部变量，因此R会在`environment(f)`中查找`y`，并在`nested`环境中找到它：

```
f()
## [1] 5
```

仅仅因为你在全局环境中修改了`formals(f)`，并不会改变R计算默认参数promise的环境。即使有一个全局变量`y`，`f`形式参数中的`y`仍然引用`nested`中的那个：

```
y <- 2
f()
## [1] 5
```

当然，如果你在调用`f`时显式提供参数`y`，情况就不同了。此时它会变成一个应在调用环境中计算的promise，因此在这种情况下，你得到的是对全局变量`y`的引用：

```
f(x = y)
## [1] 2
```

你也可以修改`f`的函数体。例如，不让函数体引用`x`，而是让它返回常量6：

```
body(f) 
```

现在，当我们调用它时，无论`x`是什么，它都会计算那个常量6：

```
f()
## [1] 6
f(x = 12)
## [1] 6
```

你还可以尝试让`f`的函数体更复杂，使其成为一个实际的表达式：

```
body(f) <- 2 * y
f()
## [1] 4
```

然而，这里你并没有得到完全想要的结果。你并不希望在调用函数之前就计算函数体，但当你像这样赋值时，在赋值之前你就已经计算了它。惰性求值（lazy evaluation）也有其限度。由于`y`是2，你实际上是将`f`的函数体设置成了4。之后再改变`y`也不会改变这一点：

```
y <- 3
f()
## [1] 4
```

要得到一个未经计算的函数体，你必须再次使用`quote`：

```
body(f) 
```

但现在，你又回到了函数调用的语义，这意味着函数体是在一个父环境为`nested`内部环境的计算环境中求值的，因此`y`引用的是局部变量，而非全局变量：

```
f()
## [1] 10
y <- 2
f()
## [1] 10
```

如果你想让`f`使用全局变量`y`，可以修改`environment(f)`：

```
environment(f) <- globalenv()
f()
## [1] 4
y <- 3
f()
## [1] 6
```

不过，如果这样做，它就不再知晓`nested`内部的环境了。如果你想挑选函数在哪些环境中查找变量，需要大量的环境操作（environment hacking）；如果你的确有此需求，那么最好重写函数，通过其他方式访问变量。

如果你想将函数的形式参数设置为缺失值（即让它们成为没有默认值的参数），那么你需要使用`list`来创建参数。

如果你像这样定义一个函数`f`，它接受一个参数`x`，并将其与一个全局参数`y`相加：

```
f <- function(x) x + y
```

如果你希望`y`也是一个参数，但不给它默认值，你可以尝试这样：

```
formals(f) <- list(x =, y =)
```

但这行不通，因为`list`不接受空值。相反，你可以使用`alist`。这个函数创建了一个“成对列表”（pair-list），这是R内部用于表示形式参数的数据结构。这种数据结构仅用于此目的，但如果你要着手修改函数的参数，它就是你应该使用的工具：

```
formals(f) <- alist(x =, y =)
```

使用`alist`时，表达式也会被自动引用。在前面的例子中，当你希望参数`x`默认值为`y`时，需要使用`quote(y)`来让`y`作为一个promise在`environment(f)`中计算，而不是在调用作用域中计算。使用`alist`时，你不需要引用`y`：

```
nested 
f()
## [1] 5
```

# 构建函数

你也可以通过拼接各个组成部分来构建新的函数。用于此目的的函数是 `as.function`。它接受一个 `alist` 作为输入，并将其中的最后一个元素解释为新函数的主体，其余元素解释为形式参数。

```
f <- as.function(alist(x =, y = 2, x + y))
f
## function (x, y = 2)
## x + y
f(2)
## [1] 4
```

不要试图在这里使用 `list`；它不会按你的预期工作。

```
f <- as.function(list(x = 2, y = 2, x + y))
```

如果你给 `as.function` 一个列表，它会将其解释为一个表达式，然后这个表达式会成为新函数的主体。在这里，如果你有全局定义的 `x` 和 `y` 以便能够计算 `x + y`，那么你会得到一个主体为 `c(2, 2, x+y)` 的函数，其中 `x+y` 引用的是全局变量 `x` 和 `y` 的和的值，而不是它们的表达式。

新函数的环境默认是调用 `as.function` 时的环境。因此，要创建一个闭包，你只需在另一个函数内部调用 `as.function` 即可。

```
nested <- function(z) {
function(x, y = z) x + y
}
```

这里你在 `nested` 内部调用了 `as.function`，因此在此创建的这些函数的环境将会知道 `nested` 的参数 `z`，并能够在 `y` 的默认值中使用它。

不要尝试这样写：

```
nested <- function(y) {
as.function(alist(x =, y = y, x + y))
}
```

请记住，作为默认参数的表达式会在你定义的函数主体内部进行惰性求值。这里，你指定 `y` 应该求值为 `y`，这是一个循环依赖。这与 `as.function` 无关。你在下面的定义中也会遇到同样的问题：

```
nested <- function(y) {
function(x, y = y) x + y
}
```

如果你想要类似的功能，即创建一个具有给定默认值 `y` 的函数，并且你绝对希望所创建的函数将该参数命名为 `y`，那么你需要在嵌套作用域中对表达式求值，并使用不同的名称来引用它，以避免嵌套函数的参数遮蔽它。

```
nested <- function(y) {
z <- y
function(x, y = z) x + y
}
nested(2)(2)
## [1] 4
```

如果你不希望新函数的环境是当前环境，你可以为 `as.function` 指定一个环境，以明确其定义域。在下面的例子中，你有两个用于构建闭包的函数。第一个创建的函数可以看到包围它的 `z`，而另一个则使用了全局环境，因此根本不是闭包，所以参数 `z` 不可见。相反，全局的 `z` 是可见的。

```
nested <- function(z) {
as.function(alist(x =, y = z, x + y))
}
nested2 <- function(z) {
as.function(alist(x =, y = z, x + y),
envir = globalenv())
}
```

如果你对用这两个函数创建的函数进行求值，`nested` 创建的那个会将 `x` 与你在调用 `nested` 时提供的 `z` 值相加，而 `nested2` 创建的那个则会忽略其输入，并在全局作用域中寻找 `z`。

```
z <- -1
nested(3)(1)
## [1] 4
nested2(3)(1)
## [1] 0
```

# 函数调用内部

如你所见，当你执行函数主体时，你是在求值环境中进行的。这个求值环境通过其父环境链接到函数被定义的环境。它的参数存储为 promise，这些 promise 要么在函数被定义的环境（对于默认参数）中求值，要么在函数被调用的环境（对于在该处提供给函数的参数）中求值。在上一章中，你看到了如何获取函数的形式参数、函数主体以及函数被定义的环境。在本章中，你将学习如何在函数被求值期间，从函数内部访问这些信息，以及更多其他信息。

## 获取当前函数的组成部分

在上一章中，你可以通过一个函数引用来获取它的 `formals`、`body` 和 `environment`。在函数主体内部，你并没有这样的引用。函数本身并没有名称；当你将函数赋值给变量时，你是在给它们赋予名称，但这只是你拥有该名称的环境的属性，而不是函数本身的属性。你用作闭包的函数通常根本不会被赋予任何名称。那么，你如何获取当前函数来访问其组成部分呢？

为了获取当前函数，你可以使用 `sys.function` 函数。这个函数会返回当前函数的定义，这正是你所需要的，而不是它的名称。

你可以定义这个函数来看看 `sys.function` 是如何工作的。

```
f <- function(x = 5) {
y <- 2 * x
sys.function()
}
```

如果你直接在提示符下输入函数名，你会得到函数定义。

```
f
## function(x = 5) {
##   y <- 2 * x
##   sys.function()
## }
```

由于该函数返回自身的定义，当你对它求值时，也会得到相同的结果。

```
f()
## function(x = 5) {
##   y <- 2 * x
##   sys.function()
## }
```

当你调用 `formals`、`body` 或 `environment` 中的任何一个时，你并非使用函数名作为第一个参数；你需要为它们每个提供一个函数引用，然后它们会从中获取函数定义。

不过，你不需要为 `formals` 和 `body` 显式地调用 `sys.function`，因为这两个函数已经为它们的函数参数默认值使用了 `sys.function` 的调用。如果你想获取当前函数的组成部分，你可以简单地省略掉函数参数。

因此，要获取一个函数的形式参数，在函数主体内部，你可以直接使用不带任何参数的 `formals`。

```
f <- function(x, y = 2 * x) formals()
params <- f(1, 2)
class(params)
## [1] "pairlist"
params
## $x
##
##
## $y
## 2 * x
```

对于当前函数的主体也是如此。

```
f <- function(x, y = 2 * x) {
z <- x - y
body()
}
f(2)
## {
##     z <- x - y
##     body()
## }
```

`environment` 函数的工作方式略有不同。如果你不带参数调用它，你会得到当前的（即求值）环境。

```
f <- function() {
x <- 1
y <- 2
z <- 3
environment()
}
env <- f()
as.list(env)
## $z
## [1] 3
##
## $y
## [1] 2
##
## $x
## [1] 1
```

这不是你用 `environment(f)` 得到的结果。

```
environment(f)
##
```

`f` 函数是在全局环境中定义的，而 `environment(f)` 返回的是 `f` 被定义的环境。如果你在 `f` 内部调用 `environment()`，你会得到求值环境。局部变量 `x`、`y` 和 `z` 可以在求值环境中找到，但它们不是 `environment(f)` 的一部分——或者说，如果它们存在，那也会是不同的全局参数。

要从 `f` 内部获取等同于 `environment(f)` 的东西，你必须获取求值环境的父环境。你可以使用 `parent.env` 函数来获取一个环境的父环境，因此你可以像这样获取定义环境：

```
f
```

当你像上一章那样持有一个函数定义时，你并没有一个求值环境。那个环境只在函数被调用时才存在。一个你已定义但尚未调用的函数，拥有上一章涵盖的三个组成部分，但一个正在被积极执行的函数还有更多的组成部分。函数定义（即对函数在被调用时应做什么的描述）与函数实例化（即实际运行的代码）之间存在区别。其中一个区别就是求值环境。另一个区别是，函数实例化拥有实际参数，而函数定义只拥有形式参数。后者是函数定义的一部分；前者则由函数的调用者提供。

## 访问实际函数参数

在以下示例中，你可以看到形式参数与实际参数之间的区别：

```
f <- function(x = 1:3) {
print(formals()$x)
x
}
f(x = 4:6)
## 1:3
## [1] 4 5 6
```

`formals` 返回的是你在函数定义中提供的参数，其中 `x` 被设置为表达式 `1:3`。这是一个**承诺**（promise），当你在函数调用中未提供参数而访问 `x` 时，它将在定义作用域中被求值。因此，在 `formals` 列表中，它并不等于数值 1、2 和 3，而是表达式 `1:3`。然而，在实际调用中，你提供了 `x` 参数，因此该函数调用返回的是 `4:6`。由于你将其作为表达式的结果返回，这个承诺被求值了。因此，`f` 返回 4、5 和 6。

如果你确实希望以承诺实际代表的形态获取传递给当前函数的参数，就需要在不求值的情况下获取它们。如果你获取一个参数并将其用作表达式，承诺就会被求值。这同样适用于默认参数和函数调用中提供的参数：它们都是承诺，会在不同的环境中被求值，但无论如何它们都是承诺。

获取承诺所代表表达式的一种方法是使用函数 `substitute`。这个函数（你将在第 4 章中深入了解它）会将变量所引用的值替换到表达式中。这意味着变量会被逐字表达式替换；这些表达式在替换到另一个表达式之前不会被求值。

这个小函数展示了如何获取传递给函数的表达式：

```
f <- function(x = 1:3) substitute(x)
f()
## 1:3
```

此处可见，使用默认参数调用 `f` 会返回表达式 `1:3`。这与之前看到的 `formals` 类似。你用 `x` 在形式参数中的表达式替换了 `x`；并没有对表达式求值。当然，一旦你得到表达式，就可以

```
eval(f())
## [1] 1 2 3
```

但在调用 `substitute` 时并不会执行求值。

```
f(5 * x)
## 5 * x
f(foo + bar)
## foo + bar
```

由于替换后的表达式不被求值，你甚至无需用可求值的表达式来调用函数。

```
f(5 + "string")
## 5 + "string"
```

替换是逐字进行的。如果你设置的默认参数依赖于其他参数，那么这些默认参数只会被替换成变量名；而不会获得赋给其他变量的值。

```
f <- function(x = 1:3, y = x) substitute(x + y)
f()
## 1:3 + x
f(x = 4:6)
## 4:6 + x
f(y = 5 * x)
## 1:3 + 5 * x
```

在这个例子中，你还可以看到，可以用一个表达式而非单个变量来调用 `substitute`。此外，你会注意到 `x` 被替换为提供给 `x` 的参数（无论是默认值还是实际值），而 `y` 则被替换为作为默认参数的 `x`（而不是你在函数调用中为 `x` 提供的值），当你为 `y` 提供实际参数时，它会被替换为实际参数。

如果你尝试对从 `f` 调用返回的表达式求值，你不会在 `f` 的求值环境中求值它。该环境在替换过程中并未保留。

```
x <- 5
f(x = 5 * x)
## 5 * x + x
eval(f(x = 5 * x))
## [1] 30
```

你所求值的表达式是 `5 * x + x`，而不是 `5 * x + 5 * x`（如果 `x` 的值被替换到 `y` 中，就会是后者，就像你在函数内部求值表达式时那样）。

```
g <- function(x = 1:3, y = x) x + y
g(x = 5 * x)
## [1] 50
```

`substitute` 的一个常见用途是将提供给函数的表达式作为字符串获取。例如，这在 `plot` 函数中用于将绘图默认标签设置为调用 `plot` 时所使用的表达式。这里，`substitute` 与 `deparse` 函数结合使用。`deparse` 函数接收一个表达式并将其转换为文本表示形式。

```
f <- function(x) {
cat(deparse(substitute(x)), "==", x)
}
f(2 + x)
## 2 + x == 7
f(1:4)
## 1:4 == 1 2 3 4
```

此处，我们使用`deparse(substitute(x))`模式来获取调用`f`时所传入参数的文本表示，并使用纯粹的`x`来获取其求值结果。

`substitute`返回对象的实际类型取决于你提供给函数的表达式以及表达式变量所引用的内容。如果在变量被替换后，表达式属于`简单类型`，那么`substitute`就返回该`简单类型`。

```
f <- function(x) substitute(x)
f(5)
## [1] 5
class(f(5))
## [1] "numeric"
```

如果你给`substitute`提供一个已赋值的局部变量，你也会得到一个值作为返回。这并不是因为`substitute`在这里做了什么特殊处理。像这样的局部变量不是承诺；你在赋值时已经对一个表达式进行了求值。

```
f <- function(x) {
y <- 2 * x
substitute(y)
}
f(5)
## [1] 10
class(f(5))
## [1] "numeric"
```

不过，这种特性仅在函数内部有效。如果我们在全局环境中调用`substitute`，它会将变量视为`name`，而不会将它们替换为对应的值。

```
x <- 5
class(substitute(5))
## [1] "numeric"
class(substitute(x))
## [1] "name"
```

如果我们给函数传入一个`简单类型`作为参数，`substitute`会将变量替换为值。

```
f <- function(x, y = x) substitute(y)
f(5)
## x
class(f(5))
## [1] "name"
f(5, 5)
## [1] 5
class(f(5, 5))
## [1] "numeric"
```

如果`substitute`求值得到的表达式是单个变量，那么它返回的类型是`name`，正如你刚刚看到的那样。对于更复杂的情况，`substitute`会返回一个`call`对象。即使是一个可以轻松求值为`简单类型`值的表达式，`substitute`也不会对表达式求值；它只是替换变量。

```
f <- function(x, y) substitute(x + y)
f(5, 5)
## 5 + 5
class(f(5, 5))
## [1] "call"
```

`call`对象指的是一个未求值的函数调用。在这个例子中，你有一个表达式`5 + 5`，它对应于函数调用`+`(5, 5)。

这样的`call`对象也可以被操作。你可以将一个`call`对象转换为`列表`以获取其组成部分，也可以对其进行求值以执行实际的函数调用。

```
my_call <- f(5, 5)
as.list(my_call)
## [[1]]
## `+`
##
## [[2]]
## [1] 5
##
## [[3]]
## [1] 5
eval(my_call)
## [1] 10
```

由于`substitute`不对调用求值，你可以创建包含变量的函数调用对象，稍后可以在不同的环境中对这些变量进行求值。

```
rm(x) ; rm(y)
my_call <- f(x, y)
as.list(my_call)
## [[1]]
## `+`
##
## [[2]]
## x
##
## [[3]]
## y
```

这里，我们创建了调用`x + y`，但删除了全局变量`x`和`y`，因此你无法对该调用求值。

```
eval(my_call)
## Error in eval(expr, envir, enclos): object 'x' not found
```

不过，你可以在求值调用时提供这些变量。

```
eval(my_call, list(x = 5, y = x))
```

或者，你可以设置全局变量，并在全局环境中求值该调用。

```
x <- 5; y <- 2
eval(my_call)
## [1] 7
```

你可以将`call`对象视为`列表`并进行修改。`call`中的第一个元素是你要调用的函数，你可以像这样替换它：

```
(my_call <- f(5, 5))
## 5 + 5
my_call[[1]] <- `-`
eval(my_call)
## [1] 0
```

`call`中的其余元素是函数调用的参数，你也可以修改这些：

```
my_call[[2]] <- 10
eval(my_call)
## [1] 5
```

你也可以使用`call`函数手动创建`call`对象。`call`的第一个参数是要调用的函数名称，任何额外的参数都将在`call`对象被求值时传递给该函数。

`(my_call <- call("+", 2, 2))`

```
## 2 + 2
eval(my_call)
## [1] 4
```

然而，与函数内部的`substitute`不同，`call`的参数在构建调用对象时就会被求值。这些参数并非惰性求值。

```
(my_call <- call("+", x, y))
## 5 + 2
(my_call <- call("+", x - y, x + y))
## 3 + 7
```

在函数内部，你可以使用`match.call`函数获取用于调用该函数的调用。

```
f <- function(x, y, z) {
match.call()
}
(my_call <- f(2, 4, sin(2 + 4)))
## f(x = 2, y = 4, z = sin(2 + 4))
as.list(my_call)
## [[1]]
## f
##
## $x
## [1] 2
##
## $y
## [1] 4
##
## $z
## sin(2 + 4)
```

通过该调用的第一个元素，你可以获取被调用函数的名称。请记住，函数本身没有名称，但在对函数的调用中，你有一个对它的引用，你可以通过`match.call`函数获取该引用。

```
g <- f
(my_call <- g(2, 4, sin(2 + 4)))
## g(x = 2, y = 4, z = sin(2 + 4))
my_call[[1]]
## g
```

这个函数通常用于在统计模型中记住函数调用，其中模型构造器的调用会与拟合后的模型一起保存。

### 访问调用作用域

在函数内部，表达式在由求值环境及其父环境（即定义函数的环境）定义的作用域内进行求值，但函数调用中提供的承诺（promises）除外，它们在调用作用域内求值。如果你想直接访问函数内部的调用环境，可以使用`parent.frame`函数来获取它。¹

你可以在以下函数中看到这一点：

```
nested <- function(x) {
function(local) {
if (local) x
else get("x", parent.frame())
}
}
```

你有一个函数`nested`，它的局部环境知道参数`x`的值。在它内部，你创建并返回一个函数，该函数根据其参数，要么返回`nested`的参数值，要么在调用该函数的作用域中查找`x`。

```
f <- nested(2)
f(TRUE)
## [1] 2
x <- 1
f(FALSE)
## [1] 1
```

在第一次调用`f`时，你得到了`x`的局部值，即数字`2`。在第二次调用`f`时，你绕过了局部作用域，转而在调用作用域中查找`x`，本例中调用作用域是全局环境，你发现`x`的值为`1`。

在一个稍微复杂的版本中，你可以尝试在局部求值环境或调用作用域中求值一个表达式。

```
nested <- function(x) {
y <- 2
function(local) {
z <- 2
expr <- expression(x + y + z)
if (local) eval(expr)
else eval(expr, envir = parent.frame())
}
}
```

逻辑与之前的函数相同，只是在这个函数中，你定义了一个表达式，并使用`eval`在局部作用域或调用作用域中对其求值。你需要使用`expression`函数来创建表达式；如果不这样做，表达式会在`eval`处理之前（在局部作用域中）被求值。按照定义的函数，你可以显式地选择在评估表达式时使用哪个环境。

```
f <- nested(2)
x <- y <- z <- 1
f(TRUE)
## [1] 6
f(FALSE)
## [1] 3
```

与前面的例子一样，你可以对作用域、变量和表达式进行更具创造性的操作。你想编写一个函数，允许你一次性从返回一系列值的表达式（例如函数调用）中为多个变量赋值。我们不想写成这样：

```
x <- 1
y <- 2
z <- 3
```

而是希望能够编写以下代码并获得相同的效果：

```
bind(x, y, z) <- 1:3
```

由于 R 处理替换函数的方式（它会将此表达式解释为替换函数），你无法完全实现这一点，但你可以将赋值运算符修改为你自定义的中缀函数 `%<-%`，从而得到以下结果：

```
bind(x, y, z) %<-% 1:3
```

这个语法可能不是最漂亮的，但作为示例已经足够好了。然而，你还可以更进一步，让这个 `bind` 函数根据表达式来为变量赋值。例如，以下代码将 `2` 赋值给 `x`，将 `4` 赋值给 `y`，将 `6` 赋值给 `z`：

```
bind(x, y = 2 * x, z = 3 * x) %<-% 2
```

第一个是因为它是位置参数，另外两个是因为你给它们提供了表达式，一旦知道了 `x` 的值，就可以对这些表达式进行求值。

为了实现这个语法，你需要定义 `bind` 函数和 `%<-%` 运算符。其中，`bind` 函数更简单。

```
bind <- function(...) {
bindings <- eval(substitute(alist(...)))
scope <- parent.frame()
structure(list(bindings = bindings, scope = scope),
class = "bindings")
}
```

您使用 `eval(substitute(alist(...)))` 表达式来获取函数的所有参数并放入一个配对列表中，且不对任何潜在表达式进行求值。您希望保留惰性求值特性，因为在您尝试赋值给绑定的变量之前，作为参数提供的表达式不能被求值。使用 `eval(substitute(alist(...)))` 可以实现这一点。`substitute` 调用将函数的实际参数放入 `alist(...)` 表达式中，当您随后对这个表达式求值时，就会得到配对列表。您从 `parent.frame` 中获取应该绑定变量的作用域，然后将绑定和作用域组合成一个名为 `bindings` 的类。虽然不一定要将其设为类，但这并无坏处，所以您不妨这样做。

实际工作是在 `%<-%` 运算符中完成的。在这里，您需要做几件事。您需要确定哪些参数绑定只是名称（此时应根据其位置分配值），哪些是需要求值的表达式。位置参数可以直接赋值，然后将其存储在您在绑定中记住的作用域中。表达式应同时具有名称和需要求值的表达式（您无法在任何作用域中直接对实际表达式赋值，因此这些表达式必须是有名称的参数）。如果表达式引用了您在 `bind` 调用中命名的其他参数，它们需要知道这些参数是什么，因此您需要在 `bind` 提供的作用域中对表达式求值。如果您赋给表达式的值有名称，您还需要能够引用它们，例如编写如下赋值语句：

```
bind(y = 2 * x, z = 3 * x) %<-% c(x = 4)
```

为了实现这一点，您可以将这些值转换为一个环境，并将 `bind` 的父作用域也作为该环境的父环境。这样，它们既可以引用您赋值的变量，也可以引用您绑定中的变量。关于表达式引用您定义的其他参数，唯一的复杂之处在于表达式求值的顺序。为了对一个表达式求值，它所引用的所有变量都必须先被赋值。因此，您似乎需要解析表达式并确定顺序——即根据表达式使用了哪些变量对表达式进行拓扑排序——但您可以通过借用函数参数求值的一个技巧来避免：惰性求值。如果您不为每个参数赋值，而是赋一个承诺，那么您就不必担心变量赋值的顺序。每当 R 看到对这些承诺的引用时，它会自行处理这个顺序。这意味着，如果您在访问另一个变量之前修改了某个已赋值的变量，您可能会得到函数的惰性求值行为。例如，如果执行以下操作，`y` 将引用 10 而不是 24：

```
bind(y = 2 * z, z = 3 * x) %<-% c(x = 4)
z <- 5
```

为避免此问题，您可以在完成所有表达式赋值后，强制对所有表达式求值。

整个函数如下：

```
.unpack  0)
value_env  0) force(bindings$scope[[name]])
}
}
```

它能按预期工作。

```
bind(x, y, z) %<-% 1:3
c(x, y, z)
## [1] 1 2 3
bind(y = 2 * x, z = 3 * x) %<-% c(x = 4)
c(y, z)
## [1]  8 12
bind(y = 2 * z, z = 3 * x) %<-% c(x = 4)
c(y, z)
## [1] 24 12
```

这部分唯一复杂的是如何处理惰性赋值。您需要使用 `delayedAssign`，并且求值环境需要是包含值的环境，而赋值环境需要是您在 `bind` 函数中存储的环境。困难之处在于获取要求值的表达式。您不能对其求值——这正是您试图避免的——因此您需要将其作为一个表达式给出。然而，这个表达式要到以后并在不同的作用域中才会被求值，所以您不能简单地使用 `bindings$bindings` 列表来获取表达式。您需要将表达式替换到整个赋值的表达式中，然后再对其进行求值。`eval(substitute(...))` 模式就是实现这一点的关键；在此函数中，为了可读性将其分成了两行，但其核心技巧就是用 `substitute` 将表达式嵌入另一个表达式，然后再求值。

# 第 3 章：编程自动化

有人说，重复做同一件事却期待不同结果，是疯狂的体现。虽然快速查阅牛津词典并未找到这个定义，但我们有一个类似的出发点：为了避免陷入疯狂，还是让计算机去重复执行相同的操作吧！

本章的目标是让您开始在代码中构建自动化。代码的强大之处之一在于，它能不知疲倦、毫无差错地根据需要多次重复执行相同的操作。代码的另一个有用特性是能够将逻辑编织到编程流程中。人类在最佳状态下，会自然而然地使用这样的逻辑。例如，如果父亲的钥匙在挂钩上，那他一定在家。否则，父亲一定还在外面。再举一个例子：如果 `p` 小于 `alpha`，则拒绝原假设；否则，不拒绝原假设。

由于这种自动化允许大量的重复操作，因此必须关注效率。代码运行需要多长时间？能否通过不同的代码编写方式来加快操作速度？在编程中，或许就像在生活中一样，我们很少有完美的答案，而更经常是在选择和后果之间进行权衡。

新的、更强大的硬件通常比为了挤出一点效率所需的人力成本更便宜；两位作者都曾通过为问题投入新硬件来解决计算难题。另一方面，数据集现在动辄包含数十亿条记录；从每次计算中节省一毫秒，就能节省数百小时的计算时间。我们力求采取平衡的方法，先演示一些易于理解的结构，然后再介绍更快的方法。

在探讨第一种自动化方法时，我们提醒您，编程既是一门科学，也是一门艺术。更干净、更易读的代码可能不是最快的。关于“快”的唯一必要定义就是“足够快”。如果某种特定类型的代码对您来说更直观，从而使您更可能记住并使用它，那么这就足够了。当然，如果不够，就需要稍作研究来发现更快的替代方案。

### 3.1 循环

循环会重复执行其内部的代码。需要注意避免陷入无限循环（即永远持续下去的循环）的情况。大多数循环都内置了尝试停止的机制（尽管并非总能按计划奏效）。在下一节中，我们将讨论手动退出循环的方法。循环的另一个问题与它们是函数这一事实有关。尽管我们已经使用过这个词，但我们将把关于函数的坦率讨论推迟到下一章。目前，只需记住：在函数内部创建的任何内容在函数结束时可能会消失。对于循环来说，当循环停止重复时，这种情况就会发生。因此，如果您想保留结果，就需要在循环外部构建存放这些结果的容器。同样，我们将在下一章更深入地探讨具体细节。

`for` 循环是我们讨论的第一个（或许在 R 中也是最受争议的）自动化工具。在许多计算机语言中，`for()` 被认为相当快，但在 R 中并非如此。尽管如此，这个函数易于理解和使用。可读性强的代码不应无故摒弃。然而，做事的方法通常不止一种，忽视它们将是愚蠢的。请考虑以下代码行的输出，其中我们使用函数 `print()` 来打印变量 `i` 的值：

```
for(i in 1:6) {
  print(i)
}
## [1] 1
## [1] 2
## [1] 3
## [1] 4
## [1] 5
```

# [1] 6

刚才发生的事情是，我们的循环从值为 `1` 的 `i` 开始，然后一直迭代到 `6`。这并不特别令人兴奋。然而，它展示了计算机是如何愿意一步一步地执行某些操作的。

假设我们想要提升列表中前六辆车的马力（`hp`）。我们可以给每个原始值加上 20。使用内置的 `mtcars` 数据集，我们可以逐一处理每个 `hp` 值并增加马力：

当然，这感觉有点像一个小例子，因为它确实如此。然而，它展示了 `for` 循环会重复执行一项乏味的任务，直到完成。

这样的过程有什么风险呢？嗯，它可能效率不高。在我们的代码中使用函数 `proc.time()` 来测量不同时间，我们通过计算停止时间和开始时间之间的差值来得出运行时间。此外，我们使用函数 `seq()` 创建一个从 1 到 10,000,000、步长为 1 的数字列表。

对于 `for()` 循环，我们初始化了一个空变量 `xCube`，并将其设置为 `NA` 类型的整数值。循环遍历 `x` 的 `length()`，在本例中为 1000 万个值。每个值都被立方并存储在我们的新空变量 `xCube` 中：

```
x <- seq(from = 1,
         to = 10000000,
         by = 1)

forTime <- proc.time() #存储开始时间

xCube <- NA_integer_ #创建一个空的整数变量

for(i in 1:length(x)) {
  xCube[i] = x[i] ^ 3 #将 x 在位置 i 的立方存储在 xCube 的位置 i
}

forTime <- proc.time() - forTime #停止时间减去开始时间即为所用时间

forTime #显示总耗时

## user system elapsed
## 3.1 0.2 3.3

head(x)

## [1] 1 2 3 4 5 6

head(xCube)

## [1] 1 8 27 64 125 216
```

花点时间研究前面的示例和输出。很可能，前面的代码运行需要一些时间。如果耗时太长，只需减少 `seq()` 函数中 `to =` 参数的零的个数即可。

这个过程之所以耗时，是因为虽然立方运算足够快，但将数据存入内存是一项较慢的操作。

不过，这次可以改进。尽管我们创建了一个变量 `xCube`，但它是一个空变量。`for` 循环的每次迭代不仅需要对 `x` 求立方，还必须将 `xCube` 变量的长度增加 1。事实证明，这并非一项微不足道的任务。如果我们提前将 `xCube` 创建为所需的长度，性能将显著提升。

我们首先对 `xCube` 使用 `rm()` 函数，以便有一个干净的起始点。

为了正确初始化 `xCube`，我们使用 `vector()` 函数，将其设置为数值型数据，并将长度设置为我们所需的 `length(x)`。请注意，此代码与前一个示例的唯一区别在于，`xCube` 一开始是 1000 万个 0 的副本：

```
rm(xCube) #从内存中移除旧的 xCube。

forTime2<- proc.time()

xCube <- vector(mode = "numeric", length = length(x))

for (i in 1:length(x) ) {
  xCube[i] = x[i]³
}

forTime2 <- proc.time()-forTime2

forTime2

## user system elapsed
## 1.3 0.0 1.3
```

这改善了我们的时间。值得注意的是，即使我们创建了一个不够长的虚拟 `xCube`，或者创建了一个过长而需要从末尾删除一些空条目的 `xCube`，这仍然是一个更快的选择。因此，即使在运行循环之前可能无法或不便知道所需变量的大小，先创建一个足够大的容器来存储数据可能是有益的。

现在，对于这个特定的例子，使用 `for` 循环是错误的做法。R 为一些最简单的函数提供了强大且快速的底层代码。请注意，几乎没有经过任何时间（当然，有一些时间，但取决于操作系统，一些差异可能不明显）：

```
xCube <- NULL
vTime <- proc.time()
xCube <- x³
vTime <- proc.time()-vTime
vTime

## user system elapsed
## 0.39 0.02 0.41
```

还有其他类型的循环。`for` 循环最适合于运行固定次数的过程，并在到达末尾时停止。而 `while()` 循环则最适合于在满足停止条件之前运行不确定次数的过程。通常，使用不同类型的循环可以获得相同的结果（或者正如你刚刚看到的，完全不用循环）。尽管如此，每种类型的循环在特定条件下都有更自然的用途。作为一项练习，在你研究了下面给出的 `while` 循环示例后，看看你是否能复制之前的立方结果。

或许，世界各地研究人员都非常关心的一个例子是模拟。毕竟，如果我们能模拟数据，那可能是理解现实世界结果会怎样的第一步。软件驱动的模拟通常使用随机数生成器来创建所需的变异。由于我们希望我们的结果与你的结果相匹配，我们通过 `set.seed(1234)` 函数显式设置相同的随机数起始点。虽然关于通过计算机生成随机数与伪随机数的讨论超出了本文的范围，但这个函数应该能让我们保持一致。如果你想尝试真正的随机输入，只需从代码中移除该函数即可。

讨论完随机数，建模和统计已内置于 R 中，函数 `rnorm()` 可以接受最多三个输入。第一个参数控制我们希望为样本返回的元素数量。第二个和第三个参数控制从中随机抽取样本的总体均值和标准差。让我们看看 `rnorm()` 提供了什么：

我们找到的是从同一个总体中随机抽取的五个样本，该总体的 `mean()` 为 4，标准差或 `sd()` 为 2。然而，请注意每个样本都有不同的均值。当然，这些均值都接近 4；否则就不符合正态分布了。实际上，我们可能预期大多数单个数字的平均值在 2 到 6 之间，而几乎所有数字的平均值都在 0 到 8 之间。由于我们观察的是五个数字的均值，根据中心极限定理，均值离总体均值太远的情况会相当罕见。

假设我们想从均值为 4、标准差为 2 的正态分布总体中随机抽取五个元素组成一个样本。需要随机抽取多少次，才能找到一个均值至少为 8.1 的样本？

答案是一个 `while()` 循环。与运行固定迭代次数的 `for` 循环不同，`while` 循环会一直运行，直到满足某个条件。在我们的例子中，我们想不断从分布中随机抽取一组五个数字，直到得到均值至少为 8.1 的子集（这个值是随意选择的，因为它比期望值高出好几个标准差）。

我们再次固定一个特定的随机数序列。为了确保循环至少运行一次，我们必须确保 `mean(y) < 8.1` 返回 `TRUE`。这可以通过将 `y` 的初始值设为 `8` 来实现。此外，为了学习目的，我们添加了一个初始值为零的计数器变量 `i`，用于统计循环运行的次数。最后，我们确认随机抽取的样本确实具有相对于总体分布而言相当大的均值：

```
set.seed(1234) # 允许结果可复现

y <- 8 # mean(y) < 8.1 返回 TRUE

i <- 0 # 初始化计数器并设为零

while (mean(y) < 8.1) {
    i <- i + 1 # 每次循环将计数器加 1
    y <- rnorm(5, mean = 4.0, sd = 2) # 从总体中存储随机样本
}
```

```
print(y) # 观察样本

## [1] 10.3 9.0 7.7 6.7 8.3
```

```
mean(y) # 确认 mean(y) >= 8.1

## [1] 8.4
```

注意，与我们通常对总体特征的了解相比，`y` 是一个相当异常的样本。当然，这支持了更大样本量的论点，但它也为我们提供了既符合事实又能检验假设的数据。反例和异常数据对于压力测试代码或模型非常有用。这只是 `while` 循环的一个例子。如你所见，参数是设置条件的地方。循环会一直运行，直到条件变为 `FALSE`。事实上，这个循环必须运行很多次；我们的计数器显示循环超过了 100 万次！

我们讨论的最后一个循环是 `repeat()`，它与 `while` 和 `for` 循环不同。特别地，`repeat` 不像 `while` 或 `for`，它不接受任何有机会使其停止的参数。这个函数会不断地重复运行。当然，必须有一种方法能停止它，否则我们就麻烦了。我们将在下一节“流程控制”中讨论这些技术。不过，首先我们来了解一下关于循环的一些观察。

循环旨在根据需要多次执行任务。在 R 中，我们通过三种方式控制这些任务。如果任务需要执行到一定次数，`for` 循环可能是最佳选择。`for` 循环的启动和停止由固定的迭代器控制。如果任务需要执行直到满足某个条件，`while` 循环可能是最佳选择。特别地，`while` 循环在循环运行之前测试决定循环是否运行的条件。

这一点至关重要！如果条件已经满足，`while` 循环就永远不会运行。我们讨论的最后一个循环 `repeat()` 则不同。它只是运行。现在，我们必须以某种方式停止它，我们将在下一节中手动停止 `repeat`。关键是 `repeat` 从不检查是否需要运行；它只是运行。所以，如果你希望一个过程至少运行一次，`repeat` 可能就是你要找的函数。

我们暂时不给出 `repeat` 的例子，主要是为了避免无限循环。虽然我们很快就会展示一个例子，但我们必须先学习一种控制代码流程的方法。

## 3.2 流程控制

代码流程控制通过执行测试来决定执行哪个操作，或者修改你在上一节中看到的循环的行为。

我们将依次介绍每个命令，并在本节末尾回到 `repeat` 循环。

`if`/`else` 语句是逻辑的标准组成部分，也是编程的标准组成部分。`if`/`else` 控制测试一个逻辑条件，当条件为 `TRUE` 时，执行 `if` 部分。否则，当逻辑条件为 `FALSE` 时，执行 `else` 部分。

有时，没有需要运行的替代代码；在这种情况下，只需不使用 `else`。

回到我们强制样本均值大于或等于 8.1 的样本值例子，我们可以使用 `if`/`else` 来决定图形的标题内容（换句话说，我们可以使用代码逻辑来改变图形的输出）。

以下代码使用流程控制生成了图 3-1。逻辑运算 `mean(y) > 8.1` 的结果为 `TRUE`。这进而运行了 `boxplot()` 函数，并跳过了 `plot()` 函数。`boxplot()` 将整个数据集作为第一个输入，将主标题作为第二个输入，并将 `horizontal` 参数值设为 `TRUE`（默认值为 `FALSE`）：

```
if ( mean(y) > 8.1 ) {
    boxplot(y,
        main = "This sample has an atypically large mean.",
        horizontal = TRUE)
} else {
    plot(y,
        main = "This sample mean is not so very large.")
}
```

我们的下一个流程控制函数是 `next()`，它可以用来进入循环的下一次迭代。换句话说，`next()` 会跳过它后面的代码而不执行。但是，它不会结束或停止循环过程。回想一下我们之前的 `while()` 循环。将那个早期版本的代码与下面的代码进行比较和对比。特别注意，`print(y)` 已被移到了循环内部。然而，尽管循环运行了超过 120 万次，`y` 样本的值只向控制台输出了一次：

```
set.seed(1234) # 允许结果可复现

y <- 8 # mean(y) < 8.1 返回 TRUE

while (mean(y) < 8.1) {
    y <- rnorm(5, mean = 4.0, sd = 2) # 从总体中存储随机样本
    if ( mean(y) < 8.1 ) { next() }
    print(y)
}
```

```
## [1] 10.3 9.0 7.7 6.7 8.3
```

### 第三章 编程自动化

`next` 的位置至关重要；我们可以在 `while` 函数中以六种方式排列这三行代码。至少一种方式会产生无限循环，至少一种方式则完全不会产生明显影响。当然，正如你刚才所见，还有一种方式能使这个循环的行为与之前的某些代码类似。`next()` 的一个重要特性是，我们现在可以选择（在结合 `if` 使用时）是希望完成每一个循环，还是只完成其中一部分循环。

这引出了我们对 `break` 的讨论，它不仅能停止循环的一次迭代——它还能让我们彻底跳出整个循环。当与 `repeat()` 函数配合使用时，可以创建一个会持续运行，直到满足特定条件才停止的循环。

虽然这段代码的最终结果与前两个版本相同，但请注意我们的逻辑结构略有不同。当在 `if` 语句中满足 `break` 条件时，我们那个没有原生迭代控制的 `repeat` 循环将被强制中断。请注意，这个 `break` 并不会阻止 `print(z)` 运行。它只是将代码流跳出循环——并不会终止整个运行过程：

```r
set.seed(1234) #保证结果可重现
z <- NULL
repeat{
  z <- rnorm(5, mean = 4.0, sd = 2) #从总体中存储随机样本
  if (mean(z) >= 8.1) { break }
}
print(z)
```

```
## [1] 10.3 9.0 7.7 6.7 8.3
```

## 3.3 apply 函数族

尽管这两个函数本身都很有用，但它们都依赖于正确的输入。当然，代码通常都依赖于正确的输入（“垃圾进，垃圾出”这句话浮现在脑海中）。不过，我们可以使用 `vapply()` 函数来指明期望的结果类型。该函数接受第三个输入，用于设定我们期望的输出类型。如果函数没有返回正确类型的值，会发生什么？这里我们运行两行几乎相似的代码。第一行告诉 `vapply()` 期望布尔值输出，因为默认情况下 `NA` 是逻辑值。第二次尝试则期望输出为 `double()` 类型的单个值。`double(length = 1)` 函数期望每个 double 类型的对象都是单个 double 元素。由于这正是我们的 apply 函数所产生的输出，因此下一个示例可以正常工作：

```r
vapply(xL, sqrt, FUN.VALUE = NA) #这行会报错
```

## but FUN(X[[1]]) result is type 'double'

```r
vapply(xL, sqrt, FUN.VALUE = double(1))
```

当我们的数据结构是数据框、矩阵或数组时，`apply()` 函数通常是一个不错的选择。因为这些结构往往维度更多，所以该函数需要更多关于函数将使用哪些数据作为输入的信息。在第二个形式参数（名为 `MARGIN`）中，输入值 1 指定*行*，而输入值 2 指定*列*。对于像 `mtcars` 这样的数据框，大多数计算只有按列进行才有意义，因此使用了 `MARGIN = 2`。在此例中，我们不使用均值，而是使用标准差函数 `sd()`：

```r
apply(mtcars, MARGIN = 2, FUN = sd)
```

当需要对多个数据集应用同一个函数时，就需要用到多元 apply 函数 `mapply()`。与之前的示例不同，该函数将函数作为第一个变量，然后接受提供的任意数量的数据输入。在此例中，不必重复调用函数，而是可以一次完成整个计算。

首先，考虑使用 `cor.test()` 函数将 `mpg` 与 `cyl` 进行比较的单次相关性检验：

```r
cor.test(mtcars$mpg, mtcars$cyl)
```

结果显示出相当强的负相关性证据。现在，假设除了这个比较之外，我们还希望测试 `hp` 和 `disp` 之间的关系。与其一次一次地执行两次检验，`mapply()` 函数可以处理这个计算。注意，我们测试的是相同的两对数据。换句话说，我们现在有了表 3-1。我们的函数 `mapply()` 分别对表中的第一列和第二列计算 `cor.test()`。可以通过 `MoreArgs =` 变量向 `cor.test()` 提供额外的参数，该变量接受一个列表。在此例中，虽然我们明确展示了这些输入，但我们将它们保留为默认值：

```r
mapply(cor.test,
       mtcars[, c("mpg", "hp")],
       mtcars[, c("cyl", "disp")],
       MoreArgs = list(method = "pearson", alternative = "two.sided"))
```

## 3.4 本章小结

你已经了解了几种强大的自动化工具，从控制重复操作（实际上是重复次数）的各种循环，到更专业的、专为处理我们可能遇到的数据集中常见情况而设计的工具。

这些技巧很有用，也经常被用到。然而，这还不够。如果开发出了新技术怎么办？像 `mean()` 这样的函数是如何工作的？如果我们需要创建自己的函数怎么办？在下一章中，我们将从理论框架和实际应用两个层面来探讨函数。自定义函数与循环的结合，是驱使计算机为我们完成繁重工作的核心所在。在此之前，请仔细查看表 3-2 中本章所学的函数，并思考它们“引擎盖下”可能藏有什么玄机。

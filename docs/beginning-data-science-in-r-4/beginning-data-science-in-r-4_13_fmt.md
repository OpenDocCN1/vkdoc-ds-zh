# 10. 使用向量和列表

在本章中，我们将进一步探讨向量和列表的使用。我们并不会涉及比上一章概念上更复杂的内容，只是深入一些更多的技术细节。

## 向量与向量化函数的使用

我们从表达式开始回顾。在上一章中，我们看到了针对单个（标量）值的表达式，但同时也注意到 R 语言实际上并没有真正的标量值；我们所拥有的所有原始数据本质上都是数据向量。这意味着我们在 R 中使用的表达式实际上是对向量进行操作，而非单个值。

当你编写以下代码时：

```
(x <- 2 / 3)
## [1] 0.6666667
(y <- x ** 2)
## [1] 0.4444444
```

你所写的表达式当然是在处理单个值——向量`x`和`y`的长度为 1——但这实际上只是向量操作的一个特例：

```
(x <- 1:4 / 3)
## [1] 0.3333333 0.6666667 1.0000000 1.3333333
(y <- x ** 2)
## [1] 0.1111111 0.4444444 1.0000000 1.7777778
```

R 语言通过两条规则来处理向量：运算按元素逐个执行，并且向量会根据需要进行循环复用。

当你编写诸如`x + y`这样的表达式时，实际上是在说你想创建一个新向量，该向量由向量`x`和`y`中对应元素逐个相加得到。因此，对于如下`x`和`y`：

```
x <- 1:5
y <- 6:10
```

编写：

```
(z <- x + y)
## [1]  7  9 11 13 15
```

等同于编写：

```
z <- vector(length = length(x))
for (i in seq_along(x)) {
z[i] <- x[i] + y[i]
}
z
## [1]  7  9 11 13 15
```

所有算术表达式或涉及`|`或`&`的逻辑表达式（但不包括`||`或`&&`；后者不按元素对向量进行操作）都是如此。对于大多数可以调用的函数，例如`sqrt`或`sin`，也是如此：

```
sqrt((1:5)**2)
## [1] 1 2 3 4 5
sin(sqrt((1:5)**2))
## [1]  0.8414710  0.9092974  0.1411200 -0.7568025
## [5] -0.9589243
```

当你有一个涉及不同长度向量的表达式时，无法直接按元素求值。在这种情况下，R 会尝试重复较短的向量以创建相同长度的向量。为此，较短的向量的长度应能被最长向量的长度整除，也就是说，你应该能够将较短的向量重复整数次以得到最长向量的长度。如果可行，R 会根据需要重复向量，使所有向量与最长向量等长，然后按元素进行操作：

```
x <- 1:12
y <- 1:2
x + y
##  [1]  2  4  4  6  6  8  8 10 10 12 12 14
z <- 1:3
x + z
##  [1]  2  4  6  5  7  9  8 10 12 11 13 15
```

如果较短的向量无法重复整数次以匹配长度，R 仍会根据需要重复多次以匹配最长的向量，但你会收到一个警告，因为大多数情况下此类问题是由错误代码引起的：

```
z <- 1:5
x + z
## Warning in x + z: longer object length is not a
## multiple of shorter object length
##  [1]  2  4  6  8 10  7  9 11 13 15 12 14
```

在我们之前看到的表达式中：

```
(x <- 1:4 / 3)
## [1] 0.3333333 0.6666667 1.0000000 1.3333333
(y <- x ** 2)
## [1] 0.1111111 0.4444444 1.0000000 1.7777778
```

不同的向量被重复使用。当我们将`1:4`除以`3`时，我们需要将（长度为 1）的向量`3`重复四次，才能将`1:4`向量与`3`向量相除。当我们计算`x ** 2`时，也必须将`2`重复四次。

无论何时你考虑对向量编写循环来对每个元素进行计算，都应优先考虑使用此类向量化表达式。这通常更不容易出错，而且由于它涉及由 R 运行时系统处理的隐式循环，几乎肯定比显式循环更快。

### `ifelse`

控制结构不是向量化的。例如，`if`语句就不是。如果想要根据向量`x`计算向量`y`，使得当`x[i]`为偶数时`y[i] == 5`，当`x[i]`为奇数时`y[i] == 15`，你无法将其写成一个向量表达式：

```
x <- 1:10
if (x %% 2 == 0) 5 else 15
## Warning in if (x%%2 == 0) 5 else 15:
## the condition has length > 1 and only the first element will be
## used
## [1] 15
```

相反，你可以使用`ifelse`函数，它的工作方式类似于向量化选择；如果其第一个参数中的条件为真，则返回第二个参数的值，否则返回第三个参数的值，并且这是以向量操作的方式进行的：

```
x <- 1:10
ifelse(x %% 2 == 0, 5, 15)
##  [1] 15  5 15  5 15  5 15  5 15  5
```

### 向量化函数

当你编写自己的函数时，可以使其能够处理向量，也就是说，你可以编写出能够将向量作为输入并返回向量作为输出的函数。如果以这种方式编写，它们就可以像`sqrt`和`sin`等内置函数一样，在向量化表达式中使用。

让函数适用于向量的最简单方法是，在函数体中使用能够处理向量的表达式：

```
f <- function(x, y) sqrt(x ** y)
f(1:6, 2)
## [1] 1 2 3 4 5 6
f(1:6, 1:2)
## [1] 1.000000 2.000000 1.732051 4.000000 2.236068
## [6] 6.000000
```

如果你编写的函数无法通过上述方式编写函数体，但又希望它能在向量表达式中使用，通常可以使用`Vectorize`函数来实现。

举个例子，假设我们有一个将键映射到某些值的表格。设想一下，我们可能想将班级中的姓名映射到班级参与者的角色。在 R 语言中，我们通常使用列表来实现这类表格，并且可以轻松地编写一个函数来根据此表格将姓名映射到角色：

```
role_table <- list("Thomas" = "Instructor",
"Henrik" = "Student",
"Kristian" = "Student",
"Randi" = "Student",
"Heidi" = "Student",
"Manfred" = "Student")
map_to_role <- function(name) role_table[[name]]
```

当我们用单个姓名调用它时，该函数能按预期工作：

```
map_to_role("Thomas")
## [1] "Instructor"
map_to_role("Henrik")
## [1] "Student"
```

但是，当我们用一个向量调用该函数时，它会失败，因为我们无法用向量以这种方式索引列表：

```
x <- c("Thomas", "Henrik", "Randi")
map_to_role(x)
## Error in role_table[[name]]: recursive indexing failed at level 2
```

因此，我们有一个将单个值映射到单个值的函数，但它不适用于向量。让此类函数适用于向量的简单方法是使用`Vectorize`函数。该函数会封装你的函数，使其能够处理向量，并且它对向量所做的操作正如你所期望的那样：它会计算向量中每个元素对应的值，结果将是所有结果组成的向量：

```
map_to_role <- Vectorize(map_to_role)
map_to_role(x)
##        Thomas     Henrik      Randi
##  "Instructor"  "Student"  "Student"
```

在这个特定表格示例中，失败的原因是我们使用了`[[`索引运算符。如果我们使用`[`运算符，就不会出问题（只不过结果是一个列表而不是向量）：

```
role_table[c("Thomas", "Henrik", "Randi")]
## $Thomas
## [1] "Instructor"
##
## $Henrik
## [1] "Student"
##
## $Randi
## [1] "Student"
```

因此，我们也可以通过不同的索引方式然后展平列表来直接处理向量输入：

```
map_to_role_2 <- function(names) unlist(role_table[names])
x <- c("Thomas", "Henrik", "Randi")
map_to_role_2(x)
##       Thomas       Henrik        Randi
## "Instructor"    "Student"    "Student"
```

不过，并非总能轻易地重写函数以使其适用于向量输入，当我们无法轻易做到这一点时，`Vectorize`函数就会非常有用。

补充一点，对值向量使用`[[`的问题不仅仅在于它不起作用。实际上它也能工作，但会执行与我们这里尝试不同的操作。如果你给`[[`一个索引向量，它将用于执行所谓的**递归索引**。这是一种快捷方式，它首先使用第一个变量在列表中查找，并提取出找到的向量或列表。然后，它再使用下一个索引对该序列进行查找，依此类推。以下面的代码为例：

```
x <- list("first" = list("second" = "foo"), "third" = "bar")
x[[c("first", "second")]]
## [1] "foo"
```

这里，我们有一个包含两个元素的列表，其中第一个元素是一个包含单个元素的列表。我们可以通过索引`"first"`在第一个列表中查找，并得到存储在该索引处的列表。然后，我们可以使用索引`"second"`对这个列表进行索引，从而得到`"foo"`。

其结果与下面代码类似：

```
x[["first"]][["second"]]
## [1] "foo"
```

这可能是一个有用的特性——尽管老实说，在我自己的编程中很少发现它的用处——但这并不是我们在角色映射示例中所期望的效果。

### `apply` 家族

对函数进行向量化，使我们能够隐式地将其应用于向量。我们只需将向量作为输入传递给它，就能得到向量作为输出。但请注意，**仅因为函数接受向量作为输入，并不意味着它就是一个向量化函数**——许多函数将向量作为输入，但返回单个值作为输出，例如`sum`和`mean`——但我们使用这些函数的方式与使用向量化函数不同。如果你需要这类函数，你**必须**显式地处理它如何处理序列输入。

向量化函数可以像处理单个值一样，使用完全相同的语法处理数据向量。这是一种隐式的向量操作方式。但是，当我们对向量中的所有元素调用函数时，我们也可以使其更加明确，从而让我们对函数的具体调用方式有更多控制。这反过来又让我们能够使用那些不仅实现向量到向量映射，也包括向量到单值映射的函数。

实现这一点有很多方法——因为这在 R 语言中很常见——稍后我们将看到一些通用的函数，用于处理序列并以各种方式对其调用函数。不过，在你阅读的大部分代码中，执行此操作的函数名称通常包含`apply`字样，我们接下来要研究的就是这些函数。

我们从`apply`开始。这是一个用于操作向量、矩阵（二维向量）或数组（更高维度的向量）的函数。

### `apply`

`apply`函数在矩阵上最容易解释，因此我们先创建一个矩阵：

```
m <- matrix(1:6, nrow = 2, byrow = TRUE)
m
##      [,1] [,2] [,3]
## [1,]    1    2    3
## [2,]    4    5    6
```

`apply`函数接受（至少）三个参数。第一个是向量/矩阵/数组，第二个是我们应该沿着哪些维度进行边际化，第三个是我们应该应用的函数。

这里的边际化是指，在维度的某个子集中固定一个索引，并提取出该索引对应的所有值。如果我们按行进行边际化，我们将提取所有行，因此对于每一行，我们将得到一个向量，其元素对应每一列，这就是我们将传递给函数的对象。

我们可以使用`paste`函数来演示，该函数通过连接输入创建一个字符串。

如果我们按行边际化，它将在每两行上各调用一次，并生成两个字符串：

```
apply(m, 1, \(x) paste(x, collapse = ":"))
## [1] "1:2:3" "4:5:6"
```

如果我们按列边际化，它将在每三列上各调用一次，并生成三个字符串：

```
apply(m, 2, \(x) paste(x, collapse = ":"))
## [1] "1:4" "2:5" "3:6"
```

如果我们同时按行和列边际化，它将在每个单独元素上调用：

```
apply(m, c(1, 2), \(x) paste(x, collapse = ":"))
##      [,1] [,2] [,3]
## [1,] "1"  "2"  "3"
## [2,] "4"  "5"  "6"
```

这里的输出是二维的。这是因为我们正在对两个维度进行边际化，因此我们得到了一个与这些边际相对应的输出。

我们也可以通过其他方式获得更高维度的输出。如果我们应用的函数生成向量（或更高维度的向量）作为输出，那么`apply`的输出也将是更高维度的。考虑一个函数，它接收一个向量作为输入，并通过将其与自身连接来复制它。如果我们将其应用于行或列，我们将为每行/每列得到一个向量，因此输出必须是二维的：

```
apply(m, 1, \(x) c(x,x))
##      [,1] [,2]
## [1,]    1    4
## [2,]    2    5
## [3,]    3    6
## [4,]    1    4
## [5,]    2    5
## [6,]    3    6
apply(m, 2, \(x) c(x,x))
##      [,1] [,2] [,3]
## [1,]    1    2    3
## [2,]    4    5    6
## [3,]    1    2    3
## [4,]    4    5    6
```

`apply`在这里所做的是创建一个矩阵作为其结果，其中应用函数的结果按列从左到右收集。对两行调用函数的结果是一个具有两列的矩阵，第一列包含将函数应用于第一行的结果，第二列包含将其应用于第二行的结果。同样地，对于列，结果是一个具有三列的向量，输入矩阵中的每一列对应一列。

如果我们对超过一个维度进行边际化——并通过这种方式获得多维输出——同时生成多个值，那么两种效果会结合起来，我们将得到更高维度的输出：

```
apply(m, c(1,2), \(x) c(x,x))
## , , 1
##
##      [,1] [,2]
## [1,]    1    4
## [2,]    1    4
##
## , , 2
##
##      [,1] [,2]
## [1,]    2    5
## [2,]    2    5
##
## , , 3
##
##      [,1] [,2]
## [1,]    3    6
## [2,]    3    6
```

这个输出看起来相当令人困惑。然而，发生的情况与我们之前看到按行或列边际化时相同。我们对调用函数的每个边际都会得到一个输出——在本例中，是输入中的六个单元格中的每一个——并且输出被“按列”收集，只是在更高维度上，它会在最高维度上被收集（对于二维矩阵，最高维度就是列）。因此，为了得到调用函数的六个值的结果，我们需要以它们在输入矩阵中被索引的相同方式索引这些结果——这就是边际所代表的——但我们必须在最高维度中这样做。因此，我们可以通过以下方式获得六个输入值的连接结果：

```
x <- apply(m, c(1,2), \(x) c(x,x))
k <- dim(x)[3]
n <- dim(x)[2]
for (i in 1:n) {
for (j in 1:k) {
print(x[,i,j])
}
}
## [1] 1 1
## [1] 2 2
## [1] 3 3
## [1] 4 4
## [1] 5 5
## [1] 6 6
```

那么，如果要应用的函数除了从矩阵中获取的参数之外还需要其他参数，会发生什么情况呢？

```
sumpow <- \(x, n) sum(x) ** n
apply(m, 1, sumpow)
## Error in FUN(newX[, i], ...): argument "n" is missing, with no default
```

### 看起来并不顺利

`apply`函数期望传递给它的值，但它事先不知道如何提供额外的参数。如果你希望`apply`将这些额外参数传递给函数，则必须向`apply`提供它们。你可以将这些参数作为`apply`的附加参数传入；它们将按照你提供给`apply`的顺序传递给函数：

```
apply(m, 1, sumpow, 2)
## [1]  36 225
```

不过，明确命名这些参数会大大提高可读性：

```
apply(m, 1, sumpow, n = 2)
## [1]  36 225
```

# lapply

`lapply` 函数用于在列表上进行映射。给定一个列表作为输入，它将函数应用于列表中的每个元素，并输出一个与输入长度相同的列表，其中包含应用函数的结果：

```r
(l <- list(1, 2, 3))
## [[1]]
## [1] 1
##
## [[2]]
## [1] 2
##
## [[3]]
## [1] 3
lapply(l, \(x) x**2)
## [[1]]
## [1] 1
##
## [[2]]
## [1] 4
##
## [[3]]
## [1] 9
```

如果输入列表中的元素有名称，则这些名称会在输出向量中保留：

```r
l <- list(a=1, b=2, c=3)
lapply(l, \(x) x**2)
## $a
## [1] 1
##
## $b
## [1] 4
##
## $c
## [1] 9
```

如果你提供的输入是向量而不是列表，它会将其转换为列表，并且你总是会得到一个列表作为输出：

```r
lapply(1:3, \(x) x**2)
## [[1]]
## [1] 1
##
## [[2]]
## [1] 4
##
## [[3]]
## [1] 9
```

如果列表的元素比单个数字更复杂，你仍然只是将函数应用于这些元素：

```r
lapply(list(a=1:3, b=4:6), \(x) x**2)
## $a
## [1] 1 4 9
##
## $b
## [1] 16 25 36
```

## sapply 和 vapply

`sapply` 函数的功能与 `lapply` 相同，但会尝试简化输出。本质上，它尝试将从 `lapply` 返回的列表转换为某种向量。它使用一些启发式规则来猜测你想要的输出类型，在可以简化时进行简化，但在无法确定时返回一个列表：

```r
sapply(1:3, \(x) x**2)
## [1] 1 4 9
```

这种猜测在交互式工作中很出色，但在编写程序时可能不安全。当你能够看到它创建了什么时，它猜测并产生不同类型的输出不是问题，但在程序内部深处是不安全的。

`vapply` 函数的功能与 `sapply` 基本相同，但没有猜测。你必须告诉它你想要的输出类型，如果它无法生成该输出，它将返回一个错误，而不是生成一个你的程序可能知道也可能不知道如何处理的结果。

这两个函数接口的区别在于，`vapply` 期望第三个参数，该参数应该是输出类型的值：

```r
vapply(1:3, \(x) x**2, 1)
## [1] 1 4 9
```

# 高级函数

现在我们来看一些函数的特例。本节虽然名为“高级函数”，但这些函数并非真正高级；它们只是比我们已经见过的那些基本函数稍微复杂一点而已。

## 特殊名称

但首先，需要先谈谈名称问题。函数可以拥有与变量同类的名称——毕竟，当我们命名一个函数时，实际上只是在命名一个恰好保存了函数的变量——但我们不能把所有类型的名称都放在赋值运算符的右侧。例如，`if` 在 R 中是一个函数，但你无法将 `if` 写在赋值的左侧。

具有特殊名称的函数，即通常不能放在赋值前的名称，可以通过将它们放在反引号中来引用，因此函数 `if` 可以被称为 `` `if` ``。

任何函数都可以通过其放在反引号中的名称来引用，此外，你还可以在通常无法使用其名称的上下文中使用反引号来引用函数。这适用于调用函数，例如，你可以将中缀运算符当作普通函数调用来使用：

```r
2 + 2
## [1] 4
`+`(2, 2)
## [1] 4
```

或者当为函数分配变量名称时：

```r
`%or die%` <- function(test, msg) if (!test) stop(msg)
x <- 5
(x != 0) %or die% "x 不应为零"
x <- 0
(x != 0) %or die% "x 不应为零"
## Error in (x != 0) %or die% "x 不应为零": x 不应为零
```

## 中缀运算符

如果最后一个例子让你觉得奇怪，那可能只是因为你还不了解 R 的中缀运算符。在 R 中，任何以 `%` 开头和结尾的变量都被视为中缀运算符，因此调用 `x %foo% y` 等同于调用 `` `%foo%`(x, y) ``。几个内置的中缀运算符不具有这种名称，`+` 和 `*` 就是两个例子，但这种命名约定使得创建你自己的中缀运算符成为可能。我们在 `dplyr` 包的 `%>%` 管道运算符中看到了它的良好应用。

## 替换函数

替换函数是那些假装在修改变量的函数。我们之前见过一个例子，即给向量分配名称：

```r
v <- 1:4
names(v) <- c("a", "b", "c", "d")
v
## a b c d
## 1 2 3 4
```

这里发生的事情是，R 识别出你正在向一个函数调用赋值，然后去寻找一个名为 `` `names<-` `` 的函数。它用向量 `v` 和名称向量调用这个函数，并且函数调用的结果被重新赋值给变量 `v`。

所以我刚才写的内容意味着

```r
names(v) <- c("a", "b", "c", "d")
```

是以下内容的简写

```r
v <- `names<-`(v, c("a", "b", "c", "d"))
```

替换函数通常用于修改对象的各种属性，你可以通过使用其名称必须以 `` `<-` `` 结尾的约定来编写你自己的替换函数：

```r
`foo<-` <- function(x, value) {
x$foo <- value
x
}
`bar<-` <- function(x, value) {
x$bar <- value
x
}
x <- list(foo = 1, bar = 2)
x$foo
## [1] 1
foo(x) <- 3
x$foo
## [1] 3
x$bar
## [1] 2
bar(x) <- 3
x$bar
## [1] 3
```

请记住，这只是调用函数然后将结果重新赋值给一个变量的语法糖。它实际上并没有修改任何数据。这意味着如果你有两个变量指向同一个对象，只有你调用替换函数的那个变量会受到影响。替换函数会返回一个副本，该副本被赋值给第一个变量，而另一个变量仍然指向旧对象：

```r
y <- x
foo(x) <- 5
x
## $foo
## [1] 5
##
## $bar
## [1] 3
y
## $foo
## [1] 3
##
## $bar
## [1] 3
```

因为替换函数只是函数调用和随后重新赋值的语法糖，所以你不能将某个无法被赋值的表达式作为替换函数的第一个参数。

关于替换函数还有一些其他规则。首先，你正在赋值的值的参数必须命名为 `value`。你不能给它起其他名字：

```r
`foo<-` <- function(x, val) {
x$foo <- val
x
}
x <- list(foo = 1, bar = 2)
foo(x) <- 3
## Error in `foo<-`(`*tmp*`, value = 3): unused argument (value = 3)
```

R 重写表达式的方式假定你将值参数命名为 `value`，所以请这样做。

不过，你不需要将第一个参数命名为 `x`：

```r
`foo<-` <- function(y, value) {
y$foo <- value
y
}
x <- list(foo = 1, bar = 2)
foo(x) <- 3
x$foo
## [1] 3
```

如果你有超过两个参数，还应该将 `value` 参数作为最后一个参数。只要你要修改的对象是第一个参数，并且 `value` 参数是最后一个参数，这是允许的：

```r
`modify<-` <- function(x, variable, value) {
x[variable] <- value
x
}
x <- list(foo = 1, bar = 2)
modify(x, "foo") <- 3
modify(x, "bar") <- 4
x$foo
## [1] 3
x$bar
## [1] 4
```

## 数据到底有多可变？

我们刚刚看到，替换函数会创建一个新副本，所以如果我们用它来修改一个对象，实际上根本没有改变它。引用同一对象的其他变量将看到旧值，而不是更新后的值。所以我们可以合理地提问：到底怎样才能实际修改一个对象？

简短且几乎总是正确的答案是，你永远无法修改对象。^(²¹) 每当你“修改”一个对象时，你都是在创建一个新副本，然后将这个新副本重新赋值给你用来引用旧值的那个变量。

对于向向量或列表中的索引赋值，情况也是如此。你会创建一个副本，虽然看起来像是在修改它，但如果你通过另一个引用查看旧对象，你会发现它并没有改变：

```r
x <- 1:4
f <- function(x) {
x[2] <- 5
x
}
x
## [1] 1 2 3 4
f(x)
## [1] 1 5 3 4
x
## [1] 1 2 3 4
```

除非你更改了 `` `[<-` `` 函数（我强烈建议你不要这么做），否则它是一个所谓的原始函数。这意味着它是用 C 语言编写的，并且在 C 语言中，你实际上可以修改一个对象。这对效率来说很重要。如果向量只有一个引用，那么向其赋值将不会创建新副本，并且你将在原地修改该向量，这是一种常数时间操作。如果有两个引用指向该向量，那么当你第一次向其赋值时，会创建一个副本，然后你可以就地修改该副本。这种保持对象不可变但仍能保证一定效率的方法称为写时复制。

为了编写正确的程序，请始终记住，你并不是在修改对象，而是在创建副本——你所“修改”的值的其他引用仍然会看到旧值。为了编写高效的程序，也请记住，对于原始函数，只要对象只有一个引用，你就可以进行高效的更新（常数时间的更新，而不是与你所修改对象的大小成比例的时间）。

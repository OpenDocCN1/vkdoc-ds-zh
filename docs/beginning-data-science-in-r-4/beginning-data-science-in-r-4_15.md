# 12. 面向对象编程

在本章中，我们将了解 R 中的面向对象编程风格。实际上，R 有三种不同的面向对象编程系统：S3、S4 和 RC。我们只学习 S3，它是最简单且（据我所知）使用最广泛的。

## 不可变对象与多态函数

S3 中的面向对象与你可能在 Java 或 Python 或同类语言中见过的有很大不同。这很自然，因为 R 中的数据是不可变的，而在 Java 和 Python 这类语言中，OO 的基本模型是，你拥有具有状态的对象，可以通过调用其方法来改变状态。在 S3 中，你并没有严格意义上的状态；你拥有的是不可变的对象，就像 R 中所有其他数据一样。

那么，如果我们没有对象状态，面向对象还有什么意义呢？我们从 S3 系统中获得的是多态函数，在 R 中称为“泛型”函数。这些函数的功能取决于对象的类——类似于 Java 或 Python 中的方法，在子类中可以改变在父类中定义的方法以细化行为。

你可以定义一个多态函数 `foo`，然后再定义特化函数，比如 `foo.A` 和 `foo.B`。然后，对来自 `A` 类的对象 `x` 调用 `foo(x)` 会实际调用 `foo.A(x)`，而对来自 `B` 类的对象则会实际调用 `foo.B(x)`。这里 `foo.A` 和 `foo.B` 这些名称并非随意选择的，我们将会看到，正是我们命名函数的方式决定了哪个函数被调用。

我们并没有具有状态的对象，我们只是拥有一种机制，使得函数的功能依赖于对象所属的类——这通常被称为“动态分发”或“多态方法”。当然，由于我们没有状态，我们可以称之为多态函数。



## 数据结构

在开始创建真正的类和对象之前，我们先来看看数据结构。我们在之前的章节中讨论了 R 语言中各种内置的数据结构。这些内置数据类型是 R 中数据的基本构建块，但我们从未探讨过如何利用它们构建更复杂的数据结构。

比任何面向对象系统更重要的是，将相关数据组合在一起，以便我们将其作为一个整体来处理。如果我们正在处理几个属于同一整体的数据片段，我们不想让它们分散在几个不同的变量中，可能还有不同的作用域，那样我们很难保证它们的一致性。即使是使用不可变数据，这样的程序要保持状态一致也会是一场噩梦。

因此，对于我们要分析的数据，我们通常将其保存在数据框（data frame）中。这是将数据集中在一起的一个简单思路。我们处理的所有数据都在同一个数据框中，我们可以将数据框传递给函数，并知道它们以一致的状态获取了所有数据。至少是我们能通过数据框保证的一致状态；我们无法保证数据本身不会以某种方式出错，但我们可以在编写函数时假设数据框的行为符合某种预期。

那么，像拟合模型这样的东西呢？如果我们针对某些数据拟合一个模型，那么拟合结果会存储在多个变量中。当我们处理这个模型时，我们当然希望将它们放在一起，因为我们不希望意外地混用了来自两个不同模型拟合的变量。我们可能还想将其他数据与拟合模型一起存放，例如，关于实际拟合内容的一些信息（如果我们想在之后于 R shell 中检查它），或者用于拟合的数据本身。

在 R 中，将异构数据收集到单个对象中的唯一真正选项是列表。这就是 R 中的做法。

### 示例：贝叶斯线性模型拟合

本书上一章中描述的项目 2 涉及贝叶斯线性模型。为了表示这类模型，我们会将模型的数据打包到一个列表中。对于拟合数据，假设你有一个如下所示的函数（数学细节请参考上一章）。

该函数以公式形式接收模型规范作为其参数 `model`，以及先验精度 `alpha` 和数据“精度” `beta`。然后，它会计算拟合到数据的模型的均值和协方差矩阵。这部分在此省略，因为你应将其作为练习自行实现，但你可以在上一章看到细节。接着，它将拟合模型与一些相关数据（用于拟合模型的公式、模型拟合中使用的数据，此处假设在变量 `frame` 中）打包，放入一个列表，并返回该列表：

```r
blm <- function(model, alpha = 1, beta = 1, ...) {
# 这里是计算拟合的数学部分。
frame <- model.frame(model, ...)
phi <- model.matrix(frame)
no_params <- ncol(phi)
target <- model.response(frame)
covar <- solve(diag(alpha, no_params) +
beta * t(phi) %*% phi)
mean <- beta * covar %*% t(phi) %*% target
list(formula = model,
frame = frame,
mean = mean,
covar = covar)
}
```

我们可以通过模拟一些数据并调用该函数来查看其效果：

```r

a <- 1 ; b <- 1.3
w0 <- 0.2 ; w1 <- 3
y <- rnorm(10, mean = w0 + w1 * x, sd = sqrt(1/b))
# 拟合一个模型
model <- blm(y ~ x, alpha = a, beta = b)
model
## $formula
```

将模型拟合的相关数据收集到一个列表中，这样我们就能始终处理属于同一整体的值，这会使后续对拟合模型的分析编程变得容易得多。

## 类

当我们输入

```r
model
```

时得到的输出，实际上是对一个列表调用 `print` 函数的结果。它只是向我们展示了列表中的所有内容。然而，`print` 函数是多态函数的一个例子，因此当你对对象 `x` 调用 `print(x)` 时，其行为取决于对象 `x` 所属的类。

如果你想知道一个对象属于哪个类，可以使用 `class` 函数：

```r
class(model)
## [1] "list"
```

如果你想更改它，可以使用 `` `class<-` `` 替换函数：

```r
class(model) <- "blm"
```

我们可以为类使用任何名称；这里，我使用了 `blm` 来表示贝叶斯线性模型。

按照惯例，我们通常将类名和创建该类元素的函数命名为相同的名称，因此，由于我们正在使用 `blm` 函数创建这种类型的对象，惯例要求我们也将其类命名为 `blm`。但这仅仅是一个惯例，所以你可以为类起任何名字。

我们总是可以通过这种方式为一个对象分配一个类，但更改现有对象的类被认为是一种不好的风格。我们将属于一起的数据保存在列表中以确保其一致性，但我们想为一个类提供的功能与数据本身一样，都是该类的一部分，因此我们需要确保操作特定类对象的函数始终能够获得与该类一致的数据。如果我们到处随意更改对象的类，就无法保证这一点。

创建对象的函数应该分配类，之后我们就不应该再动该对象的类了。我们可以使用 `` `class<-` `` 函数设置类，然后从 `blm` 函数中返回它：

```r
blm <- function(model, alpha = 1, beta = 1, ...) {
# 这里进行一些操作...
object <- list(formula = model,
frame = frame,
mean = mean,
covar = covar)
class(object) <- "blm"
object
}
```

不过，类是由对象的一个属性表示的，有一个名为 `structure` 的函数可以为我们设置这些属性。使用它，我们可以同时创建对象并设置类，这样会更好一些：

```r
blm <- function(model, alpha = 1, beta = 1, ...) {
# 这里进行一些操作...
structure(list(formula = model,
frame = frame,
mean = mean,
covar = covar),
class = "blm")
}
```

现在我们已经给 `model` 对象赋予了类，让我们再次尝试打印它：

## 多态函数

`print`函数是一个多态函数。这意味着调用它时发生的情况取决于其第一个参数的类。当我们调用`print`时，R 会获取对象的类（假设是示例中的`blm`），然后查看是否能找到名为`print.blm`的函数。如果能找到，它将用你调用`print`时传入的参数调用该函数。如果找不到，它会转而尝试查找`print.default`函数并调用它。

我们尚未为`blm`类定义`print`函数，因此看到的是默认`print`函数的输出。

让我们尝试定义一个`blm`专用的`print`函数：

```
print.blm <- function(x, ...) {
print(x$formula)
}
```

此处，我们仅指示它打印用于指定模型的公式，而非列表中包含的完整数据集合。

现在，如果我们打印该模型，会发生以下情况：

```
model
## y ~ x
```

提供自己的类专用`print`函数就是这么简单。通常，定义自己的类专用多态函数也是如此：只需取函数名并在其后附加`.classname`，如果你定义一个具有该名称的函数，那么当你对具有该类的对象调用多态函数时，该函数将被调用。

不过，有一件事必须小心：函数的接口。我指的是函数接受的参数（及其顺序）。每个多态函数都接受一些参数；你可以通过查看函数文档来了解：

```
?print
```

在定义专用函数时，你可以添加更多参数，但应确保至少接受与泛型函数相同的参数。即使你没有这样做，R 也不会报错，但后来当有人基于泛型接口假设函数接受的参数并调用它，却遇到行为不同的专用函数实现时，必然会导致问题。别这么做。实现你的函数时应使其接受与泛型函数相同的参数。这包括使用相同的参数名称。有人可能会向泛型函数提供命名参数，而这只有在你的参数名称与泛型函数一致时才能正常工作。这就是为什么我们之前在`print.blm`函数中使用`x`作为输入参数。

### 定义你自己的多态函数

要定义多态函数的类专用版本，你只需编写一个名称正确的函数即可。如果你想定义自己全新的多态函数，则还需要做更多工作：编写泛型函数——即当你拥有不同类型对象时使用的函数，该函数负责将函数调用分派给类专用函数。

你可以使用`UseMethod`函数来实现。泛型函数通常仅执行此操作，如下所示：

```
foo <- function(x, ...) UseMethod("foo")
```

你指定一个函数，其中包含泛型函数应接受的参数，然后只需调用`UseMethod`并传入要分派的函数名称。它会施展魔法，找出要调用的类专用函数，并将参数转发过去。

在编写泛型函数时，同时定义默认函数也是一种良好的风格：

```
foo.default <- function(x, ...) print("default foo")
```

这样，我们就可以对所有类型的对象调用该函数。如果你不希望这样，一个安全的默认函数可以是抛出错误的函数：

```
foo("a string")
## [1] "default foo"
foo(12)
## [1] "default foo"
```

当然，有了泛型函数之后，我们可以像之前一样定义类专用函数：

```
foo.blm <- function(x, ...) print("blm foo")
foo(model)
## [1] "blm foo"
```

当泛型函数接受`...`作为参数时，你可以为更专用的函数添加更多参数；泛型函数会忽略额外参数，但被调用的具体函数可能会利用它们：

```
foo.blm <- function(x, upper = FALSE, ...) {
if (upper) {
print("BLM FOO")
} else {
print("blm foo")
}
}
foo("a string")
## [1] "default foo"
foo(model)
## [1] "blm foo"
foo("a string", upper = TRUE)
## [1] "default foo"
foo(model, upper = TRUE)
## [1] "BLM FOO"
```

## 类层级结构

多态函数是面向对象编程的一个方面；另一个方面是继承。这是用于从更通用的类构建更专用类的机制。

思考这个问题的最佳方式是将其视为专业化的层次。你有一类通用的对象，例如“家具”，在该类中有更具体的类别，例如“椅子”，而在这个类别中又有更具体的对象类型，例如“厨房椅”。厨房椅也是椅子，椅子也是家具。如果某件事对所有家具都适用，那么它肯定也适用于椅子。例如，你可以点燃家具；你可以点燃椅子。然而，并非所有对椅子适用的事情都对所有家具适用。你可以把椅子扔向不受欢迎的客人，但你不能把钢琴扔向他们（除非你是绿巨人）。

这种专业化的工作方式是，有一些操作适用于通用类。这些操作可以对该类的所有实例执行，包括那些实际上是更专用类对象的实例。

这些操作可能并非完全相同——就像我们可以对`print`（一个对所有对象都可调用的操作）进行特化，使其对`blm`对象执行特殊操作——但存在某种有意义的方式来完成该操作。通常情况下，类的专业化正好是通过执行一个所有通用类对象都能完成的操作，但以更专业化的方式来完成。

更专用的类可能可以做更多事情，因此它们可能拥有更多有意义的操作。只要我们能像对待更通用类的对象一样对待专用类的所有对象，这就没问题。

这种专业化部分涉及接口，部分涉及实现。



### 特化即接口

接口是一组可以在给定类对象上调用的函数集合，它定义了如何与该类对象进行交互的协议。假设我们设想一个通用的“拟合模型”类别，那么对于所有模型，我们都应能获取其拟合参数，并能对新值进行预测。在 R 语言中，存在 `coef` 和 `predict` 这样的函数，并且所有模型都应实现它们。

这意味着我可以编写代码，通过这些通用模型函数与拟合模型交互。只要我遵循这些函数提供的接口，我就能处理任何类型的模型。如果某个时候我想将线性回归模型替换为决策树回归模型，只需接入一个不同的拟合模型，并通过相同的多态函数与之通信即可。当我调用通用函数 `coef` 和 `predict` 时，实际被调用的具体函数当然会不同，但接口是相同的。

R 语言并不会强制要求你实现这样的接口。与 Java 等语言不同，在 Java 中，如果将某个对象声明为满足特定接口，而实际并未实现必要函数，会引发类型错误。R 语言不关心这些——直到你调用一个不存在的函数，那时当然就会遇到麻烦。但实现与你的类所应匹配的类别或协议相兼容的接口，完全取决于你自己。

如果你实现了某个接口所期望的函数（并且这些函数确实完成了与该接口期望相符的操作，而不仅仅是同名而已^(22)），那么你就拥有了该接口的一个特化版本。你可以像实现该接口的其他任何类一样执行相同操作，但你的操作当然会针对你实际的类进行独特优化。

你也可以实现更多函数，使你的类具备比通用类对象更强的能力，这完全没问题。其他类也可能实现这些操作，这样你就拥有多个具备更特化操作的类——这便形成了一个新的、更通用的类别，并且可以进一步被特化。

由此，你便拥有一个由类构成的层级结构，该结构由这些类所实现的具体函数来定义。



### 实现的特化

提供通用接口，然后将其特化为特定类型的对象——在 R 语言中，即提供多态函数的实现——是面向对象编程中类层次结构概念的核心特征。它允许你将不同类型的对象视为更通用的类。

不过，类层次结构还有另一个与代码重用相关的方面。当然，通过提供用于操作对象的接口，你已经能实现大量重用，因为你可以编写适用于通用接口的代码，然后在所有实现该接口的对象上重用它。但当你构建一个从抽象通用类到更具体、更具体类的层次结构时，还会获得另一种类型的重用。当你特化一个类时，你是在利用更抽象类已有的功能，定义一个实现相同接口的新类，只需在少数地方做出一些改变。

当你以这种方式细化一个类时，你并不想为其接口中的所有多态函数都实现新版本。它们中的许多将与更通用类的实现完全相同。

假设我们想要一个类，其对象可以调用函数 `foo` 和 `bar`。我们可以将这个类称为 `A`，并如下定义它：

```
foo.A <- function(object) paste0("A::foo -> ", object$foo)
bar.A <- function(object) paste0("A::bar -> ", object$bar)
A <- function(foo, bar) {
    object <- list(foo = foo, bar = bar)
    class(object) <- "A"
    object
}
a <- A("qux", "qax")
foo(a)
## [1] "A::foo -> qux"
bar(a)
## [1] "A::bar -> qax"
```

为了对其进行细化，我们可能想要改变 `bar` 的工作方式，并添加另一个函数 `baz`：

```
baz.A <- function(object) paste0("A::baz -> ", object$baz)
bar.B <- function(object) paste0("B::bar -> ", object$bar)
baz.B <- function(object) paste0("B::baz -> ", object$baz)
```

我们希望 `foo` 函数保持原样，但如果我们像之前一样定义类 `B`，对 `B` 对象调用 `foo` 会报错，因为它会调用 `foo.default` 函数：

```
B <- function(foo, bar, baz) {
    object <- list(foo = foo, bar = bar, baz = baz)
    class(object) <- "B"
    object
}
b <- B("qux", "qax", "quux")
foo(b)
## Error in foo.default(b): foo not implemented
```

这是因为我们没有告诉 R，我们认为类 `B` 是类 `A` 的特化。我们编写了构造函数——也就是创建对象的函数 `B`——使得所有 `B` 对象都包含 `A` 对象中也存在的数据。但我们从未告诉 R，我们希望 `B` 对象同时也是 `A` 对象。

当然，我们可以通过定义 `foo.B` 来确保对 `B` 对象调用 `foo` 时，其行为与对 `A` 对象调用时相同，比如让 `foo.B` 调用 `foo.A`。对于一个单独的函数来说，这工作量不算大，但如果有很多多态函数都适用于 `A` 对象，我们就必须为所有这些函数实现对应的 `B` 版本——这是一项繁琐且容易出错的工作。

要是能有一种方法告诉 R，类 `B` 实际上是类 `A` 的扩展就好了。而且，确实有这样的方法。对象的类属性不一定非得是单个字符串，它可以是一个字符串向量。如果对于 `B` 对象，我们将类设置为 `"B"` 在前，`"A"` 在后，就像这样：

```
B <- function(f, b, bb) {
    a <- A(f, b)
    a$baz <- bb
    class(a) <- c("B", "A")
    a
}
```

那么，对 `B` 对象调用 `foo` 时——由于 `foo.B` 未定义——R 会其次尝试调用 `foo.A`，然后才会回退到 `foo.default`：

```
b <- B("qux", "qax", "quux")
foo(b)
## [1] "A::foo -> qux"
bar(b)
## [1] "B::bar -> qax"
baz(b)
## [1] "B::baz -> quux"
```

类属性在多态函数中的使用方式是：R 会按照类属性中类名的顺序，查找带有这些类名后缀的函数。找到的第一个函数会被调用；如果找不到任何特化版本，就会使用 `.default` 版本。当我们把 `B` 对象的类属性设置为向量 `c("B", "A")` 时，我们就是在告诉 R：首先应该尝试调用 `.B` 函数（如果能找到的话），否则就调用 `.A` 函数。

这是一个非常灵活的系统，它允许你从原本不相关的类实现多重继承，但这样做需要你自担风险。其语义是——函数按照向量中类名的顺序进行搜索——如果这些向量变得过于复杂，实际运行的代码可能很难推导出来。

另一个需要快速提醒的注意事项是：如果你给对象赋予一个类列表，你应该将类层次结构中的所有类都包含进去。如果我们定义一个新类 `C`，打算将其作为 `B` 的特化，我们不能仅仅说它是一个类为 `c("C", "B")` 的对象（如果我们还希望它表现得像一个 `A` 对象的话）：

```
C <- function(f, b, bb) {
    b <- B(f, b, bb)
    class(b) <- c("C", "B")
    b
}
c <- C("foo", "bar", "baz")
foo(c)
## Error in foo.default(c): foo not implemented
```

当我们在这里调用 `foo(c)` 时，R 会依次尝试函数：`foo.C`、`foo.B` 和 `foo.default`。其中只有最后一个被定义，而它被调用时会抛出错误。

因此，我们在这里定义的对象，只能在 `B` 的行为与 `A` 不同的情况下，表现得像 `B` 对象！我们的本意是，`B` 是 `A` 的一种特殊类型，所以每个 `B` 对象也都应该能被当作 `A` 对象对待。然而，对于 `C` 对象，这却行不通。

在这里，我们并没有像在 Python、C++ 或 Java 等语言中那样真正的类层次结构。我们只有一个调用多态函数的机制，其语义仅仅是按照类属性向量中找到的类名来查找函数。你的本意很可能是拥有一个类层次结构，其中 `A` 是最通用的类，`B` 是其特化，而 `C` 是最特化的类，但你这并没有告诉 R——因为你无法做到。你只是告诉 R 如何查找动态函数，而通过前面的代码，你告诉它先查找 `.C` 函数，然后查找 `.B` 函数，之后就没有更多信息了，所以下一步它会尝试查找 `.default` 函数，而不是 `.A` 函数。它并不知道你希望它去那里查找。

不过，如果你将 `A` 添加到类属性中，它就能正常工作了：

```
C <- function(f, b, bb) {
    b <- B(f, b, bb)
    class(b) <- c("C", "B", "A")
    b
}
c <- C("foo", "bar", "baz")
foo(c)
## [1] "A::foo -> foo"
bar(c)
## [1] "B::bar -> bar"
baz(c)
## [1] "B::baz -> baz"
```

不过，更好的做法是从构造函数中创建的对象那里获取类属性。如果在某个时候，你更改了 `B()` 构造函数返回对象的类属性，你肯定不希望还需要去修改所有扩展该类的类中的类向量：

```
C <- function(f, b, bb) {
    b <- B(f, b, bb)
    class(b) <- c("C", class(b))
    b
}
```

### 形状

假设我们需要为一个程序处理一些几何形状。这些形状可以是圆形、正方形、三角形等。我们需要知道的形状属性包括周长和面积。这些属性可以根据形状的属性计算出来，但不同形状的计算方式不同。

因此，对于我们的形状，我们至少需要一个提供两个函数的接口：`circumference` 和 `area`。默认函数（即当我们除了知道对象是一个形状之外没有其他额外信息时）是没有意义的，因此应该抛出错误（请查看 `stop` 函数来实现这一点），但每个特化的形状都应该实现这两个函数。

请实现这个协议/接口，并至少为圆形和矩形实现这两个函数——当然，如果你愿意，也可以实现更多的形状。



### 多项式

编写一个用于表示多项式对象的类。一个 *n* 次多项式的形式为 `c[0] + c[1]*x + c[2]*x² + · · · + c[n]*x^n`，可以用 `n + 1` 个系数（`c[0], c[1], ..., c[n]`）来表示。请编写接口，使你能够在任意点 `x` 上计算多项式的值，即通过一个函数 `evaluate_polynomial(poly, x)` 来获取多项式在点 `x` 处的值。

`uniroot` 函数（内置于 R 语言中）可让你求取任意函数的根。利用它编写一个函数来求取你多项式的根。该函数通过数值方法找到多项式为零的点。但对于一次和二次多项式，存在解析解。为这类多项式编写特殊情况，使得在这些特殊情况下调用求根函数时，能够利用已知的解析解。

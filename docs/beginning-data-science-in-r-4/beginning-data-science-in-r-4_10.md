# 9. 深入 R 编程

在本章中，我们将离开数据分析，回到编程和软件开发的主题，这也是本书剩余章节的重点。在第一章中，你通过教程初步了解了 R 编程，但我们省略了很多细节。本章将涵盖其中的许多细节，而接下来的两章将介绍 R 编程的更高级方面：函数式编程和面向对象编程。

## 表达式

我们开始本章，首先回到表达式。我们在 R 中做的每一件事都涉及表达式的求值。我们求值的大多数表达式是为了进行计算并获得结果，但有些表达式具有副作用——比如赋值——而我们通常正是因为这些副作用才对它们进行求值。

### 算术表达式

我们之前已经介绍过算术表达式，因此这里仅作简要回顾。算术表达式是涉及数字的运算符，包含一元运算符 `+` 和 `-`：

```r
+ x
- x
```

其中 `+` 实际上不执行任何操作，而 `-` 则改变其操作数的符号。此外，还有用于加法、减法、乘法和除法的中缀运算符：

```r
x + y
x - y
x * y
x / y
```

即使两个操作数都是整数，除法也会返回一个浮点数，因此如果你想要进行整数除法，需要使用专门的运算符：

```r
x %/% y
```

如果你想要整数除法的余数，则需要改用这个中缀运算符：

```r
x %% y
```

最后，还有用于幂运算的运算符。要计算 `x^y`，你可以使用以下两个运算符中的任意一个：

```r
x ^ y
x ** y
```

在所有这些示例中，`x` 和 `y` 可以是数字或指向数字的变量（实际上是数字向量，因为 R 总是在向量上操作），也可以是其他能计算得出数字的表达式。如果你用中缀运算符组合表达式，就会遵循你所熟悉的算术运算优先级规则。例如，幂运算优先于乘法，乘法优先于加法。这意味着，如果你需要以不同顺序求值，就必须使用括号。

由于这些规则是你所熟悉的，因此不太可能给你带来麻烦，除非你将这些表达式与运算符 `:` 结合使用。`:` 实际上并非算术运算符，而是一个用于生成序列的中缀运算符，其优先级高于乘法，但低于幂运算。这意味着 `1:2**2` 会先计算 `2**2` 表达式得到 `1:4`，然后再构建序列：

```r
1:2**2
## [1] 1 2 3 4
```

而表达式 `1:2*2` 会先计算 `:` 表达式，创建一个包含 `1` 和 `2` 的向量，然后将该向量与 `2` 相乘：

```r
1:2*2
## [1] 2 4
```

由于一元运算符 `-` 的优先级高于 `:`，这也意味着 `-1:2` 将生成从 `-1` 到 `2` 的序列，而不是包含 `-1` 和 `-2` 的序列。要实现后者，你需要使用括号：

```r
-1:2
## [1] -1 0 1 2
-(1:2)
## [1] -1 -2
```

函数会在运算符之前求值：

```r
1:sqrt(4)
## [1] 1 2
```

### 布尔表达式

对于布尔值（即 `TRUE` 或 `FALSE`），也有相应的逻辑运算符。运算符 `!` 用于取反一个值：

```r
!TRUE
## [1] FALSE
!FALSE
## [1] TRUE
```

而 `|` 和 `||` 是逻辑“或”运算符，`&` 和 `&&` 是逻辑“与”运算符。`|` 与 `||` 或 `&` 与 `&&` 的区别在于它们处理向量的方式。单字符版本会按元素应用运算符并创建一个向量，而双字符版本只查看向量中的第一个值：

```r
TRUE | FALSE
## [1] TRUE
FALSE | FALSE
## [1] FALSE
TRUE || FALSE
## [1] TRUE
FALSE || FALSE
## [1] FALSE
x <- c(TRUE, FALSE, TRUE, FALSE)
y <- c(TRUE, TRUE, FALSE, FALSE)
x | y
## [1] TRUE TRUE TRUE FALSE
x || y
## [1] TRUE
x & y
## [1] TRUE FALSE FALSE FALSE
x && y
## [1] TRUE
```

我们通常在诸如 `if` 这样的控制结构中使用双字符版本——因为这类结构无论如何都不会对向量进行操作——而当我们需要进行布尔算术运算，并希望表达式作为向量化表达式工作时，我们会使用单字符版本。

顺便提一下，所有算术运算符在处理多个值时，其工作方式与 `|` 和 `&` 运算符类似，即它们对向量进行按元素操作。我们在关于向量表达式的第 1 章中已经看到了这一点。

## 基本数据类型

R 中有几种基本类型：数值型、整型、复数型、逻辑型和字符型。

### 数值型

每当你在 R 中写入一个数字时，得到的就是数值型。你可以使用函数 `is.numeric()` 或通过获取对象的 `class` 来测试一个对象是否为数值型：

```r
is.numeric(2)
## [1] TRUE
class(2)
## [1] "numeric"
```

### 整型

整型顾名思义用于表示整数。令人惊讶的是，之前的 `2` 在 R 中并不是整型。它是一种数值类型，是一种更大的类型，包含所有浮点数以及整数。要得到一个整数，你必须显式地将值设为整数，可以通过函数 `as.integer()` 或在字面量后加上 `L`⁽¹⁸⁾ 来实现：

```r
is.integer(2)
## [1] FALSE
is.integer(2L)
## [1] TRUE
x <- as.integer(2)
is.integer(x)
## [1] TRUE
class(x)
## [1] "integer"
```

如果你将一个非整数转换为整数，只会得到整数部分：

```r
as.integer(3.2)
## [1] 3
as.integer(9.9)
## [1] 9
```

### 复数型

如果你需要处理复数，R 也提供了支持。你可以通过将一个虚数（一个数字后跟 `i`）加到任意数字上来构造复数，或者显式使用函数 `as.complex()`。虚数可以是零，`0i`，这会创建一个虚部为零的复数：

```r
1 + 0i
## [1] 1+0i
is.complex(1 + 0i)
## [1] TRUE
class(1 + 0i)
## [1] "complex"
sqrt(as.complex(-1))
## [1] 0+1i
```

### 逻辑型

如果你显式输入 `TRUE` 或 `FALSE`，得到的就是逻辑值；但进行诸如比较操作时，得到的也是逻辑值：

```r
x <- 4
x > 4
x
## [1] TRUE
class(x)
## [1] "logical"
is.logical(x)
## [1] TRUE
```

### 字符型

最后，当你输入一个字符串例如 `"hello, world"` 时，得到的是字符型：

```r
x <- "hello, world"
class(x)
## [1] "character"
is.character(x)
## [1] TRUE
```

与某些语言不同，这里的字符型并不仅指单个字符，而是指任意文本。因此它不像 `C` 或 `Java` 那样区分单字符类型 `'c'` 和多字符字符串 `"string"`；在 R 中，它们都是字符型。

与其他类型类似，你可以使用 `as.character()` 将一个值显式转换为字符型（字符串）：

```r
as.character(3.14)
## [1] "3.14"
```

我在此不会深入探讨 R 中的字符串处理。当然，有很多用于操作字符串的函数——尽管有所有这些函数，我仍然觉得在 R 中操作字符串比在 `Python` 等脚本语言中困难得多——但这超出了本书的范围。

## 数据结构

从基本类型出发，你可以通过将更简单的类型连接成更复杂的类型来构造其他数据结构。这里的基本构建块是向量（所有值类型相同的序列）和列表（值可以具有不同类型的序列）。

### 向量

在本书中我们已经多次见到向量，因此大家应该对它们很熟悉了。当我们看到涉及单个数字的表达式时，实际上看到的是包含单个值的向量，所以我们之前从未见过不是向量的东西。但现在我们来探讨向量更多的技术层面。

到目前为止我所说的向量，在技术术语上被称为“原子序列”。它们是由前面描述的基本类型组成的序列。通过使用 `c` 函数连接基本值来创建它们：

```r
v <- c(1, 2, 3)
v
## [1] 1 2 3
```

或者通过其他运算符或函数，例如 `:` 运算符或 `rep` 函数：

```r
1:3
## [1] 1 2 3
rep("foo", 3)
## [1] "foo" "foo" "foo"
```

我们可以使用 `is.atomic` 函数来测试某个对象是否属于这类向量：

```r
v <- 1:3
is.atomic(v)
## [1] TRUE
```

我之所以提到“原子序列”是我们迄今称为向量的东西在技术上的正确术语，是因为在 R 语言中还有一种东西被明确地称为向量。在实践中这并不会造成混淆，因为我称为向量的所有原子序列也都是向量。

```r
v <- 1:3
is.vector(v)
## [1] TRUE
```

只是 R 语言只有在这种序列没有任何属性（除了允许拥有的 `names` 属性外）时，才将其视为向量——即 `is.vector` 返回 `TRUE` 的情况。

属性是与对象关联的元信息，我们在这里不会过多涉及，但你只需要知道如果一个完全正常的向量获得了某个属性，那么 `is.vector` 将返回 `FALSE`：

```r
v <- 1:3
is.vector(v)
## [1] TRUE
attr(v, "foo") <- "bar"
v
## [1] 1 2 3
## attr(,"foo")
## [1] "bar"
is.vector(v)
## [1] FALSE
```

因此，如果你想测试某个对象是否是我这里所说的那种向量，请改用 `is.atomic`。

当你连接（原子）向量时，你总是会得到另一个向量。因此，当你像这样组合多个 `c()` 调用时，不会得到任何树状结构：

```r
c(1, 2, c(3, 4), c(5, 6, 7))
## [1] 1 2 3 4 5 6 7
```

类型可能会改变；如果你尝试连接不同类型的向量，R 语言会尝试将类型转换为这些向量中最通用的类型：

```r
c(1, 2, 3, "foo")
## [1] "1" "2" "3" "foo"
```

### 矩阵

如果你想要一个矩阵而非向量，其实你真正想要的是一个二维向量。你可以使用 `dim` 函数设置向量的维度——它会设置我们之前讨论过的属性之一——在其中指定你想要矩阵的行数和列数：

```r
v <- 1:6
attributes(v)
## NULL
dim(v) <- c(2, 3)
attributes(v)
## $dim
## [1] 2 3
dim(v)
## [1] 2 3
v
##      [,1] [,2] [,3]
## [1,]    1    3    5
## [2,]    2    4    6
```

当你这样做时，向量中的值会按列填充到矩阵中，也就是说，向量中的值会先向下填充第一列，然后继续填充下一列，依此类推。

你可以使用便捷函数 `matrix` 来创建矩阵，并且可以通过 `byrow` 参数指定是按列还是按行填充值：

```r
v <- 1:6
matrix(data = v, nrow = 2, ncol = 3, byrow = FALSE)
##      [,1] [,2] [,3]
## [1,]    1    3    5
## [2,]    2    4    6
matrix(data = v, nrow = 2, ncol = 3, byrow = TRUE)
##      [,1] [,2] [,3]
## [1,]    1    2    3
## [2,]    4    5    6
```

一旦你有了矩阵，R 语言中有大量支持线性代数的功能，但有几件事你需要了解。首先，`*` 运算符不会执行矩阵乘法。如果你想要进行逐元素乘法，请使用 `*`；对于矩阵乘法，你需要使用运算符 `%*%`：

```r
(A <- matrix(1:4, nrow = 2))
##      [,1] [,2]
## [1,]    1    3
## [2,]    2    4
(B <- matrix(5:8, nrow = 2))
##      [,1] [,2]
## [1,]    5    7
## [2,]    6    8
A * B
##      [,1] [,2]
## [1,]    5   21
## [2,]   12   32
A %*% B
##      [,1] [,2]
## [1,]   23   31
## [2,]   34   46
```

如果你想转置矩阵，请使用函数 `t`；如果你想求逆矩阵，请使用函数 `solve`：

```r
t(A)
##      [,1] [,2]
## [1,]    1    2
## [2,]    3    4
solve(A)
##      [,1] [,2]
## [1,]   -2  1.5
## [2,]    1 -0.5
solve(A) %*% A
##      [,1] [,2]
## [1,]    1    0
## [2,]    0    1
```

`solve` 函数实际上是为了求解一组线性方程而设计的，如果它也接收一个向量参数，它就能做到这一点，但你可以查阅该函数的文档来了解具体操作。

你也可以通过将维度属性设置为多于两个维度的参数来获得更高维度的向量，称为数组，或者你可以使用 `array` 函数。

### 列表

列表和向量一样，都是序列，但与向量不同的是，列表的元素可以是任何类型的对象，而且它们不必是相同类型的对象。这意味着你可以利用列表构建更复杂的数据结构。

例如，我们可以创建一个包含两个向量的列表：

```r
list(1:3, 5:8)
## [[1]]
## [1] 1 2 3
##
## [[2]]
## [1] 5 6 7 8
```

请注意，这些向量并不会像我们用 `c()` 组合它们时那样被连接起来。前面命令的结果是一个包含两个元素的列表，恰巧这两个元素都是向量。

它们的类型也不必相同；我们可以像这样创建一个列表，它也包含两个向量，但类型不同：

```r
list(1:3, c(TRUE, FALSE))
## [[1]]
## [1] 1 2 3
##
## [[2]]
## [1] TRUE FALSE
```

由于列表可以包含其他列表，你可以很自然地构建树状数据结构：

```r
list(list(), list(list(), list()))
## [[1]]
## list()
##
## [[2]]
## [[2]][[1]]
## list()
##
## [[2]][[2]]
## list()
```

你可以使用函数 `unlist()` 将列表展平为向量。当然，这会强制将列表中的元素转换为相同类型，因为这是向量的要求：

```r
l <- list(1:4, 5:7)
l
## [[1]]
## [1] 1 2 3 4
##
## [[2]]
## [1] 5 6 7
unlist(l)
## [1] 1 2 3 4 5 6 7
```

# 索引

我们在第一章中已经了解了基本索引，但 R 中的索引远不止于此。在 R 提示符下输入 `?[[`”` 并做好准备，你会感到惊讶。

我们已经了解了基本的索引。如果你想获取向量 `v` 的第 `n` 个元素，你可以使用 `v[n]`：

```r
v <- c("foo", "bar", "baz", "qux", "qax")
v[2]
## [1] "bar"
```

但这你已经知道了。你也知道，你可以使用索引范围从向量中获取一个子序列：

```r
v[2:3]
## [1] "bar" "baz"
```

这实际上只是使用索引向量的一个特例：

```r
v[c(1,1,4,3,2)]
## [1] "foo" "foo" "qux" "baz" "bar"
```

在这里，我们用正数进行索引，因为向量中的元素具有正索引，这是合理的。但在 R 中，也可以使用负数进行索引。如果你这样做，它被解释为指定你想要的那些值的补集。因此，如果你想要除第一个元素之外的所有元素，你可以使用

```r
v[-1]
## [1] "bar" "baz" "qux" "qax"
```

你也可以使用多个负索引来移除某些值：

```r
v[-(1:2)]
## [1] "baz" "qux" "qax"
```

你不能将正索引和负索引组合使用。我甚至不知道这有什么意义，但无论如何，你就是不能。

另一种索引方式是使用布尔向量。这个向量的长度应该与你索引的向量相同，它将选出布尔向量为 `TRUE` 的那些元素：

```r
w <- 1:length(v)
w
## [1] 1 2 3 4 5
w %% 2 == 0
## [1] FALSE TRUE FALSE TRUE FALSE
v[w %% 2 == 0]
## [1] "bar" "qux"
```

如果你想对一个向量进行赋值，你只需对你索引到的元素进行赋值；只要赋值运算符右侧的向量与索引取出的元素长度相同，你就可以赋值给该向量：

```r
v[w %% 2 == 0] <- "flob"
v
## [1] "foo" "flob" "baz" "flob" "qax"
```

如果向量有多个维度——请记住，矩阵和数组实际上只是具有更多维度的向量——那么你可以通过对每个维度进行子集操作来选取子集。如果你省略一个维度，你将获得该维度中的一整段值，这是获取矩阵的行和列的一种简单方法：

```r
m <- matrix(1:6, nrow = 2, byrow = TRUE)
m
##      [,1] [,2] [,3]
## [1,]    1    2    3
## [2,]    4    5    6
m[1,]
## [1] 1 2 3
m[,1]
## [1] 1 4
```

你也可以通过在一个或多个维度中提供范围，来索引出子矩阵：

```r
m[1:2,1:2]
##      [,1] [,2]
## [1,]    1    2
## [2,]    4    5
```

当你取出一个一维子矩阵时——就像我们之前用 `m[1,]` 所做的那样——结果是一个向量，而不是一个矩阵。有时，这正是你想要的；有时，你并不关心得到的是矩阵还是向量，但有时你想进行线性代数运算，那么你肯定希望你取出的子矩阵是一个矩阵。你可以通过给索引提供一个选项 `drop=FALSE` 来告诉 R 它不应该将一维矩阵缩减为一个向量：

```r
m[1,,drop=FALSE]
##      [,1] [,2] [,3]
## [1,]    1    2    3
m[,1,drop=FALSE]
##      [,1]
## [1,]    1
## [2,]    4
```

如果这让你觉得奇怪（给索引提供一个选项），那么你需要知道的是，R 中的一切都会涉及函数调用。对矩阵进行索引只是另一个函数调用，而函数可以接受具名参数。这里所发生的一切就是这样。

当你使用 `[]` 选取列表的子集时，结果总是另一个列表。如果这让你感到惊讶，只需记住，当你选取向量的子集时，你得到的也总是一个向量。你只是没有过多地考虑这个问题，因为我们看待单个值的方式总是一些长度为 1 的向量，所以我们对此更为习惯。

无论如何，你使用 `[]` 选取列表的子集时，总是会得到一个列表。即使你在选取单个元素，你得到的也不是那个元素本身；你得到的是一个包含该元素的列表：

```r
L <- list(1,2,3)
L[1]
## [[1]]
## [1] 1
L[2:3]
## [[1]]
## [1] 2
##
## [[2]]
## [1] 3
```

如果你想访问里面的实际元素，你需要使用 `[[]]` 运算符：

```r
L <- list(1,2,3)
L[[1]]
## [1] 1
```

### 具名值

向量或列表中的元素可以有名称。这些名称是不影响元素值的属性，但可以用来引用它们。

你可以在创建向量或列表时设置这些名称：

```r
v <- c(a = 1, b = 2, c = 3, d = 4)
v
## a b c d
## 1 2 3 4
L <- list(a = 1:5, b = c(TRUE, FALSE))
L
## $a
## [1] 1 2 3 4 5
##
## $b
## [1] TRUE FALSE
```

或者你可以使用 `names<-` 函数来设置名称。顺便说一下，这个奇怪的名字意味着你正在处理 `names()` 函数与赋值的组合。我们稍后会看到它是如何工作的。

```r
names(v) <- LETTERS[1:4]
v
## A B C D
## 1 2 3 4
```

你可以使用名称来索引向量和列表（其中，和 `[[]]` `[]` 的作用与之前一样，分别返回一个列表或列表中的元素）：

```r
v["A"]
## A
## 1
L["a"]
## $a
## [1] 1 2 3 4 5
L[["a"]]
## [1] 1 2 3 4 5
```

当你拥有具名值时，你还可以使用第三种索引运算符，即 `$` 运算符。它的工作方式基本上类似于 `[[]]`，只是你不需要将名称放在引号中：

```r
L$a
## [1] 1 2 3 4 5
```

从来没有什么好的时机来介绍向量的 `[[]]` 运算符，但这里还是要提一下：如果你对一个向量使用 `[[]]` 运算符，它只允许你提取单个元素，并且如果向量有名称，它会移除该名称。

### 因子

我们在第一章中看到的因子类型，在技术上也是一种向量类型，但它与之前的类型不同，不是一种原始类型。它被存储为一个整数向量——即因子中的水平——并且具有相关的属性，例如水平。它是使用我们将在两章后讨论的类系统实现的，这里不再进一步讨论。

### 公式

另一种数据类型是公式。我们在第 6 章中看到过这些，我们可以使用 `~` 运算符来创建它们。像因子一样，结果是一个使用类定义的对象。我们将在本书的最后一章中看到如何通过模型矩阵使用公式来实现我们自己的统计模型。

## 控制结构

控制结构决定了程序的执行流程。仅仅通过一个接一个的语句或表达式，你也能走得很远，但最终你将需要根据计算结果来执行一件事而不是另一件事，这就是控制结构发挥作用的地方。

像许多其他编程语言一样，R 中有两种控制结构：选择（`if` 语句）和循环（`for`、`while` 或 `repeat` 语句）。

### 选择语句

`If` 语句看起来像这样：

```r
if (boolean) {
# 执行某些操作
}
```

或者像这样：

```r
if (boolean) {
# 执行一个操作
} else {
# 执行另一个操作
}
```

你可以将它们串联起来，像这样：

```r
if (x < 0) {
# 处理负数 x
} else if (x > 0) {
# 处理正数 x
} else {
# 处理 x 为零的情况
}
```

在所有这些示例中，我将条件为真或假时要执行的语句放在了花括号中。严格来说，如果我们只讨论单个语句，这不是必需的。下面这样是可以的：

```r
if (x > 0) "positive" else if (x < 0) "negative" else "zero"
```

但是，如果你在语句之间插入换行符，它就会失败；R 解析器会对此感到困惑，这时你就需要花括号了。下面这样会是一个语法错误：

```r
if (x > 0)
print("positive")
else if (x < 0)
print("negative")
else
print("zero")
```

而下面这样是可以的：

```r
if (x > 0) {
print("positive")
} else if (x < 0) {
print("negative")
} else {
print("zero")
}
```

我建议在你对 R 更熟悉之前，始终使用花括号，因为即使你只有一个语句，花括号也能正常工作，在这种情况下你并没有做错什么，而且当你有多于一个语句或者在 `if` 语句中有换行符时，花括号是唯一可行的方式。

### 循环

最常用的循环结构可能是 `for` 循环。使用 `for` 循环遍历序列中的元素，其构造如下：

```r
for (i in 1:4) {
print(i)
}
## [1] 1
## [1] 2
## [1] 3
## [1] 4
```

但请记住，你遍历的是序列中的元素，因此赋给迭代变量的值是序列中的元素，而不是索引：

```r
for (i in c("foo", "bar", "baz")) {
print(i) # i 的值是"foo"、"bar"、"baz"，而不是索引 1、2、3
}
## [1] "foo"
## [1] "bar"
## [1] "baz"
```

如果你想遍历序列的索引，可以使用 `seq_along` 函数：

```r
x <- c("foo", "bar", "baz")
for (i in seq_along(x)) {
print(i)
print(x[i])
}
## [1] 1
## [1] "foo"
## [1] 2
## [1] "bar"
## [1] 3
## [1] "baz"
```

你有时会看到类似这样的代码：

```r
for (i in 1:length(x)) {
# 执行操作
}
```

不要这样做。如果序列 `x` 为空，它就会失效：

```r
x <- c()
1:length(x)
## [1] 1 0
```

如果你想跳到循环的下一次迭代，可以使用 `next` 关键字。例如，以下代码只打印 `x` 中每隔一个的元素：

```r
for (i in seq_along(x)) {
if (i %% 2 == 0) {
next
}
print(x[i])
}
```

如果你想完全终止循环，可以使用 `break`：

```r
for (i in 1:100) {
if (i %% 2 == 0) {
next
}
if (i > 5) {
break
}
print(i)
}
## [1] 1
## [1] 3
## [1] 5
```

另外两种不太常用的循环结构是 `while` 和 `repeat` 循环。

`while` 循环在布尔表达式为真时持续迭代，写法如下：

```r
i <- 1
while (i < 5) {
print(i)
i <- i + 1
}
## [1] 1
## [1] 2
## [1] 3
## [1] 4
```

`repeat` 循环会一直运行，直到你用 `break` 跳出循环：

```r
i <- 1
repeat {
print(i)
i <- i + 1
if (i > 5) break
}
## [1] 1
## [1] 2
## [1] 3
## [1] 4
## [1] 5
```

### 关于循环的一个警告…

如果你继续阅读关于 R 的资料，很快就会看到“循环在 R 中很慢”的说法。实际情况并没有一些人说得那么糟，但这种说法有一定道理。因为 R 是一种极其动态的语言——在程序执行过程中，函数和变量随时可以更改（如果你希望的话）——解释器很难在运行前优化代码，这点与其他一些语言不同（但与 Python 等其他动态语言差别不大）。不过，针对循环的优化尝试也不多，因为在 R 中通常有比使用显式循环语句更好的解决方案。

R 是一种所谓的函数式语言（兼有其他特性），在函数式语言中，通常不使用循环。循环的工作方式需要在执行代码时改变循环变量或布尔表达式的值，而改变变量在函数式语言中被视为“不纯”的行为（显然，R 允许这样做，所以它并非纯粹的函数式语言）。相反，递归函数被用于实现循环。大多数函数式语言甚至没有循环结构——纯粹的函数式语言当然没有。R 在这方面更为务实，但使用替代方案通常比使用循环更好。

我们将在下一章进一步讨论这一点。

## 函数

定义函数的方式如下：

```r
name <- function(arguments) expression
```

其中 `name` 可以是任何变量名，`arguments` 是函数的形参列表，`expression` 是调用函数时的执行内容。之所以用 `expression`，是因为你可以将函数体视为一个表达式，但通常它是由花括号括起来的一系列语句：

```r
name <- function(arguments) { statements }
```

只是这样一系列语句本身也是一个表达式；执行一系列语句的结果就是最后一条语句的值。

以下函数会打印一条语句并返回 5，因为函数体中的语句首先是 `print` 语句，然后才是值 5，该值将成为函数的返回值：

```r
f <- function() {
print("hello, world")

}
f()
## [1] "hello, world"
## [1] 5
```

我们通常不会编写无参数的函数——就像我前面做的那样——而是会有一个或多个形参。最简单的形式下，参数就是变量名。调用函数时，这些参数被赋值，然后在函数体内使用：

```r
plus <- function(x, y) {
print(paste(x, "+", y, "is", x + y))
x + y
}
div <- function(x, y) {
print(paste(x, "/", y, "is", x / y))
x / y
}
plus(2, 2)
## [1] "2 + 2 is 4"
## [1] 4
div(6, 2)
## [1] "6 / 2 is 3"
## [1] 3
```

### 命名参数

调用函数时，参数的顺序很重要，因为它决定了哪个参数被赋予哪个值：

```r
div(6, 2)
## [1] "6 / 2 is 3"
## [1] 3
div(2, 6)
## [1] "2 / 6 is 0.333333333333333"
## [1] 0.3333333
```

但是，如果一个函数有很多参数，要记住它们出现的顺序可能比较困难，因此还有一种替代方法可以指定哪个变量被赋予哪个值：命名参数。这意味着调用函数时，你可以明确指定每个参数对应哪个形参：

```r
div(x = 6, y = 2)
## [1] "6 / 2 is 3"
## [1] 3
div(y = 2, x = 6)
## [1] "6 / 2 is 3"
## [1] 3
```

这样就明确了哪个形参被赋给哪个值，你可以把它看作赋值运算符。但你不应该这样想，因为虽然可以使用 `=` 作为赋值运算符，但你不能使用 `<-` 来指定命名变量。看起来好像可以，但它并不能实现你想要的效果（除非你想要一些非常奇怪的结果）：

```r
div(x <- 6, y <- 2)
## [1] "6 / 2 is 3"
## [1] 3
div(y <- 2, x <- 6)
## [1] "2 / 6 is 0.333333333333333"
## [1] 0.3333333
```

赋值运算符 `<-` 会返回一个值，这个值作为位置参数传递给函数。因此，在上面的第二个函数调用中，你在函数外部将 `2` 赋给了 `y`，将 `6` 赋给了 `x`，但传递给函数的值是按位置传递的，所以在函数内部，`x` 得到的是 `2`，`y` 得到的是 `6`。

不要混淆这两个赋值运算符：代码很可能能运行，但不太可能达到你想要的效果！

### 默认参数

定义函数时，你可以为参数提供默认值，如下所示：

```r
pow <- function(x, y = 2) x^y
pow(2)
## [1] 4
pow(3)
## [1] 9
pow(2, 3)
## [1] 8
pow(3, 3)
## [1] 27
```

当你在函数调用中未提供该参数时，就会使用默认参数值。

### 返回值

函数的返回值是函数体执行过程中最后一条表达式的值。如果函数是一系列语句，那就是序列中的最后一条语句，但通过使用控制结构，你可以让不同的语句成为最后一条语句：

```r
safer_div <- function(x, y) {
if (y == 0) {
NA
} else {
x / y
}
}
safer_div(4, 2)
## [1] 2
safer_div(4, 0)
## [1] NA
```

也可以使用 `return()` 语句从函数中显式返回——类似于从循环中跳出：

```r
safer_div <- function(x, y) {
if (y == 0) {
return(NA)
}
x / y
}
safer_div(4, 2)
## [1] 2
safer_div(4, 0)
## [1] NA
```

请注意，`return()` 语句将返回值放在括号中。许多编程语言允许你写成

```r
safer_div <- function(x, y) {
if (y == 0) {
return NA
}
x / y
}
```

但这在 R 中会是一个错误。

# R 语言高级特性

## 惰性求值

我在前文多处提到，当我们调用函数时，需要向函数参数提供值。在许多编程语言中，函数调用的工作方式正是如此——为每个参数提供的表达式会被求值，然后将结果赋值给函数参数，以便函数体能够使用它们——但在 R 语言中，实际被赋值给函数参数的是**表达式本身**。这些表达式直到真正需要时才会被求值，这种机制被称为**惰性求值**。

这种处理函数参数的方式既有其优势，也会带来一些奇特的结果。

首先，它使得默认参数的设置更加灵活。我们可以编写像下面这样的函数：

```r
f <- function(x, y = x²) y + x
```

其中 `y` 的默认值依赖于另一个参数 `x`。在函数声明时，`x` 的值是未知的，但由于 `y` 并非在此处求值，因此这不会造成问题。每当我们调用该函数时，`x` 在函数体内部是已知的，而正是在这里我们才需要 `y` 的值，所以表达式也就在此处进行求值：

```r
f(2)
## [1] 6
```

正因为 `y` 在**被使用前**不会求值，这也意味着：如果你在使用 `y` 之前给 `x` 赋了一个新值，那么 `y` 求值的结果将依赖于 `x` 的**新值**，而不是调用函数时 `x` 的初始值！

```r
g <- function(x, y = x²) { x <- 0; y + x }
g(2)
## [1] 0
```

另一方面，如果 `y` 在我们给 `x` 赋值之前就被求值了，那么它将基于求值时的 `x` 值来计算结果，并且这个结果会保持不变。`y` 在第一次被需要时进行求值，之后的任何引用都会记住这个求值结果：

```r
h <- function(x, y = x²) { y; x <- 0; y + x }
h(2)
## [1] 4
```

因此，惰性求值允许你指定依赖于其他参数的默认参数，即使在这些参数尚属未知的上下文中。但代价是，参数的值将取决于它被首次求值时的上下文。

如果只是为了能够以这种方式指定变量，我们当然可以找到一种不涉及这种怪异特性的解决方案。毕竟，大多数编程语言都是这么做的。但惰性求值还有另一个好处：**你只在真正需要的时候才对表达式进行求值**。

## 作用域

R 语言的作用域是**词法作用域**。这意味着，如果一个变量在函数中被使用，但既没有在函数内部定义，也不是函数参数的一部分，那么 R 会从该函数被**创建的位置**开始，向外层代码进行搜索。这实质上意味着从代码中定义函数的那一点开始，向上、向外搜索，因为函数是在执行到定义它的代码时被创建的。

考虑以下代码：

```r
x <- "x"
f <- function(y) {
  g <- function() c(x, y)
  g()
}
f("y")
## [1] "x" "y"
```

这里，我们有一个全局变量 `x` 和一个接受参数 `y` 的函数 `f`。在 `f` 内部，我们定义了函数 `g`，它既没有定义变量 `x` 和 `y`，也没有将它们列为形式参数，但确实返回了它们。我们在 `f` 的最后一句话中求值 `g`，因此最后一行调用 `f` 的结果就是 `g` 的返回值。

在 `g` 内部，我们没有定义 `x` 或 `y`，因此为了找到它们的值，R 会从 `g` 被创建的位置向外搜索。它会找到作为函数 `f` 参数的 `y` 并从中获取其值，然后继续向外搜索，在全局层面找到 `x`。

`g` 所引用的变量是变量本身，而不是 `g` 创建时的值。因此，如果在创建 `g` 之后更新了变量，`g` 的返回值也会随之改变：

```r
x <- "x"
f <- function(y) {
  g <- function() c(x, y)
  y <- "z"
  g()
}
f("y")
## [1] "x" "z"
```

这不仅仅是惰性求值的疯狂之处——并不是因为 `g` 还没有对 `y` 求值，所以 `y` 可以被改变。实际上，`g` 是在需要用到 `y` 的时候才去查找它的值：

```r
x <- "x"
f <- function(y) {
  g <- function() c(x, y)
  g()
  y <- "z"
  g()
}
f("y")
## [1] "x" "z"
```

如果我们将函数 `g` 本身从 `f` 返回，而不是返回对它求值的结果，我们就能看到 R 作用域的另一个特性——称为**闭包**。R 会记住已经返回的、并且不再处于活跃计算过程中的函数内部的变量值。在下面的例子中，我们返回了函数 `g`，此时 `f` 函数已经不再活跃，因此也就不再存在一个活跃的 `y` 参数实例。然而 `g` 仍然引用着一个 `y`，所以传递给 `f` 的参数实际上被记住了：

```r
x <- "x"
f <- function(y) {
  g <- function() c(x, y)
  g
}
g <- f("y")
g()
## [1] "x" "y"
```

如果我们用不同的 `y` 参数值两次调用 `f`，就能看到这个机制是如何工作的：

```r
x <- "x"
f <- function(y) {
  g <- function() c(x, y)
  g
}
g <- f("y")
h <- f("z")
g()
## [1] "x" "y"
h()
## [1] "x" "z"
```

这创建了两个不同的函数。在 `f` 内部，它们都被命名为 `g`，但它们是两个不同的函数，因为它们是在对 `f` 的两次不同调用中创建的，并且它们分别记住了不同的 `y` 参数，因为 `f` 的两个实例被调用时，`y` 的值不同。

当从函数定义处向外查找时，它查找的是函数**被调用时**变量的值，而不是函数**创建时**变量的值。变量不一定需要在函数创建时就定义；它们只需要在函数最终被调用时被定义即可。

考虑下面这段代码：

```r
f <- function() {
  g <- function() c(y, z)
  y <- "y"
  g
}
h <- f()
h()
## Error in h(): object 'z' not found
z <- "z"
h()
## [1] "y" "z"
```

`g` 定义在函数 `f` 内部——在那里它引用了尚未定义的变量 `y` 和 `z`。这没关系，因为我们只是创建了函数 `g`，并没有调用它。之后我们在调用 `f` 的上下文内部设置了变量 `y`，然后返回了 `g`。在函数调用之外，我们将 `f()` 的返回值命名为 `h`。如果此时调用 `h`，它会记住 `y` 是在 `f` 内部定义的——并且记住从 `f` 返回时 `y` 的值。但此时 `z` 仍然没有被赋值，因此调用 `h` 会导致错误。由于内部函数引用 `z` 的封闭作用域中并未定义它，它必须在最外层的全局作用域中定义，但事实并非如此。如果我们在那里设置了 `z`，错误就会消失，因为现在 R 可以从函数创建的位置向外搜索找到该变量。

我本不该告诉你这个，因为我即将介绍的特性很危险。我将向你展示一种让函数产生比平常更多副作用的方法，而函数实际上根本不应该有副作用。无论如何，这是该语言的一个特性，如果你非常谨慎地使用它，当你确实觉得需要让函数产生副作用时，它会非常有用。

问题如下：如果你想在函数外部的某个作用域中给变量赋值，该怎么办？你不能直接给变量赋值，因为如果你给当前作用域中未找到的变量赋值，那么你会在当前作用域中创建该变量：

```r
f <- function() {
  x <- NULL
  set <- function(val) { x <- val }
  get <- function() x
  list(set = set, get = get)
}
x <- f()
x$get() # 获取 x——我们尚未设置它，所以为 NULL
## NULL
x$set(5) # 将 x 设置为 5
x$get()  # 现在获取新值——但还不行
## NULL
```

在这段代码中——我强烈建议你仔细阅读，因为其中包含一些巧妙的想法——我们创建了一个 getter 和 setter 函数。getter 告诉我们变量 `x` 的值，而 setter 应该更新它。然而，这目前还不太奏效。当在 `set` 函数体内设置 `x` 时，我们会在该函数内部创建一个局部变量——它并没有给上一层的 `x` 赋值。

有一个单独的赋值运算符 `<<-`，你可以用它来实现这一点。它不会创建新的局部变量，而是向外搜索以找到一个现有变量并进行赋值。不过，如果它一直搜索到最外层的全局作用域，并且该变量不存在，它会在那里创建该变量。

如果我们在前面的示例中使用这个赋值运算符，就能得到我们想要的行为：

```r
f <- function() {
  x <- NULL
  set <- function(val) { x <<- val }
  get <- function() x
  list(set = set, get = get)
}
x <- f()
x$get() # 获取 x，此时仍为 NULL
## NULL
x$set(5) # 设置 x，这次成功了
x$get()  # 正如你在这里看到的
## [1] 5
```

如果你想知道，在这个示例中，如果我们没有在 `f` 函数体内设置变量 `x`，那么 getter 和 setter 都会引用一个全局变量。第一次调用 `get` 时，如果没有全局变量，会导致错误。虽然这个示例向你展示了必须创建一个对象，其中函数具有副作用，但这比使用全局变量要好得多，因为它让函数修改隐藏在闭包中的变量。

### 函数名与变量名不同

关于作用域的最后一个说明——我不确定这应该被视为特性还是漏洞——如果 R 看到看起来像函数调用的东西，它会去搜索函数，即使从函数创建的位置向外搜索会先遇到非函数对象：

```r
n <- function(x) x
f <- function(n) n(n)
f(5)
## [1] 5
```

根据声明应该向外搜索的作用域规则，`f` 函数内部的 `n` 应该引用 `f` 的参数。但很明显，第一个 `n` 是一个函数调用，第二个是它的参数，所以当我们调用 `f` 时，它发现参数不是函数，于是会进一步向外搜索并找到函数 `n`。它用其参数调用该函数。因此，`f` 内部的两个 `n` 实际上引用了不同的东西。

当然，如果我们用实际上是一个函数的东西来调用 `f`，那么它会识别出 `n` 是一个函数，并用自身作为参数调用该函数：

```r
f(function(x) 15)
## [1] 15
```

很有趣，对吧？

## 递归函数

本章要介绍的最后一个主题是递归函数。有些人觉得这个话题很难，但在函数式编程语言中，它是最基本的构建模块之一。因此，即使你在 R 语言中需要用到递归的概率远低于在大多数纯函数式语言中，也值得花些心思去理解它。

不过，从最基础的层面来说，递归就是我们可以通过调用自身函数来定义函数的计算过程——我们允许一个函数用新的参数来调用它自己。

以阶乘运算符 *n*! = *n ×* (*n −* 1) *× · · · ×* 3 *×* 2 *×* 1 为例。我们可以将 *n* 的阶乘表示为 *n* 与另一个更小的阶乘（即 *n −* 1 的阶乘）的乘积，得到 *n*! = *n ×* (*n −* 1)!。这是一个经典的递归适用场景：我们通过较小值的计算结果来定义某个 *n* 的值。写成函数的形式，即 `factorial(n)` 等于 `n * factorial(n-1)`。

然而，递归函数包含两个方面。解决大小为 *n* 的问题需要将其分解为两个部分：一部分是当前可以直接处理的操作，另一部分是调用解决更小规模（此处为 *n −* 1）问题的函数。这部分我们称之为递归的“步骤”。我们不能无休止地将问题分解成越来越小的部分——那将导致无限递归，其危害与无限循环一样，让我们永远无法得到结果——在某个时刻，我们需要将问题缩小到足够小的规模，从而能够直接处理它。这被称为递归的“基础”。

对于阶乘来说，1 是一个自然的基础，因为 1! = 1。因此，我们可以像这样编写阶乘函数的递归实现：

```r
factorial <- function(n) {
  if (n == 1) {
    1
  } else {
    n * factorial(n - 1)
  }
}
```

这实际上是一种通用的算法策略，称为“分治法”。其核心思想是将问题分解为可以递归处理的子问题，然后以某种方式组合这些子问题的结果。

考虑对一个数字序列进行排序。我们可以使用这种策略来排序一个序列：首先，我们有一个简单的基础——排序空序列或只有一个元素的序列很容易，因为我们不需要做任何操作。对于步骤，我们可以将序列分成两个大小相等的部分，并对它们递归地进行排序。现在我们有了两个已排序的序列，如果将这两个序列合并，我们就将它们组合成了一个有序的序列。

让我们开始吧。

我们需要能够合并两个序列，因此我们先来解决这个问题。这应该可以用递归函数来实现，因为如果任一序列为空，我们就遇到了一个基本情况，可以直接返回另一个序列。如果两个序列中都存在元素，我们可以选择第一个元素较小的那个序列，将该元素提取出来作为最终结果中的第一个元素，然后将其与剩余数字合并的结果拼接起来：

```r
merge <- function(x, y) {
  if (length(x) == 0) return(y)
  if (length(y) == 0) return(x)
  if (x[1] < y[1]) {
    c(x[1], merge(x[-1], y))
  } else {
    c(y[1], merge(x, y[-1]))
  }
}
```

这里需要快速说明一下：通常情况下，这个算法应该在线性时间内运行。但由于我们的递归调用方式，每次移除第一个元素时实际上都在复制向量，导致其成为二次时间复杂度的算法。实现一个线性时间复杂度的合并函数留作练习。

使用这个函数，我们可以实现一个排序函数。这个算法被称为归并排序，因此我们这样命名函数：

```r
merge_sort <- function(x) {
  if (length(x) < 2) return(x)
  n <- length(x)
  m <- n %/% 2
  merge(merge_sort(x[1:m]), merge_sort(x[(m+1):n]))
}
```

如此，通过两个简单的递归函数，我们用几行代码解决了一个实际的算法问题。这通常是像 R 这样的函数式编程语言中常用的方式。当然，如果使用循环更简单，你也不必执着于纯函数式递归。在任何情况下，使用最简单的方法，除非你觉得速度太慢。只有到那时，你才需要开始变通。

### 线性时间合并

我们之前使用的 `merge` 函数在其递归调用中复制了向量。这使得它的速度慢于应有的水平。请实现一个线性时间复杂度的 `merge` 函数。

不过在开始之前，你需要注意一点。如果你打算通过编写类似这样的代码来向向量追加元素：

```r
v <- c(v, element)
```

那么你最终又会得到一个二次时间复杂度的算法。这是因为当你这样做时，实际上是在创建一个新的向量：首先将旧向量 `v` 中的所有元素复制到新向量的前几个位置，然后在末尾添加 `element`。如果你重复此操作 *n* 次，那么每次操作平均花费的时间复杂度就是 *n*²。正是由于人们在循环中执行类似操作（而非 R 解释器本身的问题），导致了 R 语言“循环很慢”的名声。除非万不得已，否则永远不要向向量追加元素。

就 `merge` 函数而言，我们事先已经知道结果的长度，因此可以预先分配一个结果向量，并将单个元素复制进去。你可以像这样创建一个长度为 *n* 的向量：

```r
n <- 5
v <- vector(length = n)
```

如果将来有需要，你可以像这样创建一个长度为 *n* 的列表：

```r
vector("list", length = n)
```

### 二分查找

二分查找是一种经典的算法，用于判断一个元素是否存在于有序序列中。它是一个简单的递归函数。基本情况处理只有一个元素的序列。此时，你可以直接将待查找元素与序列中的元素进行比较，以判断它们是否相同。如果序列中有多个元素，则选取中间元素。若该元素正是你要查找的，则查找结束，返回该元素包含在序列中的结果。若该元素小于待查找元素，则可知如果目标元素在列表中，它必定位于序列的后半部分，于是你可以在那半部分继续查找。若该元素大于待查找元素，则可知如果目标元素在序列中，它必定位于序列的前半部分，于是你递归地在此前半部分进行查找。

如果你完全按照上述描述实现，就需要递归调用子序列。这涉及为函数调用复制子序列，从而使实现的效率远低于应有的水平。请尝试实现无需复制序列的二分查找。

### 更多排序算法

在我们之前实现的归并排序中，我们通过将序列一分为二、对每个子序列排序、再合并它们来解决排序问题。若实现正确，此算法的时间复杂度为`O(n log n)`，这是在我们假设对排序元素唯一能做的操作是比较它们时，排序算法所能达到的最优复杂度。

如果我们的元素都是介于 1 到`n`之间的整数，并且共有`m`个元素，则可以使用桶排序在`O(n + m)`时间内完成排序。该算法首先为 1 到`n`之间的每个数字创建一个计数向量，这需要`O(n)`时间。然后遍历序列中的`m`个元素，每当遇到数字`i`时就更新其计数器，此步骤耗时`O(m)`。最后，遍历从 1 到`n`的这些数字，根据计数器的指示输出每个数字对应的次数，耗时`O(n + m)`。

请实现桶排序。

另一种基于递归的算法是快速排序，其期望时间复杂度为`O(n log n)`。它的最坏情况复杂度实际上是`O(n²)`，但平均情况下运行时间为`O(n log n)`，且开销比归并排序小（如果实现正确的话）。

其工作原理如下：
```python
def quick_sort(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[random.randint(0, len(arr)-1)]
    left = [x for x in arr if x < pivot]
    middle = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]
    return quick_sort(left) + middle + quick_sort(right)
```
基本情况（单个元素）与归并排序相同。当有多个元素时，随机选择序列中的一个元素作为基准（pivot）。然后将序列拆分为小于基准的元素、等于基准的元素和大于基准的元素。递归地对较小元素和较大元素的序列进行排序。最后依次输出所有已排序的较小元素、等于基准的元素以及已排序的较大元素。

请实现快速排序。

### 选取第 k 小的元素

如果你有`n`个元素，并想要其中最小的`k`个，一个简单的解决方案是对元素排序，然后选取第`k`个。这种方法通常效果不错且在多数情况下足够快，但实际上可以更快地完成。因为，我们并不需要完全排序所有元素，只需将第`k`小的元素移动到序列中的第`k`个位置即可。

上一练习中的快速排序算法可以修改来解决此问题。每当我们根据基准将序列拆分为较小、等于和较大三部分时，我们递归地对较小和较大的元素进行排序。如果我们只关心最终会排在第`k`个位置的元素，那么我们就不需要对不包含此索引的序列进行排序。假设有`m < k`个元素小于基准，我们可以将它们直接置于序列前端而无需排序。我们需要它们在那里，以确保第`k`小的元素能出现在正确的位置，但不需要它们有序。类似地，如果`k < m`，我们则无需排序较大的元素。因为即使排序它们，它们最终也会位于大于`k`的索引位置，而我们并不关心这些。当然，如果有`m`个元素小于基准，`l`个元素等于基准，且满足`m + l ≥ k`，那么第`k`小的元素就等于基准，我们可以直接返回它。

请实现此算法。

# 附录 B：Scrall 概述

`Scrall`（Starr 的精炼关系型动作语言）是我们在本书中用于指定模型动作的伪动作语言。你可以在[`www.executableuml.com`](http://www.executableuml.com)找到该语言最完整和最新的描述。现在，我们仅介绍本书中使用的该语言的各个方面，以便为文本中的叙述性解释提供更多上下文。

## 原则

与 `xUML` 的类模型和状态模型方面一样，动作语言必须是可执行的且与平台无关。`Scrall` 被设计为与 `xUML` 执行语义保持一致。同时，它也力求易于读写。

### 名称

`Scrall` 被设计为可读性强，同时避免不必要的冗长，将繁重的工作委托给解析器和高级编辑工具。模型元素、变量和值的名称可以包含空格，但必须注意不要将关键词嵌入到以空格分隔的名称中。为了最大限度地提高空格的舒适使用度，我们尽力定义了尽可能少的关键词。因此，像 `the shift spec` 这样的变量名是完全合法的。这种方法与那些试图通过引入冗长的关键词短语来提高可读性的语言设计不同。

## 变量类型

变量有三种类型：实例集变量、标量变量和关系变量。本书中只使用前两种，因此我们在本附录中仅对关系变量进行简要描述。

### 实例集变量

实例集变量的类型是本地域中的一个类，它指向该类的零个、一个或多个实例。

### 关系变量

关系是由一组属性/数据类型对与一组元组交叉构成，每个元组为每个属性提供一个值。可以有零个、一个或多个元组被赋值，以及零个、一个或多个属性/数据类型对。关系变量持有一个可以可视化为表的关系（即使关系实际上并不是一个表）。元组是关系的一个简单特例，因此不需要额外的元组变量类型。以下是对这样一个变量赋值的例子：

```
acdata #= /R8/Aircraft.(ID, Altitude, Airspeed)
```

这里，`acdata` 关系变量持有一个关系，其属性:数据类型对为 `ID`: `Tail Number`，`Altitude`:`MSL Altitude`，和 `Airspeed`:`K`，并且有一个元组为 `Aircraft` 的每个实例提供一组相应的值。同样，可以很容易地将其可视化为一个表，表头是属性，每一行代表 `Aircraft` 的一个实例。`#=` 赋值运算符隐式地将 `acdata` 类型化为关系变量。

### 标量变量

在我们上下文中的术语“标量”意味着“非关系”。标量变量持有一个属于由数据类型定义的集合的单一值。数据类型的定义与类中实例数据的关系组织是正交的。系统提供的标量数据类型示例有 `integer`、`real`、`rational` 和 `string`。按照惯例，系统类型使用小写名称。用户自定义类型的一个例子可能是 `GPS Coordinate`。按照惯例，用户类型的所有首字母大写——例如，`Compass Heading`。

### 数据类型

数据类型定义了一组标量值以及可以在该集合的成员上执行的操作。系统提供的数据类型通常是 `boolean`、`integer`、`real` 和 `string`。用户自定义类型如 `GPS Coordinate`、`Pressure` 或 `License Number` 可以基于这些类型的限制、扩展和结构组合来构建。

可以使用中缀、前缀和后缀运算符，以及使用 `.` 符号访问的名称来执行操作。例如，`Count` 数据类型可以定义为取值范围在 `[0..maxint]` 内的整数，支持的操作包括 `incr`、`decr` 和 `reset`。

`++cars passed` 或 `cars passed.incr` 都可能调用为 `Count` 类型定义的增量操作。`cars passed.reset` 可以将值设置为零。

`current latitude = position.latitude` 调用了 `GPS position` 类型上的纬度访问器。

## 系统变量

系统提供的变量以下划线为前缀。例如，`_now` 为任何 `xUML` 域中的模型提供当前时间。为了让模型能够在尽可能多的 `MX` 域上运行，系统变量很少。

```
Time logged in = _now.HMS
```

这里，`_now` 系统变量调用了系统定义的 `HMS` 运算符，该运算符返回以小时、分钟和秒表示的时间。该赋值隐式地将左侧的变量类型化为标量变量。

## 无字面量

动作中不能指定字面量值。其思想是将数据的编码从动作语言中剔除，并将其归入它通常所属的地方，即类模型中的实例数据。提供了允许访问特殊值（如 pi、零等）的机制。但在所有情况下，这些都是在动作语言本身之外定义的命名值。例如，可以在类图上使用标准 UML 表示法指定默认的初始值。双下划线引用在状态模型之外某处定义的命名值，如 `__pi`、`__0`。请注意，对于前面描述的、类型化为 `Count` 的变量，可以通过调用 `reset` 操作将其设置为零。

## 布尔值

使用 `set` 和 `unset` 操作代替对字面量 `true` 和 `false` 的显式赋值。

示例：

*   `Injecting.set` ⇒ 设置为 true

*   `Injecting.unset` ⇒ 设置为 false

*   `if not Injecting ...` ⇒ 测试状态

## 枚举值

虽然禁止使用字面量，但可以定义枚举数据类型值。一个 `Fluid State` 数据类型可能枚举出 `low`、`very low`、`empty` 和 `normal` 等值。要引用一个枚举值，在其前面加上 `.`。

```
Level = .very low
```

如果左侧是一个属性，它已具有类型，在本例中可能为 `Fluid State`。如果是标量变量，则可能需要使用 `::` 类型声明运算符显式指定其类型。

```
level var::Fluid State = .full
```

枚举值中允许包含空格。

## 赋值运算符

变量在赋值运算符左侧首次出现时会被隐式地确定类型。也可以使用 `::` 运算符显式地对它们进行类型化，虽然这通常不是必需的。

| 运算符 | 含义 |
| :--- | :--- |
| `.=` | 赋值零个或一个实例。如果找到多个实例，则会产生错误。通常与一组标识符值一起使用以选择一个实例。 |
| `..=` | 将零个、一个或多个实例赋值给一个实例集变量。 |
| `.=.` | 从一组实例中任意赋值一个单一的实例，如果未找到则赋值无实例。 |
| `=` | 赋一个标量值。 |
| `#=` | 赋一个关系。 |

### 实例选择

要选择一个实例，请指定一个类名，后面可选地跟圆括号内的选择条件。

### 无条件选择

选择类的单例实例时不需要条件。

```
the shift spec .= Shift Specification
```

上述语句选择了 `Shift Specification` 类的单一实例。因为没有提供条件，并且在一个单例类中只有一个实例，因此该实例被选中。如果未找到任何实例，则会发生错误。

或者，可以选择一个类的所有实例：

```
all aircraft ..=Aircraft
```

因为没有指定条件，实例集变量 `all aircraft` 将包含对 `Aircraft` 所有实例的引用。如果当前不存在 `Aircraft` 的实例，则该变量将引用零个实例。

### 条件选择

支持常用的比较运算符（`>`、`>=` 等）。`:` 符号代表 `==`，因为在最常见的情况下，您希望匹配一个值，例如选择具有匹配 ID 的实例。从概念上讲，您是在寻找一个匹配项，因此使用一个符号。将其理解为 `matches`。

例如：

```
my station .= Duty Station( Number: in.Station )
```

这选择了 `Duty Station` 类中其 `Duty Station.Number` 与输入参数值匹配的单一实例。

布尔运算符如 `and`、`not` 和 `or` 可以混用。为方便起见，`,` 分隔符被解释为 `and` 运算符。`:` 和 `.` 运算符的组合使得可以基于一组匹配值轻松选择单个实例，而无需使用一连串的 `and` 和 `==` 符号。

```
landing runway .= Runway( Airport: in.airport code, Runway ID: in.runway )
```

这选择了 `Runway` 类中与两个值匹配的实例。假设这两个值组合起来对于 `Runway` 类是唯一的。如果找到多个实例，则会发生错误。

```
high fast aircraft ..= Aircraft( Altitude > high alt and Airspeed > high speed )
```

这将选择所有高于特定高度且速度快于特定速度的飞行器。

## 关系导航

`/` 符号表示跨类模型关系的跳转。最左边的 `/` 表示以本地实例为起点的关系路径表达式的开始。

```
hoff zone .= /R2/Control Zone( Name: in.Zone )
```

右侧的路径表达式从本地实例开始，跨过`R2`关系，到达`Control Zone`类中的所有相关实例。选择条件将集合缩小到其`Name`属性与`in.Zone`值匹配的单个实例。假设`Name`属性是`Control Zone`的标识符，则应将零个或一个实例赋值给左侧。

关系名称（R1、R2等）、动词短语和类名可以出现在跳转分隔符之间，以定义明确的选取路径。

## 信号发送

要发送信号，请使用以下表达式：

```
(params) [after ] -> instance set
```

例如：

```
Low injection pressure -> /R3/Reservoir
```

这里一个事件被发送给链接的实例。如果目标实例集中有多个实例，则每个实例都将接收到一个单独的事件。

一个实例可以通过使用`me`关键字向自身发送事件。该关键字代表本地状态机。

```
Injection canceled -> me
```

赋值器状态模型不引用任何本地实例，但因为`me`关键字引用的是本地状态机，因此也可以在那里用于自定向事件。

可以指定一个延迟，如下所示：

```
Good injection -> me after /R4/Injector Design.Good injection duration
```

这里`Good injection`事件在`Injector Design`中指定的持续时间之后发送。沿`R4`的关系可能是一对一的。如果路径表达式没有恰好选择一个实例，则会发生错误。

## 链接/解除链接

关联运算符是`link &`、`unlink !&`和`swap`。

格式如下：

```
[] & /
```

可选的左侧实例集中的每个实例都与右侧集沿路径引用的每个实例进行链接。如果未指定左侧的实例集，则默认为本地实例。

```
& /R3/my station
```

这将本地实例链接到变量沿`R3`引用的每个实例。

如果关联由一个关联类形式化，则将为每个链接创建一个关联类的实例。所需的引用属性将被设置为适当值以引用每个参与的类实例。任何其他属性都将设置为其默认初始值。

另一种链接方式是设置关联上的一组引用属性的值，以匹配关联另一侧的相应标识符属性的值。通常，使用`link`操作更安全。

`unlink`运算符是`!&`，使用的格式与`link`操作相同：

```
!& /R5/takeoff runway
```

这将本地实例从变量`takeoff runway`沿`R5`引用的所有实例中解除链接。

另一种解除链接的方法是直接删除持有引用另一侧关联的引用属性的实例。

在一对一关联中，重要的是不要让关联处于未连接状态。为避免这种情况，请使用`swap`运算符代替一对`link`和`unlink`操作：

```
swap // with  [on ]
!new missing: 
!old missing: 
swap /R2/hoff zone with new controller    [handed  off]
!new missing: UI.Unknown controller( Controller: in.Controller)
!old missing: UI.Zone not handled by( Controller: ID)
!handed off {
// further actions assuming handoff succeeded
}
```

`swap`操作下的错误条件将在接下来解释。

## 错误处理

某些操作可能触发无法恢复的错误。每个此类错误都会设置一个命名守护。这些名称是操作为其预定义的。如果该错误实际上是可恢复的，建模者可以指定内部响应，并使用`[]`守护设置括号来设置可选的用户定义守护，以调节下游处理。

在`swap`操作示例中，为操作预定义了两个守护：`new missing`和`old missing`。在`swap`操作右侧设置了一个用户定义守护，如果发生任何错误，该守护将被禁用。为两个可能的错误各指定了一个单一操作，使它们都可恢复。如果两个错误均未发生，则`handed off`守护不会被禁用，并且可以指定与该守护关联的操作块。

```
my station .= Duty Station( Number: in.Station ) [station OK]
!empty: UI.No such station( Number: in.Station )
!station OK {
// 假设已选择站点的操作
}
```

这里的`.=`赋值操作预定义了两个错误：`empty`和`many`。如果两者都被忽略，它们就是不可恢复的。通过插入`!empty`子句，建模者表明空情况是可以接受的，并且存在一个响应。请注意，在之前的单例选择示例中，该错误应该是不可恢复的。如果发生`empty`错误，`station OK`守护会被禁用，并且可用于启用进一步处理。

如果有多个操作要执行，可以将它们括在括号内形成一个操作块。否则，错误名称后跟一个`:`。

### 子类迁移

`migrate`操作删除一个子类中的本地实例，在另一个子类中创建它，并将新的子类实例关联到其父超类：

```
migrate [] to
```

集合中的所有实例都会被迁移到目标子类。如果省略实例集合，则仅迁移本地实例：

```
migrate to On Duty Controller
```

如果本地实例是`Off Duty Controller`，它将被迁移到`On Duty Controller`子类。

这是一个便捷操作，它替代了原本需要的相应创建和删除操作，并确保正确进行迁移，而不会破坏模型的完整性，例如留下一个非法的孤立子类实例。

## 与外部域的交互

除了对系统提供的下划线变量的特殊访问外，还有两种方式可以在运行时与其他域进行交互。

### 异步：向外部实体发送信号

这里会向一个外部实体发送信号，然后该实体负责以某种形式将该信号调解到另一个域。与常规事件不同，异步信号不指向外部域中的任何特定实例。它只是将信号发送到外部实体。

```
Start monitoring => SIO
=>
```

当你想要向外部域发出活动信号并期望在未来某个不确定的时间点得到异步响应时，可以使用此方法。

这里警告信号被发送到作为代理的外部实体UI，推测是用于UI域。

### 同步：在外部实体上调用操作

这里是与外部域进行即时且完整的交互。可能会返回值，也可能不会，但不会触发进一步的外部活动。

```
UI.Warning( MSG Control Zones Active, ID )
.
```

## 自我引用

当向自身发送信号时，`me`关键字指的是当前状态机实例。在实例生命周期状态活动中，这对应于本地实例的状态机。在分配者状态活动中，没有类实例，因此`me`指的是分配者状态机实例。

## 向分配者状态机发送事件

分配者状态机附加于一个竞争性关联——即具有约束多重性（一侧或两侧为1）的关联，其中两侧的实例同时尝试相互链接。

在这种情况下，该关联绑定到一个或多个解决竞争的状态机。这称为单一分配者关联。如果一侧的所有实例都可以链接到另一侧的所有实例，则一个单一分配者就足够了。但如果关联一侧的实例可能只能链接到另一侧的一个子集，则需要为每个子集提供一个单独的分配者状态机。这称为多重分配者关联。

向分配者状态机发送事件的格式取决于目标竞争性关联是单一分配者还是多重分配者。

对于单一分配者，执行以下操作：

```
-> /assigner
Customer waiting -> /R2/assigner
```

对于多重分配者：

```
-> ()
Group ready -> /R6/assigner(/R5/Signal Converter)
```

分区实例是通过某种关联，将参与竞争性关联的一个类分割成子集的实例。

在这两种情况下，事件都是发送给单个分配者状态机，而不是任何实例生命周期状态机。

### 类方法

通过在实例集变量上使用点符号来调用类方法。如果集合包含多个实例，则每个实例的本地方法都会被调用。

```
allAircraft ..= Aircraft // 选择所有飞机
allAircraft.verifyPosition() // 并发应用于每个实例
Aircraft.verifyPosition() // 执行相同操作，无需实例集变量
```

活动的输入参数可作为`in.<parameter name>`使用。

当为类方法调用或任何其他需要参数列表的操作指定参数列表时，格式如下：

```
( : value, ... )
```

有一些简化表达的快捷方式。如果参数名称和提供值的变量名称相同，则可以省略参数名称。

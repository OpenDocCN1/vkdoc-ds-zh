# 提示移交

当写入一行数据时，如果一个或多个副本节点处于下线或不可用状态，此功能会非常实用。在这种情况下，协调节点会将数据副本保留在 `system.hints` 表中，直到副本节点恢复正常运行。这通常是一个很好的特性，但如果此类故障发生在多个节点上，则会增加协调节点的堆内存大小。`system.hints` 表保存了副本节点的 IP 地址以及需要在该副本节点恢复时重放的实际数据。在引导过程中，系统表会被加载到内存中，因此故障数量越多，意味着协调节点内存中的数据量越大。此类场景还可能导致数据丢失（直到修复为止）。默认情况下，此功能是启用的。禁用它可能会导致堆内存相对较小，并减少垃圾回收活动。但为了写入的持久性，建议保持启用状态。默认情况下，协调节点会将数据在 `system.hints` 表中保留 3 小时，即 `Cassandra.yaml` 文件中配置项 `max_hint_window_in_ms` 的默认值。如果副本节点在此配置的时间窗口内未能恢复，则会被视为死节点，待其恢复后，需要运行修复并从其他节点复制数据。
